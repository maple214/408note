## 一、本章知识框架

本章是全书的**计算核心章**，主线只有一句：**网络层负责把分组从源主机送到目的主机，跨越许多不同的物理网络**。围绕这句话，展开成五块：

```text
网络层要解决的问题
    │
    ├─ ① 怎么把"异构网络"连成一张网？→ 虚拟互连网络（IP 层屏蔽底层差异）
    │        向上提供：无连接、尽最大努力交付的服务
    │
    ├─ ② 靠什么把分组送到目的地？→ 路由与转发
    │        路由算法（控制平面）：静态/动态、距离-向量、链路状态、层次路由
    │        转发表（数据平面）：最长前缀匹配
    │        → 新思路：SDN 把控制平面与数据平面分离
    │
    ├─ ③ 地址与协议怎么定？→ IPv4 这一整套
    │        分组格式（首部字段）→ 分片计算
    │        地址（分类 / 子网划分 / CIDR）→ 路由聚合、最长前缀匹配
    │        配套协议：ARP、DHCP、ICMP
    │        NAT：地址不够用时的续命方案
    │
    ├─ ④ 地址真的不够了怎么办？→ IPv6（128 位、简化首部、过渡技术）
    │
    └─ ⑤ 大规模网络怎么跑？→ 路由协议（自治系统、RIP、OSPF、BGP）
             特殊场景：IP 组播、移动 IP
             落地设备：路由器（组成、路由表 vs 转发表）
```

**三条抓手**（做题时先想清楚在哪一条上）：

1. **"地址"链**：IP 地址 → 子网掩码 → `CIDR` 前缀 → 地址块 → 路由聚合 → 最长前缀匹配。**这是本章唯一的大题主战场，必须练到条件反射。**
2. **"分组"链**：首部格式 → 总长度/标识/标志/片偏移 → `MTU` 约束 → 分片与重组。**数字都是 8 的倍数、字节为单位，全靠细心。**
3. **"协议"链**：`ARP` 管"IP → MAC"、`DHCP` 管"自动拿地址"、`ICMP` 管"报错和探测"、`RIP/OSPF/BGP` 管"怎么算路"。**四条链各管一件事，别混。**

**一句话记忆**：`IP` 提供"尽力而为的送货服务"，`路由协议`负责"画地图"，`ARP/DHCP/ICMP` 是"三件配套工具"，`子网划分与 CIDR` 是"给地址编号的规则"。

## 二、概念详解

### 4.1 网络层的功能

**为什么要有网络层**：数据链路层只能把帧送到**同一个局域网**内的另一台机器（`MAC` 地址只在本地有效）。要让全世界的主机能互相通信，必须有一层"跨网络"的机制。

网络层的核心任务就是四个字：**异构网络互连**。具体包含：

| 功能 | 说明 |
| --- | --- |
| 异构网络互连 | 用路由器把不同类型的物理网络（以太网、`WiFi`、`4G`）连起来 |
| 路由与转发 | 路由 = 确定路径（控制平面）；转发 = 按表把分组从入端口挪到出端口（数据平面） |
| 拥塞控制 | 防止网络内部因分组过多而吞吐量崩塌 |
| 网际互连（`IP`） | 向上提供统一的 `IP` 服务，屏蔽底层差异 |

**异构网络互连与"虚拟互连网络"**：各种网络的帧格式、`MAC` 地址、`MTU` 都不同，直接互连很麻烦。`IP` 的做法是**在链路层之上再压一层统一的 `IP` 层**，让所有主机看到的都是"一个统一的 `IP` 网络"——这就是**虚拟互连网络（`IP` 网）**。

关键理解：**路由器在转发时，会剥掉旧的链路层首部和尾部，再按出接口的链路层协议重新封装**。所以 `IP` 分组在穿越不同网络时，**`IP` 首部基本不变，帧首部一直在换**。

**网络层提供的服务：无连接、尽最大努力交付**：

- **无连接**：发送前不建立连接，每个分组独立选路（可能走不同路径）。
- **尽最大努力交付（`best effort`）**：不保证可靠、不保证顺序、不保证不丢、不保证时延。可靠性交给上层（`TCP`）。
- 这样设计的原因：**简单 → 路由器便宜、快、可扩展**；把复杂度和可靠性放到端系统去做。

> **408 怎么考/常见坑**：选择题常问"网络层向上提供什么服务"。答案要点是**无连接、尽最大努力交付**，不要选"面向连接"或"可靠传输"。坑：`IP` 协议本身不可靠 ≠ 网络层不能有可靠协议；`TCP` 的可靠性是传输层的。

**路由与转发（务必分清）**：

| 概念 | 所在平面 | 做什么 | 依据 |
| --- | --- | --- | --- |
| 路由（`routing`） | 控制平面 | 用路由算法**算出**到各目的网络的路径 | 路由协议（`RIP`/`OSPF`/`BGP`） |
| 转发（`forwarding`） | 数据平面 | 按**转发表**把分组从入端口送到出端口 | 转发表（由路由表导出） |
| 路由表 | 控制平面产物 | 记录"目的网络 → 下一跳" | 手工配置或路由协议生成 |
| 转发表 | 数据平面使用 | 由路由表**优化**而来，常含前缀与出接口 | 硬件快速查找 |

> **408 怎么考/常见坑**：常考"路由表与转发表的区别"。要点：**路由表是算出来的（软件、可能几十万条），转发表是查的（硬件、为快速匹配而优化）**；路由表给"下一跳"，转发表可细化到"出接口 + `MAC`"。另有坑：转发是**逐跳**的，每跳只知道下一跳，不知道全程。

**`SDN` 基本概念（软件定义网络）**：传统路由器把"算路"和"转发"捆在一个盒子里。`SDN` 把它们**拆开**：

- **控制平面集中化**：一个逻辑集中的 `SDN` 控制器掌握全网视图，统一计算路由。
- **数据平面简单化**：交换机只按**流表**（`flow table`）执行"匹配 + 动作"，不再自己算路。
- **开放接口**：控制器通过**南向接口**（如 `OpenFlow`）下发流表给交换机；通过**北向接口**给应用提供编程能力。
- **流表**：表项通常包含"匹配字段（如源/目的 `IP`、端口）+ 动作（转发/丢弃/修改）+ 计数器"。

> **408 怎么考/常见坑**：一般只考"`SDN` 的核心思想是什么"——**控制平面与数据平面分离、控制逻辑集中、网络可编程**。坑：不要说"`SDN` 取消了路由算法"，算法还在，只是搬到了控制器上；也不要把 `SDN` 和 `NFV` 混为一谈。

**拥塞控制**：网络中的分组太多，超过网络的处理能力，导致吞吐量下降、时延剧增。

- **开环控制**：**事前**预防，设计时就定好策略，运行中不根据当前状态调整（如：好的路由算法、`TCP` 拥塞窗口策略的初始设计、丢弃策略）。
- **闭环控制**：**事后**反馈，根据实时监测（如链路利用率、队列长度、丢包）动态调整（如：`ICMP` 源点抑制——已废弃、`TCP` 的拥塞控制算法）。

**拥塞控制 vs 流量控制**：

| 项目 | 拥塞控制 | 流量控制 |
| --- | --- | --- |
| 关注对象 | **整个网络**的负载 | **接收方**的处理能力 |
| 目的 | 防止网络过载崩塌 | 防止发送方淹没接收方 |
| 范围 | 全局性 | 点对点 |
| 典型手段 | 开环/闭环、`TCP` 拥塞窗口 | 滑动窗口、`TCP` 接收窗口 |

> **408 怎么考/常见坑**：常见考法是给一个场景问"这是流量控制还是拥塞控制"。判断口诀：**看瓶颈在"接收方"还是"网络"**。坑：把 `TCP` 的"发送窗口 = min(接收窗口, 拥塞窗口)"乱拆；接收窗口管流量控制，拥塞窗口管拥塞控制。

### 4.2 路由算法

**静态路由 vs 动态路由**：

| 项目 | 静态路由 | 动态路由 |
| --- | --- | --- |
| 配置方式 | 管理员手工配置 | 路由协议自动学习 |
| 适应拓扑变化 | 不能（需人工改） | 能自动适应 |
| 开销 | 无协议开销 | 有计算与报文开销 |
| 适用 | 小型、稳定网络；默认路由 | 大型、变化的网络 |
| 安全性 | 高（不被欺骗） | 低（可能被恶意路由） |

> **408 怎么考/常见坑**：常考"默认路由"（`0.0.0.0/0`）属于**静态路由**，用于减少转发表项数。坑：静态路由不是"不能转发"，只是不会自适应；动态路由也不是"一定最优"。

#### 4.2.1 距离-向量路由算法

**思想**：每个路由器只知道自己到**邻居**的代价，以及邻居"自称"到各目的地的代价。基于 `Bellman-Ford` 方程：

```text
D(x, y) = min { cost(x, v) + D(v, y) }      v 取遍 x 的所有邻居
```

人话：**"我到目的地的最短距离 = 邻居报给我的距离 + 我到邻居的距离"，取最小**。

**算法流程（考试就按这个流程写）**：

```text
① 初始化：只有直连网络的距离已知，其余为无穷大
② 每个路由器每 30 秒（RIP）把自己的整张路由表发给所有邻居
③ 收到邻居 v 的报文后，对报文中的每一个表项 (目的 y, 距离 d)：
     新距离 = d + cost(自己, v)
     若 下一跳本来就是 v      → 无条件替换为 (y, 新距离, 下一跳 v)   ← 关键！
     否则与本地表项比较，新距离更小 → 替换；否则不变
④ 若本地表发生变化，继续向邻居通告（触发更新）
⑤ 距离 = 16（RIP）视为不可达
```

**为什么"下一跳相同就无条件更新"**：因为该表项本来就是从 `v` 学来的，`v` 说"变远了"，说明路径断了或变差了，必须跟着改。**这条规则是距离-向量计算题的最大考点。**

**"坏消息传得慢"（计数到无穷）**：某网络断掉后，坏消息要靠"邻居一个接一个地把距离 +1"才能传遍全网，收敛极慢。例如 `R1` 到 `N` 的网络断了，`R2` 之前记录"经 `R1` 到 `N`，距离 2"，`R1` 又听 `R2` 说"经 `R2` 到 `N`，距离 2"，于是 `R1` 更新为 3……两者互相"喂"着往上加，直到 16 才停下。

**解决办法**：

- **水平分割（`split horizon`）**：从某个接口学到的路由信息，不再从这个接口发回去。
- **毒性逆转（`poison reverse`）**：从某接口学到的路由，从该接口发回时把距离置为**无穷大（16）**，明确"此路不通"。
- **触发更新（`triggered update`）**：拓扑一变立刻通告，不等 30 秒周期。

> **408 怎么考/常见坑**：计算题给三张路由表，让你写出更新后的表。坑：① 忘了"下一跳相同无条件更新"；② 忘了自己到邻居的代价要**加进去**；③ 比较时不是比"报文距离"，而是比"报文距离 + 链路代价"；④ 把 16 当普通数字继续算。

#### 4.2.2 链路状态路由算法

**思想**：每个路由器**掌握全网拓扑**（通过洪泛 `LSA`），然后各自用 `Dijkstra` 算最短路径树。

**流程**：

```text
① 发现邻居，测量到每个邻居的代价
② 构造链路状态分组（`LSA`）：我是谁、我的邻居是谁、代价多少
③ 洪泛（`flooding`）：把 `LSA` 发给所有其它路由器（不只是邻居）
④ 每个路由器据此拼出全网拓扑图
⑤ 运行 `Dijkstra` 算法，算出到自己到各目的地的最短路径，填入路由表
```

**`Dijkstra` 要点（考试要求手算）**：

```text
① 把源点加入"已确定集合 S"，其余为候选集合
② 每轮：在候选点中选一个 D 值最小的加入 S
③ 用新加入的点松弛所有未加入的邻居：若 D(新) + cost < 旧 D，则更新
④ 重复直到所有点加入，得到最短路径树
```

> **408 怎么考/常见坑**：可能考"链路状态算法需要什么信息"——**全网拓扑**。坑：`LSA` 是**洪泛**给全网，不是只给邻居（那是距离-向量）；每个路由器算出的结果应一致（因为看到的图相同）。

#### 4.2.3 距离-向量 vs 链路状态

| 项目 | 距离-向量 | 链路状态 |
| --- | --- | --- |
| 典型协议 | `RIP` | `OSPF` |
| 交换内容 | **整张路由表**（到所有目的地的距离） | **只是自己的链路状态**（邻居 + 代价） |
| 交换对象 | **仅相邻路由器** | **全网所有路由器**（洪泛） |
| 掌握的信息 | 只知道邻居的距离向量 | 掌握**全网拓扑** |
| 算法思想 | `Bellman-Ford`（分布式迭代） | `Dijkstra`（集中式计算、分布式收集） |
| 收敛速度 | 慢，有"坏消息传得慢" | 快 |
| 对网络变化的反应 | 局部、逐步传播 | 迅速全网泛起 |
| 资源开销 | 报文大（整表）、`CPU` 小 | 报文小（增量）、`CPU`/内存大 |
| 可扩展性 | 差（大网收敛更慢） | 好（分区后更佳） |

> **408 怎么考/常见坑**：最爱考"哪个用 `Dijkstra`、哪个用 `Bellman-Ford`"，以及"向谁通告什么"。一起记住口诀：**距离-向量：跟邻居唠整张表；链路状态：跟全网报自己**。

#### 4.2.4 层次路由

**为什么需要**：互联网规模太大，路由器不可能记住所有目的地的路由（路由表爆炸），也不可能让全网都跑同一个洪泛协议。

**做法**：把互联网划分为许多**自治系统 `AS`（Autonomous System）**，`AS` 内部再用自己的路由协议（**域内路由**，如 `RIP`/`OSPF`），`AS` 之间用**域间路由协议**（如 `BGP`）。

- **为什么用 `AS`**：① 路由表规模可控制（对外只通告聚合后的网络）；② 每个 `AS` 能自由选择内部协议；③ 支持策略（不同 `AS` 是不同管理方，各有利益诉求）。
- **`OSPF` 的区域（`area`）**：`OSPF` 把一个 `AS` 再划分为多个区域，区域内部用洪泛交换链路状态，区域之间通过**主干区域（`area 0`）**和**区域边界路由器 `ABR`** 通信。作用同样是**限制洪泛范围、减小链路状态数据库规模**。
- **为什么两级不够**：`AS` 数量也很多，`AS` 之间还需要再抽象（用 `BGP` 只交换"可达性"而非具体路径代价）。

> **408 怎么考/常见坑**：常考"层次路由的目的"——**减小路由表规模、限制路由信息传播范围**。坑：别把 `AS` 的区域（`OSPF` 的 `area`）和 `AS` 本身混了；`AS` 是互联网的划分，`area` 是 `OSPF` 内部的划分。

### 4.3 IPv4

#### 4.3.1 IPv4 分组格式

`IPv4` 数据报 = **首部 + 数据**。首部**固定部分 20 字节**，可选字段最长 40 字节，故首部最长 60 字节。

| 字段 | 长度 | 含义 | 考点 |
| --- | --- | --- | --- |
| 版本 | 4 位 | `4` 表示 `IPv4` | 送交哪个 `IP` 软件处理 |
| 首部长度 | 4 位 | **以 4 字节为单位** | 最小值 `5`（20 `B`），最大值 `15`（60 `B`） |
| 区分服务 | 8 位 | 服务类型 / `DSCP` | 一般忽略 |
| 总长度 | 16 位 | **首部 + 数据**，以**字节**为单位 | 最大值 `65535 B` |
| 标识 | 16 位 | 同一数据报的分片用**同一个标识** | 用于重组，计数器加 1 产生 |
| 标志 | 3 位 | `DF`（不分片）、`MF`（后面还有分片） | **最低位 `MF`，中间位 `DF`** |
| 片偏移 | 13 位 | **以 8 字节为单位** | `片偏移 = 该片数据起始字节 / 8` |
| 生存时间 `TTL` | 8 位 | 可经过的最大路由器跳数，每经一个路由器减 1，为 0 则丢弃并回 `ICMP` 超时 | 防止兜圈子 |
| 协议 | 8 位 | 数据交给哪个上层协议 | `ICMP=1`、`TCP=6`、`UDP=17`、`OSPF=89` |
| 首部校验和 | 16 位 | **只校验首部，不校验数据** | 每经一个路由器都要重算 |
| 源/目的地址 | 各 32 位 | `IP` 地址 | — |
| 可选字段 + 填充 | 0~40 `B` | 如记录路由、时间戳 | 填充保证首部是 4 字节整数倍 |

> **408 怎么考/常见坑**：① 常考"首部长度的单位是 4 字节、片偏移的单位是 8 字节、总长度的单位是 1 字节"——**三个单位别记混**；② 只校验首部、每跳重算；③ `TTL` 单位是**跳数**不是秒（早期设计是秒，现在按跳处理）；④ 标志位顺序：`DF` 在高位、`MF` 在低位，`DF=1` 表示"不许分片"。

#### 4.3.2 IP 分片计算（标准解法）

**为什么会分片**：数据链路层有 `MTU`（最大传送单元，以太网 `1500 B`）。`IP` 数据报超过 `MTU` 就必须切成片。

**关键约束（背下来）**：

```text
每片总长度 <= MTU
每片最大数据长度 = MTU - 首部长度（通常 20）
除最后一片外，每片的数据长度必须是 8 的整数倍   ← 因为片偏移以 8 字节为单位
每片的总长度 = 该片首部长度 + 该片数据长度
片偏移 = 该片数据在原数据报数据部分中的起始字节 / 8
MF = 1 表示"后面还有片"，最后一片 MF = 0
```

**标准解题四步**：

```text
第 1 步：算要分的"数据部分"长度 = 原总长度 - 原首部长度
第 2 步：算每片最多能装多少数据 = MTU - 首部长度，并向下取整到 8 的倍数
        （先向下取整到 8 的倍数，再确认加上首部不超过 MTU）
第 3 步：片数 = 向上取整(数据总长 / 每片最大数据长)
第 4 步：逐片写出【数据长度、总长度、MF、片偏移】，核对最后一片数据 = 总数据 - 前面各片之和
```

> **408 怎么考/常见坑**：① 最常见的错是**最后一片忘了 MF = 0**，或**把 MF/DF 的位置写反**；② 片偏移忘除以 8；③ 每片都带首部（不要以为只有第一片有）；④ 若能整除到 8 的倍数正好，则不要多切一片（如数据 1580 `B`、每片 600 `B`，是 3 片而不是 4 片）；⑤ 重组是**目的主机**的事，中间路由器不分片重组（`IPv6` 中连源主机以外都不分片）。

#### 4.3.3 IPv4 地址与 NAT

**点分十进制**：`32` 位分 4 组，每组 8 位，写成 `a.b.c.d`，每组 `0~255`。

**分类地址（经典分类，`CIDR` 出现前）**：

| 类别 | 首字节范围（十进制） | 首字节最高位特征 | 网络号位数 | 主机号位数 | 用途 |
| --- | --- | --- | --- | --- | --- |
| `A` | `1 ~ 126` | 最高位 `0` | 8 | 24 | 大型网络 |
| `B` | `128 ~ 191` | 最高两位 `10` | 16 | 16 | 中型网络 |
| `C` | `192 ~ 223` | 最高三位 `110` | 24 | 8 | 小型网络 |
| `D` | `224 ~ 239` | 最高四位 `1110` | — | — | **组播地址** |
| `E` | `240 ~ 255` | 最高四位 `1111` | — | — | 保留（科研） |

注意 `127` 不在表中：`127.0.0.0/8` 整块是**环回地址**。

**私有地址（`RFC 1918`，只在内网用，不出现在公网）**：

```text
10.0.0.0    ~ 10.255.255.255    （10.0.0.0/8，1 个 A 类块）
172.16.0.0  ~ 172.31.255.255    （172.16.0.0/12，16 个 B 类块）
192.168.0.0 ~ 192.168.255.255   （192.168.0.0/16，256 个 C 类块）
```

**特殊地址**：

| 地址 | 含义 |
| --- | --- |
| 网络地址（主机号全 `0`） | 代表"这个网络本身"，如 `192.168.1.0/24` |
| 广播地址（主机号全 `1`） | **直接广播**地址，如 `192.168.1.255` |
| `255.255.255.255` | **受限广播**（本网络广播），路由器不转发 |
| `0.0.0.0` | 本网络本主机；也用作**默认路由**的目的地址 |
| `127.0.0.0/8`（常写 `127.0.0.1`） | 环回地址，测试本机协议栈 |
| `169.254.0.0/16` | 链路本地（`DHCP` 失败时自动配置） |

> **408 怎么考/常见坑**：① 记牢各类**首字节范围**，尤其 `A` 类到 `126`、`B` 类从 `128` 开始（`127` 被环回占掉）；② "主机号全 0/全 1 不能用"指的是**主机地址**不可用，当作**网络地址/广播地址**使用；③ `0.0.0.0` 有两个身份（本机、默认路由），看语境。

**`NAT`（网络地址转换）**：

- **原理**：私有地址无法在公网路由。`NAT` 路由器在**出口处**把内部私有 `IP` 换成自己的公网 `IP`，回来时再换回去。关键是维护一张**转换表**。
- **`NAPT`（网络地址端口转换）**：只用**一个公网 `IP`** 时，靠**端口号**区分不同内网主机。转换表项形如 `(内网IP, 内网端口) ↔ (公网IP, 公网端口)`。这就是家用路由器"一个宽带账号带一堆设备上网"的原理。
- **优点**：节省全球 `IP` 地址；内网结构对外隐藏（一定安全性）；内网换 `IP` 不用改公网配置。
- **缺点**：破坏了**端到端**透明性；外部主机无法主动连接内网主机（要端口映射/`UPnP`）；某些协议（把 `IP` 写在应用层载荷里的，如 `FTP` 主动模式的 `PORT` 命令、`SIP`）需要 `ALG` 特殊处理。

> **408 怎么考/常见坑**：① 常考"`NAT` 路由器转发时改的是源 `IP` 还是目的 `IP`"——**出内网时改源，回来时改目的**；② 判断"公网能否 ping 通内网主机"——默认**不能**；③ 若只给一个公网地址，则必须用 `NAPT`（带端口），别答成纯 `NAT`。

#### 4.3.4 ARP 协议

**作用**：在**同一个局域网**内，把**已知的 `IP` 地址**解析成对应的 **`MAC` 地址**。因为数据链路层组装帧时，必须知道目的 `MAC`。

**四步流程（同网段）**：

```text
① A 查自己的 ARP 高速缓存，有 B 的 (IP, MAC) 就直接用
② 没有 → A 广播 ARP 请求帧（目的 MAC = FF-FF-FF-FF-FF-FF）
   内容："谁是 192.168.1.2？请告诉 192.168.1.1（我的 MAC 是 ...）"
③ 本网段所有主机都收到，但只有 IP 匹配的 B 处理，其余丢弃
④ B 单播 ARP 应答给 A；A 把结果写入 ARP 缓存（有生存时间，通常几分钟）
```

**跨网段通信（超级高频考点）**：

> A 要给**另一个网络**的 B 发 `IP` 分组。A 查路由表发现"不在本网段，得先给默认网关 `R`"。
> 于是 **A 的 `ARP` 请求解析的是网关 `R` 的 `MAC` 地址，不是 B 的 `MAC` 地址**。
> 之后 A 发出的帧：`目的 MAC = R 的 MAC`，`目的 IP = B 的 IP`。
> 路由器收到后剥掉帧头，按 `IP` 查转发表，再从出接口用**下一跳的 `MAC`** 重新封装。

**要点补充**：

- `ARP` 请求是**广播**，`ARP` 应答是**单播**。
- `ARP` 高速缓存有**生存时间**，过期要重新解析。
- **`ARP` 只在同一局域网（同一广播域）内使用，路由器不转发 `ARP` 请求**。
- `ARP` 通常归为**网络层**协议（有的教材说"介于网络层与数据链路层之间"），其报文**直接封装在以太网帧中**（`类型字段 = 0x0806`），**不封装在 `IP` 数据报里**。
- 免费 `ARP`（`gratuitous ARP`）：主机主动广播自己的映射，用于检测地址冲突、更新他人缓存。

> **408 怎么考/常见坑**：① 最大的坑就是"跨网段时解析谁的 `MAC`"——**网关的**；② 别答"`ARP` 请求发往目的主机的 `MAC`"，请求帧的目的 `MAC` 是全 `F` 广播；③ 别把 `ARP` 说成"解析域名"（那是 `DNS`）。

#### 4.3.5 DHCP 协议

**作用**：让主机**自动获取** `IP` 地址、子网掩码、默认网关、`DNS` 服务器等配置，免手工配置。

**为什么用 `UDP`**：`DHCP` 报文要发给"还不知道自己 `IP`"的主机，用 `UDP`（无连接、开销小、易广播）最合适。**服务器用 `67` 端口，客户端用 `68` 端口**。

**四步交互（`DORA`）**：

```text
① DHCP DISCOVER  客户端 广播："有没有 DHCP 服务器？我想要地址"
② DHCP OFFER     服务器 应答："我可以给你 192.168.1.10（含掩码/网关/DNS，租期）"
③ DHCP REQUEST   客户端 广播："我要用 192.168.1.10"（同时也通知其它服务器）
④ DHCP ACK       服务器 确认："准了，租期 xx"
```

- 第①步客户端源 `IP` 为 `0.0.0.0`，目的 `IP` 为 `255.255.255.255`（受限广播），源 `MAC` 是自己的，目的 `MAC` 广播。
- **为什么要 `REQUEST` 广播**：可能有多个服务器都发了 `OFFER`，客户端要**公开**声明选谁，让其余服务器收回预留。
- **租期与续租**：地址是"租"的，租期过半时客户端单播请求续租（`REQUEST`/`ACK`），失败可再试，到期未续则释放。

**中继代理（`DHCP relay agent`）**：`DHCP` 靠广播，而路由器**不转发广播**，所以每个网段都要有服务器？不必——在路由器上配置中继代理，把广播的 `DHCP` 报文**单播**转发给远端服务器，再把应答转回来。

> **408 怎么考/常见坑**：① 四步名字与顺序（`DISCOVER`/`OFFER`/`REQUEST`/`ACK`）；② 哪几步是广播（**`DISCOVER` 和 `REQUEST` 是广播**，`OFFER`/`ACK` 可单播）；③ `UDP 67/68` 与"为什么是 `UDP`"；④ 中继代理的作用；⑤ 别把 `DHCP` 和 `ARP` 的作用搞混（一个给"地址"，一个给"`MAC`"）。

#### 4.3.6 ICMP 协议

**作用**：`IP` 只负责尽力交付，出错时怎么办？用 `ICMP`（网际控制报文协议）**报告差错、提供询问**。`ICMP` 报文**封装在 `IP` 数据报中**（协议号 `1`）。

**两类报文**：

| 类型 | 具体报文 | 用途 |
| --- | --- | --- |
| 差错报告报文 | 终点不可达 | 网络/主机/协议/端口不可达 |
| | 时间超过 | `TTL` 减为 0、分片重组超时 |
| | 参数问题 | 首部字段有错 |
| | 改变路由（重定向） | 告诉主机"下次发给另一个路由器更合适" |
| 询问报文 | 回送请求和回答 | `ping` |
| | 时间戳请求和回答 | 测时延、时钟同步 |

**`ICMP` 不发送差错报文的几种情况（必背）**：

```text
① 对 ICMP 差错报告报文本身，不再发送差错报告
② 对非第一个分片的数据报片，不发送
③ 对具有多播（组播）地址的数据报，不发送
④ 对特殊地址（如 127.0.0.0 或 0.0.0.0）的数据报，不发送
```

（记忆：**"错不报错、片只看头、组播和特殊地址不惹"**）

**`ping` 与 `traceroute`**：

- **`ping`**：使用 `ICMP` **回送请求/回答**报文，测试连通性和往返时延 `RTT`。`ping` 不通≠主机不存在（可能被防火墙拦 `ICMP`）。
- **`traceroute`（`Windows` 下 `tracert`）**：利用 **`TTL` 从 1 逐次加 1**，每个路由器把 `TTL` 减为 0 时丢弃并回 `ICMP` **时间超过**报文，从而逐个暴露路径上的路由器；到达目的主机时，`traceroute` 故意使用一个**不可能使用的 `UDP` 端口号**，目的主机回 `ICMP` **终点不可达（端口不可达）**，据此判断"到了"。

> **408 怎么考/常见坑**：① 常考"`ping` 用了什么报文/`traceroute` 的原理"；② "哪几种情况不发 `ICMP` 差错报文"是经典多选/单选；③ `ICMP` 不是传输层协议、不用端口号，它**封装在 `IP` 里**；④ 坑：把 `ICMP` 说成"可靠传输协议"——它只报告差错，不纠正差错。

### 4.4 IPv6

**为什么有 `IPv6`**：`IPv4` 地址只有 `32` 位（约 43 亿），早就不够分。`CIDR` 和 `NAT` 只是续命，根本方案是**把地址扩到 128 位**。

#### 4.4.1 IPv6 的主要特点

```text
① 地址 128 位，空间大得几乎用不完（2^128）
② 首部固定 40 字节，字段精简，路由器处理更快
   取消了：首部长度、标识、标志、片偏移、首部校验和、可选字段
   新增了：流标签（flow label，20 位）
③ 取消了首部校验和 → 由上下层（数据链路层/传输层）保证，路由器不必重算
④ 分片只由源主机做：源主机先做路径 MTU 发现，超过就分片
   中间路由器不再分片（超了直接回 ICMPv6"分组太大"）→ 路由器负担更轻
⑤ 允许对网络资源预分配（流标签支持实时音视频等）
⑥ 地址自动配置（无状态自动配置，不依赖 DHCP）
⑦ 支持即插即用、更好的安全性（IPsec 原生化）
```

**`IPv4` 首部与 `IPv6` 首部字段对照**：

| 字段 | `IPv4` | `IPv6` | 说明 |
| --- | --- | --- | --- |
| 版本 | 4 位 | 4 位 | `4` / `6` |
| 首部长度 | 有 | **取消** | `IPv6` 首部固定 40 `B` |
| 区分服务 | 8 位 | 8 位（通信量类） | 改名 |
| 流标签 | **无** | **20 位** | 新增 |
| 总长度 | 16 位 | 16 位（净荷长度） | `IPv6` 只计**数据部分**长度 |
| 标识/标志/片偏移 | 有 | **取消** | 分片信息移到扩展首部，且只由源主机分片 |
| 生存时间 | 8 位 | 8 位（跳数限制） | 改名，语义仍是跳数 |
| 协议 | 8 位 | 8 位（下一个首部） | 指向上层协议或扩展首部 |
| 首部校验和 | 16 位 | **取消** | 减少路由器计算 |
| 地址 | 32 位 ×2 | 128 位 ×2 | — |
| 可选字段 | 有（首部内） | **移到扩展首部** | 基本首部之后可挂多个扩展首部 |

> **408 怎么考/常见坑**：常考"`IPv6` 相比 `IPv4` 取消了哪些字段""分片由谁做"。坑：`IPv6` 的**净荷长度不含首部**（与 `IPv4` 总长度含首部相反）；`IPv6` 不是"不校验"，是"不由 `IP` 层校验"。

#### 4.4.2 IPv6 地址

**表示法**：`128` 位，分成 `8` 组，每组 `16` 位，用**冒号十六进制**书写：

```text
完整写法（8 组，每组 4 个十六进制数字）：
2001:0db8:0000:0000:0000:ff00:0042:8329
```

**零压缩规则（两条，必须写对）**：

```text
① 每组开头的 0 可以省略：0db8 → db8，0042 → 42
② 连续的多个全 0 组可以用 "::" 代替，但 "::" 在整个地址中只能出现一次
```

```text
上面的地址压缩后：2001:db8::ff00:42:8329
```

**常见地址类型**：

| 类型 | 前缀 | 含义 |
| --- | --- | --- |
| 单播（`unicast`） | — | 一对一 |
| 组播（`multicast`） | `FF00::/8` | 一对多 |
| 任播（`anycast`） | — | 一组中"最近"的一个，`IPv6` 新增 |
| 链路本地 | `FE80::/10` | 同一链路上使用，自动配置 |
| 环回 | `::1` | 相当于 `IPv4` 的 `127.0.0.1` |
| 未指定 | `::` | 相当于 `IPv4` 的 `0.0.0.0` |

注意：**`IPv6` 没有广播地址**，广播的功能由组播承担。

**过渡技术**：

- **双协议栈（`dual stack`）**：一台设备同时装 `IPv4` 和 `IPv6` 两套协议，按目的地址决定用哪套。`DNS` 返回 `AAAA` 记录（`IPv6`）或 `A` 记录（`IPv4`）来决定。
- **隧道技术（`tunneling`）**：`IPv6` 分组要穿过只支持 `IPv4` 的网络时，把整个 `IPv6` 分组当成 `IPv4` 分组的**数据部分**封装起来，到了对端再拆开。**逻辑上是一条直连的 `IPv6` 链路。**

> **408 怎么考/常见坑**：① 常考"以下哪个是合法的 `IPv6` 地址写法"——重点检查 `::` 是否用了两次；② `FE80::/10` 是链路本地、`FF00::/8` 是组播，别混；③ 过渡技术就考两个名字和一句话原理；④ 坑：说"`IPv6` 地址 64 位"或"用点分十进制"。

### 4.5 路由协议

#### 4.5.1 自治系统与域内/域间路由

**自治系统 `AS`**：由**单一行政机构管理**、使用**统一路由策略**的一组网络与路由器的集合。每个 `AS` 有唯一编号。

- **域内路由（`intra-AS`）**：`AS` 内部的路由选择。目标简单——**找最短/最优路径**。协议：`RIP`、`OSPF`。
- **域间路由（`inter-AS`）**：`AS` 之间的路由选择。目标复杂——除了可达性，还要考虑**策略**（商业关系、安全、不转发他人流量）。协议：`BGP`。

> **408 怎么考/常见坑**：常考"为什么域间路由不能用 `OSPF`"——因为 `OSPF` 是链路状态，要求 `AS` 内共享全部拓扑，而 `AS` 之间**互不信任、不愿暴露内部结构**，也无法统一度量。域间路由首选**策略**而非最短路径。

#### 4.5.2 RIP 路由协议

- **类型**：内部网关协议，**距离-向量**算法。
- **度量**：**跳数**，直连网络为 `1` 跳。**最大 15 跳，16 表示不可达**（限制了网络直径 ≤ 15）。
- **通告**：仅向**相邻路由器**，每 **30 秒**广播一次自己的**整张路由表**。
- **传输**：基于 **`UDP`，端口 `520`**（应用层进程实现，报文封装在 `UDP` 中）。
- **特点**：实现简单、开销小；**收敛慢**，有"坏消息传得慢"问题（靠水平分割/毒性逆转/触发更新缓解）。
- **`RIP` 报文**：请求（`request`）和响应（`response`）两种。

> **408 怎么考/常见坑**：① 最常考**跳数上限 15、16 为不可达**；② "只和邻居交换、交换整张表、30 秒一次"；③ 计算题见下方例题；④ 坑：`RIP` 的度量不考虑带宽/时延，所以**会选出一条跳数少但很慢的路**。

#### 4.5.3 OSPF 路由协议

- **类型**：内部网关协议，**链路状态**算法，用 `Dijkstra`。
- **通告**：向**本区域所有路由器洪泛**链路状态（`LSA`）；只在**链路状态变化时**发送（增量），不是周期性全表。
- **传输**：**直接封装在 `IP` 数据报中，协议号 `89`**（不用 `TCP`/`UDP`）。
- **五种分组**：问候（`hello`）、数据库描述（`DBD`）、链路状态请求（`LSR`）、链路状态更新（`LSU`）、链路状态确认（`LSAck`）。
- **分层**：把 `AS` 划分为**区域（`area`）**，主干区域为 `area 0`；区域边界路由器 `ABR` 连接多个区域，自治系统边界路由器 `ASBR` 连接其它 `AS`。
- **优点**：**收敛快**、无"坏消息传得慢"、支持**多条等代价路径的负载均衡**、支持**可变长子网掩码**与认证、度量可基于带宽/时延。
- **问候分组的作用**：发现和维护邻居关系、选举指定路由器 `DR`/备份 `DR`（`BDR`）以减少邻接关系数量。

> **408 怎么考/常见坑**：① `OSPF` 用 `IP` 协议号 `89`、`RIP` 用 `UDP 520`——**这对数字是必背对比**；② "洪泛给全网 vs 只给邻居"；③ 五种分组名字；④ 坑：`OSPF` 虽叫"最短路径优先"，但它的度量可以是带宽等，不一定是跳数。

#### 4.5.4 BGP 路由协议

- **类型**：**外部网关协议**，**路径向量（`path vector`）**算法，用于 `AS` 之间。
- **传输**：基于 **`TCP`，端口 `179`**（保证可靠交付，因为 `BGP` 报文很重要且量大）。
- **两种会话**：`eBGP`（不同 `AS` 的边界路由器之间）、`iBGP`（同一 `AS` 内部的路由器之间）。
- **交换内容**：**到达某个网络所要经过的 `AS` 序列**（`AS-PATH`）等属性，而不是具体代价。
- **核心是策略**：`BGP` 力求找到一条**较好**（而不是最好）的路由，选择时综合考虑 `AS` 跳数、本地偏好、商业关系等策略。
- **四种报文**：打开（`OPEN`）、更新（`UPDATE`）、保活（`KEEPALIVE`）、通知（`NOTIFICATION`）。

> **408 怎么考/常见坑**：① `TCP 179`、路径向量、`eBGP`/`iBGP` 是常考点；② "`BGP` 为什么用 `TCP`"——需要可靠传输，且报文可能很长；③ 坑：说 `BGP` 用"最短路径优先"——它是**策略优先**，可能故意绕远。

#### 4.5.5 RIP vs OSPF vs BGP（必背对比表）

| 项目 | `RIP` | `OSPF` | `BGP` |
| --- | --- | --- | --- |
| 适用范围 | `AS` 内部（域内） | `AS` 内部（域内） | `AS` 之间（域间） |
| 算法类别 | 距离-向量（`Bellman-Ford`） | 链路状态（`Dijkstra`） | 路径向量 |
| 交换的信息 | 到所有目的地的**距离**（整张路由表） | 自己的**链路状态** | 到达某网络的 **`AS` 序列**与属性 |
| 交换对象 | 仅**相邻**路由器 | **全网/本区域内**路由器（洪泛） | `eBGP`/`iBGP` 邻居（`TCP` 连接） |
| 度量 | **跳数**（≤ 15，16 不可达） | 代价（可基于带宽/时延等） | 策略（`AS` 跳数、本地偏好、商业关系） |
| 传输层 | **`UDP`，端口 `520`** | **直接封装在 `IP`，协议号 `89`** | **`TCP`，端口 `179`** |
| 通告时机 | 每 **30 秒**周期广播 | 链路状态**变化**时增量洪泛 | 路由变化时通过 `TCP` 更新 |
| 收敛速度 | 慢 | 快 | 视策略与规模，通常较慢但可扩展 |
| 分层/规模 | 不分层，规模受限 | 划分**区域（`area 0` 主干）** | 面向全球 `AS` 体系 |
| 负载均衡 | 不支持（一般只留一条） | 支持等代价多路径 | 通过策略多路径 |
| 适用规模 | 小型网络 | 中大型网络 | 全球互联网 |

> **408 怎么考/常见坑**：这张表是选择题提款机。易错点：① `RIP` 的 15/16；② 端口与协议号（`520`/`89`/`179`）；③ 谁用 `Dijkstra`；④ `BGP` 是"路径向量"不是"距离向量"；⑤ 只有 `OSPF` 直接封装在 `IP` 里（不用 `TCP/UDP`）。

### 4.6 IP 组播

**为什么需要组播**：一台服务器要把同一份视频发给 1000 个用户。单播要发 1000 份（`n` 倍带宽），广播会打扰所有不想看的人。**组播**让发送方**只发一份**，由网络中的路由器**在分叉处复制**，送给"加入了组播组"的主机。

**概念要点**：

- **组播地址属于 `D` 类地址**（`224.0.0.0 ~ 239.255.255.255`），只用作**目的地址**，绝不作为源地址。
- **组播 `MAC` 地址**：`01-00-5E` 开头的以太网地址，由组播 `IP` 映射而来（`IPv4` 组播 `IP` 的低 23 位映射到 `MAC` 低 23 位，所以映射**不唯一**）。
- **`IGMP`（因特网组管理协议）**：让**主机**告诉**本地路由器**"我要加入/离开某个组播组"。它在主机与**直连**的组播路由器之间工作，**不负责**路由器之间的组播路由。
- **组播路由协议**：负责在路由器之间建立组播转发树（如 `DVMRP`、`PIM`）。考纲只要求**概念性了解**：转发时用"反向路径"检查避免环路，树形结构分为**源基树/共享树**等。
- **组播地址中还有一部分是保留的**（如 `224.0.0.1` 表示本子网所有主机、`224.0.0.2` 所有路由器），只在本地使用，路由器不转发。

> **408 怎么考/常见坑**：① 组播地址范围（`224~239`，`D` 类）是送分点；② `IGMP` 的作用范围（**主机 ↔ 直连路由器**，不跨路由器）最易错；③ 坑：说"组播地址可以作为源地址"；④ `IGMP` 是网络层协议，但报文封装在 `IP` 中（协议号 `2`）。

### 4.7 移动 IP

**问题**：一台主机从北京（`10.0.0.0/8`）搬到上海（`200.0.0.0/8`），`IP` 地址变了，正在进行的通信就断了。移动 `IP` 的目标是：**让主机在改变接入点时不改变自己的 `IP` 地址，通信不中断**。

**三个角色 + 一个地址**：

| 术语 | 含义 |
| --- | --- |
| 移动节点 | 会换位置的主机 |
| 归属代理（`home agent`） | 移动节点**原籍网络**上的路由器 |
| 外部代理（`foreign agent`） | 移动节点**当前所在网络**上的路由器 |
| 归属地址（永久地址） | 移动节点在原籍网络的 `IP`，**永远不变** |
| 转交地址（`care-of address`） | 移动节点在外部网络获得的临时地址 |

**通信过程**：

```text
① 移动节点进入外部网络，通过外部代理（或 DHCP）获得一个转交地址
② 移动节点向归属代理注册：告诉它"我在这个转交地址"
③ 通信对端发给移动节点的分组，按归属地址路由 → 到达归属代理
④ 归属代理用"隧道"把分组封装后转发给转交地址（外部代理或移动节点直接收）
⑤ 外部代理拆掉隧道封装，把原始分组交给移动节点
⑥ 移动节点回送的报文可以直接发给对端（三角路由问题），也可以再经归属代理
```

> **408 怎么考/常见坑**：① 考"归属地址不变、转交地址可变"；② 考归属代理/外部代理的分工；③ 坑：说"移动 `IP` 会给移动节点换 `IP`"（换了就没意义了）；④ 记住用的是**隧道**技术转发。

### 4.8 网络层设备：路由器

**路由器的组成（四个部分）**：

```text
① 输入端口：物理层接收 → 数据链路层拆帧 → 网络层查转发表（最长前缀匹配）→ 交给交换结构
② 交换结构（switching fabric）：把分组从输入端口搬到输出端口
      三类实现：通过存储器、通过总线、通过互连网络（如 Crossbar）
③ 输出端口：从交换结构取分组 → 加链路层首部 → 发到链路上（可能排队、可能丢弃）
④ 路由处理器（route processor）：运行路由协议、构造路由表、维护转发表
```

**关键理解**：

- **查表和转发在输入端口完成**（现代路由器）；**排队和丢弃可能发生在输入端口（`HOL` 队头阻塞）和输出端口（缓冲区溢出）**。
- **输入端口查表用的是转发表**（由路由表生成、为快速匹配优化的版本），而**路由表由路由处理器维护**。
- 路由器**隔离广播域**（不像交换机/集线器那样转发广播），但**不隔离冲突域**（每个端口就是一个冲突域）。

**路由表与转发表、最长前缀匹配的转发过程**：

```text
① 从分组首部取出目的 IP 地址
② 在转发表中用「目的网络前缀」逐条匹配，选中最长（最具体）的那一条
③ 按该表项的"下一跳"和"出接口"转发；若下一跳在直连网段，还需用 ARP 得到其 MAC
④ 没有任何前缀匹配 → 用默认路由 0.0.0.0/0；若连默认路由都没有 → 丢弃，回 ICMP 终点不可达
```

**路由器 vs 交换机（对比表）**：

| 项目 | 路由器 | 交换机（二层） |
| --- | --- | --- |
| 工作层次 | 网络层（第 3 层） | 数据链路层（第 2 层） |
| 转发依据 | `IP` 地址（转发表/路由表） | `MAC` 地址（`MAC` 地址表） |
| 是否隔离广播域 | **隔离**（不转发广播，除非配置） | **不隔离**（广播帧泛洪，`VLAN` 除外） |
| 是否隔离冲突域 | 隔离（每个端口一个冲突域） | 隔离（每个端口一个冲突域） |
| 表怎么来 | 人工配置或路由协议**计算** | **自学习**源 `MAC` 与端口的对应 |
| 主要功能 | 异构网络互连、路由选择、`NAT`、防火墙、`ACL` | 同一局域网内高速转发、扩展端口数 |
| 转发速度 | 较慢（需拆到网络层，查表更复杂） | 较快（硬件查 `MAC` 表） |
| 典型位置 | 网络边界、子网之间 | 局域网内部 |

> **408 怎么考/常见坑**：① "谁隔离广播域"是必考——**路由器隔离、交换机不隔离**（`VLAN` 能逻辑隔离）；② 路由器每个端口都是冲突域；③ 坑：说"路由器自学习 `MAC` 地址"（那是交换机）；④ "输入端口排队导致队头阻塞 `HOL`"偶尔考。

## 三、易混对比表

### 3.1 `RIP` vs `OSPF` vs `BGP`

见前文 **4.5.5** 的完整对比表，此处只记三句口诀：

```text
RIP ：邻居之间唠整表，跳数最多 15 跳，30 秒一次，UDP 520，收敛慢
OSPF：全网洪泛报自己，Dijkstra 算最短路，直接封装在 IP（协议号 89），收敛快
BGP ：AS 之间讲策略，交换 AS 路径，TCP 179，域间路由首选
```

### 3.2 `IPv4` vs `IPv6`

| 项目 | `IPv4` | `IPv6` |
| --- | --- | --- |
| 地址长度 | `32` 位 | `128` 位 |
| 地址写法 | 点分十进制 `192.168.1.1` | 冒号十六进制 `2001:db8::1` |
| 首部长度 | 可变（20~60 `B`） | **固定 40 `B`** |
| 首部校验和 | 有（每跳重算） | **取消** |
| 分片 | 源主机和**沿途路由器**都可分片 | **只有源主机**分片（路径 `MTU` 发现） |
| 分片相关字段 | 首部内有标识/标志/片偏移 | 首部内**没有**，信息放扩展首部 |
| 可选字段 | 首部内 | 移到**扩展首部** |
| 广播 | 支持广播地址 | **没有广播**，用组播代替 |
| 任播 | 无 | 有（`anycast`） |
| 配置 | 手动或 `DHCP` | 支持**无状态自动配置** |
| `NAT` | 广泛使用（地址不够） | 不需要（地址充足） |
| 过渡 | — | 双协议栈、隧道技术 |
| 首部字段数 | 13 个基本字段 | 8 个基本字段 |

> **408 怎么考/常见坑**：最爱考"取消了哪些字段""分片由谁做""首部固定 40 `B`"。坑：`IPv6` 的"净荷长度"**不含首部**；`IPv6` 首部**没有** `TTL` 之名（叫跳数限制 `Hop Limit`）。

### 3.3 距离-向量 vs 链路状态

见前文 **4.2.3** 完整对比表。核心三句：

```text
距离-向量：只和邻居说话，交换整张路由表，Bellman-Ford，RIP，收敛慢（坏消息传得慢）
链路状态：向全网洪泛，只说自己周围，Dijkstra，OSPF，收敛快
信息量：距离-向量"我不知道全图"，链路状态"我有全图"
```

### 3.4 路由器 vs 交换机

见前文 **4.8** 完整对比表。核心一句：**路由器看 `IP`、隔离广播域；交换机看 `MAC`、不隔离广播域。**

### 3.5 `ARP` vs `DHCP` vs `DNS`

| 项目 | `ARP` | `DHCP` | `DNS` |
| --- | --- | --- | --- |
| 解决什么 | `IP` → `MAC` | 自动获取 `IP` 配置 | 域名 → `IP` |
| 所在层次 | 网络层（报文封装在以太网帧中） | 应用层（`UDP` 67/68） | 应用层（`UDP/TCP` 53） |
| 请求方式 | 广播请求 | `DISCOVER`/`REQUEST` 广播 | 通常单播给本地域名服务器 |
| 应答方式 | 单播应答 | `OFFER`/`ACK` | 单播 |
| 作用范围 | **仅同一局域网**（路由器不转发） | 可通过**中继代理**跨网段 | 全球分布式 |
| 有无缓存 | 有 `ARP` 高速缓存 | 有租期，租期过半续租 | 有 `DNS` 缓存（按 `TTL`） |

> **408 怎么考/常见坑**：三者都是"先把某样东西查/换成另一样东西"，最容易混。**记忆锚点：`ARP` 换 `MAC`、`DNS` 换 `IP`、`DHCP` 发 `IP`**。坑：`ARP` 请求不跨网段，`DHCP` 可以（靠中继代理）。

### 3.6 子网掩码 vs `CIDR` 前缀

| 项目 | 子网掩码 | `CIDR` 前缀 |
| --- | --- | --- |
| 写法 | `255.255.255.0` | `/24` |
| 本质 | 一串**连续的 1** + 一串**连续的 0** | 网络前缀的**位数** |
| 关系 | 掩码中 1 的个数 = 前缀长度 | `/24` 等价于 `255.255.255.0` |
| 出现背景 | 为"子网划分"服务（在分类地址内部再借位） | 为"无分类编址"服务（打破 `A/B/C` 类边界） |
| 共同点 | 都用 `IP 地址 AND 掩码 = 网络地址` 求网络号 | 同左 |
| 路由聚合 | 子网掩码也可以表达聚合结果 | `CIDR` 天然支持路由聚合（超网） |

**地址计算四件套（必背）**：

```text
网络地址   = IP 地址 AND 子网掩码
广播地址   = 网络地址 OR (NOT 子网掩码)     即主机号全置 1
可用主机数 = 2^(32 - 前缀长度) - 2
地址块大小 = 2^(32 - 前缀长度)
```

> **408 怎么考/常见坑**：① 求可用主机数**必须减 2**（网络地址 + 广播地址）；② 若问"地址块内共有多少个地址"，**不减 2**；③ 路由聚合要求被聚合的地址块**前缀连续且大小是 2 的幂**，否则只能覆盖更大的块（并且会顺带覆盖无关网络，属于"不精确聚合"）。

## 四、例题精练（3 道）

### 例题 1（选择题：`ARP` 的跨网段解析对象）

**题目**：主机 `A`（`192.168.1.1/24`）要向另一网络的服务器 `B`（`10.1.1.5/24`）发送 `IP` 数据报，`A` 的默认网关是路由器 `R`（`192.168.1.254`）。假设 `A` 的 `ARP` 高速缓存为空。下列说法**正确**的是（　　）。

`A.` `A` 会广播 `ARP` 请求询问 `10.1.1.5` 的 `MAC` 地址，并收到 `B` 的 `MAC` 地址，随后把数据报直接封装成目的 `MAC = B 的 MAC` 的帧发出

`B.` `A` 会广播 `ARP` 请求，路由器 `R` 收到后把该请求转发到 `10.1.1.0/24` 网段，最终由 `B` 应答

`C.` `A` 广播 `ARP` 请求询问 `192.168.1.254` 的 `MAC` 地址，`R` 单播应答，`A` 封装数据报时目的 `MAC` 填 `R` 的 `MAC`、目的 `IP` 仍填 `10.1.1.5`

`D.` `A` 先通过 `DNS` 把 `10.1.1.5` 解析为 `MAC` 地址，再直接发送

**逐项解析**：

- `A` **错**。`ARP` 只在**同一局域网**内工作，`A` 的广播根本到不了 `10.1.1.0/24` 网段；而且 `A` 也不该去问 `B` 的 `MAC`——跨网段通信时 `A` 只需要知道**网关**的 `MAC`。
- `B` **错**。路由器**不转发 `ARP` 请求**，这正是"路由器隔离广播域"的表现。
- `C` **对**。`A` 查路由表发现目的网络不是本网段，于是把分组交给默认网关 `R`。要交给 `R` 就得知道 `R` 的 `MAC`，所以 `ARP` 解析的对象是 `192.168.1.254`；`ARP` 请求广播、应答单播。封装后的帧**目的 `MAC` = `R` 的 `MAC`，目的 `IP` = `10.1.1.5`**（`IP` 地址端到端不变，`MAC` 地址逐跳改变）。
- `D` **错**。`DNS` 做的是"域名 → `IP`"，不做"→ `MAC`"；这里已经是 `IP` 地址，用不到 `DNS`。

**答案：`C`**

**采分点与常见坑**：

- 采分点：① 判断"目的主机与自己在不同网段"；② 指出 `ARP` 解析的是**默认网关**的地址；③ 说明 `IP` 地址端到端不变、`MAC` 地址逐跳改变；④ 指出 `ARP` 请求广播、应答单播。
- 坑 1：认为 `ARP` 能跨网段解析到远端主机的 `MAC`（最常见错误）。
- 坑 2：把封装帧的目的 `IP` 写成网关地址（网关的 `IP` 只用于查路由，不写进目的 `IP`）。
- 坑 3：把 `DNS` 和 `ARP` 混为一谈。

### 例题 2（计算题：`CIDR` 子网划分 + 路由聚合 + 最长前缀匹配）

**题目**：某单位分到一个 `CIDR` 地址块 `192.168.0.0/22`，需要划分给四个部门，需求如下（每个部门都需要**可分配给主机的地址数**不少于表中数值，且不得跨子网重叠）：

```text
部门 A：至少 500 个可用主机地址
部门 B：至少 240 个可用主机地址
部门 C：至少 100 个可用主机地址
部门 D：至少  50 个可用主机地址
```

请回答：

1. 为每个部门分配一个**尽量小**（刚好够用）的子网前缀，按需求从大到小依次分配，给出每个部门的**网络地址/前缀**、**可用主机数**和各自的**广播地址**，并说明该 `/22` 块中还剩余多少地址。
2. 路由器 `R1` 的转发表如下，请写出目的地址为 `192.168.3.100` 的分组的转发结果，并说明依据的匹配规则。若又收到目的地址 `192.168.3.200`，结果是什么？

```text
R1 转发表：
192.168.0.0/22    → 接口 0
192.168.0.0/23    → 接口 1
192.168.3.0/25    → 接口 2
192.168.3.128/26  → 接口 3
0.0.0.0/0         → 接口 4
```

3. 若路由器 `R2` 的转发表中有 `192.168.0.0/24 → 下一跳 X`、`192.168.1.0/24 → 下一跳 X`、`192.168.2.0/24 → 下一跳 X`，能否聚合成一条表项？能的话写出聚合结果；若还想把 `192.168.3.0/24` 也一起聚合，结果是什么？这样聚合有什么代价？

**解答步骤**：

**第 1 问**：

```text
先算每种需求所需的"主机位数"：
    500 个可用地址 → 需要 2^h - 2 >= 500 → 2^h >= 502 → h = 9（2^9=512，可用 510）→ 前缀长度 = 32-9 = /23
    240 个可用地址 → 2^h - 2 >= 240 → 2^h >= 242 → h = 8（2^8=256，可用 254）→ 前缀长度 = /24
    100 个可用地址 → 2^h - 2 >= 100 → 2^h >= 102 → h = 7（2^7=128，可用 126）→ 前缀长度 = /25
     50 个可用地址 → 2^h - 2 >=  50 → 2^h >=  52 → h = 6（2^6= 64，可用  62）→ 前缀长度 = /26

按从大到小依次分配（每次都从剩余空间的最低位开始切，保证对齐）：
    部门 A：192.168.0.0/23      （192.168.0.0 ~ 192.168.1.255） 可用 510 个
    部门 B：192.168.2.0/24      （192.168.2.0 ~ 192.168.2.255） 可用 254 个
    部门 C：192.168.3.0/25      （192.168.3.0 ~ 192.168.3.127） 可用 126 个
    部门 D：192.168.3.128/26    （192.168.3.128 ~ 192.168.3.191）可用  62 个

广播地址（主机号全 1）：
    A：192.168.1.255     B：192.168.2.255     C：192.168.3.127     D：192.168.3.191

剩余空间：
    原块 192.168.0.0/22 共 2^(32-22) = 1024 个地址
    已用：512 + 256 + 128 + 64 = 960 个
    剩余：1024 - 960 = 64 个 → 即 192.168.3.192/26（可用 62 个）
```

**第 1 问答案**：`A: 192.168.0.0/23`（510 个可用，广播 `192.168.1.255`）；`B: 192.168.2.0/24`（254 个，广播 `192.168.2.255`）；`C: 192.168.3.0/25`（126 个，广播 `192.168.3.127`）；`D: 192.168.3.128/26`（62 个，广播 `192.168.3.191`）；剩余 `192.168.3.192/26`，共 `64` 个地址。

**第 2 问**：

```text
用"IP AND 掩码"逐个匹配（只列前缀位）：
192.168.3.100 = 11000000.10101000.00000011.01100100

① 192.168.0.0/22   前 22 位：11000000.10101000.000000 | xx
   目的前 22 位：       11000000.10101000.000000        → 匹配（前缀长 22）
② 192.168.0.0/23   前 23 位：11000000.10101000.0000000 | x
   目的前 23 位：       11000000.10101000.0000000        → 匹配（前缀长 23）
③ 192.168.3.0/25   前 25 位：11000000.10101000.00000011.0 | xxxxxxx
   目的前 25 位：       11000000.10101000.00000011.0        → 匹配（前缀长 25）★最长
④ 192.168.3.128/26 前 26 位要求第 4 字节最高位为 1（128~191）
   目的第 4 字节 100 = 01100100，最高位为 0 → 不匹配
⑤ 0.0.0.0/0 默认路由，一定匹配（前缀长 0）

最长前缀匹配：25 > 23 > 22 > 0 → 选中 192.168.3.0/25
转发结果：从【接口 2】发出
```

```text
再看 192.168.3.200 = 11000000.10101000.00000011.11001000
③ 192.168.3.0/25：要求第 4 字节首位为 0（0~127），而 200 的首位为 1 → 不匹配
④ 192.168.3.128/26：第 4 字节 11001000，前两位为 11 → 落在 192~255 内，前 26 位匹配 ✓（前缀长 26）
① ② 也都匹配（22、23 位）
最长前缀匹配：26 → 选中 192.168.3.128/26 → 从【接口 3】发出
```

**第 2 问答案**：`192.168.3.100` 匹配 `192.168.3.0/25`（最长匹配长度 25），从**接口 2** 发出；`192.168.3.200` 匹配 `192.168.3.128/26`（最长匹配长度 26），从**接口 3** 发出。依据是**最长前缀匹配**原则：所有匹配的前缀中取前缀最长（最具体）的那一条，与表项顺序无关。

**第 3 问**：

```text
把三个网络写成二进制前 24 位：
192.168.0.0/24 → 第三字节 00000000
192.168.1.0/24 → 第三字节 00000001
192.168.2.0/24 → 第三字节 00000010

逐位比较第三个字节：00000000 / 00000001 / 00000010
    第 1~6 位都是 000000（相同）
    第 7 位分别是 0 / 0 / 1 → 不同，最长公共前缀到此为止
    第 8 位就算相同也不能往前算（第 7 位已经不同了）→ 第三字节只有前 6 位相同
所以最长公共前缀 = 8 + 8 + 6 = 22 位：
    192.168.0.0/22  （注意：这个块包含 192.168.3.0/24，但转发表里没有它）
```

**关键结论**：`192.168.0.0/24`、`192.168.1.0/24`、`192.168.2.0/24` 这三个**不连续**的块**不能精确聚合**成一条 `/23` 或更短的表项，只能聚合成 `192.168.0.0/22`，而这会**顺带覆盖 `192.168.3.0/24`**。

```text
若把 192.168.3.0/24 也一起聚合：四个 /24 恰好填满 192.168.0.0/22
    聚合结果 = 192.168.0.0/22         （这是精确聚合）
代价：
    ① 该 /22 的下一跳必须都与 X 一致（若 192.168.3.0/24 走别的下一跳，就不能合并）
    ② 若无条件合并，会把"本不属于 X"的地址也引向 X；若 192.168.3.0/24 实际不存在，
       则造成了"黑洞"（这些地址的分组会被错误地转发给 X），也可能与其它路由冲突
```

**第 3 问答案**：三个 `192.168.0.0/24 ~ 192.168.2.0/24` 的**最长公共前缀只有 22 位**，只能聚合成 `192.168.0.0/22`，且该结果会**覆盖到 `192.168.3.0/24`**；若把 `192.168.3.0/24` 也包含进来，则四个 `/24` 正好填满 `192.168.0.0/22`，**精确聚合为 `192.168.0.0/22`**。代价是要求这四个网段的下一跳相同，否则会引入错误转发（黑洞）或路由冲突。

**采分点与常见坑**：

- 采分点：① 第 1 问必须**先由"可用主机数 + 2"反推主机位数**，再定前缀长度（`2^h - 2 >= 需求`）；② 分配时要从**大块到小块**切、保持前缀对齐；③ 广播地址要按"主机号全 1"算，别写成网络地址 + 1；④ 第 2 问必须写出**每个候选前缀都匹配、然后再比长度**的过程；⑤ 第 3 问必须点出"**连续性**"这一必要条件。
- 坑 1：看到"500 台主机"直接取 `/24`（256 个不够）或取 `2^8 = 256`（还是不够）——**必须用 `2^h - 2 >= 需求`**。
- 坑 2：把"地址块总地址数"和"可用主机数"混用（问可用数一定减 2）。
- 坑 3：以为"路由表里先出现的表项优先"——**最长前缀匹配与顺序无关**。
- 坑 4：以为 `192.168.0.0/24`、`192.168.1.0/24` 可以直接聚合为 `192.168.0.0/23` 之后，再加 `192.168.2.0/24` 仍是 `/23`——第三个 `/24` 一加，前缀就退到 `/22`。
- 坑 5：默认路由 `0.0.0.0/0` 前缀长度为 `0`，**永远匹配但优先级最低**，只有其它前缀都不匹配时才用。

### 例题 3（计算题：`IP` 分片计算）

**题目**：某 `IP` 数据报总长度为 `1600 B`（其中首部 `20 B`，无选项），要经过一条 `MTU = 620 B` 的链路。请回答：

1. 该数据报需要分成几片？写出每片的**数据长度、总长度、`MF` 标志、片偏移**。
2. 若该数据报首部的 `DF` 标志置为 `1`，会发生什么？
3. 这些分片在哪里重组？中途经过的路由器会重组吗？

**解答步骤**：

**第 1 问**：

```text
第 1 步：数据部分长度 = 总长度 - 首部长度 = 1600 - 20 = 1580 B

第 2 步：每片最多能装的数据长度
    理论上 = MTU - 首部长度 = 620 - 20 = 600 B
    600 是 8 的整数倍（600 / 8 = 75）→ 可直接取 600 B
    （若算出的值不是 8 的倍数，必须先向下取整到 8 的倍数）

第 3 步：片数 = 向上取整(1580 / 600) = 向上取整(2.633) = 3 片

第 4 步：逐片填表
    第 1 片：数据 600 B → 总长度 = 20 + 600 = 620 B → MF = 1 → 片偏移 = 0 / 8     = 0
    第 2 片：数据 600 B → 总长度 = 20 + 600 = 620 B → MF = 1 → 片偏移 = 600 / 8   = 75
    第 3 片：数据 1580 - 600 - 600 = 380 B
             总长度 = 20 + 380 = 400 B → MF = 0（最后一片）→ 片偏移 = 1200 / 8 = 150
```

**第 1 问答案：需要分成 3 片**，如下表：

| 片号 | 数据长度(`B`) | 总长度(`B`) | `MF` | 片偏移 | 该片数据在原数据中的字节范围 |
| --- | --- | --- | --- | --- | --- |
| 1 | 600 | 620 | 1 | 0 | 0 ~ 599 |
| 2 | 600 | 620 | 1 | 75 | 600 ~ 1199 |
| 3 | 380 | 400 | 0 | 150 | 1200 ~ 1579 |

**第 2 问**：

```text
DF = 1 表示"不允许分片（Don't Fragment）"。
数据报 1600 B > MTU 620 B，又禁止分片 → 路由器无法转发，
丢弃该数据报，并向源主机发送 ICMP 差错报告报文（终点不可达，代码为"需要分片但 DF 置 1"）。
```

**第 2 问答案**：路由器**丢弃**该数据报，并回送 `ICMP` **终点不可达**差错报告报文（"需要分片但设置了 `DF`"），源主机需自己减小报文长度后重发。这正是 `IPv6` 中"路径 `MTU` 发现"机制的雏形。

**第 3 问**：

```text
目的主机（最终接收方）的网络层负责重组。
中间路由器只按 MTU 分片并转发，不重组——因为各分片可能走不同路径到达，路由器无法保证收齐，
且重组会显著增加路由器负担。IP 首部的"标识"字段就是用于让目的主机把同一数据报的
各分片识别并组装在一起的。
```

**第 3 问答案**：在**目的主机**上重组；**中途路由器不重组**，各分片可能经不同路径到达，靠首部中的**标识字段**区分归属、靠**片偏移**确定位置、靠 **`MF`** 判断是否收齐最后一片。

**采分点与常见坑**：

- 采分点：① 明确"数据部分 = 总长度 - 首部"；② 写清"每片最大数据 = `MTU` - 首部"，且**必须是 8 的倍数**；③ 每片都**自带 20 `B` 首部**；④ 片偏移**除以 8**；⑤ 总长度**每片都不同**（不是原总长度）；⑥ 最后一片 `MF = 0`。
- 坑 1：最后一片忘了把 `MF` 置 `0`（最常见）。
- 坑 2：把片偏移写成字节数（`600` 而非 `75`）——**必须以 8 字节为单位**。
- 坑 3：以为只有第一片有首部，其余片是纯数据。
- 坑 4：每片的数据都按 `600 B` 硬算，最后一片多算出一片（`1580 / 600 = 2.63` 是 3 片，不是 4 片）。
- 坑 5：`DF = 1` 时答"路由器帮忙分片"——正确是**丢弃 + 回 `ICMP` 不可达**。
- 坑 6：答"由路由器重组"——**重组只在目的主机进行**。

## 六、简便方法与易错口诀（速算 · 防错）

> 本节把本章能"省时间"和"防掉坑"的招集中在一处：二轮复习与考前只看这一节。每条都写清**适用条件**。

### 6.1 速算招式

| 场景 | 常规做法（慢/繁） | 简便做法（快/稳） | 为什么成立 / 适用条件 |
| --- | --- | --- | --- |
| 可用主机数 | 写出主机位、逐位算地址块 | 数主机位数 `n = 32 − 前缀长度`，直接 `可用主机数 = 2^n − 2` | 减去**网络地址**（主机号全 0）与**广播地址**（主机号全 1）两个；仅当 `n ≥ 2` 成立。`/31`、`/32` 是例外：`/31` 用于点对点链路（`RFC 3021`，两地址均可用）、`/32` 是单主机路由，此时不能套 `−2` |
| 子网个数 | 逐个列子网 | 向**主机位**借 `k` 位，`子网数 = 2^k`，前缀长度变为 `原前缀 + k` | 前提：每子网至少还要留 `n ≥ 2` 位主机位。经典教材另有"**是否允许子网号全 0/全 1**"的约定（`CIDR`/`RFC 950` 之后均可用，若题干限定"子网号不能全 0/全 1"则要额外 `−2`）；必须**先看题干口径** |
| 一个子网的地址块大小 | 逐个子网推算边界 | `地址块大小 = 2^n`（`n` 为主机位数）；若某字节是"归属字节"，则该字节上的块大小 = `256 − 该字节掩码值` | 块大小是 2 的幂、且**正好整除 256**，所以子网边界一定落在块大小的整数倍上；长度只有 `/25`、`/26`… 这类"后一字节切分"才用得到"归属字节"的说法 |
| 判断"同网段 / 能否直达" | 写出两边二进制逐位比 | 两个 `IP` 分别 `AND` 自己的掩码，**比较结果是否相等**；相等即同网段，可直接 `ARP` 直达 | 同一网段 ⇔ 网络地址相同。若不同网段，源主机解析的是**网关 `MAC`**，不是目的主机 `MAC` |
| 路由聚合 | 把各地址块二进制全写出来 | **只找最长公共前缀**：从第 1 位往右数，数到**第一个不同**的位，前面相同的位数就是聚合后的前缀长度 | 前提是各地址块**连续且能对齐成 2 的幂次块**；聚合结果**必须真的覆盖且不越界**。补充：十进制数值上"看起来相近"不等于前缀相同，**必须看二进制**，否则会出现聚合出覆盖无关网络的错误 |
| `IP` 分片三件套 | 每片逐字段手算 | ① 每片数据长度（**除最后一片**）必须是 **8 的整数倍**；② `片偏移 = 该片数据起始字节 ÷ 8`；③ `每片总长度 = 片数据长度 + 20` | 片偏移字段只有 13 位、单位是 **8 字节**，所以非末片必须按 8 对齐；各分片都**自带 `IP` 首部**（最小 `20 B`），所以总长度要"各加各的首部"；重组只在**目的主机**进行 |
| `MTU` 换分片 | 用总长度直接除 `MTU` | 先算**待分片的数据长度 = 原总长度 − 首部长度**；再 `每片最大数据长度 = ⌊(MTU − 20) ÷ 8⌋ × 8`（向下取 8 的倍数）；片数 = `数据长度 ÷ 每片最大数据长度` **向上取整** | 公式里的 `20` 是 `IP` 首部最小长度（大多数题目就取 20）。坑：不能拿"原总长度"当被除数，也不能用 `MTU` 本身当除数 |
| `ARP` 的作用范围 | 背定义 | 一句话记：**同一网段内解析 `MAC`；跨网段解析默认网关的 `MAC`** | `ARP` 请求以**广播**发出、应答**单播**返回，广播不过路由器，所以只能覆盖本网段 |
| 三个路由协议"身份证" | 翻表逐项回忆 | `RIP`：**距离-向量、跳数 ≤ 15（`16` = 不可达）、每 30 s 广播、`UDP 520`**；`OSPF`：**链路状态、洪泛、划分区域、直接封装在 `IP`，协议号 `89`**；`BGP`：**路径向量、`TCP 179`** | 三项一步到位用于选择题；记忆锚点是"**只有 `OSPF` 不借 `TCP/UDP`**" |
| 最长前缀匹配 | 按表项顺序从上往下试 | 把表里**所有能匹配的条目**找出来，取**前缀最长**（最具体）的那条；默认路由 `0.0.0.0/0` 前缀最短，**最后才用** | 与转发表的**存放顺序无关**；默认路由能匹配任何目的地址，所以它是兜底项而非优先项 |
| `ICMP` 两种工具 | 背报文名 | `ping` = **回送请求/应答**；`traceroute` = **把 `TTL` 依次设为 `1,2,3…`**，靠路由器回"**时间超过**"报文暴露每一跳 | 两者属于**询问报文**；`ICMP` 本身封装在 `IP` 数据报里（协议号 `1`）。注意 `traceroute` 依赖 `TTL` 递减，所以**只能逐跳测到路径**，且中间节点可能不回应 |

### 6.2 口诀与记忆钩子

- **口诀**：主机数"**二的 n 次减二**"，子网数"**借几就是二的几次**"；`n = 32 − 前缀长度`，`−2` 减的是**网络号与广播号**。
- **口诀**：聚合"**只数相同位**"——从左往右数到第一个不同的位为止；**数位只看二进制，不看十进制像不像**。
- **口诀**：分片"**八倍、除八、加二十**"：非末片数据长是 **8 的倍数**，片偏移是**起始字节 ÷ 8**，总长度是**数据 + 20**。
- **口诀**：`ARP` "**同网段问 `MAC`，跨网段问网关**"——广播出不了路由器，这一句同时记住流程和范围。
- **口诀**：三兄弟"**`520` 数着 `15` 跳，`89` 直接躺 `IP`，`179` 稳坐 `TCP`**"——`RIP`/`UDP 520`、`OSPF`/`IP 89`、`BGP`/`TCP 179`。
- **口诀**：查表"**最长前缀先赢，默认路由垫底**"——能匹配的多条里取最具体的那条，`0.0.0.0/0` 永远最后兜底。
- **口诀**：`ICMP` "**`ping` 来回送，`traceroute` 数 `TTL` 从 `1` 起步**"——两个工具的报文类型与机制一句串起来。

### 6.3 反例黑名单（这些"简便法"是错的）

- ❌ **"可用主机数 = `2^n`" 或 "`= 2^n − 2` 之后再减一遍网络号/广播号"**：正确做法是 `可用主机数 = 2^(32−前缀长度) − 2`，**只减一次**，且减的是网络地址与广播地址这两个；`/31`、`/32` 不适用 `−2`。
- ❌ **"子网数永远等于 `2^k`"**：正确做法是先确认**扣除子网位后主机位是否还剩 ≥ 2 位**，并**按题干口径**决定要不要去掉子网号全 0/全 1 的情形。`CIDR`/现代设备默认允许，老口径要额外 `−2`。
- ❌ **"聚合就是把地址块尾数相加 / 输出最后一条匹配的表项"**：正确做法是**求最长公共前缀**，并回验聚合结果**是否仍覆盖全部原子地址块、又没有覆盖到其他已分配网络**；最长前缀匹配要取**前缀最长者**，不是"表里最后一条"。
- ❌ **"每片数据长度都要是 8 的倍数 / 总数据长度除以 `MTU` 就是片数"**：正确做法是**非末片**按 8 对齐（**末片例外**，可以不是 8 的倍数），被除数是**数据长度**、除数是 `每片最大数据长度`，结果**向上取整**；片偏移写**字节数**而非"除以 8 后的值"同样是错的。
- ❌ **"`ARP` 一次查询就能拿到最终目的主机的 `MAC`"**：正确做法是——同网段才直接解析目的主机 `MAC`；**跨网段解析的是默认网关的 `MAC`**，数据报随后由网关接力，目的主机的 `MAC` 全程不出现在源主机的 `ARP` 结果里。
- ❌ **"`RIP` 的跳数上限是 `16`"**：正确做法是**`RIP` 的跳数 ≤ `15`，`16` 表示不可达**——正因为 `16` 被留作"无穷大"，才产生"坏消息传得慢"（计数到无穷）问题，需要用水平分割/毒性逆转/触发更新缓解。
- ❌ **"所有路由协议都跑在 `TCP`/`UDP` 之上"**：正确做法是 `RIP` 用 `UDP 520`、`BGP` 用 `TCP 179`，而 **`OSPF` 直接封装在 `IP` 中（协议号 `89`）**，不用传输层协议。
- ❌ **"默认路由前缀最短，所以最先匹配 / 匹配不上就是查表失败"**：正确做法是默认路由 `0.0.0.0/0` **永远能匹配、永远最后用**，它是兜底项；"前缀最短"不等于优先。
