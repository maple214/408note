## 二、概念详解

### 7.1 I/O 系统基本概念

#### 7.1.1 外设为什么不能直接挂在系统总线上

三点"不匹配"：

1. **速度不匹配**：外设与 `CPU`、主存的速度差几个数量级（键盘毫秒级、磁盘微秒级、`CPU` 纳秒级）。若外设直接挂总线由 `CPU` 逐字伺候，机器会慢到不可用。
2. **数据格式与工作方式不匹配**：外设可能是**串行位流**、可能是**模拟量**，而总线是**并行数字量**；外设的定时方式、电平标准也与总线规范不一致。
3. **不具备总线控制能力**：总线上一次通信需要地址、命令、状态一整套通信联络（握手）信号，外设本身没有这种能力；而且外设数量多，必须能按**设备地址**被选中。

所以外设与总线之间必须插入一层"翻译官 + 缓冲站 + 联络员"，这就是 `I/O` 接口。

#### 7.1.2 I/O 接口存在的意义

- **数据缓冲与速度匹配**：把 `CPU` 的一次快速传送和外设的慢速工作解耦（靠数据缓冲寄存器）
- **格式转换**：串行 ↔ 并行、模拟 ↔ 数字
- **控制与状态传递**：`CPU` 的命令下达到外设，外设的"忙/就绪/出错"反馈给 `CPU`
- **地址译码与设备选择**：让多台外设共用一套总线
- **产生中断请求 / `DMA` 请求**，实现 `CPU` 与外设的并行工作

`I/O` 系统的层次：**外设 → 设备控制器（接口）→ `I/O` 总线 → 主机（`CPU` + 主存）**，再往上还有设备驱动程序等软件。

> **408 怎么考/常见坑**：常作为选择题的错误选项出现，如"外设可直接与主存交换信息，无须接口"、"接口中的数据缓冲寄存器是为了扩大存储容量"。记住接口的核心使命是**速度匹配 + 通信联络**。

### 7.2 外部设备（了解即可）

> **大纲提示**：自 2022 年大纲改版起，原"外部设备"整块内容**移入操作系统的 `I/O` 管理部分**，计组大纲不再单独要求。下面只需认识名词。

- **输入设备**：键盘、鼠标、触摸屏、扫描仪
- **输出设备**：显示器、打印机
  - 小计算：**显存容量 = 分辨率 × 每个像素的位数**。例：分辨率 1024×768、256 色（8 位/像素）→ 1024×768×8 bit = 768 KB
  - 刷新率越高，对显存带宽要求越高
- **外存**：磁盘、`SSD`、光盘。**磁盘存取时间（寻道时间 + 旋转延迟 + 传输时间）的计算在计组第 3 章"存储系统"里考**，本章不重复

> **408 怎么考/常见坑**：考到也只考"显存容量 = 分辨率 × 灰度级位数"这类小计算和名词识别。`SPOOLing` 假脱机、磁盘调度算法属于操作系统，别在计组里花时间。

### 7.3 I/O 接口（I/O 控制器）

#### 7.3.1 I/O 接口的功能（记 6 条）

1. **地址译码和设备选择**：对地址总线上的地址译码，只有被选中的接口（端口）才响应
2. **数据缓冲**：用数据缓冲寄存器 `DBR` 暂存数据，弥补 `CPU` 与外设的速度差
3. **控制和定时**：接收 `CPU` 发来的命令/控制字，向外设发出控制信号，并保证时序配合
4. **状态监视**：把外设的"忙/就绪/出错"状态记在状态寄存器中供 `CPU` 查询
5. **数据格式转换**：串 ↔ 并、模 ↔ 数转换
6. **与主机的通信联络**：产生中断请求信号、`DMA` 请求信号，报告错误

#### 7.3.2 I/O 接口的基本结构

**内部的三个可寻址寄存器（即三类端口）**

| 寄存器（端口） | 方向 | 作用 |
| --- | --- | --- |
| 数据缓冲寄存器 `DBR`（数据端口） | 可读可写 | 暂存 `CPU` 与外设之间传送的数据 |
| 状态寄存器 `SR`（状态端口） | `CPU` 只读 | 反映外设状态，如 `D`（完成/就绪）、`B`（忙）、错误位 |
| 控制寄存器 `CR`（控制端口） | `CPU` 只写 | 存放 `CPU` 发来的命令字/控制字（启动、读/写方向、中断允许等） |

**其他部件**

- **地址译码电路 + 设备选择电路**：把地址总线上的设备号/端口号译码，选中本接口的某个端口
- **内部控制逻辑与时序电路**：产生读/写控制信号，完成与外设的握手时序
- **中断请求触发器 + 中断屏蔽触发器**：中断方式接口必备（外部设备就绪时置中断请求触发器）
- **`DMA` 相关部件**：只有 `DMA` 接口才有（地址计数器、长度计数器等）

**连接关系**

- 面向总线一侧：数据线（双向）、地址线（单向，`CPU` → 接口）、控制线（读/写、中断请求、`DMA` 请求与响应）
- 面向外设一侧：数据线、状态线、控制线（使用设备自己的信号标准）

**接口 ≠ 端口**：**端口是接口中可被 `CPU` 用地址访问的寄存器**（数据端口、状态端口、控制端口）；**接口 = 端口 + 地址译码 + 控制逻辑 + 中断/`DMA` 逻辑**。

> **408 怎么考/常见坑**：① 爱考三个寄存器各起什么作用、谁是"解决速度匹配"的（数据缓冲寄存器）；② 注意访问方向——状态端口 `CPU` 只读、控制端口 `CPU` 只写、数据端口可读可写，选项里换成"状态寄存器由 `CPU` 写入"就是错的；③ 一个端口地址对应一组寄存器时，靠读/写控制信号区分方向。

### 7.4 I/O 端口及其编址

两种编址方式（对比表见 **§三.1**）：

**统一编址（存储器映射方式，`Memory-Mapped I/O`）**

- 把 `I/O` 端口当作主存单元一样统一编址，**与主存共用同一个地址空间**
- 用**普通访存指令**访问端口（`MOV`、`LW`、`SW`、`AND` 等）
- 优点：不需要专门的 `I/O` 指令，可用指令多、功能强（能直接对端口内容做算术/逻辑运算）；可复用访存的控制逻辑
- 缺点：**占用主存地址空间**，使主存容量变小；译码电路相对复杂；程序中不易区分访存还是访端口，可读性差

**独立编址（`I/O` 映射方式，`Isolated I/O`）**

- `I/O` 端口有**自己独立的地址空间**，与主存地址空间分开
- 需要**专门的 `I/O` 指令**（`IN`、`OUT`）和**专门的控制信号**（`IOR`、`IOW`）来区分是访存还是访端口
- 优点：不占用主存地址空间；程序清晰；端口地址位数少、译码简单（如 16 位 `I/O` 地址线对应 64 K 个端口）
- 缺点：必须有专用 `I/O` 指令，指令种类少、功能弱（一般只能做简单的输入输出，不能直接参与运算）；需要额外的控制信号线

> **408 怎么考/常见坑**：① 给一段汇编，出现 `IN`/`OUT` 就是独立编址，出现 `MOV`/`LW` 访问某地址就是统一编址；② 独立编址的端口数量由 `I/O` 地址线位数决定，与主存地址线无关；③ 统一编址"省指令不省地址空间"，独立编址"省地址空间不省指令"，这两个结论方向别背反。

### 7.5 程序查询方式

#### 7.5.1 基本思想

`CPU` 执行程序：先启动外设，然后**反复读状态端口**判断外设是否就绪；未就绪就转回去继续读（**踏步等待**，也叫轮询），就绪后再通过数据端口传送一个字/字节。

#### 7.5.2 查询流程

```
1. CPU 把设备地址送地址总线，向控制端口写"启动"命令
2. 读状态端口，测试"完成/就绪"位
3. 未就绪 → 返回第 2 步（踏步等待，死循环）
4. 就绪 → 从数据端口读入一个字（或写入一个字）
5. 修改主存地址指针、传送计数器
6. 未传完 → 回第 2 步；传完 → 结束
```

伪代码：

```
启动设备
while (状态寄存器.就绪位 == 0) { }   // 踏步等待，CPU 空转
数据 = 数据端口
主存[地址] = 数据
地址++ ； 计数--
```

#### 7.5.3 效率分析

- `CPU` 与外设是**串行**工作：外设准备数据期间，`CPU` 一直空转查询，**不能做别的事，也不能响应其他外设的请求**
- 所以 `CPU` 用于 `I/O` 的时间比例**接近 100%**（就"伺候这一台外设"而言），是三种方式中效率最低、硬件最简单的
- 传送一个字的 `CPU` 时间 = 查询开销 + 传送开销

> **408 怎么考/常见坑**：① 选择题高频错项——"程序查询方式下 `CPU` 与外设并行工作"（错）；② 小计算：给"查询一次的时间"和"外设准备一个数据的时间"，算 `CPU` 用于 `I/O` 的比例或系统能达到的最高传送率，答案往往是"CPU 被占满"；③ 程序查询是**软件**方式，但仍要经过接口的状态端口和数据端口，别答成"不经过接口"。

### 7.6 程序中断方式

#### 7.6.1 中断的基本概念

**定义**：`CPU` 在执行程序的过程中，出现某些急需处理的异常情况或特殊请求，`CPU` 暂时中止现行程序，转去执行相应的处理程序，处理完毕后自动返回原程序的断点处继续执行。

**意义**：`CPU` 与外设**并行**工作——外设准备数据期间 `CPU` 照常执行主程序，只在数据真的准备好时才花少量时间处理，效率远高于程序查询。

**中断源的分类**

| 分类角度 | 类型 | 说明 |
| --- | --- | --- |
| 产生位置 | 内中断（异常/例外） | 来自 `CPU` 内部：除零、算术溢出、非法操作码、缺页、`trap` 指令等 |
|  | 外中断（狭义"中断"） | 来自 `CPU` 外部：`I/O` 中断、时钟中断、键盘中断等 |
| 能否屏蔽 | 可屏蔽中断 | 通过 `INTR` 请求，受中断允许触发器 `EINT`（`IF`）控制 |
|  | 不可屏蔽中断 | 通过 `NMI` 请求（如电源故障），不受 `EINT` 控制，优先级很高 |
| 产生方式 | 硬件中断 / 软件中断 | 硬件信号引起 / `trap`、系统调用指令引起 |

#### 7.6.2 中断请求与中断响应

- 每个中断源在接口中有一个**中断请求触发器**：外设就绪时置 1，向 `CPU` 发中断请求
- 还有一个**中断屏蔽触发器**：置 1 时禁止该设备发中断请求（注意与"中断屏蔽字"区分，见 §7.6.6）
- 多个中断源同时请求时，由**中断判优电路**（硬件排队器/优先级编码器）选出优先级最高者；也可以用软件查询判优
- **中断响应条件（三条同时满足）**：
  1. 有中断请求（且未被屏蔽）
  2. `CPU` 允许中断（**开中断**，`EINT` = 1）
  3. **一条指令执行结束**
- **响应时机**：`CPU` 在**每条指令执行阶段结束时**检查中断请求，而不是每个时钟周期、也不是任意时刻

> 对比记：`DMA` 请求的响应时机是**一个存储周期（总线周期）结束时**。

#### 7.6.3 中断隐指令

**定义**：`CPU` 响应中断后，由**硬件自动**完成的一系列操作。它**不是指令系统中的指令**——没有操作码、不由程序编写、程序员看不见，因此叫"隐指令"。

**内容（三项）**：

1. **关中断**：把 `EINT` 置 0，使保护现场期间不被新的中断打断
2. **保存断点**：把当前 `PC`（下一条待执行指令的地址）压栈或存入指定单元
3. **引出中断服务程序**：取中断类型号 → 形成**中断向量地址** → 从该单元取出**中断向量**（服务程序入口地址）→ 送入 `PC`

> **关键坑**：中断隐指令保存的是**断点 `PC`**（有的教材还包括程序状态字 `PSW`）；**通用寄存器的保存是由中断服务程序用压栈指令（软件）完成的**。所以完整的"保护现场" = 硬件保存断点 + 软件保存通用寄存器。这一条几乎每年都能出现在选项里。

#### 7.6.4 中断向量与中断向量地址

| 名词 | 含义 |
| --- | --- |
| 中断向量 | 中断服务程序的**入口地址** |
| 中断向量地址 | **存放中断向量的存储单元地址**（中断向量表中该表项的地址） |
| 中断类型号 | 用于索引向量表的编号（由中断源/接口提供） |

关系：**中断向量地址 = 向量表基址 + 中断类型号 × 每个表项的字节数**。

例：中断类型号为 20H，每个表项 4 字节，向量表基址为 0 → 向量地址 = 20H × 4 = 80H，即服务程序入口地址存放在 80H ~ 83H 单元（低地址存低位字节）。

> **408 怎么考/常见坑**：① 判断"中断向量地址单元里存放的是入口地址"这类表述的正误；② 给类型号和表项长度算向量地址，是常见的 1 分小计算；③ 别把"向量"和"向量地址"当成同一个东西——前者是入口地址，后者是它的存放地址。

#### 7.6.5 中断处理过程

| 阶段 | 由谁完成 | 做什么 |
| --- | --- | --- |
| 1 中断请求 | 硬件（外设 + 接口） | 外设就绪，置中断请求触发器，发 `INTR` |
| 2 中断判优 | 硬件排队器（或软件查询） | 多个请求同时到达时选出优先级最高者 |
| 3 中断响应 | 硬件（执行**中断隐指令**） | 关中断、保存断点、引出中断服务程序 |
| 4 保护现场 | 硬件存断点 + 软件存通用寄存器 | 保证返回后原程序能正确继续 |
| 5 中断服务 | 软件（服务程序） | 真正的数据传送、状态处理等 |
| 6 恢复现场 | 软件 | 弹出通用寄存器（一般先关中断） |
| 7 中断返回 | `IRET` 指令 | 断点送回 `PC`，开中断，返回原程序 |

**中断服务程序流程（多重中断版本）**：

```
关中断 → （硬件保存断点）→ 保存通用寄存器和屏蔽字
      → 开中断（允许嵌套）
      → 设备服务（真正干活）
      → 关中断
      → 恢复通用寄存器和屏蔽字
      → 开中断
      → IRET 返回
```

#### 7.6.6 单重中断与多重中断

- **单重中断**：整个服务过程都关中断，服务完才开中断返回。实现简单，但服务期间其他外设的请求得不到及时响应。
- **多重中断（中断嵌套）**：服务过程中允许**更高优先级**的中断打断自己。
  **实现条件**：① 在保护现场**之后**提前开中断；② 有优先级机制（硬件判优 + 中断屏蔽字）。

**中断屏蔽字**：每个中断源有一个 n 位屏蔽字（n = 中断源个数），**每一位对应一个中断源，1 = 屏蔽（禁止），0 = 未屏蔽（允许）**；**自己那一位恒为 1**，表示服务自己时屏蔽自己，防止同一中断源反复打断。

**核心结论**：**硬件优先级决定"谁先被响应"；中断屏蔽字决定"谁能打断谁"，也就是最终的处理（完成）次序。** 二者可以不一致，考试正是考这种"改次序"。

**处理次序推导方法（四步）**：

1. 写下要求的**处理次序**（谁先处理完，谁优先级就高）
2. 按处理次序给中断源重排优先级
3. 对每个中断源 X：屏蔽字中把**自己**和**处理次序在它之后（更低）**的源置 1，处理次序在它之前（更高）的源置 0
4. 自检：设共有 n 个中断源，**处理次序第 k 高**的源，其屏蔽字中恰好有 **n − k + 1** 个 1（即它要屏蔽自己 + 所有比它低的源）；处理次序最高的源屏蔽字全为 1，最低的源只有自己那一位为 1

> **408 怎么考/常见坑**：① 几乎年年有类似题：给硬件优先级 + 要求的处理次序，写各中断源屏蔽字（大题第一步）；② 判断"开中断/关中断"插在服务程序的什么位置能不能实现嵌套；③ 别忘"同时到达的多个请求仍由硬件优先级决定先响应谁"，这决定了嵌套的实际发生顺序；④ "处理次序"问的是**完成次序**，不是响应次序。

### 7.7 DMA 方式

#### 7.7.1 基本思想

`DMA`（`Direct Memory Access`，直接存储器存取）：在主存和外设之间开辟直接的数据通路，**数据传送不经过 `CPU`、也不由 `CPU` 执行程序逐字搬运**，而由 `DMA` 控制器（硬件）控制，一次传送一整块数据。`CPU` 只在传送前初始化、传送结束后做后处理。

#### 7.7.2 DMA 控制器的组成

| 部件 | 作用 |
| --- | --- |
| 主存地址计数器 `AR` | 存放本次要传送数据的主存地址，每传送一个字自动 ±1 |
| 传送长度计数器 `WC` | 记录剩余要传送的字数，每传一字 −1，减到 0 表示传送结束 |
| 数据缓冲寄存器 `DR` | 暂存每次传送的数据（外设 ↔ 主存的中转站） |
| `DMA` 请求触发器 | 外设准备好一个数据时置位，向 `CPU` 发出总线请求（`HRQ`） |
| 控制/状态逻辑 | 接收 `CPU` 的初始化命令、协调总线使用权、产生读写控制信号 |
| 中断机构 | 数据块传送结束时向 `CPU` 发中断请求，用于"后处理" |
| 设备地址/选择逻辑 | 选中外设（一个 `DMA` 控制器接多台设备时） |

#### 7.7.3 DMA 传送过程（三阶段）

1. **预处理**：`CPU` 执行几条指令，把主存起始地址送 `AR`、传送字数送 `WC`、传送方向与设备地址送控制寄存器，然后**启动 `DMA` 控制器**；此后 `CPU` 继续执行自己的程序
2. **数据传送**：`DMA` 控制器接管总线，按字（或字节）在主存与外设之间直接传送；每传一个数据 `AR` ±1、`WC` −1，直到 `WC` = 0；整个过程**不需要 `CPU` 干预**
3. **后处理**：`WC` = 0 后 `DMA` 控制器通过**中断机构**向 `CPU` 发中断请求，`CPU` 执行中断服务程序：校验数据、决定是否继续下一块、收回总线控制权

> **最容易考的一句话**：`DMA` **只在结束时才用中断**，中断在 `DMA` 中只承担"报告结束/出错"的职责，**不用来传送数据本身**。这正是它与程序中断方式最本质的区别。

#### 7.7.4 DMA 与 CPU 争用总线的三种方式

| 方式 | 做法 | 优点 | 缺点 / 适用 |
| --- | --- | --- | --- |
| 停止 `CPU` 访存（成组传送） | `DMA` 传送期间 `CPU` 完全不能访存，让出总线 | 控制简单，传送效率高 | `CPU` 停顿长；适合高速外设成块传送 |
| **周期窃取（周期挪用/周期偷取）** | `DMA` 每次只占**一个存储周期**，传完一个字立即把总线还给 `CPU` | 兼顾 `CPU` 访存，效率高 | 存在访存冲突：同时访存时 `DMA` 优先，`CPU` 推迟一个周期 |
| `DMA` 与 `CPU` 交替访存 | 把 `CPU` 周期一分为二，一半给 `CPU`、一半给 `DMA`（透明 `DMA`） | 不需要总线申请/响应时序，固定分时 | 要求 `CPU` 周期比存储周期长；灵活性差 |

**周期窃取的三种情形（常考）**：

1. `CPU` 不在访存（正在译码/执行运算）→ `DMA` 直接占用，无冲突
2. `CPU` 正在访存 → `DMA` 等这一个存储周期结束后再占用
3. `CPU` 与 `DMA` 同时请求访存 → **`DMA` 优先**（否则高速外设数据会丢失），`CPU` 被推迟一个存储周期

#### 7.7.5 DMA 方式的特点

- 数据在**主存 ↔ 外设**之间直接传送，**不经过 `CPU`**
- 以**数据块**为单位传送，只在开始/结束需要 `CPU` 干预
- 请求优先级**高于**中断请求（`DMA` 请求不及时响应会丢数据）
- 不需要保存/恢复 `CPU` 现场（`CPU` 的程序状态没被打断，只是让出了总线）

> **408 怎么考/常见坑**：① 选择题最爱考——`DMA` 传送结束后**是否**要中断（要，用于后处理）、`DMA` 与 `CPU` 谁优先（`DMA` 优先）、周期窃取"偷"的是什么（一个存储周期/总线周期）；② 大题常与中断方式合起来对比分析，或算 `DMA` 传送时间、`DMA` 占用总线（`CPU` 减速）的比例；③ `DMA` 不是"不需要 `CPU`"，而是"只在首尾需要 `CPU`"。

### 7.8 三种 I/O 方式的定性比较

- **程序查询**：纯软件方式，`CPU` 全程参与，与外设**串行**，效率最低、硬件最简单
- **程序中断**：软硬件结合，`CPU` 每传一个字/字节参与一次，与外设**并行**，适合中低速、随机性强的设备
- **`DMA`**：纯硬件方式，`CPU` 只在传送首尾参与，与外设**并行**，效率最高，适合高速成批数据（磁盘、显卡）

完整对比表见 **§三.4**。

## 三、易混对比表

### 三.1 统一编址 vs 独立编址

| 比较项 | 统一编址（存储器映射） | 独立编址（`I/O` 映射） |
| --- | --- | --- |
| 地址空间 | `I/O` 端口与主存**共用**同一地址空间 | `I/O` 端口有**独立**的地址空间 |
| 访问指令 | 普通访存指令（`MOV`/`LW`/`SW`） | 专用 `I/O` 指令（`IN`/`OUT`） |
| 控制信号 | 复用访存的读写信号 | 需要专门的 `IOR`/`IOW` 信号 |
| 对主存容量的影响 | **减少**主存可用地址范围 | **不影响**主存地址空间 |
| 指令功能 | 强，可直接对端口做算术/逻辑运算 | 弱，一般只能单纯输入/输出 |
| 译码与硬件 | 需区分访存/访端口，译码相对复杂 | 端口地址位数少，译码简单 |
| 程序可读性 | 差（不易看出访问的是外设） | 好（一看 `IN`/`OUT` 就知道） |
| 典型代表 | `ARM`、`RISC-V`（`RISC` 多用） | x86（`IN`/`OUT`） |

> **一句话记忆**：统一编址"省指令、费地址空间"；独立编址"省地址空间、费指令"。

### 三.2 中断与异常（内中断 vs 外中断）

| 比较项 | 中断（外中断） | 异常（内中断/例外） |
| --- | --- | --- |
| 产生来源 | `CPU` **外部**（外设、时钟） | `CPU` **内部**（执行指令引起） |
| 与当前指令的关系 | 无关，随机发生 | 与当前指令**相关** |
| 检测/响应时机 | 一条指令执行**结束**后 | 一般在指令执行**过程中**或结束时被检测 |
| 可否屏蔽 | 可屏蔽中断可屏蔽；`NMI` 不可屏蔽 | 一般不可屏蔽（`trap` 类软件中断除外） |
| 返回位置 | 返回**下一条**指令 | 多数返回**当前指令**重新执行（缺页、缺段）；`trap` 返回下一条 |
| 典型例子 | `I/O` 中断、时钟中断、键盘中断 | 除零、算术溢出、非法操作码、缺页、系统调用 |

### 三.3 单重中断 vs 多重中断

| 比较项 | 单重中断 | 多重中断（中断嵌套） |
| --- | --- | --- |
| 服务期间是否允许新中断 | 不允许（全程关中断） | 允许更高优先级的中断打断 |
| 开中断的位置 | 服务结束、返回之前才开中断 | **保护现场之后立即开中断** |
| 现场保护要求 | 简单，不怕被覆盖 | 必须先把现场（含屏蔽字）压栈，否则嵌套会破坏现场 |
| 响应及时性 | 差，后来的请求要排队等 | 好，高优先级请求能立刻得到处理 |
| 硬件要求 | 低 | 需要优先级判优电路 + 中断屏蔽字 |
| 实现关键 | 无 | ①提前开中断 ②有优先级机制 |

### 三.4 程序中断 vs DMA

| 比较项 | 程序中断方式 | `DMA` 方式 |
| --- | --- | --- |
| 数据传送的控制者 | `CPU` 执行程序（软件） | `DMA` 控制器（硬件） |
| 数据传送路径 | 外设 → 接口 → **`CPU` 寄存器** → 主存（或反向） | 外设 ↔ 主存**直接**传送，不经过 `CPU` |
| 传送单位 | 一个字/字节中断一次 | 一个**数据块** |
| 响应时机 | **一条指令执行结束后** | **一个存储周期（总线周期）结束后** |
| 请求优先级 | 低 | **高**（不及时响应会丢数据） |
| 中断的作用 | 传送数据本身 + 处理异常 | 仅用于传送结束/出错的**后处理** |
| 是否需要保护/恢复现场 | 需要（断点 + 通用寄存器） | 不需要（`CPU` 程序状态未被打断） |
| `CPU` 干预程度 | 每传一个字都要干预 | 只在预处理和后处理阶段干预 |
| 适用场景 | 中低速、随机性强的字符设备（键盘、打印机） | 高速、成批成块的设备（磁盘、网卡、显卡） |
| 硬件复杂度 | 较复杂 | 最复杂 |

### 三.5 三种 I/O 方式综合对比

| 比较项 | 程序查询 | 程序中断 | `DMA` |
| --- | --- | --- | --- |
| `CPU` 干预程度 | 全程干预（踏步等待） | 每个字/字节干预一次 | 仅开始和结束干预 |
| `CPU` 与外设的工作方式 | **串行** | **并行** | **并行** |
| 数据是否经过 `CPU` | 经过 | 经过 | **不经过** |
| 传送单位 | 字 | 字/字节 | 数据块 |
| 响应/启动时机 | 程序主动查询 | 一条指令执行结束 | 一个存储周期结束 |
| 请求优先级 | —（无请求） | 低 | **最高** |
| `CPU` 时间开销 | 约 100%（最大） | 中等 | 极小 |
| 硬件复杂度 | 最简单 | 较复杂 | 最复杂 |
| 典型适用 | 低速简单设备、`CPU` 空闲时 | 中低速随机设备 | 高速成批数据传送 |

## 四、例题精练（3 道）

### 例题 1（单项选择题）

下列关于 `I/O` 方式与中断的叙述中，**错误**的是（　　）

A. 中断隐指令由硬件自动执行，主要包括关中断、保存断点和引出中断服务程序，它不是指令系统中的指令
B. `CPU` 响应中断的时间是一条指令执行结束后，而响应 `DMA` 请求的时间是一个存储周期结束后
C. 程序查询方式中 `CPU` 与外设并行工作，因此 `CPU` 的利用率比程序中断方式高
D. 多重中断中，可以通过修改各中断源的中断屏蔽字来改变中断处理次序

**答案：C**

**逐项解析**

- **A 正确**：中断隐指令是硬件在中断响应阶段自动完成的操作序列，没有操作码、不由程序编写，因此不属于指令系统的指令；其三项内容是关中断、保存断点、引出中断服务程序。
- **B 正确**：中断请求在**一条指令执行结束时**被检查，因为指令执行中途打断会破坏指令的完整性；`DMA` 以存储周期为单位窃取总线，所以请求在**一个存储周期结束后**被响应。
- **C 错误**：程序查询方式下 `CPU` 与外设是**串行**工作的——外设准备数据期间 `CPU` 只能在循环里踏步等待，既不空闲也不能响应其他外设，`CPU` 时间几乎全被 `I/O` 占满，利用率**低于**中断方式。把"串行"说成"并行"是本章最经典的错项。
- **D 正确**：硬件优先级决定"谁先被响应"，中断屏蔽字决定"谁能打断谁"，即最终的处理次序；改屏蔽字就能改处理次序，无须改动硬件判优电路。

**采分点与常见坑**

- 得分核心是识别 C 的"并行/串行"偷换；只要记得"查询 = 踏步等待 = 串行"就能秒杀。
- 常见坑 1：把"中断隐指令保存断点"误解成"保存全部现场"——通用寄存器由**软件**（服务程序压栈）保存。
- 常见坑 2：混淆两类响应时机，记反成"DMA 在指令执行结束时响应"。
- 常见坑 3：以为改处理次序要动硬件优先级——屏蔽字就能改。

### 例题 2（综合应用题：中断屏蔽字与多重中断处理次序）

某机有 4 个中断源 A、B、C、D，硬件判优优先级为 **A > B > C > D**。现要求把中断处理次序改为 **C > A > D > B**。

(1) 按 A、B、C、D 的位序写出各中断源的中断屏蔽字（1 表示屏蔽，0 表示不屏蔽）。
(2) 若 `CPU` 正在执行 B 的中断服务程序（已开中断），此时 A、C、D 三个中断源**同时**发出中断请求，写出各中断服务程序实际**完成**的次序，并说明理由。

**解题步骤**

**第 1 步：把"处理次序"翻译成"处理优先级"**

要求处理次序 C > A > D > B，即处理优先级 C(第 1) > A(第 2) > D(第 3) > B(第 4)。

**第 2 步：逐行填屏蔽字**

规则：处理 X 时，屏蔽**自己**和**所有处理次序比 X 低**的源；处理次序比 X 高的源**不**屏蔽（留着打断自己）。

| 中断源 | A | B | C | D | 屏蔽字 | 含义 |
| --- | --- | --- | --- | --- | --- | --- |
| A | 1 | 1 | 0 | 1 | 1101 | 屏蔽自己、B、D；不屏蔽 C |
| B | 0 | 1 | 0 | 0 | 0100 | 只屏蔽自己 |
| C | 1 | 1 | 1 | 1 | 1111 | 屏蔽全部（处理次序最高） |
| D | 0 | 1 | 0 | 1 | 0101 | 屏蔽自己、B；不屏蔽 C、A |

**第 3 步：自检**

自检规则：共 n = 4 个中断源，处理次序**第 k 高**的源，屏蔽字中应有 **n − k + 1** 个 1（自己 + 所有比它低的源）。

| 中断源 | 处理次序名次 k | 应有 1 的个数 = 4 − k + 1 | 实际 1 的个数 | 校验 |
| --- | --- | --- | --- | --- |
| C | 1 | 4 | 1111 → 4 | ✓ |
| A | 2 | 3 | 1101 → 3 | ✓ |
| D | 3 | 2 | 0101 → 2 | ✓ |
| B | 4 | 1 | 0100 → 1 | ✓ |

> 提示：这条自检规则只在"屏蔽字位数 = 中断源个数、且每个源都要屏蔽自己"的常规题型下成立。**考试时仍应按语义逐行填**（屏蔽自己 + 处理次序低于自己的源），再用个数规则验算。

**第 4 步：分析 (2) 的执行过程**

1. B 的中断服务程序已开中断，B 的屏蔽字 0100 只屏蔽 B，因此 A、C、D 三者的请求都**未被屏蔽**，都能被响应。
2. 三个请求**同时**到达时，由**硬件判优**决定先响应谁：硬件优先级 A > B > C > D，所以先响应 **A**，转入 A 的服务程序。
3. A 的屏蔽字为 1101，其中 C 位 = 0，因此 C **可以打断 A**（C 的处理次序高于 A）→ 响应 C，转入 C 的服务程序。
4. C 的屏蔽字为 1111，服务期间任何请求都打不进来，C **最先完成**，返回 A。
5. 回到 A 的服务程序：D 的请求仍在，但 A 的屏蔽字中 D 位 = 1，D 被 A 屏蔽，不能打断 A；A 继续执行完，返回 B。
6. 回到 B：此时 D 未被 B 屏蔽，响应 D；D 的屏蔽字 0101 屏蔽 B，B 不能打断 D，D 执行完返回 B。
7. B 的服务程序继续执行完。

**答案**

(1) 各中断源屏蔽字（位序 A、B、C、D）：
A = 1101，B = 0100，C = 1111，D = 0101。

(2) 各中断服务程序**完成**的次序为：**C → A → D → B**。
理由要点：三个请求同时到达时由**硬件优先级**决定先响应 A；A 不屏蔽 C，C 打断 A 并因屏蔽全部而最先完成；A 屏蔽 D，故 A 完成后才响应 D；D 屏蔽 B，D 完成后 B 才收尾。可见"**先被响应 ≠ 先完成**"——A 最先被响应，却比 C 晚完成。

**采分点与常见坑**

- **采分点 1**：屏蔽字的位序必须与题目给定顺序（A、B、C、D）严格一致，位序写反整题作废。
- **采分点 2**：每一位的含义必须写清"1 = 屏蔽、0 = 允许"，只写 4 位数字不写含义容易被扣分。
- **采分点 3**：自己那一位必须是 1（防止同一中断源重入），这是默认约定。
- **采分点 4**：(2) 的关键是"同时到达由硬件优先级决定先响应谁"，漏掉这一步就会把顺序答成 C 或 A 直接开始。
- **常见坑 1**：把问题当成"响应次序"，答成 A → C → D → B。题目问的是**处理（完成）次序**。
- **常见坑 2**：忘记"中断服务程序已开中断"这一前提，认为三个请求要等 B 做完才响应。
- **常见坑 3**：以为屏蔽字可以改写硬件优先级。屏蔽字改变的是"能否打断"，同时到达时仍按硬件优先级响应。

### 例题 3（综合应用题：三种 I/O 方式的 CPU 开销与传送时间计算）

某机主频 50 MHz（1 个时钟周期 = 20 ns），一台外设以**每 10 μs 传送一个字节**的速率连续传送数据（即传输率 100 KB/s）。回答下列问题：

(1) 若采用**程序查询**方式，每次读状态端口并判断"就绪"位需 4 个时钟周期；就绪后传送一个字节另需 20 个时钟周期。求 `CPU` 用于该外设 `I/O` 的时间比例。
(2) 若采用**程序中断**方式，每次中断的服务程序共 20 条指令，平均 `CPI` = 2；中断隐指令及现场保护/恢复等硬件开销折合 5 个时钟周期。求 `CPU` 用于该外设 `I/O` 的时间比例。
(3) 若采用 `DMA` 方式，每传送 4 KB 数据块后中断一次做后处理，预处理 + 后处理共 200 条指令（`CPI` = 2）。求 `CPU` 用于该外设的时间比例，并说明 `DMA` 的数据传送时间由什么决定。

**解题步骤与解答**

**(1) 程序查询方式**

一个字节的间隔时间 = 10 μs = 10000 ns。

- 单次查询耗时 = 4 × 20 ns = 80 ns
- 等待期间需要查询的次数 = 10000 ns ÷ 80 ns = 125 次
- 查询总耗时 = 125 × 80 ns = 10000 ns = 10 μs（恰好把 10 μs 用满）
- 再加上就绪后传送一个字节的 20 个时钟周期 = 400 ns

传送一个字节 `CPU` 共需 10000 + 400 = **10400 ns > 10000 ns**。

**CPU 用于该外设 `I/O` 的时间比例 ≈ 100%**（已经饱和，实际会因来不及查询而降低数据传送速率）。结论：程序查询方式下 `CPU` 几乎被 `I/O` 完全占满，是三种方式中最差的。

**(2) 程序中断方式**

- 中断服务程序耗时 = 20 条 × 2 = 40 个时钟周期 = 40 × 20 ns = 800 ns
- 硬件开销（隐指令 + 现场保护/恢复）= 5 × 20 ns = 100 ns
- 每个字节 `CPU` 共花 800 + 100 = **900 ns**

**时间比例 = 900 ns ÷ 10000 ns = 9%**

即 `CPU` 约 91% 的时间可以执行自己的主程序，只在外设就绪时被打断约 0.9 μs。

**(3) DMA 方式**

- 传送一个 4 KB 数据块所需时间 = 4096 × 10 μs = 40960 μs ≈ **40.96 ms**
- `CPU` 干预时间 = 200 条 × 2 = 400 个时钟周期 = 400 × 20 ns = 8000 ns = **8 μs**
- **时间比例 = 8 μs ÷ 40960 μs ≈ 0.0195% ≈ 0.02%**

`DMA` 的数据**传送时间由外设的数据传输率（以及主存/总线带宽）决定**，与 `CPU` 主频无关——`DMA` 只是把数据搬过去，不执行指令。`CPU` 只在预处理（初始化 `AR`、`WC`、传送方向）和后处理（校验、决定是否继续）阶段介入。

**拓展（周期窃取的影响）**

若 `DMA` 采用周期窃取，每传送 1 个字节占用 1 个存储周期（设存储周期 = 0.1 μs），则 4096 字节共占用 4096 × 0.1 μs = 409.6 μs 的存储周期，占传送时间的 409.6 ÷ 40960 ≈ **1%**。这段时间 `CPU` 不能访存，是 `DMA` 带来的额外开销上限；由于 `CPU` 通常有 `Cache`，多数访存并不冲突，实际影响远小于这个上界。

**三种方式对比小结**

| 方式 | `CPU` 时间比例 | 说明 |
| --- | --- | --- |
| 程序查询 | ≈ 100% | 全程踏步等待，串行工作 |
| 程序中断 | 9% | 每字节被打断一次，软硬件结合 |
| `DMA` | ≈ 0.02% | 只在一头一尾干预，数据传送由硬件完成 |

**采分点与常见坑**

- **采分点 1**：所有时间先统一到同一单位（ns 或 μs）再算比例，比例题最终要写成百分数。
- **采分点 2**：指令耗时 = 指令条数 × `CPI` × 时钟周期，**`CPI` 不能漏**（本题 CPI = 2，漏了就整体少一半）。
- **采分点 3**：中断方式的开销必须把题目给出的"隐指令及现场开销 5 个时钟周期"加上，只算服务程序会少 100 ns。
- **采分点 4**：比例的分母是"外设传送一个字节/一块数据所需的时间"（10 μs / 40.96 ms），不是 `CPU` 自己花的时间。
- **常见坑 1**：认为程序查询方式 `CPU` 开销是"50%"或"查询时间占比"——等待期间 `CPU` 是空转，比例接近 100%。
- **常见坑 2**：用 `CPU` 主频去算 `DMA` 的传送时间。`DMA` 传送时间由外设速率和主存带宽决定。
- **常见坑 3**：结论方向写反（把 `DMA` 的 `CPU` 开销写成最大）。三者的开销排序固定为：查询 > 中断 > `DMA`。
- **常见坑 4**：周期窃取的"1% 存储周期占用"与"`CPU` 时间比例 0.02%"是两个不同口径——前者是总线/访存被占用的时间，后者是 `CPU` 执行指令的时间，别混在一起比值。

## 六、简便方法与易错口诀（速算 · 防错）

> 本节把本章能"省时间"和"防掉坑"的招集中在一处：二轮复习与考前只看这一节。每条都写清**适用条件**。

### 6.1 速算招式

| 场景 | 常规做法（慢/繁） | 简便做法（快/稳） | 为什么成立 / 适用条件 |
| --- | --- | --- | --- |
| 写中断屏蔽字（`n` 个源，题目另给处理次序） | 逐位推敲"谁屏蔽谁"，容易漏写或多写 `1` | 按处理次序从高到低编号 `k` = 1, 2, …, `n`；第 `k` 高的源只做两件事：自己置 `1`，处理次序比它低（`k` 更大）的源全部置 `1`，其余置 `0` | 屏蔽字的语义就是"屏蔽自己 + 比自己低的源"，所以第 `k` 高的源恰好有 `n − k + 1` 个 `1`，可用来 3 秒自检：处理次序最高的源整行全 `1`，最低的源只有自己那一位是 `1`。适用条件：位序按题目给定的源顺序（通常就是硬件优先级从左到右）排列，`1` = 屏蔽 |
| 判断"谁先响应"（多个中断源同时到达） | 把硬件优先级和屏蔽字混在一起推，两个结论互相打架 | 先响应只查**硬件优先级**（排队器 / 优先级编码器）；"谁能打断谁"（即最终处理次序）才查屏蔽字 | 二者由不同机构决定、互不覆盖，所以"先响应 ≠ 先完成"是正常现象。适用条件：只有"同时到达"才谈得上硬件判优；不同时刻到达则先到先响应 |
| 记"中断隐指令"内容 | 把"保护现场"整体记成硬件行为 | 只背硬件自动做的三件：关中断、保存断点（只保存 `PC`）、引出中断服务程序（取类型号 → 形成向量地址 → 取向量 → 送 `PC`） | 例外：① 通用寄存器由中断服务程序用压栈指令（软件）保存；② 有的教材把保存 `PSW` 也算入隐指令，答题按所用教材口径 |
| 判断中断与 `DMA` 的响应时机 | 都记成"一条指令执行结束后" | 中断：**一条指令执行阶段结束**后检查并响应；`DMA`：**一个机器周期（存储周期 / 总线周期）结束**时即可响应（周期窃取） | 例外：`DMA` 采用"停止 `CPU` 访存"的成组传送时，是整块占用总线，不是每个周期响应一次 |
| 比较三种 `I/O` 方式的 `CPU` 开销 | 每种方式都从头算细节 | 一句话"谁在等谁"：查询是 `CPU` 等设备（≈ 100% 空转）、中断是每传一个字陪一次、`DMA` 只在首尾各陪一次（≈ 0） | 排序恒为 查询 > 中断 > `DMA`；定量时中断方式 = 一次中断的全部开销 × 中断次数 ÷ 外设传送这批数据的总时间 |
| 算中断方式的 `CPU` 开销（定量） | 只算设备服务程序那几行 | 一次中断开销 = 隐指令 + 现场保护 + 服务程序 + 恢复现场 + 返回；题目给了几个时钟周期就全加上，再乘中断次数 | 漏掉"隐指令及现场保护"的开销会系统性偏小；分母是**外设传送时间**，不是 `CPU` 自己花的时间 |
| 算 `DMA` 传送时间 | 拿 `CPU` 主频去换算 | 数据在主存与外设之间的传送时间 = 数据量 ÷ 传送速率；若"每个存储周期窃取一次、每次传一个字"，则 `DMA` **占用总线**的时间 = 字数 × 存储周期 | 两个口径别混：传送总时间由外设速率与主存带宽中较慢的一方决定；"占用总线时间 ÷ 传送时间"才是 `CPU` 被拖慢的上界（约 1% 量级） |
| 由中断类型号求中断向量地址 | 把"中断向量"与"中断向量地址"当成同一个东西 | 向量地址 = 向量表基址 + 中断类型号 × 每个表项的字节数（`x86` 实模式：基址 0、表项 4 字节，即类型号 × 4）；该地址单元里**存放的内容**才是服务程序入口地址 | 表项长度题目一般会给；不问基址时默认 0。填空问"向量地址"填门牌号，问"中断向量"才填入口地址 |
| 判断一段程序用统一编址还是独立编址 | 逐条背对比表 | 只看访端口用的指令：用 `IN` / `OUT` 等专用 `I/O` 指令 → 独立编址；用 `MOV` / `LW` / `SW` 等普通访存指令 → 统一编址 | 统一编址的代价是占用主存地址空间，独立编址的代价是需要专用指令与 `IOR` / `IOW` 信号 |

### 6.2 口诀与记忆钩子

- **口诀 1（隐指令三件套）**："关中断、存断点、引服务"——全是硬件自动干；断点只存 `PC`（部分教材加 `PSW`），**通用寄存器靠软件**。
- **口诀 2（两次序）**："响应看排队器，完成看屏蔽字"；同时到达时**先响应 ≠ 先做完**。
- **口诀 3（屏蔽字自检）**："自己是 `1`，比自己低的也是 `1`；第 `k` 高有 `n − k + 1` 个 `1`；最高那行全 `1`，最低那行只 `1` 位。"
- **口诀 4（响应时机）**："中断看指令尾，`DMA` 看周期尾"；`DMA` 只在**传送结束时**中断一次，中断在 `DMA` 里只做后处理。
- **口诀 5（向量）**："向量是入口地址，向量地址是它的门牌号；门牌号 = 基址 + 类型号 × 表项长。"
- **口诀 6（开销排序）**："查询等、中断陪、`DMA` 送"；`CPU` 开销恒为 查询 > 中断 > `DMA`。

### 6.3 反例黑名单（这些"简便法"是错的）

- ❌ "屏蔽字里 `1` 表示允许、`0` 表示屏蔽"：正确做法是 `1` = 屏蔽（禁止）、`0` = 允许，且每个源屏蔽字里**自己那一位恒为 `1`**。
- ❌ "屏蔽字只屏蔽别人、不屏蔽自己"：正确做法是自己那一位必须置 `1`（防止同一中断源反复打断自己），漏掉自己的写法必错。
- ❌ "先响应的一定先处理完"：正确做法是响应次序由**硬件优先级**决定、完成（处理）次序由**屏蔽字**决定，两者可以完全不同。
- ❌ "中断隐指令保存了通用寄存器"：正确做法是硬件只保存断点 `PC`（及部分教材的 `PSW`），通用寄存器由中断服务程序用压栈指令保存。
- ❌ "中断请求在每个时钟周期（或任意时刻）检查"：正确做法是在**每条指令执行阶段结束**时检查；`DMA` 请求才是每个机器周期结束时响应。
- ❌ "`DMA` 传送时间用 `CPU` 主频算"或"`DMA` 完全不需要 `CPU`"：正确做法是传送时间用 数据量 ÷ 传送速率（占用总线时间用 字数 × 存储周期），且 `DMA` 在传送首尾仍需要 `CPU` 初始化和后处理。
- ❌ "按屏蔽字里 `1` 的个数直接比优先级高低"：正确做法是 `1` 的个数只是自检结果（第 `k` 高有 `n − k + 1` 个 `1`），不能脱离处理次序反推优先级。
- ❌ "屏蔽字位序可以随便定"：正确做法是按题目给定的中断源顺序（通常即硬件优先级从左到右）对位，位序错则整张表全错。
