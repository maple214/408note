## 一、本章知识框架

**一条主线**：`CPU` 要干活，先得有「身体」（数据通路）和「大脑」（控制器）；干活的过程就是不断重复「取指 → 间址 → 执行 → 中断」；为了干得快，把执行过程拆段重叠起来就是流水线；干到一半来了紧急情况要能停下来处理，这就是异常和中断；一台机器不够用就堆多台，这就是多处理器。

**骨架图（文字版）**

```
CPU
├── 运算器：ALU、通用寄存器组、暂存寄存器、移位器、PSW（标志寄存器）
├── 控制器
│   ├── 硬布线控制器（组合逻辑，快而硬）
│   └── 微程序控制器（控制存储器 CM + 微指令，慢而软）
└── 关键寄存器
    ├── 用户可见：PC、通用寄存器、PSW
    └── 用户不可见：IR、MAR、MDR、暂存寄存器

指令执行过程（一遍遍循环）
    取指周期 → 间址周期（可能没有）→ 执行周期 → 中断周期（可能有）
    单总线结构下：任何寄存器想上总线都要排队，MAR/MDR 是访存的固定中转站

数据通路 vs 控制器
    数据通路 = 数据流动与加工的路径（执行部件）
    控制器   = 产生控制信号、指挥数据通路（控制部件）

异常与中断
    异常（内，指令执行中检测）：fault / trap / abort
    中断（外，一条指令结束后检测）：可屏蔽 / 不可屏蔽
    响应 = 中断隐指令（关中断 → 保存断点 → 引出中断服务程序）
    多重中断 = 中断屏蔽字

指令流水线
    时空图 → k 段流水线做 n 条指令：T = (k + n - 1) × 时钟周期
    三类冒险：结构 / 数据 / 控制 —— 各自有对策
    进阶概念：超标量、动态流水线（乱序执行只记名词）

多处理器
    Flynn 分类：SISD / SIMD / MISD / MIMD
    向量处理器、硬件多线程、多核、SMP（UMA / NUMA）
```

**本章在 408 里的三个必拿分点**

1. **微操作序列**：给你一段数据通路图，让你写出某条指令的微操作序列（大题）。
2. **流水线计算**：吞吐率、加速比、执行时间，含停顿与冒险（大题）。
3. **异常/中断的概念辨析**：分类、检测时机、中断隐指令、中断屏蔽字（选择 + 大题）。

## 二、概念详解

### 5.1 CPU 的功能和基本结构

#### 5.1.1 `CPU` 的五大功能

| 功能 | 干什么 | 靠什么实现 |
| --- | --- | --- |
| 指令控制 | 保证指令按程序规定的顺序执行 | `PC` + 时序 |
| 操作控制 | 把每条指令翻译成一串操作信号，送给各部件 | 控制器（硬布线/微程序） |
| 时间控制 | 给各种操作规定先后与时长 | 时钟 + 时序系统 |
| 数据加工 | 算术运算、逻辑运算 | `ALU` |
| 中断处理 | 对异常事件和外部请求作出响应 | 中断机构 + `PSW` |

- **为什么有这五条**：程序的本质是「指令序列 + 数据」，所以既要「按序取指」（指令控制）、又要「分解成动作」（操作控制）、还要「有先后」（时间控制）、「算得出」（数据加工）、「能应对意外」（中断处理）。前两条是控制器的活，后三条分别落在 `ALU`、时序、中断机构上。
- **408 怎么考**：直接问「下列不属于 `CPU` 功能的是」，典型错误项是「**存储程序**」（那是冯·诺依曼思想，不是 `CPU` 功能）、「**编译优化**」（那是软件的事）。也可能问「中断处理由谁完成」——答 `CPU` 内部的中断机构，不是操作系统，`OS` 只是提供中断服务程序。

#### 5.1.2 `CPU` 的基本结构

`CPU` = **运算器** + **控制器**（外加若干寄存器、内部总线）。

**运算器**：`ALU`、通用寄存器组、暂存寄存器（如 `Y`、`Z`）、移位器、`PSW`。

**控制器**：`PC`、`IR`、`MAR`、`MDR`、微操作信号发生器、时序系统。

**寄存器逐个过关（本章最高频的送分点）**

| 寄存器 | 全称/含义 | 位数由谁决定 | 用户可见 | 关键作用 |
| --- | --- | --- | --- | --- |
| `PC` | 程序计数器 | 由**主存地址位数**（寻址空间）决定 | 可见 | 存放下一条指令的地址；有自增功能，支持顺序执行 |
| `IR` | 指令寄存器 | 由**指令字长**决定 | 不可见 | 存放当前正在执行的指令，`OP` 送译码器 |
| `MAR` | 存储器地址寄存器 | 由**地址总线位数**决定 | 不可见 | 存放要访问的主存单元地址，单向送地址总线 |
| `MDR` | 存储器数据寄存器 | 由**数据总线位数**（存储字长）决定 | 不可见 | 存放与主存交换的数据/指令，双向 |
| `PSW` | 程序状态字寄存器 | 由标志位数决定 | 可见 | 存 `OF`/`SF`/`ZF`/`CF` 等标志，以及中断允许位、优先级 |
| 通用寄存器 | `AX`/`BX`… | 一般等于机器字长 | 可见 | 程序员可编程使用，减少访存 |
| 暂存寄存器 | `Y`/`Z` | 依需要 | 不可见 | 为 `ALU` 暂存一个操作数，避免总线冲突 |

- **怎么来的**：单总线结构下，`ALU` 是组合逻辑，两个输入端不能同时接总线上的同一个源，所以必须有一个「先存住」的寄存器（`Y`），这就是暂存寄存器存在的原因。
- **408 怎么考 / 常见坑**：
  - 「`PC` 的位数取决于机器字长」——**错**，取决于主存地址位数；「`MAR` 的位数等于 `PC` 的位数」——**对**（两者都由地址位数决定）。
  - 「`IR` 的位数 = 机器字长」——**不一定**，等于指令字长；「`MDR` 的位数 = 存储字长 = 数据线位数」——通常对，但按字节编址、支持非对齐访问时 `MDR` 可能等于两个存储字长。
  - `PC` 与 `MAR`、`IR` 与 `MDR` 之间常常**直接相连**（图中画成两条线），很多微操作序列题就是靠这一点省掉一步。

### 5.2 指令执行过程

#### 5.2.1 四个机器周期

一条指令的执行可能经过四个阶段，每个阶段称为一个**机器周期**（CPU 周期）：

```
取指周期 FE  →  间址周期 IND（只有间接寻址才有）  →  执行周期 EX  →  中断周期 INT（有中断请求才进入）
```

| 周期 | 任务 | 典型微操作（单总线结构） |
| --- | --- | --- |
| 取指 `FE` | 把 `PC` 指向的指令取到 `IR` | `(PC) → MAR`；`M(MAR) → MDR`；`(MDR) → IR`；`(PC) + 1 → PC` |
| 间址 `IND` | 由形式地址取出有效地址 | `(IR 的 Ad) → MAR`；`M(MAR) → MDR`；`(MDR) → IR 的 Ad`（把有效地址写回地址字段） |
| 执行 `EX` | 按操作码完成实际运算/传送 | 因指令而异，例如 `ADD X`：`(IR 的 Ad) → MAR`；`M(MAR) → MDR`；`(ACC) + (MDR) → ACC` |
| 中断 `INT` | 响应中断请求 | `(PC) → MDR`（保存断点）；`中断服务程序入口 → PC`；`(MDR) → M(MAR)`（断点写回主存/压栈） |

- **为什么有间址周期**：间接寻址要访存两次才能拿到操作数，第一次访存专门用来「把形式地址换成有效地址」，这一步无法并入取指或执行，于是单列一个周期。**一次间接寻址一个间址周期，多次间接就有多个间址周期**。
- **408 怎么考 / 常见坑**：
  - 「间址周期是必需的」——**错**，只有间接寻址指令才有；「一条指令的机器周期数固定」——**错**，不同指令差别很大。
  - 取指周期结束后 `PC` 已经指向下一条指令；`PC + 1` 中的「1」是**一条指令占的地址单元数**，按字节编址时 4 字节指令要 `PC + 4`。
  - 取指周期的微操作序列**所有指令都一样**，间址周期**只有间接寻址类指令一样**，执行周期**各不相同**——这是写微操作题的三句口诀。

#### 5.2.2 单总线结构下的「中转」问题

单总线结构里，**任何两个寄存器之间传数据都要经过总线，且同一时刻总线上只能有一个数据**。于是出现两个固定角色：

- `MAR`：**访存必备**。所有访存都要先把地址送进 `MAR`，再由 `MAR` 送地址总线。
- `MDR`：**数据必经**。主存读出的指令/数据先到 `MDR`，再转给 `IR`/`ACC`；写主存也要先进 `MDR`。

因此单总线结构的微操作必然是「一步一搬」，例如 `(PC) → MAR` 和 `(PC) + 1 → PC` 可以放在同一时钟（因为一个走总线、一个走 `PC` 自身的自增线路，且不同时占用总线资源），但 `(PC) → MAR` 和 `(R0) → MAR` 绝不能同周期。

- **408 怎么考**：给出数据通路图，要求「写出取指周期的微操作序列，并指出哪些微操作可并行」（大题第一问常见）。判断并行的原则：**不冲突的源和目的，且不抢占同一总线**。

### 5.3 数据通路的功能和基本结构

#### 5.3.1 数据通路做什么，控制器做什么

| 项目 | 数据通路 | 控制器 |
| --- | --- | --- |
| 是什么 | 数据在部件之间**流动和加工**的路径（含 `ALU`、寄存器、总线、多路选择器） | 产生**微操作控制信号**的部件 |
| 分工 | 执行体，决定「数据怎么走」 | 指挥体，决定「什么时候走、走哪条」 |
| 决定性因素 | 由**指令系统 + 结构设计**决定 | 由数据通路结构和指令功能决定 |
| 一般实现 | 寄存器传送级（`RTL`）描述 | 硬布线逻辑或微程序 |

**控制信号的来源（谁来产生）**：控制信号由**指令译码器**输出的操作码信息 + **时序系统**的节拍 + **`PSW` 的标志位** + **外部请求信号**共同决定。

- **一句话总结**：**数据通路是被控制者，控制器是控制者；控制信号的「因」是当前的指令和时间节拍。**

#### 5.3.2 两种数据通路结构

| 结构 | 组织方式 | 特点 | 微操作步数 |
| --- | --- | --- | --- |
| 单总线（CPU 内部单总线） | 所有寄存器挂在**一条公共内部总线**上 | 结构简单、成本低；但**同一时刻只能有一个数据在总线上**，需分步 | 多 |
| 多总线 / 专用数据通路 | 为部件之间设**专门的数据线**（或双总线、三总线），例如 `PC → MAR` 直连、`ALU` 输出直连寄存器 | 速度快，可并行；硬件复杂、控制信号多 | 少 |

举例对比「取指」的微操作：

- 单总线：`(PC) → MAR`；`M(MAR) → MDR`；`(MDR) → IR`；`(PC) + 1 → PC`（4 步）
- 专用通路（`PC` 直连 `MAR`、`MDR` 直连 `IR`）：`(PC) → MAR`（同时 `PC + 1 → PC`）；`M(MAR) → MDR → IR`（2 步）

- **408 怎么考 / 常见坑**：题目常要求「在给定数据通路上写出微操作序列」，评分看的是**每一步是否合法（总线上有没有冲突）+ 步骤是否最少**。常见扣分点：忘记了 `PC` 自增；反复用 `MDR` 绕路导致步数多余；把 `(MDR) → IR` 写成 `M(MAR) → IR`（**主存不能直接送 `IR`，必须经过 `MDR`**）。

#### 5.3.3 微操作序列的书写规范

1. 用括号表示「取内容」，`M(addr)` 表示按地址访存。
2. 赋值的箭头方向左端为目的，右端为源：`(PC) → MAR`。
3. 打上节拍号 `T0`、`T1`、`T2`…，**同一节拍内的多个微操作必须互不冲突**。
4. 分周期书写：取指 / 间址 / 执行 / 中断，分段列清。
5. 遇访存，务必走 `MAR → 主存 → MDR` 这条固定链路。

### 5.4 控制器的功能和工作原理

#### 5.4.1 控制器的功能

- **取指令**：给出指令地址并控制取指。
- **分析指令**：对 `IR` 中的操作码译码，产生相应操作信号；同时处理寻址方式的地址计算。
- **执行指令**：按时序发出微操作控制信号序列。
- **控制程序与数据的输入输出**、**处理异常和中断**。

#### 5.4.2 硬布线控制器

- **原理**：把微操作控制信号写成**操作码、节拍、标志位、外部条件**的布尔函数，用门电路/`PLA`/`ROM` 实现组合逻辑（含少量触发器做状态）。
- **结构**：`PC` + `IR` + 指令译码器 + 时序系统（节拍发生器）+ 组合逻辑网络 → 输出微命令。
- **优点**：速度快（信号延迟小，无访存取微指令的开销），适合 `RISC`。
- **缺点**：设计繁琐、不易修改与扩充，指令系统一变就要重新设计电路；控制逻辑庞杂。

#### 5.4.3 微程序控制器

- **核心思想**：把**一条机器指令**的执行过程，写成一段**微程序**（由若干**微指令**组成），存到 CPU 内部的**控制存储器 `CM`** 里。执行指令就是「从 `CM` 里按顺序取微指令并执行」。
- **概念链条（务必背准，年年有人混）**：

| 概念 | 定义 | 层次 |
| --- | --- | --- |
| 微命令 | 控制器发出的、控制一个部件做一次动作的**控制信号** | 最小 |
| 微操作 | 微命令所对应的**操作**（与微命令一一对应） | 最小 |
| 微指令 | 一个时钟周期内发出的**一组微命令**（含操作控制字段 + 顺序控制字段） | 中 |
| 微程序 | 实现一条机器指令的**微指令序列** | 大 |
| 微地址 | 微指令在 `CM` 中的地址 | 定位 |
| `CM` | 控制存储器，存放微程序，**在 CPU 内部**，用 `ROM` 实现 | 载体 |

- **一段话串起来**：**一条机器指令 = 一段微程序；一段微程序 = 若干条微指令；一条微指令 = 若干微命令；一个微命令 = 一个微操作。**
- **微程序控制单元的基本组成**：控制存储器 `CM`、微指令寄存器 `μIR`（或 `CMAR`/`CMDR` 一对）、微地址形成部件（微地址寄存器 `μAR` + 增量/断定逻辑）、时序系统。
- **执行一条微指令的流程**：微地址 → 取微指令到 `μIR` → 操作控制字段译码发出微命令 → 顺序控制字段决定下条微地址。
- **优点**：设计规整（像写程序一样），易修改扩充（只改 `CM` 内容），可把复杂控制逻辑规整化。
- **缺点**：速度慢（每条微指令都要访存 `CM`；虽然 `CM` 很快，仍比纯组合逻辑慢），需要额外的 `CM`。

#### 5.4.4 微指令的编码方式

| 编码方式 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 直接编码（水平型） | 操作控制字段**每一位对应一个微命令**，1 表示发 | 速度最快，不需译码 | 微指令最长，`CM` 容量大 |
| 字段直接编码 | 把**互斥**的微命令分成若干字段，每字段用二进制编码 | 显著缩短微指令字长，速度仍较快 | 需译码器；**每段要留一个编码表示「不发任何微命令」**；互斥判断有设计成本 |
| 字段间接编码 | 一个字段的含义由**另一个字段的译码结果**解释 | 进一步缩短字长 | 并行能力更差，译码更慢，微程序设计复杂 |

- **为什么字段直接编码要留空码**：如果 3 位字段全用 8 种编码表示 8 个互斥微命令，就没有编码能表示「这一拍不发该字段的任何微命令」，而程序中经常需要「本拍不发」。所以 3 位只能表示 **7 个互斥微命令**（`2^3 - 1`）。这是**必考小计算**。
- **408 怎么考**：给「`n` 个互斥微命令」问需要几位字段编码 → 答案 `⌈log2(n+1)⌉`；给总微命令数与分段方案，问微指令字长与 `CM` 容量。

#### 5.4.5 微指令的格式与微地址形成方式

**格式对比**

| 类型 | 特点 | 并行能力 | 字长 | 微程序长度 |
| --- | --- | --- | --- | --- |
| 水平型微指令 | 一次能定义并执行**多个并行**微操作 | 强 | 长 | 短（微指令条数少） |
| 垂直型微指令 | 类似机器指令，一条微指令**只能完成一个**微操作（甚至只控制一个部件） | 弱 | 短 | 长（微指令条数多） |

**微地址（下条微指令地址）的形成**

| 方式 | 原理 | 特点 |
| --- | --- | --- |
| 增量方式（计数器方式） | 设微程序计数器 `μPC`，顺序执行时 `μPC + 1`；遇转移微指令则按地址字段或条件修改 `μPC` | 微指令中地址字段可短，但**顺序执行与转移都要多花时间**，且需要专门的转移微指令 |
| 断定方式 | 下条微地址由**微指令的地址字段 + 判别测试条件**直接决定（硬件断定） | 微指令中要给出下条地址，字长长；但**速度快**，可实现多路转移 |

- **408 怎么考 / 常见坑**：
  - 「微程序存放在主存中」——**错**，存放在 CPU 内的 `CM`（`ROM`）。
  - 「一条微指令就是一条机器指令」——**错**，一条机器指令对应一段微程序。
  - 「微程序控制器比硬布线控制器速度快」——**错**，方向反了。
  - 「所有机器指令的微程序都存放在 `CM` 中且长度相同」——**错**，长度一般不同（除非按最长对齐）。
  - 微程序里的「微指令条数」与「机器指令条数」没有任何比例关系，不要想当然。

### 5.5 异常和中断机制

#### 5.5.1 基本概念：异常 vs 中断

- **异常（exception，内中断）**：`CPU` **内部**在执行指令过程中检测到的、与当前指令有关的意外事件。如除零、溢出、缺页、越界、非法操作码、系统调用、断电。
- **中断（interrupt，外中断）**：来自 `CPU` **外部**（`I/O` 设备、时钟、其他处理器）、与当前指令**无关**的请求。如 `I/O` 完成、时钟中断、键盘输入。
- **共同点**：都会打断当前程序流，转去执行处理程序，处理完再返回。
- **本质差别在「来源」和「检测时机」**：

  - **异常**：与当前指令同步，**在指令执行过程中**由 `CPU` 自己检测到，所以「断点」可能还在这条指令上。
  - **中断**：与当前指令异步，**在一条指令执行结束后**才检查中断请求。所以中断响应一定发生在**两条指令之间**。

#### 5.5.2 异常的分类

| 类型 | 英文 | 何时被发现 | 返回后做什么 | 典型例子 |
| --- | --- | --- | --- | --- |
| 故障 | `fault` | 指令**执行中**发现 | 处理完**重新执行**当前指令 | 缺页、缺段、除数为零（某些体系）、`TLB` 缺失 |
| 自陷 | `trap` | 指令执行中，但由**程序主动**安排 | 处理完执行**下一条**指令 | 系统调用、断点指令、溢出陷阱、单步调试 |
| 终止 | `abort` | 发生**硬故障**，程序无法继续 | 不返回，**终止**当前程序 | 主存校验错、总线错误、电源故障 |

- **怎么记**：故障是「**绊了一跤**」——处理完接着走这一步；自陷是「**自己按的暂停键**」——是程序故意触发的，回去走下一步；终止是「**机器坏了**」——走不了了。
- **408 怎么考 / 常见坑**：
  - 「`fault` 处理后执行下一条指令」——**错**，是**重新执行当前指令**；`trap` 才是执行下一条。
  - 「缺页属于 `trap`」——**错**，缺页是 `fault`（重新执行）。
  - 「非法指令属于 `abort`」——一般归 `fault`（或视为不可恢复的 `fault`），不要随意套 `abort`。

#### 5.5.3 中断的分类

| 分类维度 | 类别 | 说明 | 例子 |
| --- | --- | --- | --- |
| 来源 | 内中断（异常） | `CPU` 内部产生 | 除零、缺页、系统调用 |
| 来源 | 外中断 | `CPU` 外部产生 | `I/O` 完成、时钟、键盘 |
| 可否屏蔽 | 可屏蔽中断 | 受 `PSW` 中 `IF`（中断允许位）控制，`IF = 0` 时不响应 | `I/O` 设备请求 |
| 可否屏蔽 | 不可屏蔽中断 | 不受 `IF` 影响，**必须响应**，优先级最高 | 电源故障、内存奇偶校验错 |
| 触发方式（外中断细分） | 可屏蔽/不可屏蔽 | 见上 | — |
| 触发方式（外中断细分） | 向量中断 / 非向量中断 | 由设备提供中断类型码（向量）直接找到入口为**向量中断**；否则需软件查询中断源为**非向量中断** | `8259` 向量中断 |

- **中断优先级的确定原则**：**不可屏蔽中断 > 内部异常（`fault`/`trap`）> 可屏蔽中断**；可屏蔽中断之间按设备优先级排队。**DMA 请求 > 中断请求**（`DMA` 优先级高于 `CPU` 响应中断，且 `DMA` 期间 `CPU` 交出总线）。
- **408 怎么考 / 常见坑**：
  - 「中断处理程序一定由操作系统提供」——通常对，但**中断隐指令由硬件完成**，不要混。
  - 「外中断一定是可屏蔽的」——**错**，外中断里也有不可屏蔽的。
  - 优先级排序题：记住「**不可屏蔽 > `DMA` > 可屏蔽**」这条粗线（`DMA` 与中断谁更优先，按教材口径 `DMA` 请求优先于中断请求）。

#### 5.5.4 中断的检测与响应

**检测**

- 外中断：`CPU` 在**每条指令执行结束后**采样中断请求信号（如 `INTR` 引脚），有条件则进入中断周期。
- 异常：在**指令执行过程中**由 `CPU` 内部逻辑检测（除零检测器、缺页判断、越界比较器等）。

**响应条件（三个同时满足）**

1. 有中断请求；
2. 中断允许（`PSW` 中 `IF = 1`，或该中断不可屏蔽）；
3. **一条指令执行完毕**（有 `DMA` 请求时还要等 `DMA` 让出总线）。

**响应过程 —— 中断隐指令**

「隐指令」的意思是：它**不是程序里的指令**，也没有操作码，是**硬件自动完成**的一串操作，程序员看不见。它做三件事：

| 步骤 | 操作 | 为什么要做 |
| --- | --- | --- |
| ① 关中断 | `IF ← 0`（把 `PSW` 中的中断允许位清零） | **保证保存断点、取中断向量的过程不被打断**（否则新中断会覆盖现场） |
| ② 保存断点 | 把当前 `PC`（下一条指令地址）压栈或存入指定单元 | 将来要回来继续执行 |
| ③ 引出中断服务程序 | 把**中断向量（服务程序入口地址）送 `PC`** | 转向处理程序 |

- **保护现场 vs 保存断点**：中断隐指令只保存**断点 `PC`**；**通用寄存器和 `PSW` 内容的保存（保护现场）由中断服务程序用指令完成**。这是最经典的选择题陷阱。
- **中断向量 vs 中断向量地址**：

| 概念 | 含义 | 存/取方式 |
| --- | --- | --- |
| 中断向量 | 中断服务程序的**入口地址** | 存在中断向量表中 |
| 中断向量地址（中断向量表指针） | 中断向量在**向量表中所在的存储单元地址** | 由设备提供的中断类型码 × 向量长度算出 |

  **关系**：`中断向量地址 = 中断类型码 × 每个向量占的字节数`，而 `M(中断向量地址) = 中断向量 = 服务程序入口地址`。**中断类型码 → 中断向量地址 → 中断向量（入口地址）→ 服务程序**，四步链条要顺。
- **408 怎么考 / 常见坑**：
  - 「响应中断后先保存通用寄存器」——**错**，隐指令只存断点。
  - 「关中断由中断服务程序完成」——**错**，关中断是隐指令的第一步（但服务程序中也可能再次关中断保护现场）。
  - 「中断向量的地址就是中断服务程序的入口地址」——**错**，入口地址是**中断向量**，不是向量**地址**。

**中断服务程序的流程**

```
关中断 → 保存现场与断点（断点已由隐指令存PC，此处存通用寄存器和PSW）
      → 判断中断源（向量中断跳过，非向量中断需软件查询）
      → 执行中断服务（设备服务）
      → 恢复现场与断点 → 开中断 → 中断返回（IRET/RTI）
```

**多重中断（中断嵌套）**

- **含义**：在中断服务程序执行期间，允许响应**优先级更高**的中断请求，形成嵌套。
- **前提条件**：① 在服务程序中**提前开中断**（`IF = 1`）；② 有**中断屏蔽字**机制控制谁能打断谁。
- **中断屏蔽字**：每个中断源对应一个屏蔽字，字中的每一位对应一个中断源。**`1` 表示屏蔽（不允许它打断我），`0` 表示开放**。注意：**屏蔽字里对自己那一位通常也置 1**（自己不能打断自己）。
- **怎么设计**：把中断源按**处理优先级从高到低**排序；优先级越高，说明它越「霸道」——**除了比自己更高的，其余都能屏蔽**。
  - 例：优先级 `A > B > C > D`，则
    - `A` 的屏蔽字：`1 1 1 1`（A 能屏蔽 A、B、C、D）
    - `B` 的屏蔽字：`0 1 1 1`（只不能屏蔽 A）
    - `C` 的屏蔽字：`0 0 1 1`
    - `D` 的屏蔽字：`0 0 0 1`
- **408 怎么考 / 常见坑**：
  - 「`1` 表示开放」——**反了**，`1` 是屏蔽。
  - 屏蔽字设计题常与「画出中断处理次序（时间轴）」结合：**处理次序由屏蔽字决定，不由请求先后决定**。若题目给的屏蔽字与优先级不一致，**一切以屏蔽字为准**。
  - 「多重中断中，低优先级中断可以打断高优先级」——**错**，只有更高优先级才能打断。

### 5.6 指令流水线

#### 5.6.1 基本概念

- **思想**：把一条指令的执行过程分成若干**阶段**（如取指 `IF`、译码 `ID`、执行 `EX`、访存 `MEM`、写回 `WB`），让**不同指令的不同阶段在时间上重叠**，就像工厂流水线。
- **时空图**：横轴时间、纵轴各阶段，一条指令走成一条「阶梯斜线」。是分析流水线一切计算的工具。
- **流水线寄存器**：阶段之间必须插入寄存器（`IF/ID`、`ID/EX`、`EX/MEM`、`MEM/WB`），用来**锁存上一阶段的中间结果**，使各阶段能独立并行。没有流水线寄存器，重叠无从谈起。
- **理想流水线的性能公式**（设 `k` 段流水线，时钟周期为 `Δt`，执行 `n` 条指令）：

```
总时间 T = (k + n - 1) × Δt          （理想情况，无停顿）
吞吐率 TP = n / T = n / ((k + n - 1) × Δt)
最大吞吐率 TP_max = 1 / Δt           （n → ∞ 时，每个时钟周期完成一条指令）
加速比 S = 非流水线总时间 / 流水线总时间 = (n × k × Δt) / ((k + n - 1) × Δt) = nk / (k + n - 1)
效率 E = S / k = n / (k + n - 1)     （= 时空图中有效面积 / 总面积）
```

  当 `n → ∞`：`S → k`（加速比上限等于流水线段数），`E → 1`。

- **带停顿的公式**：设停顿了 `m` 个时钟周期，则

```
T = (k + n - 1 + m) × Δt
TP = n / T
其中 m 由冒险引起：例如 m 条 load-use 冒险各停 1 拍 → m = 冒险次数
```

- **408 怎么考 / 常见坑**：
  - `k + n - 1` 里 `k - 1` 是「填满流水线的时间」，容易被写成 `n × k`（那就退化成非流水线）。
  - **单位**：题目若给「每段 1 个时钟周期，时钟频率 1 GHz」，则 `Δt = 1 ns`，答案要写 `ns` 别写「周期」。
  - 「流水线提高了单条指令的执行速度」——**错**，单条指令的**延迟反而增加**（多了流水线寄存器），提高的是**吞吐率**。
  - 「流水线段数越多数越好」——**错**，段数增加会带来更多冒险、更多寄存器开销和更复杂的控制。

#### 5.6.2 三类冒险的成因与处理

| 冒险 | 别名 | 成因 | 处理办法 | 代价 |
| --- | --- | --- | --- | --- |
| 结构冒险 | 资源冲突 | **硬件资源不够**，两条指令同一拍争用同一部件（如同时访存取指与取数、争用同一个寄存器端口） | ① 指令与数据**分开的 `Cache`/存储器**（哈佛结构）；② 让冲突的指令**停顿一拍（气泡）**；③ 增加硬件资源/设置独立部件 | 硬件成本 或 停顿 |
| 数据冒险 | 数据相关 | 后面指令**要用前面指令还没写回的结果**（`RAW` 为主） | ① **转发/旁路（forwarding/bypassing）**：把 `EX`/`MEM` 阶段的结果直接送给需要的 `ALU` 输入端，不必等写回；② 转发也救不了的（`load-use` 冒险）**插入气泡/停顿 1 拍**；③ 编译器**指令重排**、插入 `nop` | 转发需额外数据线；停顿损失性能 |
| 控制冒险 | 转移/分支冒险 | **转移指令改变了 `PC`**，而 `PC` 的新值要过几拍才算出来，导致后面已经预取的指令可能取错 | ① **分支预测**：静态预测（预测总不转移/总转移）、动态预测（记录历史）；② **延迟槽/延迟转移**：把与分支无关的指令填进转移指令后的槽位；③ **提前在译码/取指阶段算出转移地址**（尽早得到分支结果）；④ 预测失败时**清空流水线（冲刷）** | 预测失败要冲刷，代价大 |

- **数据冒险三种类型**（易考名词）：`RAW`（先写后读，真相关，最常见）、`WAR`（先读后写，反相关）、`WAW`（先写后写，输出相关）。**只有 `RAW` 才是真数据相关**，`WAR`/`WAW` 只在乱序执行里出现，顺序流水线不会发生。
- **`load-use` 冒险为什么转发救不了**：`load` 指令的数据要到 `MEM` 阶段结束才从 `MDR`/`Cache` 出来，而下一条指令 `EX` 阶段就要用它，时间上到不了，只能停 1 拍（停顿那一拍此时 `load` 到了 `MEM`，下一拍转发路径就通了）。
- **408 怎么考 / 常见坑**：
  - 题目给一段汇编，问「有几处数据冒险 / 需要停顿几拍」——做法是**逐条画时空图**，标出「写回拍」与「使用拍」，写回拍晚于使用拍就要停。
  - 「转发能消除所有数据冒险」——**错**，`load-use` 至少停 1 拍。
  - 「分支预测一定提高性能」——**错**，预测失败要冲刷流水线，可能在分支规律性差时反而变慢。
  - 大纲只要求**基本概念与处理办法**，不要求分支预测器的具体硬件实现，不要展开。

#### 5.6.3 超标量和动态流水线

- **超标量（`superscalar`）流水线**：**一个时钟周期内并发发射多条指令**（多条流水线并行），靠**多条并行通路 + 多套功能部件**实现。典型 4 发射 = 每拍最多流出 4 条指令。理想吞吐率可超过 1 条/周期，但受**指令级并行度**限制。
- **动态流水线**：允许**不同指令在同一时刻处于不同阶段、且可以按不同的顺序推进**（即支持乱序执行/乱序完成，由硬件在运行时调度）。与之相对的是**静态流水线**：同一时刻只能按同一固定顺序推进（如只能「先都做加法」再「都做乘法」）。
- **超流水线（`superpipelining`）**：把每段再细分，**增加段数、提高时钟频率**，每拍仍只发射一条，但流水得更细。与超标量的区别：**超标量靠「并行多套」，超流水靠「切得更细」**。
- **408 怎么考 / 常见坑**：本节只考**概念辨析**（是什么、和谁对比、靠什么实现），**不考乱序执行的具体算法**（记分牌、`Tomasulo`）。选择题常问「超标量提升吞吐率靠什么」——答「增加并行部件、每拍发射多条」，不要答「提高时钟频率」（那是超流水线）。

### 5.7 多处理器的基本概念

#### 5.7.1 Flynn 分类（按「指令流 × 数据流」划分）

| 类型 | 全称 | 指令流 | 数据流 | 典型代表 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `SISD` | 单指令流单数据流 | 1 | 1 | 传统单核机、标量流水线机 | 一条指令处理一个数据；**流水线本身仍属 `SISD`** |
| `SIMD` | 单指令流多数据流 | 1 | 多 | 向量处理机、阵列处理机、`GPU` | 一条指令同时对一组数据做同样运算 |
| `MISD` | 多指令流单数据流 | 多 | 1 | 少见，主要用于**容错**（多机同时算同一数据比对结果） | 几乎没有实用商用机 |
| `MIMD` | 多指令流多数据流 | 多 | 多 | 多核处理器、`SMP`、机群 | 各核独立执行不同指令、处理不同数据 |

- **408 怎么考 / 常见坑**：
  - 「流水线处理机属于 `SIMD`」——**错**，是 `SISD`；`SIMD` 必须是「一条指令同时作用于多个数据」。
  - 「多核处理器属于 `MIMD`」——**对**。
  - 判据只有一条：**看指令流和数据流各是几条**。

#### 5.7.2 向量处理器

- **特点**：面向**向量数据**（一维数组）设计，用**向量寄存器**一次装入一组数据，一条向量指令可完成对整组数据的运算，指令内部用**流水线**逐元素处理。
- **关键优势**：大幅**减少指令条数**（循环展开被一条向量指令代替）、**减少取指和译码开销**、便于流水化。
- **与 `SIMD` 的关系**：向量处理器通常被归入 `SIMD` 范畴。
- **408 怎么考**：一般只考「向量处理器的特点」和「一条向量指令处理多个数据元素」这一层。

#### 5.7.3 硬件多线程

- **动机**：一个线程的指令流有停顿（访存、冒险），流水线会空转；**让多个线程共享同一套执行部件**，把别的线程的指令填进来，提高资源利用率。
- **三种实现**：

| 方式 | 做法 | 切换代价 | 说明 |
| --- | --- | --- | --- |
| 细粒度多线程 | 每个时钟周期切换线程（轮流发射不同线程的指令） | 极小（每拍切） | 单线程性能下降，吞吐率提升；能掩盖短停顿 |
| 粗粒度多线程 | 只在**发生较长停顿时**才切换线程 | 较大（要清空流水线） | 单线程性能损失小，能掩盖长停顿（如 `Cache` 缺失） |
| 同时多线程（`SMT`） | 一个时钟周期内**同时发射多个线程的指令** | 无切换 | 一个物理核在 `OS` 看来像多个逻辑核（如超线程） |

- **408 怎么考 / 常见坑**：`SMT` 与超标量的区别——**超标量是同一线程内的多条指令并行，`SMT` 是不同线程的指令并行**；两者都需要多个功能部件。

#### 5.7.4 多核处理器

- **概念**：把**多个完整的处理器核**（每个核有自己的寄存器、`ALU`、控制器、一级 `Cache`）集成在**同一个芯片**上，共享或部分共享二级/三级 `Cache`、内存控制器、总线。
- **要点**：
  - **共享 `Cache` 带来缓存一致性问题**，需要**缓存一致性协议**（如监听式/目录式）保证各核看到的内存视图一致；软件层面还需要**内存屏障/同步**。
  - 多核属于 `MIMD`；**多核 ≠ 多线程**（多线程是单核内的并发技术，多核是多套硬件）。
- **408 怎么考**：基本概念题，问「多核处理器共享什么、私有什么」「多核与 `SMT` 的区别」。

#### 5.7.5 共享内存多处理器（`SMP`）

- **`SMP`（对称多处理）**：多个**对等**的处理器（核）**共享同一个主存**和 `I/O` 系统，每个处理器都能访问全部内存，由同一个 `OS` 统一管理，各处理器地位**对称**（都能运行内核代码）。
- **访存模型对比**：

| 模型 | 全称 | 访存时间 | 说明 |
| --- | --- | --- | --- |
| `UMA` | 统一内存访问 | **各处理器访存时间相同**（与处理器位置无关） | 就是 `SMP` 的经典模型；扩展性差（总线/内存成为瓶颈），核数通常较少 |
| `NUMA` | 非统一内存访问 | **访问不同地址的时间不同**（本地内存快、远端内存慢） | 每个处理器有自己的本地内存，通过互联网络访问他人内存；扩展性更好，是 `SMP` 扩展后的主流形态 |

- **补充概念**：`SMP` 之外还有 **`MPP`（大规模并行处理）** 与 **机群（`cluster`）**，它们属于**分布式存储**的多处理机（一般划到 `MIMD` 的多计算机范畴），大纲只要求了解名词。
- **408 怎么考 / 常见坑**：
  - 「`UMA` 与 `NUMA` 的区别在于是否共享内存」——**错**，**两者都共享内存**，区别是**访存时间是否一致**。
  - 「`SMP` 各处理器的地位不对称」——**错**，对称；
  - 「多处理器一定共享内存」——**错**，还有分布式存储（消息传递）的多处理机。

### 例题 1（选择题）中断响应过程中硬件自动完成的操作

**题目**：在中断响应过程中，由硬件自动完成（无须执行任何指令）的操作是（　　）。

A. 保存通用寄存器的内容
B. 将断点（下一条指令的地址）保存到栈或指定单元，并将中断向量送 `PC`
C. 判断中断源并转去执行相应的中断服务程序
D. 保存 `PSW` 的内容并恢复现场

**答案：B**

**逐项解析**

| 选项 | 判断 | 理由 |
| --- | --- | --- |
| A | ✗ | 保存通用寄存器属于「保护现场」，由**中断服务程序**用 `PUSH`/`MOV` 等指令完成，硬件不管 |
| B | ✓ | 这正是**中断隐指令**的内容：关中断 → 保存断点 `PC` → 把中断向量（服务程序入口地址）送 `PC`。全过程由硬件在中断周期内自动完成 |
| C | ✗ | 若为**向量中断**，硬件只负责把入口地址送 `PC`；「判断中断源」是**非向量中断**下由中断服务程序**用软件查询**完成的。无论如何不属于硬件自动完成的范畴 |
| D | ✗ | 保存 `PSW` 和恢复现场都在服务程序中由指令完成；恢复现场更是在**中断返回前**才做 |

**采分点与常见坑**

- 采分点：能准确说出中断隐指令的**三件事**（关中断、保存断点、引出中断服务程序）。
- 常见坑 ①：把「保护现场」当成隐指令的内容 —— 隐指令**只保存断点 `PC`**，通用寄存器和 `PSW` 由服务程序保存。
- 常见坑 ②：把「关中断」误认为由服务程序完成 —— 关中断是隐指令的**第一步**。
- 常见坑 ③：混淆「中断向量」与「中断向量地址」：隐指令取出的是**中断向量（入口地址）**，送 `PC`。

### 例题 2（综合应用题）单总线数据通路下的微操作序列

**背景**：某机采用单总线结构的 `CPU` 数据通路，相关部件与连接如下（均为 `8` 位机器字长、按字节编址、指令字长 `2` 字节）：

- `PC` 的输出可送 `MAR` 和内部总线；`PC` 具有自增功能（`+1`，这里「1」表示一条指令占 2 个字节，故实际为 `PC + 2`）。
- `IR` 的输出（操作码 `OP` 与地址码 `Ad`）可送总线；`IR` 的地址字段可由总线装入。
- `MAR` 只能接收总线数据，其输出送往主存地址总线（单向）。
- `MDR` 输入来自主存数据总线，输出可送内部总线。
- `ACC`（累加器）、`Y`（`ALU` 的暂存寄存器）接在内部总线上。
- `ALU` 的两个输入端为 `ACC` 与 `Y`，输出可送回 `ACC`。
- 直连通路：`PC → MAR`、`MDR → IR`。

现有指令 **`ADD (R0)`**，采用**寄存器间接寻址**，功能为 `(ACC) + M((R0)) → ACC`。

**要求**：

(1) 写出该指令的取指周期、间址周期、执行周期的微操作序列，标明节拍（同一节拍内的微操作必须互不冲突）。
(2) 若把「间址周期」的访存结果直接送 `MAR` 而不经过 `IR`，是否可行？说明理由。

**解题步骤**

**第 1 步：判断该指令需要哪些机器周期。** `ADD (R0)` 用寄存器间接寻址，形式地址是寄存器号，操作数地址在 `R0` 中，**不需要访存取有效地址**，因此**没有间址周期**（间址周期专指「用形式地址访存去取有效地址」）。整个指令只有取指和执行两个周期。这正是本题的第一个考点。

**第 2 步：写取指周期。** 要点：先送地址、再读主存、再送 `IR`，最后 `PC` 自增；`PC → MAR` 走直连通路，可与 `PC + 2 → PC` 放在同一节拍。

| 节拍 | 微操作 | 说明 |
| --- | --- | --- |
| `T0` | `(PC) → MAR`，`(PC) + 2 → PC` | 送地址与自增不冲突（自增用 `PC` 自身线路，不占总线） |
| `T1` | `M(MAR) → MDR` | 读主存（用时可能不止 1 拍，这里按 1 拍处理） |
| `T2` | `(MDR) → IR` | 指令送到 `IR`，`OP` 开始译码 |

**第 3 步：写执行周期。** 要点：地址来自 `R0`，操作数要访存，`ACC` 与内存数据相加。

| 节拍 | 微操作 | 说明 |
| --- | --- | --- |
| `T3` | `(R0) → MAR` | 寄存器间接：`R0` 的内容就是操作数地址 |
| `T4` | `M(MAR) → MDR` | 取出操作数 |
| `T5` | `(MDR) → Y` | **必须先送 `Y` 暂存** |
| `T6` | `(ACC) + (Y) → ACC` | `ALU` 运算，结果写回 `ACC` |

**关键说明**：`T6` 不能写成 `(ACC) + (MDR) → ACC`。因为单总线结构下 `ALU` 的两个输入不能同时来自总线上的两个源，必须先经 `Y` 暂存一个操作数（`Y` 就是为此存在的暂存寄存器）。这是本题最主要的采分点。

**第 4 步：回答 (2)。** **不可行。** 寄存器间接寻址的操作数地址已经在 `R0` 中，直接 `(R0) → MAR` 即可，**不需要任何访存来形成有效地址**，「把间址访存结果送 `MAR`」这一步在本题中根本不存在。更重要的是：真正需要间址的场合（如 `ADD @X`，一次间接寻址），从主存取回的是**有效地址**，它既可以经 `MDR → IR 的地址字段`，也可以在**不需要保留形式地址**时经 `MDR → MAR` 直接使用；一旦再一次间接（多次间址），就必须把新地址写回 `IR`（或专用间址寄存器）以供下一轮使用。所以「是否可行」取决于**是否需要保留中间地址**，不能一概而论。

**答案**

(1) 取指周期：`T0`：`(PC) → MAR`，`(PC) + 2 → PC`；`T1`：`M(MAR) → MDR`；`T2`：`(MDR) → IR`。
执行周期：`T3`：`(R0) → MAR`；`T4`：`M(MAR) → MDR`；`T5`：`(MDR) → Y`；`T6`：`(ACC) + (Y) → ACC`。**无间址周期**。
(2) 见第 4 步，核心结论：本指令不需要间址；一般情形下是否经 `IR` 取决于是否需要保留该地址，多次间址必须写回 `IR`。

**采分点与常见坑**

- 采分点 ①：**正确判断有没有间址周期**（寄存器间接寻址没有间址周期）——每年都有人多写一段间址周期。
- 采分点 ②：取指周期四件事齐全（送地址、读主存、送 `IR`、`PC` 自增），且 `PC` 自增量与指令字节数一致（本题 `+2`）。
- 采分点 ③：访存链路必须走 `MAR → 主存 → MDR`，**不能写 `M(MAR) → IR`**。
- 采分点 ④：`ALU` 前先经 `Y` 暂存，写出 `(MDR) → Y` 这一拍。
- 常见坑：同一节拍内写出互相冲突的两个微操作（如 `(R0) → MAR` 与 `(PC) → MAR` 同拍）；漏掉 `PC` 自增；把 `ACC` 换成通用寄存器（题目给的是 `ACC`）。

### 例题 3（综合应用题）流水线吞吐率、加速比与执行时间

**背景**：某 `CPU` 采用 `5` 段流水线，各段名称与功能为：取指 `IF`、译码/取数 `ID`、执行 `EX`、访存 `MEM`、写回 `WB`。每个流水段耗时均为 `1` 个时钟周期，时钟频率为 `1 GHz`。执行某程序共 `100` 条指令，其中：

- `20%` 的指令是 `load` 指令，且**每条 `load` 之后紧跟着一条使用其结果的指令**（产生 `load-use` 数据冒险，需停顿 `1` 个时钟周期）；
- 其余指令之间无任何冒险。

**要求**：

(1) 求理想情况下（无任何停顿）执行完这 `100` 条指令的总时间、吞吐率、加速比与效率。
(2) 求实际情况下（考虑上述 `load-use` 停顿）的总时间与吞吐率，并求此时的实际加速比。
(3) 若把流水线改为 `10` 段（每段 `0.5` 个时钟周期，时钟频率 `2 GHz`），但仍需停顿 `1` 个时钟周期/次冒险，问总时间变为多少？据此说明「流水线段数越多越好」是否正确。

**解题步骤**

**第 1 步：确定基本参数。** `k = 5` 段，`Δt = 1 / 1 GHz = 1 ns`，`n = 100` 条。

**第 2 步：算 (1) 理想情况。**

```
T_ideal = (k + n - 1) × Δt = (5 + 100 - 1) × 1 ns = 104 ns
TP_ideal = n / T_ideal = 100 / 104 ns ≈ 0.9615 条/ns ≈ 9.62 × 10^8 条/s
TP_max = 1 / Δt = 1 条/ns = 10^9 条/s
加速比 S = nk / (k + n - 1) = (100 × 5) / 104 = 500 / 104 ≈ 4.81
效率 E = S / k = 4.81 / 5 ≈ 0.962
```

**第 3 步：算 (2) 实际情况。** 先数停顿次数：`load` 指令占 `20%`，即 `100 × 20% = 20` 条，各引起 `1` 拍停顿，共停顿 `m = 20` 个时钟周期。

```
T_real = (k + n - 1 + m) × Δt = (5 + 100 - 1 + 20) × 1 ns = 124 ns
TP_real = 100 / 124 ns ≈ 0.8065 条/ns ≈ 8.06 × 10^8 条/s
实际加速比 S_real = 非流水线时间 / 流水线时间 = (n × k × Δt) / T_real
                  = (100 × 5 × 1 ns) / 124 ns = 500 / 124 ≈ 4.03
（插入气泡后也可用 S_real = 500 / (100 + 5 - 1 + 20) = 500 / 124，与上式一致）
```

**第 4 步：算 (3) 十段流水线。**

```
新 Δt' = 0.5 ns
T_10 = (k' + n - 1 + m') × Δt'
```

注意陷阱：冒险引起的停顿次数**由程序决定，不随段数变化**，一般仍是 `20` 次；但题目说明「仍需停顿 `1` 个时钟周期/次冒险」，此时 `1` 拍 = `0.5 ns`，停顿的**绝对时间变短**：

```
T_10 = (10 + 100 - 1 + 20) × 0.5 ns = 129 × 0.5 ns = 64.5 ns
```

比 `124 ns` 快了近一倍（这正是提高时钟频率的收益）。但若流水段变细后**冒险次数增加**（例如 `load-use` 需要停更多拍、或同一拍争用部件导致结构冒险增多），收益就会被吞掉：设停顿次数增到 `60` 次，则 `T = (10 + 100 - 1 + 60) × 0.5 ns = 84.5 ns`，仍更快；若增到 `100` 次，`T = (10 + 100 - 1 + 100) × 0.5 ns = 104.5 ns`，优势已大幅缩水。**所以「流水线段数越多越好」不成立**：段数增加带来更多冒险、更多流水线寄存器开销、更复杂的控制与时序（时钟偏斜），收益递减甚至为负。

**答案**

(1) `T_ideal = 104 ns`，`TP_ideal ≈ 9.62 × 10^8 条/s`（`TP_max = 10^9 条/s`），`S ≈ 4.81`，`E ≈ 0.962`。
(2) `T_real = 124 ns`，`TP_real ≈ 8.06 × 10^8 条/s`，`S_real ≈ 4.03`。（插入的 `20` 个气泡使加速比从 `4.81` 降到 `4.03`。）
(3) `T_10 = 64.5 ns`；段数增加能提高时钟频率而缩短总时间，但会引入更多冒险与开销，**并非越多越好**。

**采分点与常见坑**

- 采分点 ①：公式写对且**说明 `k - 1` 是填满流水线的时间**；直接写 `n × Δt` 的按错处理。
- 采分点 ②：**正确数出停顿拍数**：`load` 指令 `20` 条 → `20` 拍。写 `T = (5 + 100 - 1 + 20) × 1 ns` 时，`+20` 必须放在括号里**乘同一个 `Δt`**，不能写成 `104 + 20 ns` 之外的奇怪形式（数值恰好相同，但要说明它是流水线拍，不是额外时间）。
- 采分点 ③：加速比分母是**流水线的总时间**，分子是**同样条数的非流水线总时间 = n × k × Δt**；不要用 `n × Δt` 当分子（那等于把每段当成 1 拍执行完一条指令，是错的）。
- 采分点 ④：单位统一。`1 GHz` → `1 ns`；答案带 `ns` 或 `s` 且数量级正确。
- 常见坑：把「`20%` 的 `load` 指令」直接当成停顿 `20%` 的时间去乘总时间（应换算成**拍数**）；忽略 `TP_max = 1 / Δt` 与 `TP` 的区别（题目问「理想吞吐率」时两者数值不同）；把效率算成 `1 / k`。

## 六、简便方法与易错口诀（速算 · 防错）

> 本节把本章能"省时间"和"防掉坑"的招集中在一处：二轮复习与考前只看这一节。每条都写清**适用条件**。

### 6.1 速算招式

| 场景 | 常规做法（慢/繁） | 简便做法（快/稳） | 为什么成立 / 适用条件 |
| --- | --- | --- | --- |
| 取指周期的微操作 | 对着一道题的寄存器图重新推，容易漏 `(PC) + 1 → PC` 或写错顺序 | 固定背四条：`(PC) → MAR`；`M(MAR) → MDR`；`(MDR) → IR`；`(PC) + 1 → PC` | 任何指令的微操作序列都从这四条开始，顺序唯一。**间址周期不算在取指里**：有间址时在取指之后另加 `(IR 的地址字段) → MAR`、`M(MAR) → MDR`，且取到的有效地址常要先送 `Y` 暂存（`MDR` 下一拍还要用来接操作数） |
| 单总线数据通路写微操作 | 硬记某道题的具体序列，换个题就不会 | 两条铁律：① 一条总线同一时刻只能有**一个数据源**（同时写两个寄存器、两个源同时上总线都是冲突）；② `ALU` 两个输入端不能同时直接来自总线，必须一个先入 `Y` | 只适用于**单总线**结构。**专用数据通路（多总线）**允许同一拍内多个部件并行传送，可以把微操作合并；别把单总线的约束硬套到专用通路的题上 |
| `k` 段流水线执行 `n` 条指令的理想时间 | 画完整时空图逐格数 | 记「首条占 `k` 拍，之后每条只加 1 拍」→ `T = (k + n - 1) × Δt` | 各段执行时间相等且都记为 `Δt`。若各段不等，取 `Δt = 最慢段的时间`（此时为理想近似，题目一般会给等时条件） |
| 带停顿的流水线时间 | 在时空图上逐拍数气泡 | `T = (k + n - 1 + m) × Δt`，其中 `m` 是**总停顿拍数** | `m` 必须先换算成**拍数**再乘 `Δt`。例：`100` 条指令中 `20%` 是 `load` 且每条 `load-use` 停 1 拍 → `m = 20` 拍，绝不是 `0.2 × T` |
| 三个性能指标 | 三个公式各自单独推 | `TP = n / T`；`S = k × n / (k + n - 1)`；`E = S / k = n / (k + n - 1)`；三者互通：`S = k × E`、`E = TP × Δt = TP / TP_max` | 上式为理想无停顿情形；有停顿时 `T` 换成实际时间，`S` 的分子仍是同条数非流水执行时间 `k × n × Δt`。**分母永远是流水线总时间** |
| 加速比的上界 | 代入公式算完才知道对不对 | 直接判 `S < k`（只有 `n → ∞` 才趋近 `k`）；选项里出现「加速比超过 `k` 倍」直接排除 | 适用条件：等时理想流水线、与非流水线（每条指令 `k` 拍）比较。若题目额外改变时钟周期或换了比较基准，先看清基准再判 |
| 中断屏蔽字（设计题） | 逐位试填、来回改 | 先排**处理次序**，再按「`1` 表示屏蔽（**含自己**那一位）」填：只把**排在它前面（更优先）**的源写 `0`，其余（含自己）写 `1`。个数速查：`n` 个源中处理次序第 `k` 位（`k = 1` 为最先处理）的屏蔽字恰有 `n - k + 1` 个 `1` | 位序按题目给定的硬件优先级（通常从左到右）排列；个数公式只能**验算** `1` 的数目，不能代替逐位填写 |
| 由屏蔽字反推处理次序 | 逐位比较、越比越晕 | 「`1` 最多者（屏蔽面最大 = 最不该被打断）最先被处理」，按 `1` 的个数从多到少排即为处理次序 | 屏蔽字与硬件优先级不一致时**一切以屏蔽字为准**：处理次序由屏蔽字决定，不由请求先后决定 |
| 中断隐指令的内容 | 与中断服务程序的动作混着背 | 三字诀「**关、存、引**」：关中断、保存断点（只存 `PC`）、引出中断服务程序（取中断向量送 `PC`）；三件**全由硬件自动完成** | 保护现场/恢复现场、判断中断源（非向量中断时由软件查询）、开中断、返回等都是**中断服务程序**的动作，不能算作隐指令 |
| 微指令字段编码位数 | 把互斥微命令当成独立位来数 | `n` 个**互斥**微命令用字段直接编码需 `⌈log2(n + 1)⌉` 位（**加 1** 是留给「本字段不发任何微命令」的码点）；对比：一位一命令的直接编码要 `n` 位 | 仅对**同一字段内互斥**的微命令成立。不互斥的微命令不能塞进同一字段，只能分字段或各占一位 |
| `load-use` 的停顿拍数 | 以为「有转发就 0 停顿」 | `load-use` 一律**停 1 拍**（转发救不了）；`ALU-ALU`（如 `add` 后紧跟用其结果的 `sub`）靠转发**0 停顿** | 原因是 `load` 的数据到 `MEM` 阶段末尾才从存储器取出，而 `EX` 阶段开头就要用。**例外**：`lw` 后紧跟的是 `sw`（数据到 `MEM` 阶段才用）可纯转发不停；编译器用无关指令把两者隔开（指令调度）后也可不停 |
| 中断向量地址 | 把入口地址误当成向量地址 | `中断向量地址 = 中断类型码 × 每个向量占的字节数`（常见每向量 4 字节即 `×4`），而 `M(中断向量地址) = 中断向量 = 服务程序入口地址` | 链条要顺：类型码 → 向量地址 → 向量（入口地址）→ 服务程序。题目给了「每个向量占几字节」就先看它，不要默认乘 4 |
| 加细流水段 / 提高主频后的时间 | 沿用旧的停顿数，直接套新的 `Δt` | 重新写 `T = (k' + n - 1 + m') × Δt'`，`k'`、`Δt'`、`m'` **三个量一起变** | 段数变多后时钟更快（`Δt` 变小），但同一类冒险在新流水线里停顿的拍数 `m'` 往往更多；`m'` 必须按新流水线重新数，不能沿用旧值 |

### 6.2 口诀与记忆钩子

- **取指四条**：「`PC` 送 `MAR`，内存进 `MDR`，`MDR` 进 `IR`，`PC` 自己加。」——任何指令的起手式。
- **单总线两铁律**：「一线一源；`ALU` 两脚不同线，一脚先入 `Y`。」
- **流水线时间**：「首条占 `k` 拍，之后每条加一拍」；「停顿先换拍，再乘同一个 `Δt`」。
- **三率一家**：「吞吐率看快不快，加速比看省几倍，效率看忙不忙」；`E = S / k`、`S = k × E`、`E = TP × Δt`。
- **加速比封顶**：「`S` 追 `k` 追不上，`n` 再大也 `< k`。」——选项说「超过 `k` 倍」就是错。
- **屏蔽字**：「`1` 屏蔽、含自己；排我前面的放 `0`；`1` 最多的最先处理」，个数速查 `n - k + 1`。
- **隐指令**：「关中断、存 `PC`、引向量——硬件三件事，现场不归它。」
- **异常三类**：「`fault` 回来重做本条，`trap` 往后走一条，`abort` 收工不回头。」
- **停一拍**：「`load` 之后马上用，转发也没用，乖乖停一拍。」

### 6.3 反例黑名单（这些"简便法"是错的）

- ❌ 「加速比可以超过流水线段数 `k`，或者刚好等于 `k` 倍」：正确做法是记住等时理想流水线 `S = k × n / (k + n - 1)` **严格小于** `k`，只有 `n → ∞`（指令条数无限多）才趋近 `k`，有停顿只会更小。
- ❌ 「有了转发（旁路）就不会有任何数据冒险停顿」：正确做法是分两类——`ALU-ALU` 冒险转发可解，`load-use` 冒险**必须停 1 拍**（数据在 `MEM` 阶段末尾才拿到）。
- ❌ 「中断屏蔽字里 `0` 表示屏蔽，而且不必包含自己那一位」：正确做法是 `1` 表示屏蔽、`0` 表示开放，且**每个源的屏蔽字必含自己那一位为 `1`**（自己不能打断自己）。
- ❌ 「取中断向量、保护现场都属于中断隐指令」：正确做法是隐指令只有关中断、保存断点 `PC`、引出中断服务程序三件，且**全由硬件自动完成**；保护现场是中断服务程序（软件）的事。
- ❌ 「`n` 个互斥微命令用字段直接编码需 `⌈log2 n⌉` 位」：正确做法是**要加 1**，即 `⌈log2(n + 1)⌉`，因为要留一个「不发任何微命令」的码点（`n = 4` 时是 3 位，不是 2 位）。
- ❌ 「流水线提高了单条指令的执行速度」：正确做法是单条指令的**延迟反而增加**（多了流水线寄存器），提高的是**吞吐率**。
- ❌ 「流水线段数越多越好」：正确做法是段数多、主频高，但冒险与停顿、流水寄存器开销、时钟偏斜都增加，收益递减，要具体算 `T` 比较（段数翻倍时 `m` 也会变大）。
- ❌ 「单总线结构下一拍可以同时把两个寄存器的内容送上总线，或一拍完成两次数据传送」：正确做法是一拍只能有一个数据源，且 `ALU` 的一个操作数要先入 `Y`；要一拍多传送只能用专用（多总线）数据通路。
- ❌ 「中断处理次序由中断请求到达的先后决定」：正确做法是由**屏蔽字（处理优先级）**决定；题目给的屏蔽字与硬件优先级矛盾时，以屏蔽字为准。
- ❌ 「算加速比时分子用 `n × Δt`」：正确做法是分子为同条数的非流水执行时间 `n × k × Δt`，分母为流水线总时间 `(k + n - 1 + m) × Δt`。
