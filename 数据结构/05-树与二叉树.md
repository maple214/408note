## 二、概念详解

### 5.1 树的基本概念

**定义**：树是 `n`（`n ≥ 0`）个结点的有限集合。`n = 0` 时称为空树；`n > 0` 时，有且仅有一个根结点 `root`，其余结点被分成 `m`（`m > 0`）个互不相交的有限集合，每个集合本身又是一棵树，称为根的子树。

**为什么这样定义**：这是**递归定义**——树由"根 + 若干子树"构成，所以树的所有算法天然是递归的。这一点是后面所有遍历/求高/计数模板的思想来源。

关键术语：

| 术语 | 含义 |
| --- | --- |
| 结点的度 | 该结点拥有的子树个数（即孩子数） |
| 树的度 | 树中所有结点度的最大值 |
| 叶子结点 | 度为 0 的结点，也叫终端结点 |
| 分支结点 | 度不为 0 的结点，也叫非终端结点 |
| 层次 | 根为第 1 层，其孩子为第 2 层，依次递增 |
| 树的高度/深度 | 结点最大层次（有的教材把边数当高度，408 用**结点层数**定义，空树高为 0） |
| 路径 | 两结点间经过的结点序列；路径长度 = 路径上**边的条数** |
| 有序树 | 子树有左右次序，交换后是另一棵树 |
| 无序树 | 子树无次序，交换后仍是同一棵树 |
| 森林 | `m`（`m ≥ 0`）棵互不相交的树的集合 |

**常用性质（务必记牢）**：

- 树中**结点总数 = 所有结点的度数之和 + 1**。因为除根之外，每个结点恰有一条来自双亲的边（入边），即每个结点贡献 1 条边；而总边数 = 总度数。
- 度为 `m` 的树中，第 `i` 层最多有 `m^(i-1)` 个结点。
- 高度为 `h` 的 `m` 叉树最多有 `(m^h - 1) / (m - 1)` 个结点。
- 高度为 `h` 的 `m` 叉树至少有 `h` 个结点（每层仅 1 个，退化成链）。
- 设叶子数 `n0`、度为 1 的结点数 `n1`、……、度为 `k` 的结点数 `nk`，则 `n0 = n1 + 2*n2 + 3*n3 + ... + (k-1)*nk + 1`。对二叉树即 `n0 = n2 + 1`。
- 含 `n` 个结点的 `m` 叉树最小高度为 `⌈log_m(n*(m-1) + 1)⌉`（即每层尽量塞满）。

> **408 怎么考/常见坑**：①"树的高度是结点层数还是边数"——408 一律按**结点层数**，单结点树高度为 1、空树为 0；但路径长度按**边数**。②`n0 = n2 + 1` 只对**二叉树**成立，别乱推广到三叉树。③"树的度"是最大值，不是某结点的度。④常考套用"总度数 + 1 = 结点数"反解某个未知度数的结点个数。

### 5.2 二叉树：定义与主要特性

**定义**：二叉树是 `n`（`n ≥ 0`）个结点的有限集合，或为空，或由一个根结点和两棵**互不相交**的、分别称为左子树和右子树的二叉树组成。

**二叉树与度为 2 的有序树的区别**（高频陷阱）：
- 度为 2 的有序树要求**每个结点都恰好有 2 个孩子**（度必须为 2）；二叉树允许结点只有左孩子或只有右孩子。
- 二叉树的子树有**严格左右之分**，即使只有一棵子树也要区分是左还是右，所以二叉树**不是**树的特例，是独立的数据结构。

**二叉树的 5 种基本形态**：①空二叉树；②只有根结点；③根只有左子树；④根只有右子树；⑤根同时有左右子树。

**5 个主要性质**：

1. 非空二叉树第 `i` 层最多有 `2^(i-1)` 个结点（`i ≥ 1`）。
2. 高度为 `h` 的二叉树最多有 `2^h - 1` 个结点（此时为满二叉树）；最少有 `h` 个结点（每层 1 个，每层都是单链）。
3. 对任何非空二叉树，叶子数 `n0` 与度为 2 的结点数 `n2` 满足 **`n0 = n2 + 1`**。
   推导：设结点总数 `n = n0 + n1 + n2`；从边数看，`n = 总度数 + 1 = n1 + 2*n2 + 1`；两式相等得 `n0 + n1 + n2 = n1 + 2*n2 + 1`，即 `n0 = n2 + 1`。
4. `n` 个结点的**完全二叉树**按层序从 1 开始编号，则对结点 `i`：
   - `i = 1` 时是根，无双亲；`i > 1` 时双亲为 `⌊i/2⌋`；
   - 若 `2i ≤ n`，左孩子为 `2i`，否则无左孩子；
   - 若 `2i + 1 ≤ n`，右孩子为 `2i + 1`，否则无右孩子；
   - 结点 `i` 所在层次为 `⌊log2 i⌋ + 1`。
5. `n` 个结点的完全二叉树高度为 **`⌊log2 n⌋ + 1`**（也常写成 `⌈log2(n+1)⌉`）。

**满二叉树**：高度为 `h` 且含 `2^h - 1` 个结点，即每一层都被结点填满，不存在度为 1 的结点。
**完全二叉树**：结点编号与同高度满二叉树**一一对应**——若按层序编号，编号 `1..n` 的结点与满二叉树中编号 `1..n` 的结点位置完全相同。等价说法：只有最下面两层结点的度可以小于 2，且最下层叶子**依次集中在左侧**。

| 对比项 | 满二叉树 | 完全二叉树 |
| --- | --- | --- |
| 结点数 | 必须是 `2^h - 1` | `n` 任意，`2^(h-1) ≤ n ≤ 2^h - 1` |
| 度为 1 的结点 | 不存在（叶子占一半） | 至多 1 个，且该结点只有左孩子 |
| 叶子位置 | 全在最下层 | 最下层靠左连续，次下层右侧可能也有叶子 |
| 叶子出现条件 | — | 出现一个叶子后，后续全是叶子；出现度为 1 的结点后，后续全是叶子 |
| 关系 | 满二叉树一定是完全二叉树 | 完全二叉树不一定是满二叉树 |

**由结点数判断完全二叉树形状的速算**：
- 有 1 个孩子的结点数 `n1`：`n` 为偶数时 `n1 = 1`，`n` 为奇数时 `n1 = 0`。
- 已知 `n`，则 `n0 = ⌈n/2⌉`（向上取整），`n2 = n0 - 1`，可直接反推叶子数和度为 2 的结点数。

> **408 怎么考/常见坑**：①最常考"完全二叉树中 `n0`/`n1`/`n2` 各是多少、编号为 `i` 的结点在第几层、有无孩子"。②`n0 = n2 + 1` 对**任意**二叉树都成立，考试常用它来解方程。③注意"完全二叉树第 `i` 个结点有左孩子 ⟺ `2i ≤ n`"这个判断是**判完全二叉树算法**的核心。④别把"度为 2 的有序树"当成二叉树。

### 5.3 二叉树的存储结构

**顺序存储**：用一组连续单元按**层序编号**存放结点，下标 `1` 存根（下标 `0` 通常空出或不用），结点 `i` 的左右孩子存放在 `2i` 和 `2i+1`。此时父子下标关系与性质 4 完全一致。

```c
#define MaxSize 100
typedef struct {
    ElemType data[MaxSize];   // 下标从 1 开始使用
    int n;                    // 结点个数
} SqBiTree;
```

- 优点：数组下标直接体现父子关系，找双亲/孩子都是 `O(1)`，不需要指针。
- 缺点：**只适合完全二叉树**。对一般二叉树（尤其单支树）为保持下标关系必须补空结点，高度为 `h` 的单支树需 `2^h - 1` 个存储单元，空间浪费极大。

**链式存储**：
```c
// 二叉链表：每个结点 3 个域
typedef struct BiTNode {
    ElemType data;
    struct BiTNode *lchild, *rchild;
} BiTNode, *BiTree;
```
- 含 `n` 个结点的二叉链表共有 `2n` 个指针域，其中只有 `n - 1` 个用来指向孩子（除根外每个结点恰被一个指针指向），因此**空链域个数 = 2n - (n - 1) = n + 1**。这 `n + 1` 个空链域正是线索二叉树要利用的资源。
- **三叉链表**：再加一个 `*parent` 域指向双亲，共 4 个域，找双亲是 `O(1)`，代价是多一个指针的空间。

| 对比项 | 顺序存储 | 二叉链表 | 三叉链表 |
| --- | --- | --- | --- |
| 找孩子 | `O(1)`（下标运算） | `O(1)`（`lchild`/`rchild`） | `O(1)` |
| 找双亲 | `O(1)` | 需从头遍历 `O(n)` | `O(1)`（`parent`） |
| 空间 | 完全二叉树很省；一般二叉树浪费严重 | 每结点 2 指针 | 每结点 3 指针 |
| 适用 | 完全二叉树、堆 | 通用 | 需频繁找双亲时 |

> **408 怎么考/常见坑**：①必背结论"`n` 个结点的二叉链表有 `n + 1` 个空指针域"，选择题常直接问。②顺序存储的容量上限要按**满二叉树**算：高度 `h` 需 `2^h - 1` 个单元。③注意顺序存储判断"是否为完全二叉树"的方法：遍历整个数组，若出现空位之后又出现非空，则不是完全二叉树。

### 5.4 二叉树的遍历

**遍历**：按某条搜索路径巡访每个结点，使每个结点被访问一次且仅一次。约定"左子树先于右子树"，按访问根的时机分三种：先序（根—左—右）、中序（左—根—右）、后序（左—右—根）；再加按层序（借用队列，自上而下、自左至右）。

**递归实现（模板骨架，会背）**：
```c
void PreOrder(BiTree T) {
    if (T) {
        visit(T);              // 访问根
        PreOrder(T->lchild);   // 递归左子树
        PreOrder(T->rchild);   // 递归右子树
    }
}
// 中序、后序只是把 visit(T) 挪到两个递归之间 / 之后
```

**非递归实现**：核心是**用栈模拟递归调用栈**。
- 先序非递归：访问结点后一路向左压栈，出栈后转向右孩子。
- 中序非递归：一路向左压栈到空，出栈即访问，再转向右孩子。
- 后序非递归：**最麻烦**，需记录"上一次访问的结点" `r`，只有当右子树已访问或为空时才访问根；也可用"双栈法"（先序变体：根—右—左 入栈后再逆序）。

```c
// 中序非递归
void InOrder(BiTree T) {
    BiTree stack[MaxSize], p = T;
    int top = -1;
    while (p || top >= 0) {
        if (p) {                       // 一路向左
            stack[++top] = p;
            p = p->lchild;
        } else {
            p = stack[top--];          // 出栈
            visit(p);
            p = p->rchild;             // 转向右子树
        }
    }
}
```

**层序遍历**：
```c
void LevelOrder(BiTree T) {
    if (!T) return;
    Queue Q; InitQueue(&Q); EnQueue(&Q, T);
    while (!QueueEmpty(Q)) {
        BiTree p; DeQueue(&Q, &p);
        visit(p);
        if (p->lchild) EnQueue(&Q, p->lchild);
        if (p->rchild) EnQueue(&Q, p->rchild);
    }
}
```
层序遍历是**判完全二叉树、求树宽、求最大宽度**的必备工具（配合"记录每层结点数"或"空结点判断"）。

**由遍历序列唯一确定二叉树**：

| 已知序列 | 能否唯一确定 | 原因/做法 |
| --- | --- | --- |
| 先序 + 中序 | ✅ 能 | 先序第一个是根，在中序中切开左右子树，递归 |
| 后序 + 中序 | ✅ 能 | 后序最后一个是根，在中序中切开，递归 |
| 层序 + 中序 | ✅ 能 | 层序第一个是根，中序切开，再按层序顺序分配 |
| 先序 + 后序 | ❌ 不能 | 只能确定根，无法确定左右子树归属（除非是满二叉树/真二叉树） |
| 先序 / 中序 / 后序 单独 | ❌ 不能 | 信息量不足 |

**注意**：先序和后序的组合，只有在**每个非叶结点都有两个孩子**（真二叉树）时才能唯一确定。中序是"定左右"的关键，因为它把根夹在中间。

**遍历的应用（大题模板来源）**：
- 求高度/深度：`h = max(左子树高, 右子树高) + 1`。
- 求结点总数：`count = 1 + 左子树数 + 右子树数`。
- 求叶子数/输出叶子：左右孩子均为空即为叶子。
- 复制二叉树：先序递归，各自建立新结点。
- 建立二叉链表：由先序 + 中序序列递归建树。
- 求 `WPL`：递归传深度参数 `depth`，叶子处累加 `data * depth`。
- 表达式树：中序遍历得中缀表达式（**需按优先级加括号**）、后序遍历得后缀表达式（逆波兰式），后序序列正是求值的计算顺序。

> **408 怎么考/常见坑**：①"先序 + 后序能否确定二叉树"是判断题高频陷阱，答案是**不能**（除非真二叉树）。②先序和中序序列相同的情况只出现在"每个结点都没有左孩子"（单支右链）时；中序与后序相同出现在"每个结点都没有右孩子"时。③非递归后序遍历代码最容易写错，注意访问根的判定条件。④层序遍历必须用**队列**，非递归先/中/后序用**栈**，别混。⑤表达式树输出中缀时必须处理括号，否则语义错误。

### 5.5 线索二叉树

**为什么需要**：`n` 个结点的二叉链表有 `n + 1` 个空链域被浪费；且在二叉链表中**找不到某结点在某种遍历下的前驱/后继**（除非再遍历一遍，`O(n)`）。线索化就是把空链域改造成指向"前驱/后继"的线索，使找前驱后继可在 `O(1)` 完成，并让遍历**不需要栈**。

**结点结构与标志位**：
```c
typedef struct ThreadNode {
    ElemType data;
    struct ThreadNode *lchild, *rchild;
    int ltag, rtag;   // 0 表示指向孩子，1 表示指向前驱/后继线索
} ThreadNode, *ThreadTree;
```
- `ltag = 0`：`lchild` 指向左孩子；`ltag = 1`：`lchild` 指向前驱。
- `rtag = 0`：`rchild` 指向右孩子；`rtag = 1`：`rchild` 指向后继。

**什么时候挂线索**：若结点左孩子为空 → 令 `lchild` 指向前驱、`ltag = 1`；若右孩子为空 → 令 `rchild` 指向后继、`rtag = 1`。线索化过程就是**按某种遍历顺序走一遍，同时记录前驱结点 `pre`**：

```c
void InThread(ThreadTree p, ThreadTree *pre) {
    if (p) {
        InThread(p->lchild, pre);        // 递归左子树
        if (!p->lchild) {                // 左空 -> 前驱线索
            p->lchild = *pre;
            p->ltag = 1;
        }
        if (*pre && !(*pre)->rchild) {   // 前驱右空 -> 后继线索
            (*pre)->rchild = p;
            (*pre)->rtag = 1;
        }
        *pre = p;                        // 更新前驱
        InThread(p->rchild, pre);        // 递归右子树
    }
}
```

**在中序线索二叉树中找前驱/后继**：
- 找**后继**：若 `rtag = 1`，`rchild` 即后继；若 `rtag = 0`，后继是**右子树中最左下的结点**。
- 找**前驱**：若 `ltag = 1`，`lchild` 即前驱；若 `ltag = 0`，前驱是**左子树中最右下的结点**。

**先序线索与后序线索的特点**：
- **先序线索**找**后继**容易（若有左孩子，左孩子就是后继；否则右孩子是后继；`rtag = 1` 时 `rchild` 是后继）；但先序线索找**前驱**困难（需要双亲信息或三叉链表）。因此先序线索化时必须**先判断 `ltag` 再递归左子树**，否则会把线索当成真孩子而**死循环**。
- **后序线索**找**前驱**容易，找**后继**困难（同样需要双亲）。
- **中序线索**是三者中最好用的：前驱后继都能 `O(1)` 找到，且遍历不需要栈，空间 `O(1)`。

| 对比项 | 先序线索 | 中序线索 | 后序线索 |
| --- | --- | --- | --- |
| 找后继 | 容易 | 容易 | 困难（需双亲） |
| 找前驱 | 困难（需双亲） | 容易 | 容易 |
| 遍历是否需要栈 | 否 | 否 | 需栈/需双亲 |
| 递归线索化注意 | 先判 `ltag` 再进左子树 | 无特殊 | 递归后处理 |

> **408 怎么考/常见坑**：①线索二叉树是**物理结构改造**，本质仍是二叉树，只是把空指针征用作线索，**并未新增结点**。②"中序线索二叉树中找前驱/后继"是必考：`rtag = 0` 时后继 = 右子树最左下，别答成右孩子。③`ltag`/`rtag` 的含义别记反：`1` 表示**线索**（前驱/后继），`0` 表示真孩子。④线索二叉树中"某个结点有左孩子"不能只看 `lchild != NULL`，必须看 `ltag == 0`。⑤先序线索化代码里不判断 `ltag` 会导致死循环，是大题扣分点。

### 5.6 树的存储结构

**双亲表示法**：用连续数组存结点，每个结点记 `data` 和 `parent` 下标。找双亲 `O(1)`，找孩子要遍历全表 `O(n)`。
```c
typedef struct { ElemType data; int parent; } PTNode;
typedef struct { PTNode nodes[MaxSize]; int n; } PTree;
```

**孩子表示法**：把每个结点的孩子串成单链表，数组存各结点的孩子链表头指针。找孩子方便，找双亲不方便。

**孩子兄弟表示法（二叉树表示法）**：每个结点两个指针——`firstchild` 指向第一个孩子，`nextsibling` 指向下一个兄弟。**这是树与二叉树转换的实现基础**，任意树都能用它转成二叉树。
```c
typedef struct CSNode {
    ElemType data;
    struct CSNode *firstchild, *nextsibling;
} CSNode, *CSTree;
```

| 存储法 | 找双亲 | 找孩子 | 找兄弟 | 特点 |
| --- | --- | --- | --- | --- |
| 双亲表示法 | `O(1)` | `O(n)` | `O(n)` | 并查集用它 |
| 孩子表示法 | `O(n)` | 遍历孩子链表 | `O(n)` | 适合"求孩子"密集 |
| 孩子兄弟表示法 | 难 | `O(1)` 得第一个孩子 | `O(1)` 得下一个兄弟 | 树/森林转二叉树 |

> **408 怎么考/常见坑**：①问"并查集用什么存储"→**双亲表示法**。②问"树转二叉树用什么存储"→**孩子兄弟表示法**。③孩子表示法中数组 + 多个单链表，注意它**不便于找双亲**。

### 5.7 森林与二叉树的转换

**树的转换规则（左孩子右兄弟）**：
1. 在每个兄弟结点之间加一条连线；
2. 对每个结点，只保留它与**第一个孩子**之间的连线，删去与其余孩子的连线；
3. 以根为轴心顺时针旋转约 45° 整理层次。
结果：**第一个孩子变成左子树，原来的兄弟变成右子树**。

**森林转二叉树**：
1. 把每棵树先转成二叉树；
2. 从第一棵树起，后一棵树的根作为前一棵树根的**右孩子**依次串起来。

**二叉树转森林（逆过程）**：
1. 若二叉树非空，根及其**左子树**构成第一棵树（根拆下来，左子树独立成树）；
2. 根的**右子树**继续拆，形成其余各棵树；
3. 对每棵树，把"右链"上的结点还原为兄弟关系。

| 对比项 | 树 | 二叉树（转换后） |
| --- | --- | --- |
| 左指针含义 | 第一个孩子 `firstchild` | 原树的第一个孩子 |
| 右指针含义 | 下一个兄弟 `nextsibling` | 原树的兄弟 |
| 根的右孩子 | 无（树只有一个根） | 森林中下一棵树的根 |

> **408 怎么考/常见坑**：①转换规则写错方向是常见失分——记住"**左孩子、右兄弟**"。②森林转二叉树后，**根的右子树链**上是各棵树的根。③一棵树转成二叉树后，**根结点一定没有右孩子**（因为它没有兄弟）——这个结论常直接考判断。

### 5.8 树和森林的遍历

**树的遍历**：
- **先根遍历**：先访问根，再依次先根遍历每棵子树。
- **后根遍历**：先依次后根遍历每棵子树，再访问根。
- 树的**层序**遍历（不常考）。

**森林的遍历**：
- **先序遍历森林**：先访问第一棵树的根，先序遍历第一棵树的根的各子树，再先序遍历其余树。
- **中序遍历森林**：中序遍历第一棵树的根的各子树，访问第一棵树的根，再中序遍历其余树。

**对应关系（必背表）**：

| 树 | 对应的二叉树 | 森林 | 对应的二叉树 |
| --- | --- | --- | --- |
| 先根遍历 | **先序遍历** | 先序遍历 | **先序遍历** |
| 后根遍历 | **中序遍历** | 中序遍历 | **中序遍历** |

也就是说：**树的先根遍历 = 其对应二叉树的先序遍历；树的后根遍历 = 其对应二叉树的中序遍历**。森林同理（森林的中序遍历 = 对应二叉树的中序遍历）。这解释了为什么二叉树的中序地位特殊——它在树里对应"后根"。

> **408 怎么考/常见坑**：①对应关系表必背，选择题直接考"树的先根遍历对应于二叉树的什么遍历"。②**注意树没有"中根遍历"**，只有先根、后根。③森林的中序遍历有的教材叫"后序遍历森林"（因其对每棵树等价于后根），按王道说法以"中序遍历"为准。

### 5.9 哈夫曼树与哈夫曼编码

**基本概念**：
- **路径长度**：从一个结点到另一个结点所经过的**边数**。
- **结点的带权路径长度**：从根到该结点的路径长度 × 该结点的权值。
- **树的带权路径长度 `WPL`**：树中**所有叶子结点**的带权路径长度之和：`WPL = Σ wi × li`（`wi` 为第 `i` 个叶子的权，`li` 为该叶子的路径长度）。
- **哈夫曼树（最优二叉树）**：在含 `n` 个带权叶子的二叉树中，`WPL` 最小的那棵。

**构造过程（贪心，必背）**：
1. 把 `n` 个权值分别看作 `n` 棵只有根的单结点树，组成森林 `F`；
2. 从 `F` 中选出**权值最小的两棵树**，合并为一棵新树，新根权值为两者之和；
3. 从 `F` 中删除这两棵树，把新树加入 `F`；
4. 重复 2~3，直到 `F` 中只剩一棵树。

**关键性质**：
- 哈夫曼树**没有度为 1 的结点**，故对 `n` 个叶子有 `n0 = n2 + 1`，且 `n0 = n`，所以 `n2 = n - 1`。
- **结点总数为 `2n - 1`**（`n` 个叶子 + `n - 1` 个内部结点）。
- 权值越大的叶子离根越近，`WPL` 最小。
- 哈夫曼树**不唯一**（左右子树可互换、同权可任意取舍），但**`WPL` 唯一**。
- 若构造中出现相同权值，取法不同会得到不同形状但 `WPL` 相同的哈夫曼树。

**哈夫曼编码**：对每个字符以其出现频率（或权值）为叶权构造哈夫曼树，左分支标 `0`、右分支标 `1`，从根到叶的路径上的标号串即为该字符的编码。
- **前缀性质**：任一编码都不是另一编码的前缀。为什么？因为字符都在**叶子**上，根到叶的路径不会经过其他叶子。这保证解码无歧义（无需分隔符）。
- **平均码长** = `WPL / Σ wi`（即加权平均）。若所有字符等概率，则平均码长 = `WPL / n`。
- 哈夫曼编码是**不等长编码**，但能保证被编码的总长度最短，所以又叫**最优前缀编码**。

**为什么哈夫曼编码最优**：把"编码长度"看作路径长度、"频率"看作权值，总编码长度就是 `WPL`；哈夫曼树使 `WPL` 最小，因此总码长最短。高频字符码短、低频字符码长，正是最优的直观含义。

> **408 怎么考/常见坑**：①`WPL` 只算**叶子**的带权路径长度，内部结点的权不参与（内部结点的权只是辅助量）。②"结点总数为 `2n - 1`"是高频填空/选择。③哈夫曼树**不唯一**但 `WPL` 唯一——选项里出现"哈夫曼树唯一"必错。④"前缀编码"的判断：逐对检查是否互为前缀；只要一个码是另一个的前缀就不是前缀编码。⑤平均码长要除以**总权值/频次和**，别忘记除。⑥`n` 个叶子的哈夫曼树形态可能有多种，但都没有度为 1 的结点。

### 5.10 并查集

**是什么**：处理**不相交集合**的合并与查询的数据结构，只支持三种操作：`Initial`（初始化）、`Find`（查所属集合）、`Union`（合并两个集合）。用**双亲表示法的树（森林）**实现：每个集合是一棵树，根作为该集合的代表元，`parent` 指向双亲，根的双亲设为 `-1`（或指向自身）。

```c
#define MaxSize 100
int parent[MaxSize];

void Initial(int n) {                 // 每个元素自成一个集合
    for (int i = 0; i < n; i++) parent[i] = -1;
}

int Find(int x) {                     // 查 x 所属集合的根
    while (parent[x] >= 0) x = parent[x];
    return x;
}

void Union(int a, int b) {            // 合并两个集合（简单版：前者的根挂到后者根下）
    int ra = Find(a), rb = Find(b);
    if (ra != rb) parent[ra] = rb;
}
```

**优化一：按秩/按大小合并**。简单版可能把长链挂到短链下，导致树越来越高、`Find` 退化成 `O(n)`。改进做法是用根结点的 `parent` 存**负数表示集合大小**（或用 `rank` 存高度），合并时**把矮/小的树挂到高/大的树下面**：

```c
void UnionBySize(int a, int b) {
    int ra = Find(a), rb = Find(b);
    if (ra == rb) return;
    if (parent[ra] > parent[rb]) { int t = ra; ra = rb; rb = t; }  // 保证 ra 更大
    parent[ra] += parent[rb];      // 大小相加（负数）
    parent[rb] = ra;               // 小的挂到大的下面
}
```
这样树高不超过 `⌊log2 n⌋ + 1`，`Find` 为 `O(log n)`。

**优化二：路径压缩**。在 `Find` 过程中把查找路径上的所有结点直接挂到根下，使后续查找几乎 `O(1)`（**均摊**接近常数）：
```c
int Find(int x) {
    int root = x;
    while (parent[root] >= 0) root = parent[root];   // 找根
    while (x != root) {                              // 路径压缩
        int t = parent[x];
        parent[x] = root;
        x = t;
    }
    return root;
}
```
（也可用递归一行写法：`return parent[x] < 0 ? x : (parent[x] = Find(parent[x]));`）

**复杂度**：只按大小合并 → `O(log n)`；只路径压缩 → 均摊 `O(log n)`；**两者同时用 → 均摊 `O(α(n))`**（`α` 为反阿克曼函数，实际可视为常数）。

**应用**：
- 判断等价类 / 无向图的连通分量个数（`n` 个顶点，每加一条边合并一次，最终根的数量即连通分量数）；
- **`Kruskal` 算法**求最小生成树：按边权递增选边，用并查集判断两端点是否已在同一连通分量（`Find(u) == Find(v)` 则跳过，否则 `Union` 并选入该边）；
- 判断无向图中是否有环（加入边时两端已同集合则有环）。

| 对比项 | 简单 `Union` | 按大小/秩合并 | 路径压缩 | 两者结合 |
| --- | --- | --- | --- | --- |
| 树高上界 | `O(n)` | `O(log n)` | 均摊降低 | 近常数 |
| `Find` 复杂度 | `O(n)` 最坏 | `O(log n)` | 均摊 `O(log n)` | 均摊 `O(α(n))` |
| 代价 | 无 | 多存大小/秩 | 改结构但不改语义 | — |

> **408 怎么考/常见坑**：①并查集的 `parent` 数组**根结点存负数**（表示集合大小/秩）时，`Find` 的循环条件是 `parent[x] >= 0`，别写成 `!= -1`。②`Union` 前**必须先 `Find` 找根再合并根**，直接改某个元素的双亲会破坏结构（高频扣分点）。③路径压缩改变树形但**不改变集合划分**。④`Kruskal` 用并查集、`Prim` 用最小堆/邻接矩阵，别记混。⑤并查集**不支持删除**元素、也不支持分裂集合。

### 5.11 堆及其应用

**定义**：堆是**完全二叉树**的顺序存储形式，且满足堆序性质：
- **大根堆（大顶堆）**：任一结点的关键字 ≥ 其左右孩子的关键字，故**堆顶（`A[1]`）是全局最大值**。
- **小根堆（小顶堆）**：任一结点的关键字 ≤ 其左右孩子的关键字，故**堆顶是最小值**。

**用数组存储**：`A[1..n]`，结点 `i` 的孩子为 `2i` 和 `2i+1`，双亲为 `⌊i/2⌋`。注意：堆**只保证父子间的大小关系**，兄弟之间、层与层之间无任何约束；因此**大根堆的中序序列不是有序的**。

**初始建堆（自下而上调整，`O(n)`）**：从最后一个**分支结点** `⌊n/2⌋` 开始，依次向前对每个结点执行"向下调整"（`Heapify`/筛选），直到根。为什么是 `O(n)` 而不是 `O(n log n)`：越靠近底层的结点越多，但需要下沉的高度越小，加权求和 `Σ (n / 2^h) × h` 收敛到 `O(n)`。

```c
void SiftDown(int A[], int k, int n) {   // 大根堆：把 A[k] 向下调整到合适位置
    A[0] = A[k];                          // A[0] 暂存
    for (int i = 2 * k; i <= n; i *= 2) {
        if (i < n && A[i] < A[i + 1]) i++;   // 取较大的孩子
        if (A[0] >= A[i]) break;             // 已满足堆序
        A[k] = A[i]; k = i;                  // 孩子上移
    }
    A[k] = A[0];
}

void BuildHeap(int A[], int n) {
    for (int k = n / 2; k >= 1; k--) SiftDown(A, k, n);
}
```

**插入（`O(log n)`）**：把新元素放到数组末尾（即完全二叉树的下一个位置），再**向上调整**（不断与双亲比较并交换），最多走树高 `⌊log2 n⌋ + 1` 步。
**删除堆顶（`O(log n)`）**：用**最后一个元素**替换堆顶，堆长度减 1，再对堆顶执行一次**向下调整**。

**堆排序**：先建大根堆 `O(n)`；然后重复"堆顶与当前末尾元素交换 → 堆长度减 1 → 堆顶向下调整"，`n - 1` 趟，每趟 `O(log n)`，总计 `O(n log n)`。空间 `O(1)`。**升序排序用大根堆，降序用小根堆**。堆排序是**不稳定**排序。

**`TopK` 应用**：求 `n` 个数中最大的 `k` 个，用**大小为 `k` 的小根堆**——遍历数据，堆未满则插入，堆满则与堆顶比较：比堆顶大就替换堆顶并向下调整。时间复杂度 `O(n log k)`，空间 `O(k)`，远优于全排序 `O(n log n)` 或维护大小为 `k` 的有序数组。求最小的 `k` 个则用**大根堆**（反着来）。

**应用**：`TopK` 问题、堆排序、`Prim` 算法中用堆选最小边、优先队列、`Dijkstra` 优化。

> **408 怎么考/常见坑**：①"堆是一棵完全二叉树"——**必须是完全二叉树**，这是堆能用数组高效存储的前提。②建堆 `O(n)`、插入/删除 `O(log n)` 是必背三件套，常考"建堆时间复杂度的比较次数"大题。③判断某序列是否为堆：只需检查每个结点 `i` 与 `2i`、`2i+1` 的大小关系，**不需要**检查兄弟之间。④删除堆顶是"**末尾元素补到堆顶再下沉**"，不是逐个前移。⑤堆排序的空间是 `O(1)`，别写成 `O(n)`。⑥`TopK` 求最大 `k` 个用小根堆（因为堆顶是当前 `k` 个里最小的，方便淘汰）。

### 5.12 算法设计题模板（大题核心，至少背熟 2 个）

**模板 1：求二叉树高度（后序递归）**
思路：空树高 0；否则高度 = `max(左子树高, 右子树高) + 1`。必须先算出左右子树高度才能算根，天然是**后序**。

```c
int TreeHeight(BiTree T) {
    if (T == NULL) return 0;                     // 空树高度为 0
    int lh = TreeHeight(T->lchild);              // 递归求左子树高
    int rh = TreeHeight(T->rchild);              // 递归求右子树高
    return (lh > rh ? lh : rh) + 1;              // 取较大者加 1
}
```
- 时间复杂度 `O(n)`（每个结点访问一次），空间复杂度 `O(h)`（递归栈深，最坏 `O(n)`）。
- 采分点：①空树返回 0 的判断（1 分）；②左右递归调用（2 分）；③取 `max` 加 1 的表达式（1 分）；④复杂度说明（1 分）。
- 变体考法：求"以 `T` 为根的子树中值为 `x` 的结点所在层次"、求"最大宽度"（用层序遍历改动）。

**模板 2：判断二叉树是否为完全二叉树（层序遍历 + 空结点编号判断）**
思路一（`NULL` 标记法）：层序遍历，遇到第一个空孩子后，其**后续所有结点都必须是空**，否则不是完全二叉树。

```c
int IsComplete(BiTree T) {
    if (T == NULL) return 1;                     // 空树视为完全二叉树
    Queue Q; InitQueue(&Q);
    EnQueue(&Q, T);
    int seenNull = 0;                            // 是否已遇到空结点
    while (!QueueEmpty(Q)) {
        BiTree p; DeQueue(&Q, &p);
        if (p == NULL) {
            seenNull = 1;                        // 出现空结点，之后不能再有真结点
            continue;
        }
        if (seenNull) return 0;                  // 空结点后又出现真结点 -> 不是
        EnQueue(&Q, p->lchild);                  // 空孩子也要入队，作为标记
        EnQueue(&Q, p->rchild);
    }
    return 1;
}
```

思路二（编号法，更直观）：层序遍历时给每个结点维护"完全二叉树中的应有编号"，根为 1，左孩子 `2i`、右孩子 `2i+1`；若出现某个结点编号 `> n`（`n` 为结点总数），则不是完全二叉树。

```c
int IsComplete2(BiTree T, int n) {   // n 为二叉树结点总数
    if (T == NULL) return 1;
    Queue Q; InitQueue(&Q);
    EnQueue(&Q, T); EnQueueNum(&Q, 1);
    int cnt = 0;
    while (!QueueEmpty(Q)) {
        BiTree p; int id;
        DeQueue(&Q, &p); DeQueueNum(&Q, &id);
        if (id > n) return 0;                    // 编号超出总数 -> 有空缺
        cnt++;
        if (p->lchild) { EnQueue(&Q, p->lchild); EnQueueNum(&Q, 2 * id); }
        if (p->rchild) { EnQueue(&Q, p->rchild); EnQueueNum(&Q, 2 * id + 1); }
    }
    return cnt == n;
}
```
- 时间复杂度 `O(n)`，空间复杂度 `O(n)`（队列）。
- 采分点：①层序遍历框架（队列初始化、出队访问、孩子入队）（3 分）；②"空结点后不得再有真结点"的判断逻辑（2 分）；③空树/单结点的边界处理（1 分）；④复杂度（1 分）。

**模板 3（延伸）：求二叉树的 `WPL`**
```c
int WPL(BiTree T, int depth) {
    if (T == NULL) return 0;
    if (!T->lchild && !T->rchild)                // 叶子才计入
        return T->data * depth;
    return WPL(T->lchild, depth + 1) + WPL(T->rchild, depth + 1);
}
// 调用：WPL(T, 0)
```
- `O(n)` 时间，`O(h)` 空间。采分点：**只在叶子处累加**、深度参数随递归 +1。

**模板 4（延伸）：输出值为 `x` 的结点的所有祖先**
```c
int PrintAncestors(BiTree T, ElemType x) {
    if (T == NULL) return 0;
    if (T->data == x) return 1;                  // 找到了，本层不再输出自己
    if (PrintAncestors(T->lchild, x) || PrintAncestors(T->rchild, x)) {
        visit(T);                                // 回溯时输出祖先
        return 1;
    }
    return 0;
}
```
- 思路：**后序思想 + 返回值回溯**，只有在子树中找到 `x` 才输出当前结点。`O(n)` 时间、`O(h)` 空间。

**模板 5（延伸）：最近公共祖先 `LCA`**
```c
BiTree LCA(BiTree T, BiTree p, BiTree q) {
    if (T == NULL || T == p || T == q) return T;
    BiTree left  = LCA(T->lchild, p, q);
    BiTree right = LCA(T->rchild, p, q);
    if (left && right) return T;                 // 分居两侧 -> 当前即 LCA
    return left ? left : right;                  // 都在同一侧
}
```

**模板 6（延伸）：交换左右子树**
```c
void SwapChildren(BiTree T) {
    if (T == NULL) return;
    BiTree t = T->lchild; T->lchild = T->rchild; T->rchild = t;
    SwapChildren(T->lchild);
    SwapChildren(T->rchild);
}
```

> **408 怎么考/常见坑**：①算法题**先写清思路再写代码**，代码要注意 `NULL` 边界和返回值语义，这是采分点。②结构体名沿用题目给的定义（如 `BiTree`/`BiTNode`），别自创。③递归函数的**参数设计**是难点：求 `WPL`/层次类问题要传 `depth` 参数，求祖先/`LCA` 要用**返回值回溯**。④复杂度要写出**时间 + 空间**两项。⑤若题目要求"非递归"，必须明确用栈（先/中/后序）或队列（层序）。⑥不要写 `main` 函数，一般不额外给分还占版面。

## 四、例题精练（3 道）

### 例题 1（选择题）

【题】已知一棵有 2011 个结点的树，其叶结点个数为 116，该树对应的二叉树中无右孩子的结点个数是（　　）。

A. 115　　B. 116　　C. 1895　　D. 1896

【解析】
用**孩子兄弟表示法**把树转成二叉树后：左指针指向**第一个孩子**，右指针指向**下一个兄弟**。

关键结论：在原树中，一个结点在转换后的二叉树里**没有右孩子，当且仅当它在原树中没有下一个兄弟**，即它是其双亲的**最后一个孩子**。而"某个结点是其双亲的最后一个孩子"这件事，对每个双亲恰好发生一次（每个双亲的最后一个孩子唯一）。

- 树中有 2011 个结点，其中叶子 116 个，则非叶结点（分支结点）= `2011 - 116 = 1895` 个。
- 每个分支结点都有"最后一个孩子"，共 `1895` 个结点在其兄弟中排最后。
- 另外，**整个树的根结点**在原树中也没有兄弟，转换后同样没有右孩子，且根不是任何结点的孩子，不在上面 `1895` 个之内。

因此无右孩子的结点数 = `1895 + 1 = 1896`。

逐项分析：
- **A. 115**：错。混淆了"叶子数 - 1"之类的错误推导，与结论无关。
- **B. 116**：错。116 是叶子个数，把"最后一个孩子"与"叶子"混为一谈；叶子也未必是最后一个孩子。
- **C. 1895**：错。只数了"各双亲的最后一个孩子"，**漏掉了根结点**（根在转换后也没有右孩子）。
- **D. 1896**：正确。`1895 + 1 = 1896`。

> 408 常见坑：做树↔二叉树转换题时，**务必单独考虑根结点**——根没有兄弟，所以转换后右指针必为空；同时"叶子"和"最后一个孩子"是两个完全不同的概念。

### 例题 2（算法设计题）

【题】设二叉树以二叉链表存储，结点结构为 `(lchild, data, rchild)`，`data` 为正整数。设计算法求该二叉树的带权路径长度 `WPL`（`WPL = Σ wi × li`，`wi` 为叶子结点的权值，`li` 为该叶子的路径长度/层数减一）。要求：给出算法思想、完整 C 函数、时间与空间复杂度。

**【算法思想】**
树的 `WPL` 是**所有叶子结点**带权路径长度之和，只有叶子才计入，内部结点的权不参与计算。用**先序遍历**（深度优先）递归求解：
1. 递归函数带一个参数 `depth`，表示当前结点所在的层数（根为 0，对应路径长度）。
2. 若当前结点为空，返回 0。
3. 若当前结点是**叶子**（`lchild == NULL && rchild == NULL`），返回 `data * depth`。
4. 否则返回左右子树 `WPL` 之和，递归时 `depth` 加 1。

**【完整代码】**
```c
typedef struct BiTNode {
    int data;
    struct BiTNode *lchild, *rchild;
} BiTNode, *BiTree;

int WPL(BiTree T, int depth) {
    if (T == NULL)                                   // 空树/空子树
        return 0;
    if (T->lchild == NULL && T->rchild == NULL)      // 叶子结点才计入 WPL
        return T->data * depth;
    return WPL(T->lchild, depth + 1)                 // 递归处理左子树
         + WPL(T->rchild, depth + 1);                // 递归处理右子树
}
/* 调用方式：
   WPL(T, 0);   // 根结点路径长度为 0，其孩子路径长度为 1
   若题目定义根的路径长度为 1，则调用 WPL(T, 1)，其余不变。 */
```

**【复杂度分析】**
- 时间复杂度：每个结点恰好被访问一次，且每次访问只做常数工作，故为 `O(n)`（`n` 为结点总数）。
- 空间复杂度：递归栈深度等于树高 `h`，最坏（单支树）为 `O(n)`，平均为 `O(log n)`。

**【采分点】**
1. 判断空树并返回 0（边界处理）——1 分；
2. **判叶子条件** `lchild == NULL && rchild == NULL`——1 分；
3. 叶子返回 `data * depth`，权重乘以路径长度——2 分；
4. 非叶结点递归调用左右子树，且**深度参数传 `depth + 1`**——2 分；
5. 时间复杂度 `O(n)`——1 分；
6. 空间复杂度 `O(h)`（说明最坏 `O(n)`）——1 分。

> 常见坑：①把内部结点的权也累加进去（错，`WPL` 只统计叶子）；②`depth` 忘记 `+1` 或从 1 开始导致整体偏移；③忘记处理空树导致空指针解引用；④只给代码不写思路和复杂度，直接丢一半分。

### 例题 3（计算题：哈夫曼树与 `WPL`）

【题】设字符集为 `{a, b, c, d, e}`，各字符在电文中出现的次数（权值）依次为 `{7, 5, 2, 4, 9}`。

（1）构造哈夫曼树，画出树形并求 `WPL`；
（2）写出各字符的哈夫曼编码，验证其前缀性质；
（3）求该电文编码后的平均码长（以出现次数为权重）。

**【解答】**

（1）**构造过程**（每步取权值最小的两棵树合并，新根权值为和）：

- 初始森林：`2, 4, 5, 7, 9`（分别对应 `c, d, b, a, e`）
- 取 `2, 4` 合并 → 新结点权 `6`；森林变为 `5, 6, 7, 9`
- 取 `5, 6` 合并 → 新结点权 `11`；森林变为 `7, 9, 11`
- 取 `7, 9` 合并 → 新结点权 `16`；森林变为 `11, 16`
- 取 `11, 16` 合并 → 根，权 `27`

树形（左分支标 `0`，右分支标 `1`）：

```
                  (27)
                0/    \1
              (11)     (16)
            0/   \1   0/   \1
          (5)b  (6)  (7)a  (9)e
              0/   \1
             (2)c  (4)d
```

**计算 `WPL`**（只算叶子）：叶子路径长度——`b` 在深度 2、`c` 在深度 3、`d` 在深度 3、`a` 在深度 2、`e` 在深度 2。

```
WPL = 5×2 + 2×3 + 4×3 + 7×2 + 9×2
    = 10 + 6 + 12 + 14 + 18
    = 60
```

（也可用"所有内部结点权值之和"快速校验：内部结点权值为 `6 + 11 + 16 + 27 = 60`，两者相等，说明计算无误。）

（2）**哈夫曼编码**（从根到叶，左 `0` 右 `1`）：

| 字符 | 权值 | 编码 | 码长 |
| --- | --- | --- | --- |
| `a` | 7 | `10` | 2 |
| `b` | 5 | `00` | 2 |
| `c` | 2 | `010` | 3 |
| `d` | 4 | `011` | 3 |
| `e` | 9 | `11` | 2 |

**前缀性质验证**：码长为 2 的码是 `{10, 00, 11}`，码长为 3 的码是 `{010, 011}`。检查：`01` 不是任何字符的编码（`c` 和 `d` 的前两位都是 `01`，但没有任何字符的编码恰为 `01`），且 `010`、`011` 互不为前缀；`10`、`00`、`11` 之间也没有前缀关系。**任一编码都不是另一编码的前缀**，因此满足前缀编码要求，解码无歧义。

（直观原因：所有字符都位于哈夫曼树的**叶子**上，故根到任一叶的路径都不会完全包含另一条根到叶的路径。）

（3）**平均码长**：

```
平均码长 = WPL / Σ wi
         = 60 / (7 + 5 + 2 + 4 + 9)
         = 60 / 27
         ≈ 2.22
```

即平均每个字符约需 `2.22` 个二进制位。

> 408 常见坑：①`WPL` **只算叶子**，把内部结点权 `27` 也乘进去是最常见错误；②哈夫曼树**不唯一**（同权值合并顺序不同、左右可交换），但 `WPL` **唯一为 60**，若题目问"树唯一吗"要答不唯一；③结点总数应为 `2n - 1 = 2×5 - 1 = 9`，可与画出的树核对；④平均码长必须**除以总权值**，不要只写 `60`；⑤编码只要满足前缀性质且总长最短，具体 `0/1` 分配可不同，答案不唯一。

## 六、简便方法与易错口诀（速算 · 防错）

> 本节把本章能"省时间"和"防掉坑"的招集中在一处：二轮复习与考前只看这一节。每条都写清**适用条件**。

### 6.1 速算招式

| 场景 | 常规做法（慢/繁） | 简便做法（快/稳） | 为什么成立 / 适用条件 |
| --- | --- | --- | --- |
| 叶结点数与度为 2 的结点数互推 | 画树逐个点数 | `n0 = n2 + 1`，再配 `n = n0 + n1 + n2` 直接解方程 | 由 `n = 总度数 + 1 = n1 + 2*n2 + 1` 推出；**只对二叉树成立** |
| 已知 `n` 求完全二叉树的 `n0`/`n1`/`n2` | 逐层画图再数 | `n1`："偶 1 奇 0"；`n0 = ⌈n/2⌉`（`n` 偶即 `n/2`，`n` 奇即 `(n+1)/2`）；`n2 = n0 - 1` | 完全二叉树度为 1 的结点至多 1 个且必为左孩子，故 `n` 的奇偶唯一决定 `n1` |
| 完全二叉树的高度 | 逐层数 | `⌊log2 n⌋ + 1`（等价写法 `⌈log2(n+1)⌉`） | 前 `h - 1` 层已满最多 `2^(h-1) - 1` 个，第 `h` 层至少 1 个；要求 `n ≥ 1` |
| 查双亲 / 孩子 | 遍历或靠指针 | 左孩子 `2i`、右孩子 `2i + 1`、双亲 `⌊i/2⌋`、结点 `i` 在第 `⌊log2 i⌋ + 1` 层 | 必须"按层序从 1 开始编号"；一般二叉树用顺序存储要先补齐空位再编号 |
| 哈夫曼树的 `WPL` | 先求每个叶子的深度，再 `Σ wi × li` | 构造时把**每次合并产生的新结点权值累加**，和就是 `WPL` | 依赖"树是严格二叉树（无度为 1 的结点）且内部结点权值 = 其孩子权值之和"；哈夫曼算法构造时该前提自动满足 |
| 哈夫曼树的结点数 | 画完再数 | 叶子 `n` 个 → 总结点 `2n - 1`、度为 1 的结点 0 个、由 `n0 = n2 + 1` 得 `n2 = n - 1` | 每次合并是"2 个结点换 1 个新结点"，共合并 `n - 1` 次 |
| 平均码长 | 逐字符"码长 × 频率"求和 | `平均码长 = WPL / Σ wi` | 分母是**全部叶子权值之和**（不是字符个数） |
| 二叉链表空链域个数 | 逐结点数空指针 | `n + 1`（三叉链表则为 `n + 2`） | `2n` 个指针域中只有 `n - 1` 个指向孩子；三叉链表 `3n` 个域中非空 `2n - 2` 个 |
| 由遍历序列还原树形 | 手工试画试凑 | "先序 / 后序 / 层序**找根**，中序**分左右**"递归切分；先序首元素、后序末元素、层序首元素都是根 | 必须含中序，且只对二叉树；单序列或"先序 + 后序"一般不够 |
| 树转二叉树后无右孩子的结点数 | 转换完再逐个看 | 无右孩子的结点数 = 非叶结点数 + 1 = `n - 叶结点数 + 1` | 有右孩子 ⟺ 原树中"有下一个兄弟"；这类结点共 `(n - 1) - 非叶结点数` 个，剩下的都无右孩子 |
| 树 / 森林遍历与二叉树遍历挂钩 | 各写一套遍历代码 | 树的先根 = 二叉树先序；树的后根 = 二叉树中序；森林同理 | 孩子兄弟表示法中"左 = 第一个孩子、右 = 下一个兄弟"，先根先走孩子链、后根后走根 |
| 建堆与堆排序代价 | 逐个 `Insert` 建堆 | 自下而上建堆 `O(n)`（从 `⌊n/2⌋` 起逐个 `AdjustDown`）；插入/删除 `O(log n)`；堆排序 `O(n log n)`、空间 `O(1)` | 第 `i` 层结点调整代价 `O(h - i)`，加权求和收敛到 `O(n)`；逐个插入才是 `O(n log n)` |
| 并查集复杂度 | 担心退化成链 | 路径压缩 + 按秩/按大小合并 → 单次**均摊** `O(α(n))`，实际当常数 | `Kruskal` 判环直接用；只用其中一种只是均摊 `O(log n)` |
| 树算法手写模板 | 每次现推 | 三行骨架：判空返回 → 递归左子树 → 递归右子树（按需换序） | 树是递归定义，求高、计数、叶子、复制、交换左右子树、求祖先都能套 |

> **订正 / 收紧提示（对候选招式的两处补充）**：①"`WPL` = 所有非叶结点权值之和"并非哈夫曼树独有，它对**任何严格二叉树**（没有度为 1 的结点）都成立，前提是"内部结点权值 = 左右孩子权值之和"——哈夫曼算法构造时该前提自动满足；但若题中给的是一棵**含度为 1 结点**的普通二叉树，此式失效，只能退回 `Σ wi × li`。②"先序 + 后序不能唯一确定二叉树"要补一个例外：当二叉树是**真二叉树**（每个非叶结点都有 2 个孩子）时，先序 + 后序**可以**唯一确定。

### 6.2 口诀与记忆钩子

- **叶结点数**："叶二加一"——`n0 = n2 + 1`；逆用成"给叶求总"：`n = 2*n0 + n1 - 1`，完全二叉树里 `n1` 只会是 0 或 1。
- **完全二叉树**："偶一奇零、高取对数再加一"——`n` 偶则 `n1 = 1`、`n` 奇则 `n1 = 0`；高 `⌊log2 n⌋ + 1`；再配"叶取上整"`n0 = ⌈n/2⌉`。
- **编号关系**："左二右二加一，双亲除二取整"——`2i`、`2i + 1`、`⌊i/2⌋`，只对按层序编号的完全二叉树生效。
- **哈夫曼**："合并一路加，`WPL` 就是内部和；叶子 `n` 个结点 `2n - 1`，度为 1 的一个也没有"。
- **遍历定树**："先序后序层序找根，中序一刀分左右；先中、后中、层中都行，先后同框要靠'真'（真二叉树）"。
- **空链域**："指针总数减边数"——二叉 `n + 1`，三叉 `n + 2`。
- **建堆**："半场回溯是 `O(n)`，逐个插入 `n log n`"——从 `⌊n/2⌋` 开始往前调才是线性建堆。
- **并查集**："压缩加秩并，均摊近常数"——路径压缩 + 按秩合并 → `O(α(n))`。
- **树转二叉树**："左孩子、右兄弟；根必无右孩，无右孩者 = 非叶 + 1"。
- **线索二叉树**："中序线索最好用，前驱后继都直接；先序找后继易找前驱难，后序正好反过来"。

### 6.3 反例黑名单（这些"简便法"是错的）

- ❌ **把 `n0 = n2 + 1` 推广到三叉树或一般 `m` 叉树**：正确做法是用一般式 `n0 = 1 + n2 + 2*n3 + ... + (m - 1)*nm`（即 `n0 = 1 + Σ(i - 1) × ni`，`i ≥ 2`）；`n0 = n2 + 1` 只对二叉树成立。
- ❌ **把 `WPL` 当平均码长，或把内部结点权也乘进 `WPL`**：正确做法是 `平均码长 = WPL / Σ wi`，分母必须除以所有叶子权值之和；`WPL` 只算叶子（等价地只算内部结点之和），两者不可混着加、重复计。
- ❌ **说"哈夫曼树唯一"**：正确说法是哈夫曼树**不唯一**（同权值合并次序不同、左右子树可交换），但 `WPL`（最短带权路径长度）**唯一**。
- ❌ **认为"先序 + 后序"能唯一确定二叉树**：一般情况下不能；只有二叉树是**真二叉树**（每个非叶结点都有 2 个孩子）时先序 + 后序才唯一。要唯一就再加中序：先序 + 中序、后序 + 中序、层序 + 中序都可以。
- ❌ **把 `2i`、`2i + 1`、`⌊i/2⌋` 套到非完全二叉树**：正确做法是先认识到这组关系只对"按层序从 1 编号的完全二叉树"直接成立；一般二叉树用顺序存储必须先补齐空结点再编号。
- ❌ **认为"初始建堆是 `O(n log n)`"**：正确做法是自下而上建堆为 `O(n)`；`O(n log n)` 是"逐个 `Insert` 建堆"或"堆排序整体"的代价，不要张冠李戴。
- ❌ **认为"完全二叉树可以有多个度为 1 的结点 / `n1` 随便取"**：正确做法是先定 `n1`（偶 1 奇 0，至多 1 个且只有左孩子），再由 `n0 = ⌈n/2⌉`、`n2 = n0 - 1` 补齐其余。
- ❌ **把 `n + 1` 个空链域套到三叉链表**：正确值是二叉链表 `n + 1` 个、三叉链表 `n + 2` 个空指针域。
- ❌ **说"路径压缩后单次 `Find` 是 `O(1)`、树高恒为 1"**：正确说法是"路径压缩 + 按秩合并"的单次操作**均摊** `O(α(n))`（近似常数），单次最坏仍可能到 `O(log n)`。
- ❌ **把"树的高度"按边数算（单结点树高记 0）**：408 约定树高/深度按**结点层数**——空树 0、单结点 1；只有"路径长度"才按边数计。
