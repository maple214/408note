
## 二、概念详解

### 2.1 线性表的定义与逻辑特征

**定义**：线性表是具有**相同数据类型**的 `n`（`n >= 0`）个数据元素的**有限序列**，记作 `(a1, a2, ..., an)`。

三个关键词，一个都不能少：

- **相同数据类型**：每个元素占同样大小的空间。这条决定了顺序表能用"首地址 + i × 元素大小"算地址。
- **有限**：`n` 是确定的数。这是"线性表"和"无限序列"的分界。
- **序列（有序）**：除第一个元素外，每个元素**有且仅有一个直接前驱**；除最后一个元素外，每个元素**有且仅有一个直接后继**。`ai` 是 `ai+1` 的**直接前驱**，`ai+1` 是 `ai` 的**直接后继**。

> 注意：**线性表是逻辑结构**，顺序表和链表是它落地的两种**存储结构**。它们的关系是"同一个接口的两套实现"，不是并列的两个概念。选择题很爱考"下列说法正确的是"，选项里常把两者混为一谈。

`n` 个元素的**位序从 1 开始**，这一点非常关键：`a1` 是第 1 个元素，对应数组下标 `0`。王道书和 408 真题一律用位序描述位置，"在第 `i` 个位置插入"指的是插到 `ai` 前面。

**408 怎么考 / 常见坑**：

- 判断题里出现"线性表可以存储不同类型的数据"——错。
- "空表是不是线性表"——是，`n = 0` 时叫空表，仍然满足定义。
- 题目给的位序是 1 开始，写代码时别忘了 `-1`。

### 2.2 线性表的基本操作

这些操作是"逻辑结构层面"的操作定义，不含任何实现细节（考场写算法时先把操作清单想一遍，不容易漏边界）：

| 操作名 | 含义 | 成功条件 / 注意点 |
| --- | --- | --- |
| `InitList(&L)` | 初始化，构造空表 | 顺序表要给 `length` 赋 0；链表要看是否带头结点 |
| `DestroyList(&L)` | 销毁，释放内存 | 链表要逐个 `free`，顺序表的 `malloc` 区也要 `free` |
| `ListInsert(&L, i, e)` | 在第 `i` 个位置插入 `e` | 合法 `i` 范围：`1 <= i <= n+1` |
| `ListDelete(&L, i, &e)` | 删除第 `i` 个元素并用 `e` 带回 | 合法 `i` 范围：`1 <= i <= n` |
| `LocateElem(L, e)` | 按值查找，返回位序或指针 | 找不到返回 `0` 或 `NULL` |
| `GetElem(L, i, &e)` | 按位查找 | 顺序表 `O(1)`；链表 `O(n)` |
| `Length(L)` | 求表长 | 顺序表 `O(1)`；链表不带 `length` 字段时 `O(n)` |
| `PrintList(L)` | 遍历输出 | 链表的遍历结束条件要按"带头结点/循环"改写 |
| `Empty(L)` | 判空 | 顺序表：`L.length == 0`；带头结点链表：`L->next == NULL` |

**为什么插入的合法位置比删除多一个**：插入是"放到第 `i` 个元素前面"，`i = n+1` 表示放到表尾之后，是合法的；删除必须删一个真实存在的元素，所以最大到 `n`。

**408 怎么考 / 常见坑**：算法设计题里如果没做**边界检查**（比如 `i` 越界、`k` 大于表长、空表），采分点会被扣。养成"函数第一行就判空/判界"的习惯。

### 2.3 顺序表的实现：静态分配与动态分配

**静态分配**：

```c
#define MaxSize 50
typedef struct {
    ElemType data[MaxSize];   // 静态数组，编译期确定大小
    int length;               // 当前表长
} SqList;
```

**动态分配**：

```c
#define InitSize 10
typedef struct {
    ElemType *data;   // 指向 malloc 出来的连续空间
    int length;       // 当前长度
    int MaxSize;      // 当前容量上限
} SeqList;

void InitList(SeqList *L) {
    L->data = (ElemType *)malloc(sizeof(ElemType) * InitSize);
    L->length = 0;
    L->MaxSize = InitSize;
}
```

**为什么要有动态分配**：静态分配的容量写死在编译期，小了溢出、大了浪费；动态分配把"容量"变成运行期可调整的量，满了就 `realloc` 扩一块更大的、把老数据搬过去。

```c
// 空间不够时扩容（线性增长写法，用于理解；王道书也用这种写法）
void IncreaseSize(SeqList *L, int len) {
    ElemType *p = L->data;
    L->data = (ElemType *)malloc(sizeof(ElemType) * (L->MaxSize + len));
    for (int i = 0; i < L->length; i++)
        L->data[i] = p[i];        // 老数据搬过去
    L->MaxSize = L->MaxSize + len; // 容量更新
    free(p);                       // 释放旧空间，否则内存泄漏
}
```

**关键认知**：`data` 是指针还是数组，**都不改变"逻辑相邻即物理相邻"这个本质**，所以动态分配的顺序表**仍然是随机存取的**，`GetElem` 依然是 `O(1)`。选择题常拿"动态分配了就不是顺序表/不能随机访问"来骗人。

**随机访问的来历**：每个元素占 `sizeof(ElemType)` 字节，起始地址为 `LOC(A)`，则第 `i`（1 起）个元素的地址为

`LOC(ai) = LOC(A) + (i - 1) * sizeof(ElemType)`

这是一个**与 n 无关的常数时间计算**，所以 `O(1)`。这也是"顺序表按位查找 `O(1)`、链表按位查找 `O(n)`"的根因。

**408 怎么考 / 常见坑**：

- 结构体里 `length` 从 0 开始计数，表长就是 `length`，**不是** `length + 1`。
- 扩容后一定要 `free` 旧空间；考"时间复杂度"时，单次扩容是 `O(n)`，均摊到每次插入是 `O(1)`。
- 判断题陷阱："顺序表插入元素不需要移动数据"——错，除非插在表尾。

### 2.4 顺序表的插入与删除：移动次数与平均移动次数

**插入 `ListInsert(&L, i, e)`**：把第 `i` 到第 `n` 个元素**整体后移一位**，空出位置放 `e`，然后 `length++`。

```c
bool ListInsert(SqList *L, int i, ElemType e) {
    if (i < 1 || i > L->length + 1) return false;   // 位序非法
    if (L->length >= MaxSize) return false;          // 空间满
    for (int j = L->length; j >= i; j--)             // 从后往前挪
        L->data[j] = L->data[j - 1];
    L->data[i - 1] = e;
    L->length++;
    return true;
}
```

**插入的移动次数**（表长 `n`，插入到第 `i` 个位置，需要移动 `n - i + 1` 个元素）：

| 情形 | 插入位置 | 移动次数 |
| --- | --- | --- |
| 最好 | 表尾之后（`i = n+1`） | `0` |
| 最坏 | 表头（`i = 1`） | `n` |
| 平均 | 等概率均匀分布 | `n/2` |

**平均移动次数的推导**（假设 `n+1` 个插入位置等概率，每个概率为 `1/(n+1)`）：

`平均移动次数 = (1/(n+1)) × Σ(i=1..n+1) (n - i + 1) = (1/(n+1)) × (n(n+1)/2) = n/2`

其中用到了等差数列求和 `1 + 2 + ... + n = n(n+1)/2`。时间复杂度 `O(n)`。

**删除 `ListDelete(&L, i, &e)`**：把第 `i` 个元素取走，第 `i+1` 到第 `n` 个元素**整体前移一位**，`length--`。

```c
bool ListDelete(SqList *L, int i, ElemType *e) {
    if (i < 1 || i > L->length) return false;   // 注意是 length，不是 length+1
    *e = L->data[i - 1];
    for (int j = i; j < L->length; j++)         // 从前往后挪
        L->data[j - 1] = L->data[j];
    L->length--;
    return true;
}
```

**删除的移动次数**（删除第 `i` 个元素，需要移动 `n - i` 个元素）：

| 情形 | 删除位置 | 移动次数 |
| --- | --- | --- |
| 最好 | 表尾（`i = n`） | `0` |
| 最坏 | 表头（`i = 1`） | `n - 1` |
| 平均 | 等概率均匀分布 | `(n-1)/2` |

**推导**：`平均移动次数 = (1/n) × Σ(i=1..n) (n - i) = (1/n) × (n(n-1)/2) = (n-1)/2`。

**记忆抓手**：插入是"多一个位置可选"，所以分母 `n+1`、结果 `n/2`；删除是"每个元素都可能被删"，分母 `n`，最坏少一次移动，结果 `(n-1)/2`。**插入比删除多半次移动**，这是因为它多了一个"表尾插入不动"的机会。

**408 怎么考 / 常见坑**：

- 问"插入第 `i` 个元素要移动几个元素"，答案随 `i` 变，**别写成 `n/2`**；只有问"平均"才是 `n/2`。
- 顺序表插入删除的循环方向：**插入从后往前**（否则数据被覆盖），**删除从前往后**。
- 时间复杂度永远是 `O(n)`，即使只插入一个元素——因为要移动。
- 只按位查找 `O(1)`，按值查找是 `O(n)`（要顺序比较），两者别混。

### 2.5 顺序表的优缺点与适用场景

**优点**：

1. **随机访问**：`GetElem` 是 `O(1)`，按下标直接取。
2. **存储密度高**：`存储密度 = 数据本身占的字节 / 结点总共占的字节`，顺序表为 `1`，没有额外指针开销。
3. **存储空间连续**，对 CPU 缓存友好（这一点 408 不考，理解即可）。

**缺点**：

1. 插入、删除需要移动大量元素，`O(n)`。
2. 容量固定（静态）或扩容要整体搬迁（动态），难以"按需增长"。
3. 需要一整块连续空间，碎片多时可能申请不到。

**适用场景**：**表长可预估、变化不大，且以"按位置取元素"为主**的场合。例如：查表、矩阵运算中的向量、需要频繁随机访问且很少增删的场景。

**408 怎么考 / 常见坑**：题目常给出"需要频繁插入删除"或"表长变化剧烈"作为信号，让你选链表；出现"按位查找频繁"则选顺序表。看到"存储密度"要会算：单链表结点有 `data` 和 `next` 两部分，所以存储密度**小于 1**。

### 2.6 单链表：结点结构与头指针、头结点

**结点结构**：

```c
typedef struct LNode {
    ElemType data;        // 数据域
    struct LNode *next;   // 指针域，指向直接后继
} LNode, *LinkList;
```

`LNode` 是结点类型，`LinkList` 是指向结点的指针类型。`LinkList L` 和 `LNode *L` 是等价的写法，考场上用哪个都行，但**语义上**当强调"这是一个链表"时用 `LinkList` 更规范。

**头指针（head pointer）**：指向链表中**第一个结点**的指针。它是链表的"身份证"——只要有头指针，整条链就能走通。**头指针必须存在，不能为空表就省略**（空表的头指针是 `NULL`）。

**头结点（head node）**：在第一个**数据结点（首元结点）**之前**附加**的一个结点，它的 `data` 域通常不存数据（王道书里常常也不初始化），`next` 指向首元结点。**头结点不是必须的**，是人为加的一个"哨兵"。

**为什么要有头结点**（这是本章第一个必背问答）：

1. **统一空表与非空表的处理**：带头结点时，空表是 `L->next == NULL`，非空表是 `L->next != NULL`，`L` 本身永远不是 `NULL`；不带头结点时，空表是 `L == NULL`，任何操作都要额外判一次"是不是空表/是不是在操作第一个结点"。
2. **统一第一个位置与其他位置的插入删除**：不带头结点时，在表头插入/删除首元结点要修改头指针 `L` 本身，参数得传 `&L`（二级指针或引用）；带头结点时，首元结点也有前驱（头结点），操作逻辑与中间结点完全一致，函数签名统一成 `LinkList L` 即可。
3. **方便统一处理**：很多算法（如删除值为 `x` 的结点）用头结点可以让"要删的是第一个结点"这种特殊情况消失。

**头指针 vs 头结点的核心区别**（详见第三章对比表）：头指针是**指针变量**，头结点是**实实在在的一个结点**；即使不带头结点，头指针也在。

**带头结点初始化**：

```c
bool InitList(LinkList *L) {
    *L = (LNode *)malloc(sizeof(LNode));  // 分配头结点
    if (*L == NULL) return false;          // 内存分配失败
    (*L)->next = NULL;                     // 空表标志
    return true;
}
```

**不带头结点初始化**：

```c
bool InitList2(LinkList *L) {
    *L = NULL;   // 空表：头指针为空
    return true;
}
```

**"`L` 与 `L->next`"的读法**：`L` 是头指针，指着头结点；`L->next` 是首元结点的地址；`L->next->data` 是第一个元素。判空看 `L->next == NULL`（带头结点）或 `L == NULL`（不带头结点）。写代码时把这三层读清楚，能避免大半的指针错误。

**408 怎么考 / 常见坑**：

- 题目若明说"带头结点的单链表"，你的代码里就必须用 `L->next`；没说时，自适应写法是"先判断是否需要处理首元结点"。
- "头结点的数据域一定为空"——严格说不一定，只是**不使用**它。选择题若说"头结点的 `data` 域必须为空"，一般算错。
- `void InitList(LinkList L)` 这种**按值传指针**的写法是错的：要修改 `L` 本身必须传 `LinkList *L` 或 `LinkList &L`。

### 2.7 单链表的查找、插入与删除

**按位查找（取第 `i` 个结点）**：只能从头挨个走，`O(n)`。

```c
LNode *GetElem(LinkList L, int i) {   // 返回第 i 个结点；带头结点
    if (i < 0) return NULL;
    LNode *p = L;                      // p 指向头结点，即"第 0 个"
    int j = 0;
    while (p != NULL && j < i) { p = p->next; j++; }
    return p;                          // i 越界时 p 为 NULL
}
```

**按值查找**：同样是 `O(n)`。

```c
LNode *LocateElem(LinkList L, ElemType e) {
    LNode *p = L->next;
    while (p != NULL && p->data != e) p = p->next;
    return p;   // 找到返回结点指针，否则 NULL
}
```

**关键对比**：顺序表按位查找 `O(1)`、链表 `O(n)`；但**按值查找两者都是 `O(n)`**——顺序表也要一个一个比。这是选择题的常客。

**插入**：在第 `i` 个位置插入 `e`，核心是**先找到第 `i-1` 个结点**（前驱），然后"新结点接管前驱的 `next`，前驱指向新结点"。

```c
// 在后插：在 p 之后插入 s（这是链表插入的基本功，一定要背）
bool InsertNextNode(LNode *p, ElemType e) {
    if (p == NULL) return false;
    LNode *s = (LNode *)malloc(sizeof(LNode));
    if (s == NULL) return false;   // 分配失败
    s->data = e;
    s->next = p->next;   // ① 新结点先接住后继
    p->next = s;         // ② 再让前驱指向新结点
    return true;
}
```

**指针修改顺序为什么不能反**：如果先写 `p->next = s`，那么 `p` 原来的后继地址就**丢了**（没人再指向它），链表从 `s` 处断裂，后面的结点全部失联——这就是"指针丢失"。所以铁律是：**先让新结点接管后面，再让前驱接管新结点**。双链表同理，先把新结点两边都接好，再改邻居。

**前插**：在 `p` 之前插入。单链表拿不到 `p` 的前驱，正规做法是从头找 `p` 的前驱，`O(n)`。**王道书里有一个巧办法**：在 `p` 之后插入一个新结点 `s`，把 `p->data` 与 `s->data` 交换——逻辑上等于在 `p` 前插了一个 `e`，时间 `O(1)`。要能看懂这个"偷梁换柱"。

**按位插入完整函数**：

```c
bool ListInsert(LinkList L, int i, ElemType e) {   // 带头结点
    if (i < 1) return false;
    LNode *p = L;              // 从头结点出发
    int j = 0;
    while (p != NULL && j < i - 1) { p = p->next; j++; }  // 找第 i-1 个
    if (p == NULL) return false;                            // i 越界
    return InsertNextNode(p, e);
}
```

**删除**：删除第 `i` 个结点，同样要**先找到第 `i-1` 个结点**，让它跨过第 `i` 个，再 `free`。

```c
bool ListDelete(LinkList L, int i, ElemType *e) {
    if (i < 1) return false;
    LNode *p = L;
    int j = 0;
    while (p != NULL && j < i - 1) { p = p->next; j++; }
    if (p == NULL || p->next == NULL) return false;   // 前驱不存在或第 i 个不存在
    LNode *q = p->next;      // q 是被删结点
    *e = q->data;
    p->next = q->next;       // 跨过 q
    free(q);                 // 释放
    return true;
}
```

**删除结点 `p` 本身（只知道 `p`，不知道前驱）**：王道书的正规解是从头找前驱，`O(n)`。如果题目允许"逻辑删除"，可以 `p->data = p->next->data; q = p->next; p->next = q->next; free(q);`，时间 `O(1)`——**但这个方法不能删最后一个结点**（`p->next` 为 `NULL` 会崩）。这个边界是选择题最爱设的陷阱。

**408 怎么考 / 常见坑**：

- 插入删除的循环条件 `p != NULL && j < i - 1` 两个条件缺一不可，少了 `p != NULL` 就越界访问。
- 删除后要 `free`，否则内存泄漏；但 `free` 之前必须先把 `p->next` 改好。
- 时间复杂度的说法："单链表插入删除是 `O(1)`"**只有在已经拿到前驱指针时成立**；只知道位序 `i` 时整体是 `O(n)`。选择题喜欢拿这个做文章。

### 2.8 单链表的建立：头插法与尾插法

**头插法**：每次把新结点插到头结点之后。**读入顺序与链表中顺序相反**。

```c
LinkList List_HeadInsert(LinkList *L) {   // 逆序建表
    *L = (LinkList)malloc(sizeof(LNode));
    (*L)->next = NULL;                     // 先建头结点，且必须先置 NULL
    ElemType x;
    scanf("%d", &x);
    while (x != 9999) {                    // 9999 为结束标志
        LNode *s = (LNode *)malloc(sizeof(LNode));
        s->data = x;
        s->next = (*L)->next;   // 新结点接到头结点后面
        (*L)->next = s;         // 头结点指向新结点
        scanf("%d", &x);
    }
    return *L;
}
```

**尾插法**：维护一个尾指针 `r`，每次把新结点接到 `r` 后面，再让 `r` 后移。**顺序与读入顺序一致**。

```c
LinkList List_TailInsert(LinkList *L) {   // 顺序建表
    *L = (LinkList)malloc(sizeof(LNode));
    LNode *r = *L;            // r 始终指向表尾
    ElemType x;
    scanf("%d", &x);
    while (x != 9999) {
        LNode *s = (LNode *)malloc(sizeof(LNode));
        s->data = x;
        r->next = s;          // 接到尾部
        r = s;                // 尾指针后移
        scanf("%d", &x);
    }
    r->next = NULL;           // 收尾！最容易漏的一步
    return *L;
}
```

**两者差别的来历**：头插法每次都在"最前面"插入，后进来的排在前面，所以逆序；尾插法每次都在"最后面"追加，所以保持原序。

**408 怎么考 / 常见坑**：

- **头插法必须先把头结点的 `next` 置 `NULL`**，否则最后走到别人（野指针/垃圾数据）的链表上去了。
- **尾插法必须最后 `r->next = NULL`**，否则表尾不是 `NULL`，遍历时越界。
- 头插法还有个"隐藏用途"：它天然是**就地逆置**的实现方式（见 2.12）。
- 若题目要"逆序输出"而没说改链表，用递归或栈也可以，不要看到"逆序"就条件反射改指针。

### 2.9 双链表

**结点结构**：

```c
typedef struct DNode {
    ElemType data;
    struct DNode *prior, *next;   // 前驱 + 后继
} DNode, *DLinkList;
```

**为什么要有双链表**：单链表找前驱要 `O(n)`，双链表牺牲一个指针的空间换来"找前驱 `O(1)`"，从而"给定结点 `p` 就能 `O(1)` 删掉它"，并且能双向遍历。

**插入：在 `p` 之后插入 `s` —— 四步，顺序有讲究**

```c
bool DInsertNextNode(DNode *p, DNode *s) {
    if (p == NULL || s == NULL) return false;
    s->next = p->next;          // ① 新结点先接管后继
    if (p->next != NULL)
        p->next->prior = s;     // ② 后继回头指新结点（若后继存在）
    s->prior = p;               // ③ 新结点前驱指 p
    p->next = s;                // ④ 最后才让 p 指新结点
    return true;
}
```

**为什么必须最后改 `p->next`**：`p->next` 是后面几步要用的"老后继"地址，一旦先改掉，`p->next->prior = s` 就会把 `s` 的 `prior` 指错（或对 `NULL` 解引用）。记忆口诀：**新结点先把两边接好，再改老邻居**。此外 `p` 若是表尾结点，`p->next` 为 `NULL`，② 步必须判空，否则直接崩。

**删除：删 `p` 的后继结点 `q` —— 两步**

```c
bool DDeleteNextNode(DNode *p) {
    if (p == NULL || p->next == NULL) return false;
    DNode *q = p->next;
    p->next = q->next;              // ① 跨过 q
    if (q->next != NULL)
        q->next->prior = p;         // ② 后继回头（同样要判空）
    free(q);
    return true;
}
```

**删除 `p` 自身**（双链表可以 `O(1)` 做到，这是它相对单链表的优势）：

```c
p->prior->next = p->next;
if (p->next != NULL) p->next->prior = p->prior;
free(p);
```

**408 怎么考 / 常见坑**：

- 考"下面哪段代码是正确的插入/删除"，就是考指针顺序和**判空**，看 ①②③④ 有没有把 `NULL` 解引用。
- 判断题："双链表删除结点一定需要修改 4 个指针"——视情况，删 `p` 自身是 2 个；插到 `p` 后面是 4 个（含判空分支）。
- 双链表插入后要保证"双向一致"：`p->next->prior == p` 与 `s->prior->next == s` 这类不变式可以自查。

### 2.10 循环链表

**循环单链表**：尾结点的 `next` 不指向 `NULL`，而是**指回头结点**（带头结点）或首元结点（不带头结点），整个链成为一个环。

**判空条件**（与普通单链表不同，这是必考）：

| 链表形态 | 判空条件 |
| --- | --- |
| 带头结点的循环单链表 | `L->next == L`（头结点指向自己） |
| 不带头结点的循环单链表 | `L == NULL` |
| 带头结点的循环双链表 | `L->next == L`（此时 `L->prior == L` 也成立） |

**判尾条件**：从某个结点 `p` 出发，`p->next == L`（或 `p->next == 头结点`）就说明 `p` 是尾结点。

**循环链表的好处**：从**任意一个结点**出发都能遍历整条链，不需要回到头指针。因此实际中常**只设尾指针**而不设头指针——有了尾指针 `r`，`r->next` 就是首元结点（或头结点），插入表头和表尾都 `O(1)`。

**循环双链表**：`L->prior` 指向尾结点，尾结点的 `next` 指向头结点。它的插入删除写法与普通双链表几乎一样，**唯一区别是判空/判尾的边界条件**，以及要额外维护"头结点的 `prior` 指向表尾"这一条不变式（考点常见于"在表尾插入结点时要更新 `L->prior`"）。

**408 怎么考 / 常见坑**：

- 循环链表遍历时**不能用 `p != NULL` 作为结束条件**，否则死循环；要用 `p != L` 或 `p->next != L`。
- 选择题常问"带头结点循环单链表判空"，答 `L->next == L`；顺手把"普通带头结点单链表判空是 `L->next == NULL`"一起记住，成对记忆不会串。
- 循环链表中"找前驱"：单链表仍然 `O(n)`，双链表 `O(1)`。

### 2.11 静态链表

**定义**：用**数组**来描述链式结构。数组的每个分量是一个结点，结点里有 `data` 和 `next`，这里的 `next` 存的是**下一个结点在数组中的下标**，叫**游标（cursor）**。

```c
#define MaxSize 10
typedef struct {
    ElemType data;
    int next;      // 游标：下一个结点的数组下标，不是指针
} SLinkList[MaxSize];
```

**为什么要有它**：早期高级语言没有指针类型，用数组下标来"模拟指针"；而且静态链表不需要 `malloc`，适合在不支持动态内存的场合（也常出现在"既要链式存储又不能动态分配"的题设里）。

**约定**（王道书约定，不同教材可能不同，题目会说明）：

- 下标 `0` 的分量充当**头结点**；
- `next == -1` 表示**链表结束**（相当于 `NULL`）；
- 初始化时 `next` 也置 `-1` 表示该位置"空闲/未使用"。

**基本操作就是"用下标走链表"**：

```c
// 按位查找：返回第 i 个结点的数组下标（0 号充当头结点）
int GetElem(SLinkList L, int i) {
    if (i < 0) return -1;
    int p = 0;             // 从头结点（下标 0）出发
    int j = 0;
    while (p != -1 && j < i) { p = L[p].next; j++; }
    return p;              // 越界时返回 -1
}
```

**408 怎么考 / 常见坑**：

- **游标是数组下标，不是地址**，所以 `-1` 表示结束，而**不是** `NULL`；也**不能**用 `p != NULL` 判断。
- 静态链表的插入删除**不需要移动元素**，只需要改游标，这点和动态链表一致；但它的容量固定，是"静态"的。
- 常有题问"静态链表与顺序表的区别"：元素在数组里的物理次序与逻辑次序**不一定一致**，所以它不属于顺序存储。
- 想插一个结点要先"申请"一个空闲分量（找 `next == -1` 的位置），这一步是它比动态链表麻烦的地方。

### 2.12 线性表的应用：常见算法思路（大题题库）

这一节是本章的"大题弹药库"，把每个思路的**出发点**想通，比背代码更抗变形。

**（1）两个有序表合并（归并思想）**

- 思路：两个指针 `p`、`q` 分别指向两个有序表的第一个元素，每次比较 `p->data` 与 `q->data`，**把小的那个摘下来接到结果表尾**，然后该指针后移。一个表走完后，把另一个表剩下的整段接上。
- 为什么是 `O(n + m)`：每个元素恰好被访问一次，没有嵌套循环。
- 顺序表版本（王道高频）：在**原数组 A 的尾部**从后往前填，避免额外的辅助数组（前提是 A 的容量够）。
- **坑**：结果表的尾结点 `next` 必须置 `NULL`；用"摘结点"还是"复制结点"要看清题目要求（要求"利用原表空间"就不能 `malloc` 新结点）。

**（2）就地逆置（头插法重建）**

- 思路：把原链表**拆成"已处理部分 + 待处理部分"**，每次从待处理部分摘下第一个结点 `p`，用头插法插到已处理部分的表头。循环结束后，已处理部分就是原链表的逆序。
- 为什么是 `O(n)` / `O(1)`：每个结点走一趟，只用几个指针变量，不需要额外数组。
- 考试变体："就地"两个字是关键词——**不允许新建结点、不允许用数组**，否则空间复杂度不是 `O(1)`，扣分。
- 顺序表逆置更简单：前后双指针 `i`、`j` 相向而行交换，`O(n)` / `O(1)`。

**（3）删除所有值为 `x` 的结点**

- 单链表标准解：`while (p->next)` 检查 `p->next->data == x`，命中就摘下 `free`，否则 `p` 后移。**必须用"检查后继"的循环形式**，因为在单链表里删结点需要它的前驱。
- 顺序表标准解：用一个"写入指针" `k`，扫一遍数组，**不是 `x` 的就写回 `L->data[k++]`**，最后 `length = k`。这就是"双指针原地删除"，`O(n)` / `O(1)`。
- **坑**：如果题目要求"删除有序表中值在 `[s, t]` 区间的元素"，顺序表版本可以只用一个 `k` 记录要覆盖的位置；链表版本要注意"区间可能在表头"，用头结点能免去特判。

**（4）找倒数第 `k` 个结点（快慢指针）**

- 思路：`p` 先走 `k` 步，`q` 从头开始；然后 `p`、`q` 同步后移，`p` 走到 `NULL` 时 `q` 正好在倒数第 `k` 个。
- 为什么成立：两者相距恒为 `k`，`p` 到表尾时 `q` 距表尾就是 `k`。
- 为什么是 `O(n)`：只要一趟，`p` 走 `n` 步，不是两趟（两趟也能做，但要写清"第一趟求表长"）。
- **坑**：**必须先判 `k` 是否大于表长**。`p` 走 `k` 步时如果提前变 `NULL`，说明表长不足 `k`，直接返回失败，否则后面 `p->next` 会崩。

**（5）找中间结点（快慢指针）**

- 思路：`slow` 每次走 1 步，`fast` 每次走 2 步。`fast` 到表尾时 `slow` 在中点。
- 长度奇偶的处理：`fast` 走到表尾（`fast->next == NULL`）时 `slow` 是正中间；偶数个结点时，循环条件写成 `fast != NULL && fast->next != NULL`，`slow` 停在**前半个**的最后一个。
- **坑**：偶数长度下"中间"有两种定义，答案可能都算对，但**循环条件要与你的答案自洽**，写清楚。

**（6）判断回文（链表）**

- 思路（王道高频）：先用快慢指针找中间结点 → 把**后半部分就地逆置** → 前后两半同时从头比较 → 比较完再**把后半部分逆置回去**（题目要求"时间复杂度 `O(n)`、空间复杂度 `O(1)`"时，逆置回去是好习惯，避免破坏原表）。
- 为什么不能用栈：用栈要 `O(n)` 空间，题目通常明确限制 `O(1)`。
- 顺序表判回文：双指针相向比较，`O(n)` / `O(1)`，最省事。

**（7）链表拆分 / 去重**

- 拆分成两个表（如"按位序奇偶拆"）：设两个结果表的尾指针 `r1`、`r2`，遍历原表，把结点交替接过去，**最后两个尾结点都要置 `NULL`**。
- 有序表去重：一次遍历，比较当前结点与后继结点，值相等就删后继；**保留第一个出现的**（题目一般这么要求，写清楚"保留第一个"）。

**（8）判断链表是否有环（Floyd 判圈 / 快慢指针）**

- 思路：`slow` 每步 1 个结点，`fast` 每步 2 个结点。若链表无环，`fast` 会先到 `NULL`；若有环，`fast` 会追上 `slow`，二者相遇。
- 为什么相遇即说明有环：有环时 `fast` 每轮比 `slow` 多走一步，在环内必然追上（相当于在环上以相对速度 1 逼近）。
- **坑**：题目如果问"求入环点"，还要第二步：相遇后让一个指针回头结点，两个指针每次各走 1 步，再次相遇处就是入环点。只问"是否有环"就别多做。
- 还想拿分就说清"未破坏原链表结构"。

## 三、易混对比表

### 表 1 顺序表 vs 链表（本章最重要的对比）

| 对比项 | 顺序表 | 链表 |
| --- | --- | --- |
| 存储方式 | 地址连续的存储单元，逻辑相邻即物理相邻 | 任意存储单元，靠指针/游标表达逻辑关系 |
| 存取方式 | **随机存取**：按位查找 `O(1)` | **顺序存取**：按位查找 `O(n)` |
| 按值查找 | `O(n)`（逐个比较） | `O(n)` |
| 插入删除 | 平均移动 `n/2` 或 `(n-1)/2` 个元素，`O(n)` | 改指针 `O(1)`；但定位前驱要 `O(n)` |
| 容量 | 静态固定；动态分配需整体扩容搬迁 | 动态按需 `malloc`，容量不设上限 |
| 存储密度 | `1`（无额外开销） | `< 1`（每个结点多一个指针域） |
| 空间 locality | 需要一整块连续空间 | 可以用零散空间，但指针本身占空间 |
| 是否支持双向遍历 | 天然支持（下标可增可减） | 单链表不支持，双链表支持 |
| 适用场景 | 表长可预估、很少增删、频繁按位访问 | 表长变化大、频繁插入删除、不要求随机访问 |

### 表 2 头指针 vs 头结点

| 对比项 | 头指针 `L` | 头结点 |
| --- | --- | --- |
| 是什么 | 一个**指针变量** | 一个**实际的结点**（占内存、需 `malloc`） |
| 是否必要 | **必须有**，是链表的标识 | 可有可无，人为附加 |
| 指向谁 | 指向链表第一个结点（带头结点时即头结点） | 它的 `next` 指向首元结点 |
| 空表时 | 不带头结点时 `L == NULL` | 头结点仍在，`L->next == NULL` |
| 数据域 | 无数据域 | 有 `data` 域但通常不使用 |
| 作用 | 让我们能找到整条链表 | 统一空表/非空表、统一首元结点与中间结点的操作 |

### 表 3 带头结点 vs 不带头结点

| 对比项 | 带头结点 | 不带头结点 |
| --- | --- | --- |
| 空表判据 | `L->next == NULL` | `L == NULL` |
| 首元结点 | 是 `L->next` | 是 `L` |
| 表头插入 | 与中间插入逻辑一致，不用改 `L` | 要改头指针 `L`，参数须传 `LinkList *` 或引用 |
| 代码量 | 少，边界少 | 多，处处要判"是不是第一个结点" |
| 是否空表能统一处理 | 能 | 不能，空表时 `L == NULL`，不能解引用 |

### 表 4 头插法 vs 尾插法建表

| 对比项 | 头插法 | 尾插法 |
| --- | --- | --- |
| 新结点位置 | 头结点之后 | 当前表尾之后 |
| 结果顺序 | 与输入**逆序** | 与输入**同序** |
| 需要维护 | 只用头指针 | 需要一个尾指针 `r` |
| 关键易错点 | 头结点 `next` 必须先置 `NULL` | 结束前必须 `r->next = NULL` |
| 典型用途 | 就地逆置、逆序建表 | 顺序建表、保持输入次序 |

### 表 5 单链表 vs 双链表 vs 循环链表 vs 静态链表

| 对比项 | 单链表 | 双链表 | 循环链表 | 静态链表 |
| --- | --- | --- | --- | --- |
| 结点成员 | `data`, `next` | `prior`, `data`, `next` | 同单/双链表 | `data`, `next`（游标） |
| 找前驱 | `O(n)` | `O(1)` | 单链 `O(n)` / 双链 `O(1)` | `O(n)` |
| 找后继 | `O(1)` | `O(1)` | `O(1)` | `O(1)` |
| 表尾标志 | `p->next == NULL` | `p->next == NULL` | `p->next == 头结点` | `next == -1` |
| 判空（带头结点） | `L->next == NULL` | `L->next == NULL` | `L->next == L` | 头结点 `next == -1` |
| 存储空间 | 需动态分配 | 每个结点多一个指针 | 同单/双链表 | 固定数组，无需 `malloc` |
| 遍历是否有穷 | 是（遇 `NULL` 停） | 是 | 要从环上正确终止条件退出 | 是（遇 `-1` 停） |

### 表 6 顺序表与静态链表的"看起来像"陷阱

| 对比项 | 顺序表 | 静态链表 |
| --- | --- | --- |
| 底层容器 | 数组 | 数组 |
| 逻辑次序与下标次序 | **一致** | **不一定一致**，靠游标串起来 |
| 属于哪类存储 | 顺序存储 | 链式存储（用数组模拟） |
| 插入删除 | 需要移动元素 | 只需改游标，不移动元素 |
| 访问第 `i` 个元素 | `O(1)` 直接算地址 | `O(n)` 顺游标走 |

## 四、例题精练（3 道）

> 说明：以下例题为**自编题与真题风格改编题**，用于训练思路，**不宣称是某年真题**。

### 例题 1（选择题）

**题目**：在长度为 `n`（`n > 0`）的带头结点的单链表中，指针 `p` 指向表中某个结点。下列说法中**正确**的是（　　）

A. 若 `p` 是首元结点，则 `L->next == p`
B. 已知 `p` 指向某结点，一定能在 `O(1)` 时间内把 `p` 所指结点从链表中删除
C. 删除 `p` 所指结点的后继结点 `q` 时，应先执行 `free(q)`，再执行 `p->next = q->next`
D. 删除 `p` 所指结点的后继结点 `q`，当且仅当 `p->next->next != NULL` 时才可以进行

**逐项解析**：

- **A（正确）**：带头结点时，首元结点就是头结点的直接后继，所以 `L->next == p` 恒成立。这是"头结点 + 首元结点"关系的直接考查。
- **B（错）**：单链表只给 `p` 拿不到前驱。一般情形要从头找 `p` 的前驱，是 `O(n)`。"偷梁换柱"（把后继的 `data` 复制到 `p` 再删后继）虽然 `O(1)`，但**当 `p` 是表尾结点时后继为 `NULL`，无法进行**，所以"一定"两个字让它错。这是本章最经典的陷阱。
- **C（错）**：顺序反了。`free(q)` 之后 `q` 已不再有效，再用 `q->next` 就是访问已释放内存（野指针）。**必须先把 `p->next = q->next` 改好，再 `free(q)`**。
- **D（错）**：删除 `p` 的后继 `q` 只要求 `q` 存在，即 `p->next != NULL`。题目给的条件 `p->next->next != NULL` 意味着 `q` 还有后继，那只是"`q` 不是表尾"，删 `q` 本来不需要这个条件，条件写得过强。

**答案：A**

**常见坑复盘**：这题一个选项考一个知识点——A 考头结点关系，B 考"删除需要前驱 + 边界"，C 考 `free` 与改指针的先后，D 考删除的充分必要条件。四个选项都是本章反复出现的错误说法，值得抄进错题本。

### 例题 2（算法设计题）

**题目**：设有一个**带头结点**的单链表 `L`，结点结构为 `(data, next)`，`data` 为整数。请设计一个在**一趟遍历**中完成下列两件事的算法，并分析时间复杂度：

1. 输出该链表中**倒数第 `k` 个结点**的 `data` 值（若表长不足 `k` 个结点，则输出提示信息并不输出数据）；
2. 输出该链表的**中间结点**的 `data` 值（若结点个数为偶数，约定输出**前一个**中间结点）。

**要求**：用 C 语言写出完整函数；要求时间复杂度尽量低，并说明空间复杂度。

**思路**：

- 两个任务都需要"在不知道表长的前提下从表头走到特定位置"，用**快慢指针**一趟解决。
- 倒数第 `k` 个：让 `p`、`q` 初始都指向首元结点，`p` 先走 `k - 1` 步，此后 `p`、`q` 同步后移；`p` 到表尾时，`q` 与 `p` 相距 `k - 1`，正好是倒数第 `k` 个。**`p` 先走时若提前变 `NULL`，说明表长小于 `k`，直接返回 `0`。**
- 中间结点：在同一个循环里再维护一个更慢的 `s`，每两轮走一步（`s` 仅在步数计数为偶数时后移）。这样 `p` 到表尾时，`s` 恰好位于前一个中间结点。
- 关键：`q` 与 `s` 复用同一个遍历过程，只走一趟，`O(n)`；只用 3 个指针变量，`O(1)`。

**参考代码**：

```c
typedef struct LNode {
    int data;
    struct LNode *next;
} LNode, *LinkList;

/* 带头结点单链表 L，输出倒数第 k 个结点的值，以及中间结点（偶数时取前一个）的值 */
int FindKthAndMid(LinkList L, int k) {
    if (L == NULL || L->next == NULL || k < 1) return 0;   /* 空表或参数非法 */

    LNode *p = L->next;      /* p: 先行的探路指针，最终走到表尾 */
    LNode *q = L->next;      /* q: 滞后 p 共 k-1 步，指向倒数第 k 个 */
    LNode *s = L->next;      /* s: 每两步走一步，指向中间结点 */
    int cnt = 0;             /* 已走的步数，用于控制 s */

    /* p 先走 k-1 步；若不足 k 个结点则提前失败 */
    for (int i = 1; i < k; i++) {
        if (p == NULL) return 0;      /* 表长 < k */
        p = p->next;
        cnt++;
        if (cnt % 2 == 0) s = s->next; /* s 每两轮走一步（此处为对齐计数） */
    }
    if (p == NULL) return 0;          /* 表长恰为 k-1 的情形 */

    /* p、q 同步后移，s 保持每两步走一步 */
    while (p->next != NULL) {
        p = p->next;
        q = q->next;
        cnt++;
        if (cnt % 2 == 0) s = s->next;
    }

    printf("倒数第 %d 个结点的值: %d\n", k, q->data);
    printf("中间结点的值: %d\n", s->data);
    return 1;
}
```

> 说明：`s` 的步进规则与 `cnt` 的奇偶约定要与"偶数取前一个"的答案自洽。若题目约定"偶数取后一个"，把判据反过来（`cnt % 2 == 1` 时步进）即可。考场上如果对奇偶没把握，**可以退一步用两趟**：先求表长 `n`，再直接定位 `n-k+1` 与 `(n+1)/2`，仍然是 `O(n)`、`O(1)`，正确性更稳、更容易写对——但要在解答中写清"两趟遍历，总时间仍为 `O(n)`"。

**复杂度**：时间复杂度 `O(n)`（`p` 恰好走完链表一次，`q`、`s` 同步行进，没有嵌套遍历）；空间复杂度 `O(1)`（只用常数个指针变量，未额外申请结点或数组）。

**采分点**：

1. 正确写出结点结构体 / 说明指针初始化为首元结点（`L->next`）。
2. `p` 先走 `k - 1` 步，并**在过程中检查 `p == NULL`**，处理"表长不足 `k`"的分支（这是最容易丢分的一点）。
3. `p`、`q` 同步后移，循环条件用 `p->next != NULL`（保证 `p` 停在表尾结点上）。
4. 中间结点的步进规则与"偶数取前一个"的约定自洽，并在注释里说明。
5. 最后明确写出 `O(n)` / `O(1)` 并给出理由（非空口断言）。
6. 正确使用 `printf`/返回状态表示"表长不足"的情形。

**常见坑**：

- 循环写成 `while (p != NULL)` 会让 `p` 停在 `NULL` 上，此时 `q` 偏了一位，倒数第 `k` 个变成倒数第 `k+1` 个。
- 忘了判 `k` 大于表长，`p` 提前为 `NULL` 后继续 `p->next` 导致崩溃。
- 用"求表长后两趟"也行，但若题目明确要求"一趟"，写成两趟会被扣分——先看清题设。

### 例题 3（计算题）

**题目**：一个顺序表 `L` 当前有 `n = 10` 个元素，存储在数组 `data[0..9]` 中（位序 1 对应下标 0）。

（1）若在**第 4 个位置**插入一个新元素，需要移动多少个元素？
（2）若**等概率**地在各个可插入位置插入，平均需要移动多少个元素？
（3）若依次删除**前 3 个元素**（每次删除后表长减 1），总共需要移动多少个元素？
（4）若**等概率**地删除任意一个元素，平均需要移动多少个元素？

**解答**：

**（1）** 表长 `n = 10`，在第 `i = 4` 个位置插入，移动次数为

`n - i + 1 = 10 - 4 + 1 = 7`

即把原来的第 4 到第 10 个元素（共 7 个）整体后移一位，空出下标 3 的位置。

**（2）** 插入位置共有 `n + 1 = 11` 个（第 1 个位置到第 11 个位置，即表尾之后），等概率时每个概率为 `1/11`，平均移动次数为

`(1/(n+1)) × Σ(i=1..n+1)(n - i + 1) = (1/11) × (10 + 9 + ... + 1 + 0) = (1/11) × 55 = 5`

即 `平均移动次数 = n/2 = 5`。

**（3）** 第 1 次删除第 1 个元素（`i = 1`，此时 `n = 10`）：移动 `n - i = 9` 个；
第 2 次删除第 1 个元素（此时 `n = 9`）：移动 `9 - 1 = 8` 个；
第 3 次删除第 1 个元素（此时 `n = 8`）：移动 `8 - 1 = 7` 个。
合计 `9 + 8 + 7 = 24` 个。

> 注意：删除会改变表长，**每一次都要用当前的 `n` 重新算**，直接用 `3 × (10 - 1) = 27` 是典型错误。

**（4）** 删除位置共有 `n = 10` 个，等概率时每个概率为 `1/10`，平均移动次数为

`(1/n) × Σ(i=1..n)(n - i) = (1/10) × (9 + 8 + ... + 1 + 0) = (1/10) × 45 = 4.5`

即 `平均移动次数 = (n-1)/2 = 4.5`。

**采分点与提醒**：

- 三个公式要分得清：插入第 `i` 个位置移动 `n - i + 1` 个；删除第 `i` 个移动 `n - i` 个；平均分别是 `n/2` 和 `(n-1)/2`。
- 出现"依次删除/依次插入"的多步计算时，**每一步都要更新表长 `n`**。
- 时间复杂度的追问：以上操作都是 `O(n)`；只有"按位取值 `GetElem`"是 `O(1)`。

## 六、简便方法与易错口诀（速算 · 防错）

> 本节把本章能"省时间"和"防掉坑"的招集中在一处：二轮复习与考前只看这一节。每条都写清**适用条件**。

### 6.1 速算招式

| 场景 | 常规做法（慢/繁） | 简便做法（快/稳） | 为什么成立 / 适用条件 |
| --- | --- | --- | --- |
| 顺序表插入/删除的平均移动次数 | 现场推 `(1/(n+1)) × Σ(n-i+1)` 等求和式 | 直接报 `n/2`（插入）、`(n-1)/2`（删除）；估不动就用"平均移动一半元素"兜底 | 求和为等差级数，平均值就是最大位移的一半。**条件是"等概率"且各位置可插/可删**；选择题里若概率不均匀，必须回到定义式重算 |
| 按位插入/删除的移动个数（单个位置） | 记不清就用 `n` 估 | 插入第 `i` 位移动 `n-i+1` 个（含表尾之后的位置 `i=n+1`，移动 0 个）；删除第 `i` 位移动 `n-i` 个 | 插入要给新元素腾位，第 `i` 到第 `n` 个整体后移；删除要填坑，第 `i+1` 到第 `n` 个整体前移。注意插入位置有 `n+1` 种选择、删除只有 `n` 种 |
| 单链表按位插入防断链 | 背代码时把两句抄反、考场现推 | **先接后断**：先写 `s->next = p->next;`（新结点接管原后继），再写 `p->next = s;` | 顺序反了会先丢掉原后继的地址，链断成两截。**只要在 `p` 之后插结点就适用**（头插、尾插、中间插都是这两句的相对顺序） |
| 双链表插入/删除的指针条数 | 逐个回忆每步、漏 `prior` | 在 `p` 之后插 `s` 固定改 **4 个指针**（`s` 的 2 个 + `p` 和原后继各 1 个）；删 `p` 的后继 `q` 固定改 **2 个指针** + 1 次 `free` | 双链表每个结点有两个链路，接上/断开都要两侧都改到才算完整。**前提是后继结点存在**；若插在表尾、或删除的"后继"恰好是表尾，涉及 `NULL` 的那一句要加判空 |
| 快慢指针三件套 | 先求表长 `n`，再第二趟走到 `(n+1)/2` 或 `n-k+1`（两趟） | ①找中间：快 2 慢 1；②找倒数第 `k` 个：快指针先走 `k` 步，再与慢指针同步走，快指针到 `NULL` 时慢指针即答案；③判环：相遇即有环 | 三招都要 `O(n)` 时间、`O(1)` 空间，但**前提都是单链表且有头指针/头结点可用**。②的先行步数要与"快指针停在 `NULL` 还是停在表尾"配套：走 `k` 步配 `while (p != NULL)`，走 `k-1` 步配 `while (p->next != NULL)`，两套混用会差一位。③若还要问入环点，再补一步：相遇后一指针回头结点，两指针每次各走 1 步，再相遇处即入环点 |
| 链表逆置 | 开一个数组存下所有 `data` 再倒着填回 | 头插法重建：拆成"已处理 + 待处理"，每次摘下待处理的第一个结点插到已处理部分表头 | 每个结点只处理一次，`O(n)` 时间、`O(1)` 额外空间。**适用前提**：允许改 `next` 指针（"就地"题的标准解）；用数组倒填是 `O(n)` 额外空间，题目限制 `O(1)` 时会判错。注意开始前把头结点的 `next` 置 `NULL` |
| 顺序表还是链表：一句话判据 | 逐项比较表格、犹豫 | ①频繁**按下标访问**（随机存取）→ 顺序表；②频繁**插入删除且位置未知/需重新定位** → 链表；③题目给了"**有序**"又要**折半查找** → 必须是顺序表 | 折半查找要求 `O(1)` 随机存取，链表做不到，所以"有序链表"不能折半（只能顺序查找）。**例外**：插入删除虽然链表是 `O(1)` 改指针，但"定位"要 `O(n)`，若题目已经给了目标结点的前驱指针，链表的优势才真正体现；顺序表的按值查找也是 `O(n)`，和链表一样，别答成 `O(1)` |
| 写代码时先写"带头结点" | 每个函数都特判"是不是第一个位置""表是不是空" | 一律用带头结点的写法：插入删除不用特判第一个位置、空表与非空表操作统一 | 头结点是个"假结点"，`L->next` 才是首元结点，于是"在表头插/删"退化成"在某个结点后插/删"。适用条件是题目**没禁止**带头结点（多数教材题默认允许）；若题目明确给了不带头结点的定义，按题目来，别自行加结点 |
| 两个有序链表合并（归并） | 用 `if/else` 分"结果表为空/不为空"两套逻辑 | 结果表也带头结点，用尾指针 `r` 统一写 `r->next = p; r = p;`，最后接上没走完的那条链 | 头结点把"第一个结点"这个特例吃掉了，循环体内只剩"比大小 + 挂结点"一件事。**前提**：两条链都有序；收尾时 `r->next` 指向剩余链即可，不需要再遍历；若是要求"利用原表空间"，就不能 `malloc` 新结点 |
| 有序链表去重 | 每删一个就回头重扫，或另开哈希表 | 一次遍历：保留第一个出现的，`p` 与 `p->next` 值相等就删 `p->next`，否则 `p` 后移 | 有序保证等值元素**连续排列**，所以一次遍历足够，`O(n)` / `O(1)`。用哈希表虽然也是 `O(n)`，但空间变 `O(n)`，遇到限空间题目要扣分。**前提**是"有序"；无序表去重无法用这一招做到 `O(n)` 且 `O(1)` |
| 循环链表的遍历终止 | 沿用 `p->next != NULL` 的判断，结果死循环 | 判"是否绕回起点"：带头结点的循环单链表用 `p->next == L`（或 `p == L`）终止；循环双链表同理 | 循环链表里根本不存在 `NULL` 后继，任何 `NULL` 判据都会失效。**适用条件**：只有在循环链表上才需要换终止条件；判空也随之改变（带头结点时 `L->next == L`） |
| 静态链表的插入删除 | 以为要像顺序表那样搬元素 | 只改游标数组里的 `next`（下标），不移动任何 `data`；表尾标志是游标 `-1` | 静态链表用数组模拟链式存储，逻辑次序靠游标串、与下标次序无关。**前提**：`data` 与 `next` 分数组存放、`next = -1` 表示结束；它属于**链式**存储，不是顺序存储 |

### 6.2 口诀与记忆钩子

- **口诀**：**"插一半、删略少"** —— 顺序表等概率插入平均移动 `n/2` 个元素，等概率删除平均移动 `(n-1)/2` 个元素；想不起公式就记"平均要挪动一半元素"，删除的被删位不用挪，所以略少于一半。
- **口诀**：**"先接后断，断前留后"** —— 插入结点永远先让新结点的指针接管后继（`s->next = p->next`），再改前驱指向新结点（`p->next = s`）；顺序反了就丢链。
- **口诀**：**"双链四针，先二后二"**：双链表在 `p` 后插 `s` 要动 4 个指针，先把 `s` 的两个指针都接好（`s->next`、`s->prior`），再去改前面和后面那两句；删除则固定"改 2 个指针 + `free`"。
- **口诀**：**"快二慢一找中点，快先走 k 找倒数，遇上了就是环"** —— 判环再补一句"**回头再走找入口**"（相遇后一指针回头结点，两指针同步走，再遇即入环点）。
- **口诀**：**"头插逆序、尾插保序"** —— 想逆置就头插重建；要保持输入次序就尾插。配套提醒："**头插先置空，尾插收尾置空**"（头插前 `L->next = NULL`；尾插结束 `r->next = NULL`）。
- **口诀**：**"带头结点，少判一半"** —— 带头结点统一了"空表/非空表"和"表头/表中"两类特例，代码题先用这个写法，边界判断能省掉一半。

### 6.3 反例黑名单（这些"简便法"是错的）

- ❌ **"单链表删除一个结点都是 `O(1)`"** ：正确做法是分清前提——删除**已知前驱**的结点、或删除 `p` 的**后继**结点是 `O(1)`；只给一个指向待删结点自己的指针 `p`，删除它本身需要先找前驱，是 `O(n)`（"偷梁换柱"虽然 `O(1)`，但当 `p` 是表尾结点时后继为 `NULL`，不成立）。
- ❌ **"双链表插入的 4 句指针赋值顺序随便写"** ：正确做法是**先把新结点 `s` 的两个指针接好，再改前驱和后继**——例如先写 `p->next = s`，此时原后继的地址只存在 `s->next` 里，若还没写 `s->next` 就永久丢失。
- ❌ **"顺序表按值查找是 `O(1)`，因为有随机存取"** ：正确做法是区分两件事——**按位查找（给下标）** 才是 `O(1)`，**按值查找（给 `data` 值）** 要逐个比较，是 `O(n)`，与链表相同。
- ❌ **"有序链表也能折半查找，因为有序"** ：正确做法是记住折半查找的前置条件有两个——**顺序存储 + 有序**。链表是顺序存取，取中间元素就要 `O(n)`，所以在链表上折半查找并不划算（退化成 `O(n log n)` 级），只能顺序查找。
- ❌ **"快慢指针找倒数第 `k` 个：快指针走 `k` 步或走 `k-1` 步都行"** ：正确做法是**两套写法各自配套**，走 `k` 步配 `while (p != NULL)` 结束（`q` 指向倒数第 `k` 个），走 `k-1` 步配 `while (p->next != NULL)`（`q` 也指向倒数第 `k` 个）；混用会整体偏一位，而且**都必须先判 `k` 是否超过表长**。
- ❌ **"用栈做链表逆置/判回文更简便"** ：正确做法是在题目限制空间时**不用栈**（栈要 `O(n)` 额外空间）；判回文用"找中点 → 逆置后半 → 比较 → 逆置恢复"，逆置用头插法，两者都是 `O(n)` 时间、`O(1)` 空间。
- ❌ **"顺序表一次性删除多个元素，可以用 `3 × 最大移动数` 估算"** ：正确做法是**每删一个都要用当前的 `n` 重算**（如 `n=10` 依次删前 3 个：`9 + 8 + 7 = 24`，不是 `3 × 9 = 27`）。
- ❌ **"静态链表属于顺序存储，因为底层是数组"** ：正确做法是看**逻辑关系的表达方式**——静态链表用游标表达逻辑相邻，不要求物理相邻，属于**链式存储**（数组只是它的容器），因此按位访问是 `O(n)` 而不是 `O(1)`。
