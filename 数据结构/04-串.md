## 二、概念详解

### 4.1 串的基本概念与存储结构

#### 4.1.1 什么是串

**定义**：串（字符串）是由**零个或多个字符**组成的**有限序列**，一般记为 `S = 'a1a2...an'`（n ≥ 0）。

- `S` 是**串名**，引号里的字符序列是**串值**，`n` 是**串长**。
- 强调"零个"，是为了允许**空串**存在；强调"有限"，是因为串长必须有穷。
- 串的逻辑结构是**线性表**的特例：数据元素被限定成单个字符。所以串的顺序存储对应顺序表，链式存储对应链表，概念可以整段平移。

**空串与空格串**（选择题常客）：

| 名称 | 写法 | 串长 | 含义 |
| --- | --- | --- | --- |
| 空串 | `S = ''`（或 ∅） | 0 | 一个字符都没有 |
| 空格串 | `S = '   '`（3 个空格） | 3 | 有 3 个字符，都是空格字符 |

结论：**空串 ≠ 空格串**。空串是任意串的子串（含空格串）；空格串不是空串。

**子串与主串**：串中**任意个连续字符**组成的子序列称为该串的**子串**，包含子串的串叫**主串**。注意"连续"二字——`'ac'` 不是 `'abc'` 的子串，`'ab'`、`'bc'`、`'abc'` 才是。

- 长度为 n 的串，**非空子串**个数为 `n(n+1)/2`，**非空真子串**个数为 `n(n+1)/2 − 1`。
- 若把空串也算进子串，总数为 `n(n+1)/2 + 1`。**看清题目问的是"子串"还是"非空子串"。**
- 串的**位置**从 1 开始编号（王道约定）：`'b'` 在 `'abc'` 中的位置是 2。

**串的比较**：从第一个字符开始逐位比较**字符的编码值**（`ASCII` / `Unicode`），谁先出现更小的编码谁就小；若前 `min(len1, len2)` 位全同，则**短的串小**。

- 规则一：逐位比编码，先分出大小者定胜负。
- 规则二：前面全相同，则长度小者小。
- 推论：**空串小于任何非空串**；任何串等于它自身。

例：`'ab' < 'aba'`（前两位相同，短的更小）；`'Z' < 'a'`（`ASCII` 中 `'Z'` = 90、`'a'` = 97，**大写字母整体小于小写字母**，容易记反）。

> **408 怎么考 / 常见坑**：① 把空格串当空串——错；② 子串个数忘掉"连续"这个限制，或漏算/多算空串；③ 串比较误以为"先比长度"——**错，先逐位比编码**，长度只在前面全同时才起作用；④ 把 `'Z' < 'a'` 记反。这四点基本覆盖本小节的所有选择题。

#### 4.1.2 串的基本操作

与线性表最大的不同：串的操作**以"子串"为单位**，而不是以"单个元素"为单位。

| 操作 | 原型（王道写法） | 含义 | 与线性表对照 |
| --- | --- | --- | --- |
| 赋值 | `StrAssign(&T, chars)` | 把串 `T` 赋值为 `chars` | 类似 `ListAssign` |
| 复制 | `StrCopy(&T, S)` | 由 `S` 复制得 `T` | 类似 `ListCopy` |
| 判空 | `StrEmpty(S)` | 空串返回真 | `ListEmpty` |
| 求长 | `StrLength(S)` | 返回串长 | `ListLength` |
| 比较 | `StrCompare(S, T)` | 按比较规则返回 <0 / =0 / >0 | 串特有（逐位比编码） |
| 连接 | `Concat(&T, S1, S2)` | `T = S1 + S2` | 串特有 |
| 求子串 | `SubString(&Sub, S, pos, len)` | 取 `S` 第 `pos` 位起长 `len` 的子串 | 串特有（截连续一段） |
| 定位 | `Index(S, T, pos)` | 从 `S` 第 `pos` 位起找 `T` 首次出现的位置 | **模式匹配本体** |
| 清空 / 销毁 | `ClearString` / `DestroyString` | 清空只改长度，销毁连存储空间一起释放 | 同线性表 |

两个爱考的细节：

1. `Concat` 的结果若超出定长数组容量，需要**截断**（见 §4.1.3）——这是"定长"存储方式带来的限制，不是操作本身的问题。
2. `Index(S, T, pos)` 就是**模式匹配**，也是本章后两节的算法本体：`S` 是主串，`T` 是模式串。

> **408 怎么考 / 常见坑**：基本操作本身很少直接考，但 `Index` 的"从 `pos` 位开始"容易被忽略；王道默认返回的是 **`T` 在主串中的绝对起始位置**。

#### 4.1.3 串的三种存储结构

**（1）定长顺序存储**：定长数组 + 长度域。

```c
#define MAXLEN 255
typedef struct {
    char ch[MAXLEN];   // 下标 0 空出不用，有效字符在 ch[1..length]
    int  length;       // 串长
} SString;
```

- 优点：取第 `i` 个字符 `O(1)`，实现简单。
- 缺点：**长度固定**。连接、求子串时若超出 `MAXLEN` 会被**截断**——只保留放得下的部分，其余丢弃，**不报错**。这种"静默失败"是最阴的坑。
- 王道书上默认讨论的"串"就是这种结构。

**（2）堆分配存储**：容量在程序运行时用 `malloc` 动态申请，用完 `free`。

```c
typedef struct {
    char *ch;    // 指向动态申请的字符数组，按串长分配
    int   length;
} HString;
```

- 优点：**不会截断**，串长可在运行时确定（这是相对定长顺序存储的本质改进）。
- 缺点：需手动管理内存；插入/删除仍可能像顺序表一样移动元素。
- 直觉：定长是"自带水杯"，装不下就洒；堆分配是"按需买杯子"。

**（3）块链存储**：用链表存串，每个结点存放一个或多个字符。

- 每个结点的数据域放 `k` 个字符；最后一个结点不满时通常用 `'#'` 之类的特殊字符补全（或额外记录长度）。
- **结点大小直接决定两个指标**：
  - **存储密度** = 数据元素本身占的存储量 ÷ 结点结构占的总存储量。结点越大，指针开销占比越小，存储密度越高，但插入/删除要在结点内部搬字符，**操作更麻烦**；结点越小（极端情况 1 个字符 1 个结点），插入删除灵活，但指针多、**存储密度低**。
  - 结论：块链存储的**存储密度小于 1，且结点越小密度越低**；它本身没有突出优势，属于"了解即可"。

| 存储方式 | 空间分配 | 会不会截断 | 随机存取 | 408 定位 |
| --- | --- | --- | --- | --- |
| 定长顺序存储 | 编译期固定 | **会** | 可以，`O(1)` | 默认模型；考"截断" |
| 堆分配存储 | 运行期 `malloc` | 不会 | 可以，`O(1)` | 考"动态、不截断" |
| 块链存储 | 运行期按结点申请 | 不会 | 需从头遍历 | 考"存储密度与结点大小" |

> **408 怎么考 / 常见坑**：① 记牢"**定长顺序存储会截断**"，问"哪种存储方式可能丢失字符"就选它；② 堆分配的关键词是 `malloc` 动态、不截断；③ 块链存储只考**存储密度**与**结点大小对操作的影响**，别纠结它的代码；④ 串就是元素为字符的线性表，两章的概念不要割裂。

### 4.2 朴素模式匹配算法（BF）

#### 4.2.1 算法过程

设主串 `S` 长 `n`，模式串 `T` 长 `m`（`m ≤ n`）。`i` 指主串当前比较位，`j` 指模式串当前比较位，两者都从 1 开始。

```c
int Index_BF(SString S, SString T) {
    int i = 1, j = 1;
    while (i <= S.length && j <= T.length) {
        if (S.ch[i] == T.ch[j]) { i++; j++; }   // 当前位相同，继续往后比
        else { i = i - j + 2; j = 1; }          // 失配：主串指针回退到本趟起点的下一位
    }
    if (j > T.length) return i - T.length;      // 匹配成功，返回起始位置
    else return 0;                              // 失败
}
```

失配那一行 `i = i - j + 2`：本趟起点是 `i - j + 1`，回退到它的下一位即 `i - j + 2`，同时 `j` 归 1。**"主串指针回退"就是 BF 的病根**——前一节比过的信息全被扔掉。

走一遍：`S = 'abaabcac'`，`T = 'abc'`。

| 趟次 | 起点 | 比较过程 | 本趟比较次数 | 结果 |
| --- | --- | --- | --- | --- |
| 1 | 1 | `a=a` 对、`b=b` 对、`a≠c` | 3 | 失配，起点后移 |
| 2 | 2 | `b≠a` | 1 | 失配，起点后移 |
| 3 | 3 | `a=a` 对、`a≠b` | 2 | 失配，起点后移 |
| 4 | 4 | `a=a`、`b=b`、`c=c` 全中 | 3 | **成功，返回 4** |

总比较次数 3 + 1 + 2 + 3 = **9 次**。

#### 4.2.2 复杂度与最好/最坏

- **最好情况 `O(n)`**：每个起点都在第一位就失配（或一次整串命中），总比较次数约为 `n`；若 `m = n` 一次命中，也就是 `m` 次。
- **最坏情况 `O(n×m)`**：需要"每次都比到最后一位才失配"的输入。构造函数：主串前 `n−1` 位全为 `'a'`、末位为 `'b'`，模式串为 `'aa...ab'`（前 `m−1` 位 `'a'`、末位 `'b'`）。此时从每个起点出发都要比满 `m` 次才失败，总次数约 `(n − m + 1) × m`，量级 `n × m`。
- 小优化思路（不是本节重点）：失配时不必把 `j` 归 1，可以先比较**模式串首字符**与主串中"已知相同位置的字符"，一次跳过多位——这正是 `KMP` 的动机来源。

> **408 怎么考 / 常见坑**：① 分清"最好 `O(n)`、最坏 `O(n×m)`"，**别写成 `O(n+m)`**（那是 `KMP`）；② 问"某次匹配的比较次数"时老实按上表列趟次，别套公式；③ 记牢回退公式 `i = i - j + 2`，王道习题出现过"模式串指针回退到哪一位"的变形问法。

### 4.3 KMP 算法与 `next` 数组

#### 4.3.1 核心思想：主串指针永不回退

看 BF 失配时丢掉了什么。`S = 'abababc...'`，`T = 'ababaa'`，比到第 6 位 `c ≠ a` 时 BF 会把 `i` 退回起点 +1 重比。但前 5 位**已经比过了**，从"已匹配"这一事实能推出信息：

- 已匹配部分是 `'ababa'`，它的**前缀 `'aba'` 与后缀 `'aba'` 相同**。
- 所以主串刚才这 5 位的后三位 `'aba'`，必然等于模式串的前三位 `'aba'`。
- 于是**主串指针 `i` 完全不用动**，只需把模式串**向右滑动**，让 `j` 退到第 4 位继续比。

这就是 `KMP` 的全部思想：**利用"已匹配部分"的自我重复（前后缀相等）信息，让主串指针 `i` 只进不退，靠移动模式串指针 `j` 完成对齐**。由于 `i` 不回退，主串只被扫描一遍，所以在预处理完模式串之后匹配阶段是线性的。

```c
int Index_KMP(SString S, SString T, int next[]) {
    int i = 1, j = 1;
    while (i <= S.length && j <= T.length) {
        if (j == 0 || S.ch[i] == T.ch[j]) { i++; j++; }  // j==0：重新从 T 第 1 位比
        else j = next[j];                                 // i 不动，只退 j
    }
    if (j > T.length) return i - T.length;
    else return 0;
}
```

`j == 0` 这个分支是"主串当前位连 `T` 第 1 位也不匹配"的收尾处理：此时把 `j` 置 0，下一轮 `i`、`j` 同时 `+1`，相当于主串往后挪一位、模式串从头再来。

#### 4.3.2 `next` 数组的定义与两种约定

`next[j]` 回答一个问题：**当 `T[j]` 与主串失配时，`j` 应该退到哪一位继续比？** 它只和**模式串自己**有关（这正是 `KMP` 能预处理的原因），本质是"`T[1..j-1]` 的最长相等前后缀长度"。

408 考卷默认王道约定（下标从 1 开始、`next[1] = 0`），但部分教材用另一种，必须分清：

| 项目 | 约定 A：下标从 1 开始（王道默认） | 约定 B：下标从 0 开始（C 语言风格） |
| --- | --- | --- |
| 数组值定义 | `next[j]` = `T[1..j-1]` 的**最长相等前后缀长度 + 1** | `next[j]` = `T[0..j-1]` 的最长相等前后缀长度 |
| 首元素 | `next[1] = 0`（哨兵，表示"该挪主串了"） | `next[0] = -1` |
| 第二位 | `next[2] = 1` | `next[1] = 0` |
| 值域 | `0 ≤ next[j] ≤ j` | `-1 ≤ next[j] ≤ j − 1` |
| 互相转换 | A 的值 = B 的值 + 1 | B 的值 = A 的值 − 1 |
| 代码失配处理 | `j = next[j]`（配 `j == 0` 判断） | `j = next[j]`（配 `j == -1` 判断） |

**一句话记忆**：两种约定只差"整体 +1"；**看题目给的首元素是 0 还是 −1 就能判断用的是哪套**。

还有一个高频陷阱：**"最长相等前后缀的长度"与"最终填进数组的 `next` 值"不是同一个数**。在王道约定下：

- `j = 1`：规定 `next[1] = 0`（长度 0 再 +1 就成了 1，不合约定，所以特判）。
- `j ≥ 2`：`next[j]` = `T[1..j-1]` 的最长相等前后缀长度 **+ 1**。

所以"前缀函数长度数组"通常是 `[0, 0, 0, 1, 2, ...]`，而 `next` 是 `[0, 1, 1, 2, 3, ...]`——**整段错开一位再 +1**，手算时千万别直接抄。

> **408 怎么考 / 常见坑**：① 题目不给约定就按王道（1 起始、`next[1] = 0`）做，给了 `next[0] = -1` 就整体减 1；② 答题时**先写一句"按王道约定：下标从 1 开始，`next[1] = 0`"**，阅卷有依据；③ 别把长度数组当 `next` 抄——这是手算第一大错源。

#### 4.3.3 `next` 数组的手算方法（SOP）

**SOP-1（王道约定，下标从 1 开始）**

1. **列位置**：模式串逐字符排开，标上 `j = 1, 2, ..., m`。
2. **取前缀**：对每个 `j` 只看 `T[1..j-1]`（**不含 `T[j]` 自己**）。
3. **求最长相等前后缀长度 `L`**：在真前缀（去掉最后一个字符）与真后缀（去掉第一个字符）中找最长的一对完全相同者，记其长度为 `L`；找不到则 `L = 0`。
4. **换算**：`next[1] = 0`；`j ≥ 2` 时 `next[j] = L + 1`。
5. **自查三条**：`next[1] = 0`、`next[2] = 1` 恒成立；`next[j]` 每次最多比前一位大 1，不会跳变。

**完整示例一：`T = 'ababaa'`（`m = 6`）**

| `j` | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | --- | --- | --- | --- | --- | --- |
| `T[j]` | `a` | `b` | `a` | `b` | `a` | `a` |
| 考察前缀 `T[1..j-1]` | （空） | `a` | `ab` | `aba` | `abab` | `ababa` |
| 最长相等前后缀 | 无 | 无 | 无 | `a` | `ab` | `aba` |
| 长度 `L` | 0 | 0 | 0 | 1 | 2 | 3 |
| **`next[j]` = `L + 1`** | **0** | **1** | **1** | **2** | **3** | **4** |
| **`nextval[j]` （由下表推出）** | **0** | **1** | **0** | **1** | **0** | **4** |
| 约定 B 的 `next`（各值 −1） | −1 | 0 | 0 | 1 | 2 | 3 |
| 约定 B 的 `nextval`（各值 −1） | −1 | 0 | −1 | 0 | −1 | 3 |

推导要点：`j = 3` 看的是 `'ab'`，没有相等前后缀，所以 `next[3] = 1`（**本例最容易错的一位**：不要顺手拿 `'aba'` 去数，考察对象永远是 `T[1..j-1]`）；`j = 4` 看 `'aba'`，最长相等前后缀是 `'a'`（长 1），`next[4] = 2`；`j = 5` 看 `'abab'`，是 `'ab'`（长 2），所以 `next[5] = 3`；`j = 6` 看 `'ababa'`，最长相等前后缀是 `'aba'`（长 3，注意**不是** `'a'`），所以 `next[6] = 4`。

**`nextval` 怎么从 `next` 来（本例，逐位机械执行 `T[j] == T[next[j]]` 判断）**

| `j` | `next[j]` | 比较 `T[j]` 与 `T[next[j]]` | 结论 | `nextval[j]` |
| --- | --- | --- | --- | --- |
| 1 | 0 | —— | 规定 | **0** |
| 2 | 1 | `T[2]=b` vs `T[1]=a` | 不同 → 取 `next` | **1** |
| 3 | 1 | `T[3]=a` vs `T[1]=a` | **相同 → 继承 `nextval[1]`** | **0** |
| 4 | 2 | `T[4]=b` vs `T[2]=b` | **相同 → 继承 `nextval[2]`** | **1** |
| 5 | 3 | `T[5]=a` vs `T[3]=a` | **相同 → 继承 `nextval[3]`** | **0** |
| 6 | 4 | `T[6]=a` vs `T[4]=b` | 不同 → 取 `next` | **4** |

注意 `j = 5` 这一行：正确写法给出 `nextval[5] = nextval[3] = 0`；如果有人错写成 `next[next[j]]`，就会得到 `next[3] = 1`。这正是 SOP 强调"继承的是 `nextval[next[j]]`，不是 `next[next[j]]`"的原因：本例中两种写法的差别就出现在 `j = 5`（一个 0、一个 1，后续失配时就会多比一次）。

即 `T = 'ababaa'` 的结果是 `next = [0,1,1,2,3,4]`、`nextval = [0,1,0,1,0,4]`。

**完整示例二：`T = 'abaabcac'`（`m = 8`）**

| `j` | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `T[j]` | `a` | `b` | `a` | `a` | `b` | `c` | `a` | `c` |

| **`next[j]`** | **0** | **1** | **1** | **2** | **2** | **3** | **1** | **2** |

`nextval` 的推导（逐位机械执行 `T[j] == T[next[j]]` 判断）：

| `j` | `next[j]` | 比较 | 结论 | `nextval[j]` |
| --- | --- | --- | --- | --- |

| 2 | 1 | `T[2]=b` vs `T[1]=a` | 不同 → 取 `next` | **1** |

#### 4.3.4 `next` 数组的递推求法（代码）

手算靠"数前后缀"，机算靠**递推**，两者结果必须一致。递推的关键是 `next[j]` 可由更早的值推出：

```c
void get_next(SString T, int next[]) {
    int i = 1, j = 0;
    next[1] = 0;
    while (i < T.length) {
        if (j == 0 || T.ch[i] == T.ch[j]) {
            i++; j++;
            next[i] = j;          // 这一句就是 "L + 1" 的机器写法
        } else {
            j = next[j];          // 回退，继续尝试更短的前后缀
        }
    }
}
```

理解：`i` 扫描模式串，`j` 始终表示"当前已知的最长相等前后缀长度"。`T[i] == T[j]` 时前后缀同时延长一位，长度 `+1` 并写入 `next[i+1]`；不等时让 `j` 退到 `next[j]`（一个更短的候选长度）再试；`j == 0` 是"退到无处可退"的终止条件。

用 `T = 'abaabcac'` 走一遍递推，可以和 §4.3.3 的表互相校验：

```
next[1] = 0, i = 1, j = 0
i=1,j=0 → i=2,j=1, next[2] = 1
i=2: T[2]=b vs T[1]=a 不等 → j = next[1] = 0
i=2,j=0 → i=3,j=1, next[3] = 1
i=3: T[3]=a vs T[1]=a 等 → i=4,j=2, next[4] = 2
i=4: T[4]=a vs T[2]=b 不等 → j = next[2] = 1
i=4: T[4]=a vs T[1]=a 等 → i=5,j=2, next[5] = 2
i=5: T[5]=b vs T[2]=b 等 → i=6,j=3, next[6] = 3
i=6: T[6]=c vs T[3]=a 不等 → j = next[3] = 1
i=6: T[6]=c vs T[1]=a 不等 → j = next[1] = 0
i=6,j=0 → i=7,j=1, next[7] = 1
i=7: T[7]=a vs T[1]=a 等 → i=8,j=2, next[8] = 2
```

得到 `next = [0, 1, 1, 2, 2, 3, 1, 2]`，与手算表一致 ✔。

> **408 怎么考 / 常见坑**：`get_next` 的代码一般不作手写要求，但要能读懂并说清 `next[i] = j` 的含义（就是 `L + 1`）。若题目给代码留空让你填，八成填这一句。

### 4.4 `nextval` 数组与 `KMP` 匹配过程

#### 4.4.1 `nextval`：给 `next` 打的补丁

`next` 有一个不足：若 `T[j] == T[next[j]]`，那么把 `j` 退到 `next[j]` 之后，**下一次比较还是同一个字符之间比，必然再次失配**，白白浪费一次比较。

**修正规则（王道约定）**：

- `nextval[1] = 0`。
- 对 `j ≥ 2`：若 `T[j] == T[next[j]]`，则 `nextval[j] = nextval[next[j]]`（**继承**，一路跳过所有"同字符"的位置）；否则 `nextval[j] = next[j]`（保持原值）。

```c
void get_nextval(SString T, int nextval[]) {
    int i = 1, j = 0;
    nextval[1] = 0;
    while (i < T.length) {
        if (j == 0 || T.ch[i] == T.ch[j]) {
            i++; j++;
            if (T.ch[i] != T.ch[j]) nextval[i] = j;      // 不同字符：直接用 next 值
            else nextval[i] = nextval[j];                 // 同字符：继承 nextval
        } else {
            j = nextval[j];
        }
    }
}
```

**为什么"继承"是对的**：既然"退到 `next[j]` 再比"注定失败（字符相同），那就继续往前退到 `nextval[next[j]]`，一次退到位。

**SOP-2（求 `nextval`）**

1. 先拿到正确的 `next`。
2. 写 `nextval[1] = 0`，从 `j = 2` 开始逐位处理。
3. 比较 `T[j]` 与 `T[next[j]]`：
   - 不同 → `nextval[j] = next[j]`；
   - 相同 → `nextval[j] = nextval[next[j]]`（**注意是 `nextval`，不是 `next`**，这是第二步的最大坑）。
4. **自查**：恒有 `nextval[j] ≤ next[j]`；`nextval` 的值只能来自 `next` 的值或更早的 `nextval` 值；若模式串中处处 `T[j] ≠ T[next[j]]`，则 `nextval` 与 `next` 完全相同。

> **408 怎么考 / 常见坑**：① 继承时写成 `next[next[j]]` 是最高频错误；② `nextval[1]` 一律为 0（约定 B 下为 −1）；③ 题目常把 `next` 与 `nextval` 放在同一题里要求"都写出来"，先算 `next` 再补 `nextval`，顺序别倒。

#### 4.4.2 手算 SOP 汇总（可直接照抄到草稿纸）

**SOP-1 求 `next`**：逐位取 `T[1..j-1]` → 数最长相等前后缀长度 `L` → `next[1] = 0`、`next[j] = L + 1` → 自查 `next[1] = 0`、`next[2] = 1`、每次最多 +1。

**SOP-2 求 `nextval`**：有 `next` 后逐位比 `T[j]` 与 `T[next[j]]` → 不同取 `next[j]`、相同继承 `nextval[next[j]]` → 自查 `nextval[j] ≤ next[j]`。

**SOP-3 数一次 `KMP` 匹配的比较次数**

1. 写出题目指定的数组（`next` 或 `nextval`，题目说哪个用哪个）。
2. `i`（主串）、`j`（模式串）都从 1 开始，`count = 0`。
3. 循环：**每比一次就 `count++`**；
   - 相同 → `i++`、`j++`；
   - 不同 → `j = next[j]`（**`i` 不动**）。若 `j` 变成 0，则下一轮 `i++`、`j = 1`，这个"对齐动作"**不额外计比较**。
4. `j > m` 时匹配成功，返回 `i − m`；`i > n` 时匹配失败。
5. **自查**：全程 `i` 只增不减。草稿里 `i` 一旦回退，说明写成 `BF` 了。

**SOP-4 `BF` 数比较次数**：从 `i = 1` 到 `n − m + 1` 逐起点试，每趟从 `j = 1` 比到失配或比满 `m` 位，逐趟累加（失配那一次也算）。

#### 4.4.3 一次完整的 `KMP` 匹配过程演示

`S = 'abaabaabcac'`（`n = 11`），`T = 'abaabcac'`（`m = 8`），`next = [0,1,1,2,2,3,1,2]`。

| 次序 | 比较 | 结果 | 动作 | 累计比较次数 |
| --- | --- | --- | --- | --- |
| 1 | `S[1]=a` vs `T[1]=a` | 相同 | `i=2, j=2` | 1 |
| 2 | `S[2]=b` vs `T[2]=b` | 相同 | `i=3, j=3` | 2 |
| 3 | `S[3]=a` vs `T[3]=a` | 相同 | `i=4, j=4` | 3 |
| 4 | `S[4]=a` vs `T[4]=a` | 相同 | `i=5, j=5` | 4 |
| 5 | `S[5]=b` vs `T[5]=b` | 相同 | `i=6, j=6` | 5 |
| 6 | `S[6]=a` vs `T[6]=c` | **失配** | `j = next[6] = 3`（`i` 不动） | 6 |
| 7 | `S[6]=a` vs `T[3]=a` | 相同 | `i=7, j=4` | 7 |
| 8 | `S[7]=a` vs `T[4]=a` | 相同 | `i=8, j=5` | 8 |
| 9 | `S[8]=b` vs `T[5]=b` | 相同 | `i=9, j=6` | 9 |
| 10 | `S[9]=c` vs `T[6]=c` | 相同 | `i=10, j=7` | 10 |
| 11 | `S[10]=a` vs `T[7]=a` | 相同 | `i=11, j=8` | 11 |
| 12 | `S[11]=c` vs `T[8]=c` | 相同 | `i=12, j=9 > 8` | 12 |

匹配成功，返回 `i − m = 12 − 8 = 4`。校验：`S[4..11] = 'abaabcac'` ✔；`i` 从 1 单调增到 12，**一次都没有回退** ✔。合计 **12 次**比较。

若换用 `nextval = [0,1,0,2,1,3,0,2]` 匹配同一组 `S`、`T`：第 6 次失配后 `j = nextval[6] = 3`（与 `next` 同），后续路径完全一样，仍是 **12 次**。这说明 `nextval` 的优化**只在"回退位置的字符与失配字符相同"时才省比较**。

#### 4.4.4 时间复杂度

- 求 `next` / `nextval`：`O(m)`。理由是 `i` 单调递增，`j` 的回退总次数被 `i` 的推进次数"付账"，均摊后是线性的。
- 匹配过程：`O(n)`，因为主串指针 `i` 单调递增、不回退。
- **`KMP` 总计 `O(n + m)`**，额外空间 `O(m)`（存放数组）。
- 对比 `BF` 的 `O(n × m)`：`KMP` 的优势在"主串长、模式串自身重复度高"时最明显；`n`、`m` 都很小时两者实际比较次数可能接近，**但渐近量级上 `KMP` 更优**。

> **408 怎么考 / 常见坑**：① 复杂度写 `O(n + m)`，**不要写成 `O(n × m)` 或 `O(m + n×m)`**；② 额外空间是 `O(m)`，不是 `O(1)`；③ 被问"`KMP` 一定比 `BF` 快吗"——答"**渐近更优，但不是任何输入下的比较次数都更少**"，敢下这个判断。

| 对比项 | 朴素模式匹配 `BF` | `KMP` |

### 三.4 `next` vs `nextval`

| 对比项 | `next` | `nextval` |
| --- | --- | --- |
| 含义 | 失配时 `j` 退到的位置 | `next` 的优化版，退得更到位 |
| 求法 | 前缀的 `L` 再 `+1` | `T[j] == T[next[j]]` 时继承 `nextval[next[j]]`，否则取 `next[j]` |
| 关系 | 基础 | 恒有 `nextval[j] ≤ next[j]`，可相等 |
| 何时完全相同 | —— | 模式串中处处 `T[j] ≠ T[next[j]]` 时 |
| 效果 | 可能多一次注定失败的比较 | 减少比较次数，匹配更快 |
| 408 考法 | 最常单独考 | 常与 `next` 同题一起要求 |

### 三.5 两种下标约定

| 对比项 | 约定 A：下标从 1 开始 | 约定 B：下标从 0 开始 |
| --- | --- | --- |
| 首元素 | `next[1] = 0` | `next[0] = -1` |
| 次元素 | `next[2] = 1` | `next[1] = 0` |
| 定义 | `T[1..j-1]` 最长相等前后缀长度 `+ 1` | `T[0..j-1]` 最长相等前后缀长度 |
| 值域 | `0 ~ j` | `-1 ~ j − 1` |
| 互相转换 | A = B + 1 | B = A − 1 |
| 使用者 | **王道、408 默认** | 部分教材、C 语言风格实现 |

### 三.6 "最长相等前后缀长度"数组 vs 最终的 `next` 数组

| 对比项 | 长度数组 `L`（前缀函数） | `next`（王道约定） |
| --- | --- | --- |
| 定义 | `T[1..j-1]` 的最长相等前后缀长度 | `L + 1`（`j = 1` 特判为 0） |

## 四、例题精练（3 道）

> 以下 3 题为按 408 风格自编的练习题，**不是真题**。

### 例题 1（选择题）

下列关于串的叙述中，**正确**的是（　　）。

A. 空串就是由空格字符组成的串，其长度为 1
B. 两个串相等，当且仅当它们的长度相等
C. 串是一种特殊的线性表，其数据元素限定为单个字符
D. 定长顺序存储的串在做连接运算时，若结果超长，程序一定报错

**答案：C**

逐项解析：

- **A 错**：空串是长度为 0、不含任何字符的串（`''`）；由空格组成的串是空格串，长度等于空格个数（如 3 个空格长度就是 3）。两者串长不同、内容不同，不能混为一谈。这是本章出现频率最高的概念陷阱。
- **B 错**：串相等要求**长度相同且对应位置字符全部相同**，只比长度不够（`'ab'` 与 `'ba'` 长度相同却不相等）。另注意区分：串的**比较**规则是"先逐位比字符编码，全同才比长度"（得出大小关系）；串的**相等**判定只看是否完全一致，两者不要混。
- **C 对**：串的逻辑结构就是线性表，只是把数据元素类型限定为字符（且操作以子串为单位）。这也是理解串的存储结构的钥匙：顺序存储 ↔ 顺序表，链式存储 ↔ 链表。
- **D 错**：定长顺序存储的串在连接、求子串时若超出容量，处理方式是**截断**——静默丢弃超出的部分，**不报错**。正因为"静默截断"危险，才引入堆分配存储（`malloc` 动态申请、不截断）。**"报错"与"截断"这一字之差就是本项的考点。**

> **采分点与常见坑**：四个选项正好对应四个高频点——空串/空格串、串相等的条件、串与线性表的关系、定长存储的截断行为。遇到"一定 / 必然"这类绝对化表述（如 D 的"一定报错"），优先怀疑。

### 例题 2（计算题：手算 `next` / `nextval`）

已知模式串 `T = 'abaabcac'`（`m = 8`）。按**下标从 1 开始**的约定（即 `next[1] = 0`）：

1. 求 `next` 数组；
2. 求 `nextval` 数组；
3. 写出下标从 0 开始约定下的 `next` 与 `nextval`。

**解**

第一步：逐位列出考察的前缀 `T[1..j-1]` 与最长相等前后缀长度 `L`。

| `j` | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `T[j]` | `a` | `b` | `a` | `a` | `b` | `c` | `a` | `c` |
| `T[1..j-1]` | —— | `a` | `ab` | `aba` | `abaa` | `abaab` | `abaabc` | `abaabca` |
| 最长相等前后缀 | —— | 无 | 无 | `a` | `a` | `ab` | 无 | `a` |
| `L` | 0 | 0 | 0 | 1 | 1 | 2 | 0 | 1 |
| **`next[j] = L + 1`** | **0** | **1** | **1** | **2** | **2** | **3** | **1** | **2** |

自查：`next[1] = 0` ✔、`next[2] = 1` ✔、相邻值每次最多 +1 ✔。

（也可用递推法复核，见 §4.3.4，结果一致。）

第二步：`nextval`，逐位比较 `T[j]` 与 `T[next[j]]`。

| `j` | `next[j]` | 比较 | 结论 | `nextval[j]` |
| --- | --- | --- | --- | --- |
| 1 | 0 | —— | 规定 | **0** |
| 2 | 1 | `T[2]=b` vs `T[1]=a` 不同 | 取 `next[2]` | **1** |
| 3 | 1 | `T[3]=a` vs `T[1]=a` 相同 | 继承 `nextval[1]` | **0** |
| 4 | 2 | `T[4]=a` vs `T[2]=b` 不同 | 取 `next[4]` | **2** |
| 5 | 2 | `T[5]=b` vs `T[2]=b` 相同 | 继承 `nextval[2]` | **1** |
| 6 | 3 | `T[6]=c` vs `T[3]=a` 不同 | 取 `next[6]` | **3** |
| 7 | 1 | `T[7]=a` vs `T[1]=a` 相同 | 继承 `nextval[1]` | **0** |
| 8 | 2 | `T[8]=c` vs `T[2]=b` 不同 | 取 `next[8]` | **2** |

**答案 1**：`next = [0, 1, 1, 2, 2, 3, 1, 2]`。
**答案 2**：`nextval = [0, 1, 0, 2, 1, 3, 0, 2]`。
**答案 3**：下标从 0 起时各值整体减 1：`next = [-1, 0, 0, 1, 1, 2, 0, 1]`，`nextval = [-1, 0, -1, 1, 0, 2, -1, 1]`。

> **采分点与常见坑**：① **第 `j` 位看的是前 `j−1` 位**，写成前 `j` 位会把 `next[3]` 算成 2；② 继承时写 `nextval[next[j]]`，写成 `next[next[j]]` 就错；③ 务必自查 `next[1] = 0`、`next[2] = 1`、`nextval[j] ≤ next[j]`；④ 题目没给约定时，先写一句"按王道约定：下标从 1 开始、`next[1] = 0`"。

### 例题 3（计算题：`KMP` 匹配过程与比较次数）

1. 主串 `S = 'abaabaabcac'`（`n = 11`），模式串 `T = 'abaabcac'`（`m = 8`，`next = [0,1,1,2,2,3,1,2]`）。按王道约定用 `KMP` 完成匹配，求字符比较次数与首次匹配的起始位置。
2. 模式串 `T2 = 'aaaaab'`（`m = 6`），主串 `S2` 由 29 个 `'a'` 加 1 个 `'b'` 组成（`n = 30`）。分别用 `KMP` 与 `BF` 完成匹配，各需多少次比较？

**解（1）**

| 次序 | 比较 | 结果 | 动作 | 累计比较次数 |
| --- | --- | --- | --- | --- |
| 1 | `S[1]=a` vs `T[1]=a` | 相同 | `i=2, j=2` | 1 |
| 2 | `S[2]=b` vs `T[2]=b` | 相同 | `i=3, j=3` | 2 |
| 3 | `S[3]=a` vs `T[3]=a` | 相同 | `i=4, j=4` | 3 |
| 4 | `S[4]=a` vs `T[4]=a` | 相同 | `i=5, j=5` | 4 |
| 5 | `S[5]=b` vs `T[5]=b` | 相同 | `i=6, j=6` | 5 |
| 6 | `S[6]=a` vs `T[6]=c` | **失配** | `j = next[6] = 3`（`i` 不动） | 6 |
| 7 | `S[6]=a` vs `T[3]=a` | 相同 | `i=7, j=4` | 7 |
| 8 | `S[7]=a` vs `T[4]=a` | 相同 | `i=8, j=5` | 8 |
| 9 | `S[8]=b` vs `T[5]=b` | 相同 | `i=9, j=6` | 9 |
| 10 | `S[9]=c` vs `T[6]=c` | 相同 | `i=10, j=7` | 10 |
| 11 | `S[10]=a` vs `T[7]=a` | 相同 | `i=11, j=8` | 11 |
| 12 | `S[11]=c` vs `T[8]=c` | 相同 | `i=12, j=9` | 12 |

`j = 9 > m = 8`，匹配成功，起始位置 `i − m = 12 − 8 = 4`。

**答案（1）**：共 **12 次**比较，匹配位置为第 4 位（`S[4..11] = 'abaabcac'`）。

若改用 `nextval = [0,1,0,2,1,3,0,2]` 匹配同一组 `S`、`T`：第 6 次失配后 `j = nextval[6] = 3`，与 `next` 相同，后续路径完全一样，仍是 **12 次**——因为本例中"回退位置的字符"与失配字符并不相同，优化无从发挥。

**解（2）**

先求 `T2 = 'aaaaab'` 的 `next`。

| `j` | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | --- | --- | --- | --- | --- | --- |
| `T2[j]` | `a` | `a` | `a` | `a` | `a` | `b` |
| `T2[1..j-1]` | —— | `a` | `aa` | `aaa` | `aaaa` | `aaaaa` |
| 最长相等前后缀长度 `L` | 0 | 0 | 1 | 2 | 3 | 4 |
| **`next[j]`** | **0** | **1** | **2** | **3** | **4** | **5** |
| **`nextval[j]`** | **0** | **0** | **0** | **0** | **0** | **5** |

（`nextval` 前 5 位全是 `'a'`，一路继承到 0；`j = 6` 时 `T2[6]='b'` ≠ `T2[next[6]]=T2[5]='a'`，故取 `next[6] = 5`。）

`KMP` 过程：`i = 1` 起与 `T2` 前 5 位逐位匹配（`S2` 全是 `'a'`），到 `i = 6` 处 `T2[6] = 'b'` 失配，`j = next[6] = 5`；此后主串每前进一位要比较 2 次（`T2[5]` 与 `T2[6]`），直到 `i = 30` 命中末位 `'b'`。

| 阶段 | 说明 | 比较次数 |
| --- | --- | --- |
| `i = 1..5` | 与 `T2[1..5]` 逐位相同 | 5 |
| `i = 6..29` | 共 24 个位置，每处 2 次（失配 1 次 + 回退后比较 1 次） | 48 |
| `i = 30` | `S2[30]=b` vs `T2[6]=b` 命中 | 1 |
| **合计** | | **54** |

`BF` 过程：起点 `i = 1..24` 时，前 5 位都与 `T2` 相同、第 6 位失配，每趟 6 次比较；起点 `i = 25` 时 `S2[25..30] = 'aaaaab'` 整串命中，6 次比较。

| 阶段 | 说明 | 比较次数 |
| --- | --- | --- |
| `i = 1..24` | 24 趟 × 6 次（末位才失配） | 144 |
| `i = 25` | 6 次后整串命中 | 6 |
| **合计** | | **150** |

（与上界 `(n − m + 1) × m = 25 × 6 = 150` 吻合，这正是 `BF` 的最坏情况构造。）

**答案（2）**：`KMP` 需 **54 次**比较，`BF` 需 **150 次**比较。

> **采分点与常见坑**：① **失配那一次也算一次比较**（最常见的漏计）；② `j = next[j]` 后若 `j` 变成 0，下一轮 `i`、`j` 同时 `+1`，这个对齐动作**不额外计比较**；③ "`i` 单调递增"是自查 `KMP` 走没走对唯一可靠的硬标准；④ 若被追问"`KMP` 一定比 `BF` 快吗"，先给量级结论（`O(n+m)` 对 `O(n×m)`），再补一句"不是每一组输入下的比较次数都更少"。

## 六、简便方法与易错口诀（速算 · 防错）

> 本节把本章能"省时间"和"防掉坑"的招集中在一处：二轮复习与考前只看这一节。每条都写清**适用条件**。

### 6.1 速算招式

| 场景 | 常规做法（慢/繁） | 简便做法（快/稳） | 为什么成立 / 适用条件 |
| --- | --- | --- | --- |
| 手算任意模式串的 `next` | 每位都把全部前后缀从头列一遍，边列边数 | 三步 SOP：① 锁定考察串 `T[1..j-1]`（**不含第 `j` 位自己**）；② 数它的最长相等真前后缀长度 `L`；③ 写 `next[j] = L + 1`，且恒有 `next[1] = 0`、`next[2] = 1` | 定义就是"前 `j-1` 位的最长相等前后缀长度 `+ 1`"。`j = 1` 时考察的是空串、`L = 0`，但规定答案写 `0` 而不是 `1`，所以 `next[1] = 0` 必须单独记。适用条件：王道/408 默认的"下标从 1 开始"约定 |
| 检查刚算出的 `next` | 从头再算一遍对答案 | 三条硬标准，任一条不满足就是算错：`next[1] = 0`；`next[2] = 1`；相邻两位**最多 +1**。例：`'abaabcac'` 的 `next = [0,1,1,2,2,3,1,2]` 中 `3 → 1` 合法（可以掉很多），`2 → 4` 非法 | 由递推式保证：`T[1..j]` 的相等前后缀去掉末位，必是 `T[1..j-1]` 的相等前后缀，故长度最多长 1。0 起始约定同样成立（首两项为 `next[0] = -1`、`next[1] = 0`，差值上界仍是 1） |
| 由 `next` 推 `nextval` | 再按"数前后缀"重算一遍 | 逐位只比一次字符，且 `j` 从小到大扫：若 `T[j] == T[next[j]]`，则 `nextval[j] = nextval[next[j]]`（**继承 `nextval`**）；否则 `nextval[j] = next[j]` | 优化目的：退过去的那个字符不该和刚失配的字符再撞一次。必须按 `j` 递增算，被继承的 `nextval` 才有值；`nextval[1]` 仍规定为 0。适用条件：仅当下标约定与 `next` 一致时 |
| 两种下标约定互转 | 按定义把每位重推一遍 | 同一字符位置**整体差 1**：0 起始值 = 1 起始值 − 1，即约定 A 的第 `j` 位对应约定 B 的第 `j-1` 位。例 `'ababaa'`：A `next = [0,1,1,2,3,4]`、B `next = [-1,0,0,1,2,3]`；`nextval` 也整体 −1（`[0,1,0,1,0,4]` 对 `[-1,0,-1,0,-1,3]`） | 两约定只差首位规定（`next[1] = 0` 对 `next[0] = -1`）。**适用条件：答题先写一句"按王道约定：下标从 1 开始、`next[1] = 0`"**，否则选择题选项对不上 |
| 判断一次失配让模式串滑了几位 | 重走一遍匹配过程数格子 | 1 起始：`滑动位数 = 失配位置 j − next[j]`，等价于 `已匹配长度 + 1 − next[j]`（此处 `已匹配长度 = j − 1`）；0 起始：同样直接用该约定的 `j − next[j]` | 失配时新起点 `p' = p + j − next[j]`，滑动位数与下标约定无关。**⚠ 订正提示**：流传写法"移动量 = 已匹配长度 − `next[j]`"会**少算 1 位**——例 3 第 6 步 `j = 6`、`next[6] = 3`、已匹配 5 位，实际滑 3 位而不是 2 位，请按上式用 |
| 数一次 `KMP` 的比较次数 | 逐格数 `i`、`j` 的每次变化 | 两条计数规则：**失配那一次也算一次比较**；`j` 退到 0 后"`i`、`j` 同时 +1"的对齐动作**不计**比较 | 比较只发生在"拿 `S[i]` 与 `T[j]` 相比"这一步，对齐是纯指针移动。例 3(1) 共 12 次；例 3(2) 的 `KMP` 为 5 + 48 + 1 = 54 次 |
| 估 `BF` 最坏比较次数 | 老实走完整过程再数 | 上界 `(n − m + 1) × m`；最坏输入这样造：`S` 取一长串 `'a'`，`T` 取"一串 `'a'` + 末尾一个不同字符"（如 `T2 = 'aaaaab'`，`n = 30`、`m = 6` 时上限 `25 × 6 = 150`，与实际 150 次吻合） | 每趟都要比到 `T` 的最后一位才失配，而 `i` 回退后前 `m` 个字符每次重比。适用条件：这个上界只在"最坏构造"下达；一般输入可能远小于它 |
| 默写两个复杂度 | 现场现推 | `BF`：最好 `O(n)`、最坏 `O(n × m)`；`KMP`：求 `next` 是 `O(m)`、匹配是 `O(n)`，合计 `O(n + m)`，额外空间 `O(m)` | `BF` 最好 `O(n)` 的典型输入是每趟第 1 个字符就失配（约 `n` 次比较）。`KMP` 的 `O(n + m)` 是**渐近**结论，不保证任何一组输入都比较得少 |
| 数字符串的子串个数 | 一个个列举 | 长度为 `n`：非空子串 `n(n+1)/2`；非空真子串 `n(n+1)/2 − 1`；连空串也算上则 `n(n+1)/2 + 1` | 空串是任意串的子串，所以只有"含空串"的计数才 `+1`。适用条件：子串要求**连续**；题目问"子串"还是"非空子串"决定要不要 `+1` |
| 判断"谁可能丢字符 / 谁不截断" | 回忆三种存储的代码 | 关键词直接对应：**截断且不报错** → 定长顺序存储；**`malloc` 动态、不截断** → 堆分配存储；**存储密度小于 1、结点越小密度越低** → 块链存储 | 定长串做连接、求子串超容量时是**静默截断**，不是报错；只有堆分配不丢字符。适用条件：块链只考"存储密度与结点大小对操作的影响" |
| 默写 `BF` 的失配处理 | —— | `i = i − j + 2; j = 1;`（1 起始约定） | 这一行同时暴露病根：`i` 会回退、已匹配的信息被整块丢弃，这正是 `KMP` 要治的地方 |

### 6.2 口诀与记忆钩子

- **口诀**：手算 `next`——"**看前不看己，数完再加一**"（只看 `T[1..j-1]`，数出长度 `L` 再 `+1`）；两条铁律 `next[1] = 0`、`next[2] = 1`。
- **口诀**：`nextval`——"**同则继承，不同则照抄**"；继承的是 `nextval[next[j]]`，写成 `next[next[j]]` 就错（`'ababaa'` 的 `j = 5` 专门抓这个错：对的是 0，错的是 1）。
- **口诀**：两套约定——"**A 是 B 加一**"（王道 1 起始值 = 0 起始值 + 1）；下笔前先声明用哪套。
- **口诀**：指针动作——"**`KMP`：`i` 不退、`j` 退到 `next`；`BF`：`i` 回退、`j` 归 1**"。
- **口诀**：比较次数——"**失配也算，归零不算**"（失配那一次计入；`j = 0` 之后的 `i`、`j` 同时 +1 不计）。
- **口诀**：复杂度——"**`BF` 最好 n、最坏 nm；`KMP` 恒定 n+m，另加求表 m**"。
- **记忆钩子**：`next` 数组"**最多爬一格，可以掉到底**"——相邻两位涨幅不超过 1，用它 3 秒就能判出跳变错误。

### 6.3 反例黑名单（这些"简便法"是错的）

- ❌ **把第 `j` 位的前后缀算成 `T[1..j]`（含 `T[j]` 自己）**：例如 `T = 'ababaa'` 在 `j = 3` 处误拿 `'aba'` 去数，得到 `'a'`（长 1），于是写成 `next[3] = 2`。正确做法是**只看前 `j-1` 位**：`'ab'` 没有相等前后缀，故 `next[3] = 1`（同理 `j = 1` 看的是空串）。
- ❌ **把"最长相等前后缀长度 `L`"直接当 `next` 抄**：`'abaabcac'` 的 `L = 0,0,0,1,1,2,0,1`，照抄就得到 `next = [0,0,0,1,1,2,0,1]`（全表差 1、首位还错）。正确做法是每位 `+1` 并把首位规定为 0：`next = [0,1,1,2,2,3,1,2]`。
- ❌ **`nextval` 继承写成 `next[next[j]]`**：`'ababaa'` 的 `j = 5` 处错写成 `next[3] = 1`。正确做法是继承 `nextval`：`nextval[5] = nextval[3] = 0`。
- ❌ **把"`KMP` 一定比 `BF` 少比"当结论**：例 3(1) 中 `next` 与 `nextval` 都走了 12 次，优化一点没发挥。正确做法是先给量级（`O(n + m)` 对 `O(n × m)`），再补一句"不是每组输入下的比较次数都更少"。
- ❌ **漏计失配那一次比较**：`T2 = 'aaaaab'`、`S2` 由 29 个 `'a'` 加 1 个 `'b'` 组成时，漏掉失配会比较成 53 / 149 之类。正确值是 `KMP` **54 次**、`BF` **150 次**。
- ❌ **两种下标约定混用**：同一题里既用 `next[1] = 0` 又用 `next[0] = -1`，或换算时把字符位对错（应"1 起始的第 `j` 位 ↔ 0 起始的第 `j-1` 位"）。正确做法是全题只用一套，并在解答开头写明。
- ❌ **相邻 `next` 值发生跳变却不当错**：如算出 `next = [0,1,1,2,4,...]`（`2 → 4`）。正确做法是立刻用"最多 +1"回查该位的前后缀数法。
- ❌ **把空串当空格串**：空串 `''` 长度为 0，是任意串的子串；3 个空格组成的串长度为 3，它不是任意串的子串。正确做法是分别写出两者的长度与内容再判断。
- ❌ **以为定长顺序存储超长会"报错"**：正确做法是记住它**静默截断**（超出的字符直接丢弃、不报错），需要"不截断"就选堆分配存储。
- ❌ **用"移动量 = 已匹配长度 − `next[j]`"算滑动位数**：会少算 1 位。正确做法是 `失配位置 j − next[j]`（1 起始下也就是 `已匹配长度 + 1 − next[j]`），见 6.1 第 5 行的订正提示。
