## 一、本章知识框架

- **数据结构的基本概念**
  - **四个基本术语（层层包含）**
    - `数据` → `数据对象` → `数据元素` → `数据项`
    - `数据项` 是**不可分割的最小单位**；`数据元素` 是**基本单位**，又叫记录/结点/顶点
  - **数据结构的三要素**
    - 逻辑结构：集合、线性、树形、图形
    - 存储结构（物理结构）：顺序、链式、索引、散列
    - 数据的运算：定义在逻辑结构上，实现靠存储结构
  - **抽象数据类型 `ADT`**
    - 三元组：`ADT = (D, S, P)`（数据对象、数据关系、基本操作）
    - 只关心"做什么"，不关心"怎么做"
- **算法的基本概念**
  - **定义**：对特定问题求解步骤的描述，是指令的有限序列
  - **五个特性**：有穷性、确定性、可行性、输入、输出
    - 易错：有穷性 ≠ 程序终止；输入可以是 0 个，输出必须是 1 个及以上
  - **算法 ≠ 程序**：算法是"步骤与思想"，程序是"用某语言的实现"；程序可以不满足有穷性（如操作系统）
  - **好算法的五个评价标准**：正确性、可读性、健壮性、效率（时间）、低存储量（空间）
- **算法的复杂度分析**
  - **时间复杂度**
    - 度量方式：不是掐表，而是数**基本语句的执行次数** `f(n)`，再取渐进阶
    - 三种记号：`O`（上界）、`Ω`（下界）、`Θ`（紧确界）
    - 常见数量级排序：`O(1) < O(log n) < O(n) < O(n log n) < O(n^2) < O(n^3) < O(2^n) < O(n!)`
    - 计数套路：单层循环 → 循环变量跑多少趟；多层循环 → 求和/乘法；`while` 折半 → 数"折了几次"
    - 三种情况：最好、最坏、平均（`ASL` 式加权）
  - **空间复杂度**
    - 只算**辅助空间**（额外开的空间），不算输入本身
    - 原地工作：`S(n) = O(1)`
    - 递归：空间代价 = **递归调用栈的最大深度**
    - 经典对比：斐波那契递归 `O(2^n)` 时间 / `O(n)` 空间（栈深）

## 二、概念详解

### 1.1 数据、数据元素、数据项、数据对象

**为什么先讲这组词**

408 选择题喜欢在"谁包含谁"上做文章。这四个词不是并列关系，而是一层套一层的包含关系，把它们想成一栋楼的层级就通了：

- `数据`：**信息的载体**，是能被计算机识别、输入、处理的一切符号集合（数字、字符、图像、声音都算）。它是最大的集合。
- `数据对象`：具有**相同性质**的数据元素的集合，是数据的一个**子集**。例：整数数据对象 `D = {0, ±1, ±2, ...}`。
- `数据元素`：数据的**基本单位**，通常作为一个整体被处理。同一个东西在不同场合叫法不同：在链表中叫"结点"，在树中叫"结点"，在图里叫"顶点"，在数据库里叫"记录"。
- `数据项`：构成数据元素的**不可分割的最小单位**。一个数据元素可以由若干数据项组成。

**举例串起来**：一张"学生登记表"是 `数据`；全体学生构成一个 `数据对象`；某一行（张三的整条记录）是一个 `数据元素`；这一行里的"学号""姓名""班级"各自是一个 `数据项`。

**关键点**

- 层次链：`数据 ⊇ 数据对象 ⊇ 数据元素 ⊇ 数据项`（前三个是集合与元素的关系，最后一个才是组成关系）。
- `数据项` 是最小单位，不能再拆；`数据元素` 是基本单位，是"整体处理"的下限。
- 一个数据元素可以由**一个**数据项构成（此时元素 = 项，如一个整数），也可以由**多个**数据项构成。

**408 怎么考 / 常见坑**

- 最爱考"下列关系正确的是"，选项常写成"数据项由数据元素组成"——**反了**，是元素由项组成。
- "最小单位"问的是 `数据项`，"基本单位"问的是 `数据元素`，题干里两个字之差就是答案的差别。
- `数据对象` 与 `数据` 的关系是**子集**，不是同一个概念；但同一数据对象中的元素**性质相同**。

### 1.2 逻辑结构与存储结构

**为什么分两层**

数据结构研究的是"数据之间的关系"，而这种关系有两副面孔：**人怎么理解它**（逻辑）和**机器怎么存放它**（物理）。同一个逻辑结构可以用不同存储结构实现，就像同一份名单可以写在纸上，也可以贴在墙上——内容（逻辑）没变，摆放方式（存储）变了。

**（1）逻辑结构：只看关系，与存储无关**

它是数据元素之间的抽象关系，是从具体问题里剥出来的"骨架"：

| 逻辑结构 | 元素间关系 | 典型例子 |
| --- | --- | --- |
| 集合 | 除"同属一个集合"外**无其他关系** | 判断某元素是否属于某集合 |
| 线性 | 一对一，除首尾外**每个元素有唯一前驱和后继** | 线性表、栈、队列、串 |
| 树形 | 一对多，有**层次/分支**关系 | 二叉树、`B` 树、家族谱系 |
| 图形 | 多对多，任意两个元素都可能相关 | 无向图、有向图、网 |

**（2）存储结构（物理结构）：逻辑结构在内存中的映像**

| 存储结构 | 怎么做 | 特点 |
| --- | --- | --- |
| 顺序存储 | 用**一组连续**的存储单元，逻辑相邻 ⇒ 物理相邻 | 支持随机访问；插删要移动元素，需预分配 |
| 链式存储 | 结点除数据外存**指针**，靠指针链接 | 不要求连续；插删方便；只能顺序访问，指针占额外空间 |
| 索引存储 | 存数据的同时建**索引表**（关键字 → 地址） | 检索快；索引表本身费时间费空间 |
| 散列存储 | 用**散列函数**由关键字直接算出地址 | 查找最快（理想 `O(1)`）；可能冲突，需处理 |

**（3）三要素的关系**

`数据结构` 严格说是三要素的集合：**逻辑结构 + 存储结构 + 数据的运算**。运算是"定义在逻辑结构上、实现于存储结构上"的——比如"插入"这个运算，逻辑上就是"在第 `i` 个位置加一个元素"，但在顺序表里要搬元素，在链表里只改指针。**运算的定义与实现是两回事**，这句话是选择题的常客。

**408 怎么考 / 常见坑**

- 会问"以下关于存储结构的说法正确的是"，正确项一般是"存储结构是逻辑结构在计算机中的表示/映像""一种逻辑结构可以有多种存储结构"或"一种存储结构可以表示多种逻辑结构"。
- 陷阱项："顺序存储只能表示线性结构"——错，完全二叉树、堆都用顺序存储。
- 陷阱项："链式存储只能表示线性结构"——也错，孩子兄弟表示法、邻接表都能表示树/图。
- 陷阱项："逻辑结构独立于存储结构"——对；"存储结构独立于逻辑结构"——错，存储结构是逻辑结构的实现。
- 索引与散列**不是**并列于顺序/链式的"第三种、第四种基本方式"，它们必须建立在顺序或链式之上（索引表要存、散列冲突链要挂），所以才有"四种存储方法、两种基本实现"的说法。

### 1.3 抽象数据类型 ADT

**怎么来的**

写程序时，使用者只想知道"这个类型能做什么"，不想知道"它内部怎么做的"。于是把**数据的逻辑特性 + 允许的操作**打包，屏蔽实现细节——这就是 `抽象数据类型`（`Abstract Data Type`，`ADT`）。

**三元组定义**

`ADT = (D, S, P)`

- `D`：数据对象
- `S`：`D` 上的数据关系（即逻辑结构）
- `P`：`D` 上的基本操作集

**关键点**

- `ADT` 强调**抽象**：与具体存储结构、具体语言无关；同一个 `ADT` 可以有数组实现、链表实现两种。
- 与"数据类型"的区别：数据类型（如 `int`、`float`）是**高级语言已实现**的类型，包含取值范围 + 运算；`ADT` 是**自定义的、抽象的**类型，是设计层面的东西。
- 描述形式：`ADT 名字 { 数据对象; 数据关系; 基本操作; } ADT 名字`。王道书附的 `ADT` 定义只看结构，不背内容。

**408 怎么考 / 常见坑**

- 常考"`ADT` 的三元组是什么""`ADT` 的定义与实现是否相关"——定义与**存储实现无关**，与**具体语言无关**。
- 陷阱项："`ADT` 就是数据类型"——错；"`ADT` 包含存储结构"——错，三元组里没有存储结构。

### 1.4 算法的定义与五个特性

**定义**

`算法` 是对特定问题求解步骤的一种描述，它是指令的**有限序列**，其中每条指令表示一个或多个操作。通俗说：算法 = 解决一个问题的一套明确步骤。

**五个特性（必背，选择题高频）**

| 特性 | 含义 | 一句话验证 |
| --- | --- | --- |
| 有穷性 | 必须在执行**有穷步**后结束，且每一步都在有穷时间内完成 | 会不会一直跑下去？ |
| 确定性 | 每条指令有确切含义，**相同输入必得相同输出**，无二义性 | 换个人照着做结果一样吗？ |
| 可行性 | 每一步都能通过**已实现的基本运算**执行有限次完成 | 每步都做得到吗？ |
| 输入 | 有 **0 个或多个**输入 | 可以没有输入 |
| 输出 | 有 **1 个或多个**输出 | **绝不能没有输出** |

**关键点**

- 有穷性是算法与程序的分水岭：**程序可以不满足有穷性**（例如操作系统、`while(1)` 的服务程序会一直运行），算法必须满足。
- 输入个数可以是 `0`（如打印一个常量序列），输出个数至少 `1`；"有 0 个输出"的选项一律错。
- 确定性 ≠ 结果唯一：它要求的是"相同输入 → 相同输出"，允许不同输入得到相同输出。

**408 怎么考 / 常见坑**

- 经典题型："以下哪项不是算法的特性？"干扰项常写"可读性""健壮性""高效性"——这些是**好算法的评价标准**，不是特性，两套概念别混。
- 另一类题给一段描述问"是否满足有穷性"，典型反例是"求所有素数"这类无穷过程，或"输入 `n`，只要 `n != 1` 就继续，未说明 `n` 如何变化"的伪代码。

### 1.5 好算法的评价标准

| 标准 | 含义 | 达不到会怎样 |
| --- | --- | --- |
| 正确性 | 对合法输入能得到满足规格说明的结果 | 程序没用 |
| 可读性 | 便于阅读、理解、交流 | 难以维护与排错 |
| 健壮性 | 对非法输入能适当反应或处理，不产生莫名结果 | 一遇脏数据就崩 |
| 高效率与低存储量 | 时间复杂度低、空间复杂度低 | 跑不动 / 放不下 |

**关键点**：这四条和"算法的五个特性"是**两套**东西——特性是"是不是算法"，标准是"是不是好算法"。考试常把两套混在一个选项列表里让你挑。

**408 怎么考 / 常见坑**

- "算法必须满足的"→ 五特性；"衡量算法优劣的"→ 四标准（正确性、可读性、健壮性、效率与低存储量需求）。
- 有教材把"正确性"细分为四个层次（不含非法输入、含非法输入、含精心选择的非法输入、含一切合法输入），408 不考细分，知道"正确性"是第一位即可。

### 1.6 时间复杂度分析

**度量思路：为什么不用"跑一次计时"**

同一算法在不同机器、不同编译器、不同数据上跑出的秒数不同，无法比较。所以理论分析用的是：**算法中基本语句的执行次数 `f(n)`**，其中 `n` 是问题规模。

- `基本语句`：对运行时间贡献最大、执行次数与整个算法执行次数成正比的那条（通常是**最深层循环内的语句**）。
- 然后只保留 `f(n)` 中**最高阶**的项，并**去掉系数**，得到渐进复杂度。

**三个渐进记号**

| 记号 | 读法 | 含义 | 直觉 |
| --- | --- | --- | --- |
| `O` | 大 O | 上界：`f(n) ≤ C·g(n)` 当 `n` 足够大 | "最坏也就这么快" |
| `Ω` | 大 Omega | 下界：`f(n) ≥ C·g(n)` | "至少这么慢" |
| `Θ` | 大 Theta | 紧确界：上下界同阶 | "就是这个量级" |

408 里平时说"某算法的时间复杂度是 `O(...)`"，实际含义接近 `Θ`，但习惯写成 `O`。

**常见数量级排序（必须背下来）**

`O(1) < O(log n) < O(n) < O(n log n) < O(n^2) < O(n^3) < O(2^n) < O(n!)`

注意几点：

- `log n` 的**底数不影响**渐进复杂度：`log2 n` 与 `log10 n` 只差常数倍 `1/log2 10`，常数在 `O` 里被丢掉。所以写 `O(log n)` 即可，不用纠结底。
- `2^n` 与 `n!` 是指数级、阶乘级，属于"不可行算法"，一般只能处理 `n ≤ 20~30` 的规模。
- 加法规则：`O(f) + O(g) = O(max(f, g))`；乘法规则：`O(f) × O(g) = O(f × g)`。这两条是分析多段代码和多层循环的工具。

**三类计数套路**

1. **单层循环**：看循环变量从哪到哪、每轮怎么变。`for (i = 1; i <= n; i++)` 执行 `n` 次 → `O(n)`。
2. **多层循环**：内层执行次数累加求和，或直接相乘（当内层次数与外层无关时）。
   - `for (i=1; i<=n; i++) for (j=1; j<=n; j++)` → `n × n = n^2` → `O(n^2)`。
   - `for (i=1; i<=n; i++) for (j=1; j<=i; j++)` → `1+2+...+n = n(n+1)/2` → `O(n^2)`（**次数不同，阶相同**，这类"内层与 `i` 有关"的题要会求和）。
3. **`while` 折半类**：抓住"每轮规模缩为几分之一"，数**折了几次**。
   - `i = 1; while (i <= n) i = i * 2;` → 设执行 `k` 次后 `i = 2^k > n`，即 `k = log2 n + 1` → `O(log n)`。
   - `while (i * i <= n) i++;` → `i` 最终约为 `√n` → `O(√n)`，**别顺手写成 `log n`**。

**最好 / 最坏 / 平均**

- **最坏**：规模同为 `n` 的输入中，执行次数最多的情况。这是最常用的指标（"保证不超过"）。
- **最好**：执行次数最少的情况，参考价值最低。
- **平均**：按各种输入出现的概率加权，`ASL = Σ pi × ci`。需要假定概率分布，考研一般假定**等概率**。

**408 怎么考 / 常见坑**

- 数的是**基本语句的执行次数**，不是"代码有几行"、不是"循环有几层"。三层循环若内层只跑一次，仍是 `O(n^2)` 甚至更低——**要看次数，别看层数**。
- `O` 里**只留最高阶项、去掉系数**：`3n^2 + 5n + 7` → `O(n^2)`，写成 `O(3n^2)` 不规范。
- 题目问"时间复杂度"时若没特别说明，按**最坏情况**答；如果给了具体输入（如"已排好序"），要按那种输入分析。
- 循环变量按 `*2`、`/2` 变，多半是 `O(log n)`；按 `+1`、`-1` 变是线性；条件是 `i * i <= n` 是 `O(√n)`。
- 注意区分"算法执行时间"与"问题本身的复杂度"——本章只考前者。

### 1.7 空间复杂度分析

**度量什么**

`空间复杂度` `S(n)` 定义为算法**所耗费的存储空间**，是问题规模 `n` 的函数。关键是：**只算辅助空间**（算法运行中额外申请的临时空间），**不算输入数据本身占的空间**，也不算程序代码占的空间。

- 若算法所需辅助空间相对于输入是常量，即 `S(n) = O(1)`，称算法**原地工作**（就地工作）。例：冒泡排序、就地逆置数组。
- 例：把两个有序表归并成新表，需要开一个长度 `n` 的辅助数组 → `S(n) = O(n)`。
- 注意 `O(n)` 与 `O(1)` 的区别有时很微妙：**循环里反复使用同一个变量仍是 `O(1)`**，`O(n)` 必须是随着 `n` 增长而线性增长的空间。

**递归为什么空间贵**

递归调用时，每一层都要在**栈**上保存返回地址、参数、局部变量，函数不返回，这一层就不释放。所以：

- 递归算法的空间复杂度 = **递归调用栈的最大深度**（不是递归调用总次数！）
- 时间上每层也要花常数时间，所以递归的时间 = 递归树上的**结点总数**。

**经典例子：斐波那契数列**

```c
/* 递归版：F(1)=1, F(2)=1 */
int Fib(int n) {
    if (n <= 1) return n;        /* 或写成 if (n == 1 || n == 2) return 1; */
    return Fib(n - 1) + Fib(n - 2);
}
```

- **时间**：`T(n) = T(n-1) + T(n-2) + O(1)`，展开后调用次数随 `n` 指数增长，`T(n) = O(2^n)`（严格些是 `O(1.618^n)`，但考试答 `O(2^n)`）。
- **空间**：虽然是"两路"递归，但计算 `Fib(n-1)` 时 `Fib(n-2)` 还没开始，栈上最多同时存在 `n` 层 → `S(n) = O(n)`。
- **对比迭代版**：用两个变量滚动 `f1`、`f2` 循环 `n-1` 次，则时间 `O(n)`、空间 `O(1)`。这就是"用空间/时间换"的最朴素例子。

**408 怎么考 / 常见坑**

- 常见陷阱："递归算法空间复杂度等于递归调用总次数"——错，是**最大深度**。
- 常见陷阱：把"输入数组本身"算进空间复杂度——不算，只算辅助空间。
- 常见陷阱：`S(n) = O(1)` 不等于"不占空间"，而是"额外空间是常数个单元、不随 `n` 增长"。
- 大题写"空间复杂度"时，若用了辅助数组就写 `O(n)` 并说明数组用途；若只用几个变量就写 `O(1)` 并点出"原地工作"。

## 四、例题精练（3 道）

### 例题 1（选择题）

**题目**　以下关于数据结构的说法中，正确的是（　　）。

A. 数据的存储结构独立于其逻辑结构，二者可以任意组合
B. 线性表的顺序存储结构比链式存储结构更适合表示树形结构
C. 数据的逻辑结构与存储结构无关，一种逻辑结构可以有多种存储结构
D. 只有线性结构才能采用链式存储，非线性结构必须采用顺序存储

**答案**：C

**逐项解析**

- **A 错**：说反了。存储结构是逻辑结构在计算机中的**映像**，它必须能正确表达逻辑结构所要求的关系，因此**依赖**于逻辑结构，而不是"独立、可任意组合"。一种逻辑结构可以有多种存储结构，但一旦选定存储结构，就必须保证逻辑关系不失真。
- **B 错**：这是概念错位。顺序存储/链式存储是**存储结构**层面的事，而"树形结构"是**逻辑结构**；而且恰恰相反，顺序存储更适合表示完全二叉树（数组下标直接算父子关系），链式存储（孩子兄弟表示法）也完全能表示树。两句话里没有"更适合表示树形结构"这一说。
- **C 对**：逻辑结构是从具体存储中抽象出来的关系，与存储结构无关；同一种逻辑结构（如线性表）既可用顺序存储，也可用链式存储，甚至可以既用顺序又用链式（如静态链表）。
- **D 错**：链式存储同样可以表示非线性结构——树的孩子兄弟表示法、图的邻接表都是链式存储；非线性结构也不是"必须"顺序存储。

**采分点与常见坑**

- 采分点：抓住"存储结构是逻辑结构的映像 ⇒ 依赖关系是单向的（存储依赖逻辑，逻辑不依赖存储）"。
- 常见坑：把"一种逻辑结构可有多种存储结构"错读成"二者可任意组合/互相独立"。前者对，后者错。

### 例题 2（计算题）

**题目**（真题风格改编）　分析下面算法段的时间复杂度，写出基本语句、执行次数的推导过程。

```c
int i, j, count = 0;
for (i = 1; i <= n; i++)
    for (j = 1; j <= i; j = j + i)
        count++;
```

**解题步骤**

第 1 步：找基本语句。最内层的 `count++` 是被执行最频繁的语句，执行次数与整个算法同步，取它为基本语句。

第 2 步：看内层循环能跑几趟。内层循环变量 `j` 从 `1` 开始，每次增加 `i`，条件是 `j <= i`，即 `j` 取值 `1, 1+i, 1+2i, ...` 且不超过 `i`。

- 当 `i >= 1` 时，`j = 1` 满足条件；下一轮 `j = 1 + i > i`（因为 `i > 0`），不再满足。
- 所以内层循环**恒为 1 趟**，与 `n` 无关。

第 3 步：求和。外层 `i` 从 `1` 到 `n` 共 `n` 趟，每趟内层 1 次，故

`f(n) = Σ(i=1 到 n) 1 = n`

第 4 步：取渐进阶。`f(n) = n`，保留最高阶、去掉系数，得

`T(n) = O(n)`

**答案**：`T(n) = O(n)`（基本语句 `count++` 执行 `n` 次）

**采分点与常见坑**

- 采分点：明确写出"基本语句是 `count++`"和"内层恒为 1 趟"这两步，这是这道题的全部难点，只写结论不给分。
- 常见坑 1：看到"双重循环"条件反射写 `O(n^2)`。**循环层数不等于复杂度阶数**，一定要数执行次数。
- 常见坑 2：把内层步长 `j = j + i` 看成 `j++`。本题的关键陷阱就在步长是 `i`（与外层变量相关），而非 1。
- 常见坑 3：写成 `O(n)` 却在说明里写"内外层都是 `n`"，自相矛盾会被扣分。

### 例题 3（综合题）

**题目**（真题风格改编）　顺序表 `L` 中有 `n`（`n >= 1`）个整数，数据元素互不相同，用 C 语言写出在 `L` 中查找值为 `x` 的元素、返回其下标（找不到返回 `-1`）的函数，并回答：

1. 最好、最坏情况下各比较多少次？
2. 假设 `x` 在表中出现且出现在每个位置的概率相等，求查找成功的平均比较次数，并写出时间复杂度。
3. 说明该算法的空间复杂度，并判断是否原地工作。
4. 若把数据改成"按从小到大有序"，能否把时间复杂度降到 `O(log n)`？写出该算法。

**C 语言实现（顺序查找）**

```c
#define MAXSIZE 100

typedef struct {
    int data[MAXSIZE];
    int length;
} SqList;

/* 在顺序表 L 中查找 x，找到返回下标，找不到返回 -1 */
int SeqSearch(SqList L, int x) {
    int i;
    for (i = 0; i < L.length; i++) {   /* 基本语句所在循环 */
        if (L.data[i] == x)
            return i;
    }
    return -1;
}
```

**第 1 问：最好 / 最坏比较次数**

- 最好情况：`x` 恰好在下标 `0`，比较 `1` 次。
- 最坏情况：`x` 在下标 `n-1`，或 `x` 不在表中，都要比较 `n` 次。

所以 `T_best(n) = O(1)`，`T_worst(n) = O(n)`。

**第 2 问：平均比较次数**

设 `x` 出现在第 `i` 个位置（`i` 从 `1` 数起，对应下标 `i-1`）的概率为 `p_i`。等概率时 `p_i = 1/n`；查找第 `i` 个位置需要比较 `c_i = i` 次。按 `ASL = Σ pi × ci`：

`ASL_成功 = Σ(i=1 到 n) (1/n) × i = (1/n) × (1 + 2 + ... + n) = (1/n) × n(n+1)/2 = (n+1)/2`

即平均约比较 `(n+1)/2` 次，是 `n` 的同阶量，故

`T_avg(n) = O(n)`

若考虑"查找失败"的情形：失败时总是比较 `n` 次，若成功与失败的概率分别为 `p` 与 `1-p`（每次命中各位置的先验概率之和为 `p`），则

`ASL = p × (n+1)/2 + (1-p) × n`

**第 3 问：空间复杂度**

函数只用了循环变量 `i` 一个额外单元，与 `n` 无关，故

`S(n) = O(1)`，该算法**原地工作**。

注意：顺序表 `L` 的空间是**输入本身**，不计入空间复杂度。

**第 4 问：有序时可折半**

可以。有序表中用折半查找（二分查找），每比较一次就把查找区间缩小一半，最多比较 `⌈log2(n+1)⌉` 次，时间复杂度降为 `O(log n)`（要求顺序存储，能随机访问）。

```c
/* L 中数据已按从小到大有序，折半查找 x，找到返回下标，找不到返回 -1 */
int BinSearch(SqList L, int x) {
    int low = 0, high = L.length - 1, mid;
    while (low <= high) {
        mid = (low + high) / 2;       /* 每轮区间规模减半 */
        if (L.data[mid] == x)
            return mid;
        else if (L.data[mid] < x)
            low = mid + 1;            /* 到右半区找 */
        else
            high = mid - 1;           /* 到左半区找 */
    }
    return -1;
}
```

**答案汇总**

1. 最好 `1` 次（`O(1)`）；最坏 `n` 次（`O(n)`）。
2. `ASL_成功 = (n+1)/2`，`T_avg(n) = O(n)`。
3. `S(n) = O(1)`，原地工作。
4. 可以，改成折半查找，`T(n) = O(log n)`，但要求数据**有序且顺序存储**。

**采分点与常见坑**

- 采分点 1：函数必须写全"找不到返回 `-1`"的分支，并给出结构体定义或明确说明 `L.data[i]` 的含义；只有循环没有失败返回值要扣分。
- 采分点 2：`ASL` 必须写出**公式 + 代入 + 求和结果**三步。只写 `(n+1)/2` 不给推理分。
- 采分点 3：回答空间复杂度时必须点明"顺序表本身是输入，不计入"，只写 `O(1)` 容易被认为没理解概念。
- 常见坑 1：把 `ASL` 写成 `n/2`。等概率成功查找的平均比较次数是 `(n+1)/2`，来自等差数列求和，不是 `n/2`。
- 常见坑 2：`mid = (low + high) / 2` 写成 `mid = (low + high + 1) / 2` 后不调整区间边界，导致死循环或死循环式越界。
- 常见坑 3：第 4 问只答"可以"却不说前提。折半查找要求**顺序存储（可随机访问）+ 数据有序**；链表上无法折半，这是常考追问。
- 常见坑 4：把折半的 `O(log n)` 写成 `O(log2 n)` 而不说明底数无关；`O(log2 n)`、`O(log10 n)`、`O(log n)` 在渐进意义上等价。

## 六、简便方法与易错口诀（速算 · 防错）

> 本节把本章能"省时间"和"防掉坑"的招集中在一处：二轮复习与考前只看这一节。每条都写清**适用条件**。

### 6.1 速算招式

| 场景 | 常规做法（慢/繁） | 简便做法（快/稳） | 为什么成立 / 适用条件 |
| --- | --- | --- | --- |
| 单层 `for` 求复杂度 | 逐轮数执行次数 | `for (i = 1; i <= n; i++)` → `O(n)`；`i *= 2` 或 `i /= 2` 型 → `O(log n)` | 判据是**基本语句的执行次数**，不是循环层数；`i *= 2` 型跑 `log2 n + 1` 次，底数不影响阶 |
| 内层上界依赖外层 | 直接拿内外层次数相乘 | 先写求和式再定阶：`j <= i` → 共 `n(n+1)/2` 次 = `O(n^2)`；`j += i` 且 `j <= i` → 每轮只有 1 次，共 `O(n)` | 只有"每轮执行次数与外层无关"才能相乘；步长含 `i`（`j += i`）或条件含 `i`（如 `j * j <= i`）时，代值试 2~3 轮最稳 |
| `while (i * i <= n) i++;` | 展开循环慢慢数 | 直接答 `O(√n)` | 判据是"循环变量以**平方关系**逼近 `n`"（终值 ≈ `√n`）；与 `i *= 2` 的 `O(log n)` 是两回事，本章最高频陷阱 |
| 递归式定阶 | 画完整递归树 | 按 6.2 口诀 3 的四个模板对号入座 | 只适用于形如 `T(n) = aT(n/b) + f(n)` 的"可二分"递归；`T(n) = T(n-1) + T(n-2)` 这类不适用 |
| 空间复杂度 | 把输入数组、代码都算进去 | 只算**辅助空间**；递归看**调用栈最大深度** | 输入/输出与代码空间不计入；循环里反复用同一个临时变量仍是 `O(1)` |
| 斐波那契递归 | 画递归树数结点 | 直接背"时间 `O(2^n)`、空间 `O(n)`" | 时间 = 递归树**结点总数**（每层两路分叉 ⇒ 指数）；空间 = 递归树**高度**（`Fib(n-2)` 在 `Fib(n-1)` 返回前根本不会入栈，栈上只有一条链） |
| `O` / `Ω` / `Θ` 选择题 | 回背定义里的 `C` 与 `n0` | `O` = 上界、`Ω` = 下界、`Θ` = 紧确界；`O(log2 n)`、`O(log10 n)`、`O(log n)` 视为同阶 | 底数只差常数倍；`Θ` 要求上下界同阶，"最坏情况"也能给 `Θ`，记号与"哪种输入"是两个维度 |
| 数量级排序 | 现场比增长快慢 | 背全序：`O(1) < O(log n) < O(n) < O(n log n) < O(n^2) < O(n^3) < O(2^n) < O(n!)` | 只需咬住 `log n < n < n log n < n^2`，其余按"指数 > 多项式 > 对数 > 常数"外推 |
| 顺序查找的 `ASL` | 列 `ASL = Σ pi × ci` 硬算 | 等概率成功：`ASL = (n+1)/2`；失败：`n` 或 `n+1` | 前提是**等概率**（不等概率必须回到加权求和）；失败的取值取决于教材是否把哨兵/越界那次比较计入，按题目所给定义答 |
| 判断"原地工作" | 逐个变量数空间 | 只用常数个临时变量 → `S(n) = O(1)`，即原地工作 | 判据是辅助空间是否随 `n` 增长；开长度 `n` 的辅助数组就是 `O(n)` |
| "与初始状态无关"速记 | 逐个算法现场推导 | 比较次数无关：`折半插入排序`、`简单选择排序`；时间复杂度无关：`简单选择排序`、`堆排序`、`归并排序`；最好能到 `O(n)`：`直接插入排序`、`起泡排序`（基本有序时） | 前两个的比较次数由 `n` 唯一决定（折半插入的比较次数只看下标区间，简单选择排序恒为 `n(n-1)/2`）；后两个在基本有序时逆序对很少，比较与移动都退化为线性 |

> **订正提示（针对给定候选招式第 7 条）**：`归并排序` 只在**时间复杂度**意义上与初始序列无关（最好、最坏、平均都是 `O(n log n)`）；它的**比较次数其实与初始序列有关**——两路归并合并长度为 `a`、`b` 的两个有序段时，比较次数在 `min(a,b)` 与 `a+b-1` 之间浮动。验证：`n = 4` 时，输入 `1 2 3 4` 共比较 4 次，而输入 `1 3 2 4` 共比较 5 次。所以"比较次数与初始序列无关"只写 `折半插入排序` 和 `简单选择排序`（`基数排序` 不做关键字比较），不要把 `归并排序` 算进去。

### 6.2 口诀与记忆钩子

- **口诀 1（看次数不看层数）**："数的是基本语句的次数，不是循环的层数"——三层循环若内层只跑一次，整体可能只是 `O(n)`。
- **口诀 2（折半三档）**："乘二除二对数级，加一减一线性级，平方逼近根号级"——`i *= 2` → `O(log n)`；`i++` → `O(n)`；`i * i <= n` → `O(√n)`。
- **口诀 3（递归四模板）**："减一加常数是线性，减半加常数是对数，对半两路干 `n` 活是 `n log n`，对半两路干常数活是线性"。对应：`T(n) = T(n-1) + O(1)` → `O(n)`；`T(n) = T(n/2) + O(1)` → `O(log n)`；`T(n) = 2T(n/2) + O(n)` → `O(n log n)`；`T(n) = 2T(n/2) + O(1)` → `O(n)`。
- **口诀 4（空间看深度）**："时间数结点，空间看深度"——递归时间 = 递归树结点总数，递归空间 = 调用栈最大深度。
- **口诀 5（数量级全序）**："常数、对数、线性，线性乘对数是分水岭；平方、立方属多项式；指数、阶乘不可行"。
- **口诀 6（与初态无关）**："比较次数无关是折半插入与简单选择；时间复杂度无关是简单选择、堆排、归并；基本有序能到 `O(n)` 的是直接插入与起泡"。

### 6.3 反例黑名单（这些"简便法"是错的）

- ❌ **"循环几层就是几次方"**：看到三层循环就写 `O(n^3)`。正确做法是数基本语句执行次数——`for (i=1;i<=n;i++) for (j=1;j<=i;j=j+i) count++;` 内层恒为 1 趟，整体是 `O(n)`。
- ❌ **"`while (i * i <= n) i++;` 是 `O(log n)`"**：看着像倍增就写对数。正确做法：`i` 终值约 `√n`，执行约 `√n` 次 → `O(√n)`；只有循环变量每轮乘以/除以常数才是 `O(log n)`。
- ❌ **"递归的空间复杂度 = 递归调用总次数"**：于是把斐波那契递归的空间写成 `O(2^n)`。正确做法：空间 = 调用栈**最大深度**，`Fib(n)` 的栈深为 `n`，故 `S(n) = O(n)`。
- ❌ **"空间复杂度要把输入数组算进去"**：于是任何算法都至少 `O(n)`。正确做法：只算**辅助空间**，输入输出与代码不计；只用几个临时变量即为原地工作。
- ❌ **"`O(log2 n)` 比 `O(log n)` 高一档"**：按底数给复杂度排高低。正确做法：底数是常数因子，`log2 n`、`ln n`、`lg n` 同阶，一律写 `O(log n)`。
- ❌ **"`O` 只能用于最坏情况"**：把渐进记号与"最好/最坏/平均"混成一回事。正确做法：`O`/`Ω`/`Θ` 描述的是函数增长的界，与统计哪种输入是两个维度——平均情况同样可以写 `O(n)`。
- ❌ **"`T(n) = 2T(n/2) + O(1)` 是 `O(n log n)`"**：见到"对半分两路"就乘 `log n`。正确做法：每层只干常数活、共 `log n` 层、结点总数 `n` ⇒ `O(n)`；要得到 `O(n log n)`，每层的合并必须花 `O(n)`。
