# 第 3 章 栈、队列和数组

> 大纲对应：三、栈、队列和数组
> 408 权重：选择题 1~2 道；循环队列与数组地址计算是高频小计算

本章是「线性表的两种受限形态」+「数组与压缩存储」。它本身不难，但**约定多、边界多、公式多**，是 408 里最典型的「会做但容易错」的章节。第一轮/强化阶段的目标不是背公式，而是：**任何一道题先问自己「题目用的是哪种约定」，再套公式**。循环队列判满、栈顶指针约定、数组下标起点、压缩存储映射，四个坑都出在「约定没看清」上。

## 一、本章知识框架

- 栈、队列和数组
  - 栈 `Stack`
    - 逻辑结构：操作受限的线性表，只允许在**栈顶**插入/删除，`LIFO`（后进先出）
    - 术语：栈顶 `top`、栈底 `bottom`、入栈 `Push`、出栈 `Pop`、上溢 `Overflow`、下溢 `Underflow`
    - 顺序存储：顺序栈
      - `top` 指向栈顶元素（初始 `-1`）／`top` 指向栈顶元素的下一个位置（初始 `0`）
      - 判空、判满、元素个数公式随约定而变
      - 共享栈：两个顺序栈共享一段空间，栈底在两端、相向增长；判满 `top0 + 1 == top1`
    - 链式存储：链栈
      - 栈顶在链表头部，入栈 = 头插法；一般不带头结点
      - 不存在「栈满」（除内存耗尽），只有栈空
  - 队列 `Queue`
    - 逻辑结构：操作受限的线性表，**队尾入队、队头出队**，`FIFO`（先进先出）
    - 术语：队头 `front`、队尾 `rear`、入队 `EnQueue`、出队 `DeQueue`
    - 顺序存储：顺序队列与循环队列
      - 顺序队列的「假溢出」：`rear` 到底但前端有空位
      - 循环队列用取模把存储空间首尾相接
      - 队空统一为 `front == rear`；队满三种判定：牺牲一个单元／设 `size`／设 `tag`
      - 元素个数公式：`(rear - front + MaxSize) % MaxSize`
    - 链式存储：链队列
      - 带头结点，`front` 指向头结点、`rear` 指向队尾结点
      - 出队最后一个元素时要**把 `rear` 拉回 `front`**，否则 `rear` 悬空
    - 双端队列 `Deque`
      - 输入受限（只允许一端插入、两端删除）／输出受限（只允许一端删除、两端插入）
      - 判断某输出序列能否由受限双端队列得到
  - 栈和队列的应用
    - 栈：括号匹配、表达式求值（中缀转后缀、后缀求值）、递归与函数调用栈、进制转换、迷宫求解、`DFS`
    - 队列：树的层次遍历、图的 `BFS`、缓冲区、打印任务队列、各种调度
  - 数组
    - 数组是线性表的推广；一维数组是线性表，`m` 维数组是「元素为 `m-1` 维数组」的线性表
    - 一旦定义，维数与维界不变 → 只做存取与修改 → 采用顺序存储
    - 行优先存储（C 语言）与列优先存储（Fortran/MATLAB）的地址计算
    - 下标从 `0` 开始还是从 `1` 开始是最大的坑
  - 特殊矩阵的压缩存储
    - 对称矩阵：存下三角，`k` 与 `i`、`j` 的映射；共 `n(n+1)/2` 个元素
    - 三角矩阵：下（上）三角 + 1 个常数单元
    - 三对角（带状）矩阵：`|i - j| <= 1`，共 `3n - 2` 个非零元素
    - 稀疏矩阵：三元组表（顺序）、十字链表（链式）；转置算法思想（普通转置 / 快速转置）
    - 考点本质：把二维下标 `(i, j)` 映射成一维下标 `k` —— **先确定下标起点与存储次序，再数清「前面有多少个元素」**

## 二、概念详解

### 3.1 栈和队列的基本概念

- **为什么要有栈和队列**：线性表允许在任意位置插入删除，太"自由"了。但很多问题的数据访问顺序本身就是受限的——函数调用必须后调用的先返回，打印任务必须先来的先打印。于是把「插入和删除的位置」加以限制，就得到了两种新的逻辑结构。**注意：限制的是操作位置，不是数据元素之间的关系**，所以栈和队列仍然是线性表，元素之间仍是前驱后继的一对一关系。
- **栈 `Stack`**：
  - 只允许在一端（**栈顶 `top`**）进行插入和删除，另一端固定不动，称为**栈底 `bottom`**。
  - 特性：`LIFO`（`Last In First Out`，后进先出）。
  - 插入叫**入栈 / 压栈** `Push`，删除叫**出栈 / 退栈** `Pop`。
  - **卡特兰数结论**：`n` 个不同元素依次入栈（入栈序列固定），可能的出栈序列个数为 `C(2n, n) / (n + 1)`。前几个值要记牢：`n = 1 → 1`，`2 → 2`，`3 → 5`，`4 → 14`，`5 → 42`。
- **队列 `Queue`**：
  - 只允许在一端（**队尾 `rear`**）插入、在另一端（**队头 `front`**）删除。
  - 特性：`FIFO`（`First In First Out`，先进先出）。
- **栈与队列的共性**：都是操作受限的线性表；插入与删除的时间复杂度都是 `O(1)`；都不支持"随机访问中间元素"。
- **408 怎么考 / 常见坑**：
  - 最爱考**出栈序列合法性**：给定入栈序列 `1, 2, 3, 4`，问哪个输出序列不可能。判断法见「三、易混对比表」。
  - 「栈和队列是线性表吗？」——**是**，是操作受限的线性表；题目若说"栈是一种特殊的线性表"，正确。
  - 「`n` 个元素出栈序列有多少种」的答案与元素是否**互不相同**有关：若元素全部相同则只有 `1` 种。看到"互不相同"才能用卡特兰数。
  - 入栈序列本身不一定是 `1, 2, ..., n` 这种递增形式，题里给什么就用什么，卡特兰数只算**个数**，具体哪个序列合法必须模拟。

### 3.2 栈的顺序存储结构

- **是什么**：用一段连续空间 `data[0 .. MaxSize-1]` 加一个栈顶指针 `top` 来实现栈。因为是"只在顶端动"，所以顺序存储非常自然，不需要挪动元素。
- **两种约定（本章第一大坑）**：

| 约定 | `top` 初值 | 判空 | 判满 | 入栈 | 出栈 | 元素个数 |
| --- | --- | --- | --- | --- | --- | --- |
| 甲：`top` 指向**栈顶元素** | `top = -1` | `top == -1` | `top == MaxSize - 1` | `data[++top] = x` | `x = data[top--]` | `top + 1` |
| 乙：`top` 指向**栈顶元素的下一个位置** | `top = 0` | `top == 0` | `top == MaxSize` | `data[top++] = x` | `x = data[--top]` | `top` |

- **怎么记**：约定甲里 `top` 本身就是"有效元素的下标"，所以空栈只能是 `-1`；约定乙里 `top` 是"下一个空位"，所以空栈是 `0`。**判满、元素个数都是顺着这个含义推出来的，不要死背。**
- **上溢与下溢**：
  - **上溢 `Overflow`**：栈满时还要入栈。顺序栈的容量是固定的，所以**上溢是顺序栈的固有缺陷**。
  - **下溢 `Underflow`**：栈空时还要出栈。下溢通常说明程序逻辑有错，很多教材把它当作一种错误状态而非"正常现象"。
- **共享栈（两栈共享空间）**：
  - **为什么**：一个数组放两个栈，让两个栈从两端向中间生长，只有在"整个数组都被占满"时才上溢，把空间利用率提到最高。典型场景：两个栈的使用量此消彼长。
  - 设 0 号栈底在 `data[0]`，1 号栈底在 `data[MaxSize-1]`，`top0 = -1`、`top1 = MaxSize`。
  - 0 号栈入栈：`data[++top0] = x`；1 号栈入栈：`data[--top1] = x`。
  - **判满条件**：`top0 + 1 == top1`（即两个指针相邻，中间再放不下元素）。
  - 判空：`top0 == -1` 表示 0 号栈空；`top1 == MaxSize` 表示 1 号栈空。
  - 若改用约定乙（`top0 = 0`、`top1 = MaxSize - 1`），则判满条件写成 `top0 == top1 + 1`。**判满条件的形状取决于约定，先看题目给的初值。**
- **408 怎么考 / 常见坑**：
  - 题干给 `top` 初值，问"栈空 / 栈满时 `top` 等于多少"，或给一串操作问最后 `top` 的值——**先判约定再算**。
  - 共享栈的判满条件 `top0 + 1 == top1` 必须能默写；有些题会写成 `top0 == top1` 来骗你。
  - 有一类题："入栈序列长度为 `n`，要求栈的容量至少多大才能得到某出栈序列"——即求整个过程中栈内元素的最大个数，不要误答成 `n`。

### 3.3 栈的链式存储结构（链栈）

- **是什么/为什么**：用单链表实现栈，**栈顶放在链表头部**，入栈就是**头插法**。之所以把栈顶放在头部，是因为头插/头删都是 `O(1)`，而放在尾部则出栈需要找前驱，退化成 `O(n)`。
- **关键点**：
  - 通常**不带头结点**，`top` 直接指向栈顶结点（第一个数据结点），判空为 `top == NULL`。
  - 入栈：`s->next = top; top = s;`
  - 出栈：`x = top->data; p = top; top = top->next; free(p);`
  - **不存在栈满**（只要内存没耗尽），因此**不会有上溢**；只有栈空时出栈的下溢。
  - 优点：便于多个栈共享空间、无需预先估计容量；缺点：每个元素多一个指针域，且不能随机访问。
- **408 怎么考 / 常见坑**：
  - 常与顺序栈对比出选择题：链栈"不会上溢"、"不需要预先分配容量"；顺序栈"可以随机访问"、"有上溢风险"。
  - 有些题给带头结点的链栈，那么判空条件是 `top->next == NULL`，**别混**。

### 3.4 队列的顺序存储结构（重点：循环队列）

- **顺序队列与假溢出**：
  - 设 `front` 指向队头元素、`rear` 指向队尾元素的下一个位置，初始 `front = rear = 0`。
  - 每出队一个元素 `front` 后移，每入队一个元素 `rear` 后移，**两个指针都只增不减**。
  - 于是当 `rear == MaxSize` 时明明数组前面还空着一大片（因为出过队），却无法再入队——这就是**假溢出**（`false overflow`）。
  - **为什么会有假溢出**：因为把"线性"的数组当队列用，指针单向前进，空间用完却没回收。
- **循环队列**：
  - **怎么来的**：把数组在逻辑上弯成一个环，`rear` 到底后回到下标 `0`。用取模实现：
    - 入队：`data[rear] = x; rear = (rear + 1) % MaxSize;`
    - 出队：`x = data[front]; front = (front + 1) % MaxSize;`
  - **新的问题**：回到环上以后，队空和队满都会出现 `front == rear`，无法区分。于是有三种判定方案。

| 方案 | 队满判定 | 队空判定 | 最多存几个 | 特点 |
| --- | --- | --- | --- | --- |
| ① 牺牲一个存储单元 | `(rear + 1) % MaxSize == front` | `front == rear` | `MaxSize - 1` | 最常用、最省事；浪费一个单元 |
| ② 设 `size`（元素个数计数器） | `size == MaxSize` | `size == 0` | `MaxSize` | 不浪费空间；入队 `size++`、出队 `size--` |
| ③ 设 `tag` 标记 | `front == rear && tag == 1` | `front == rear && tag == 0` | `MaxSize` | 不浪费空间；每次入队置 `tag = 1`、出队置 `tag = 0` |

  - **元素个数公式（三种方案通用）**：`元素个数 = (rear - front + MaxSize) % MaxSize`
    - 记忆法：`rear - front` 可能是负数（绕环了），加一个 `MaxSize` 保证非负，再取模。
  - **`front`、`rear` 指向的两种约定**：

| 约定 | `front` 指向 | `rear` 指向 | 入队 | 出队 | 元素个数 |
| --- | --- | --- | --- | --- | --- |
| 甲（王道默认） | 队头元素 | 队尾元素的**下一个位置** | 先存 `data[rear]`，再 `rear = (rear+1) % MaxSize` | 先取 `data[front]`，再 `front = (front+1) % MaxSize` | `(rear - front + MaxSize) % MaxSize` |
| 乙 | 队头元素的**前一个位置** | 队尾元素 | 先 `rear = (rear+1) % MaxSize`，再存 `data[rear]` | 先 `front = (front+1) % MaxSize`，再取 `data[front]` | `(rear - front + MaxSize) % MaxSize` |

  - 关键提醒：**约定变了，判空判满的条件形状不变（队空仍是 `front == rear`、牺牲单元法仍是 `(rear+1)%MaxSize == front`），变的只是"存取与移指针"的先后顺序**。所以拿到题先看初始状态和"指向"的定义。

- 王道教材的循环队列类型定义与基本操作（约定甲 + 牺牲一个单元）：

```c
#define MaxSize 50
typedef struct {
    int data[MaxSize];
    int front, rear;          /* front 指向队头元素，rear 指向队尾元素的下一个位置 */
} SqQueue;

void InitQueue(SqQueue *Q) {
    Q->front = Q->rear = 0;
}

int QueueEmpty(SqQueue *Q) {
    return (Q->front == Q->rear);
}

int EnQueue(SqQueue *Q, int x) {
    if ((Q->rear + 1) % MaxSize == Q->front)   /* 队满，牺牲一个单元 */
        return 0;
    Q->data[Q->rear] = x;
    Q->rear = (Q->rear + 1) % MaxSize;
    return 1;
}

int DeQueue(SqQueue *Q, int *x) {
    if (Q->front == Q->rear)                   /* 队空 */
        return 0;
    *x = Q->data[Q->front];
    Q->front = (Q->front + 1) % MaxSize;
    return 1;
}
```

- **408 怎么考 / 常见坑**：
  - 高频小计算：给 `MaxSize`、`front`、`rear`，求元素个数或还能入队几个。**先用公式算元素个数，再算剩余可入队数**。
  - 牺牲单元法下**最多只能存 `MaxSize - 1` 个**，题目常在这里设陷阱（问"能存 `MaxSize` 个"就是错的）。
  - 有些题给"队列中元素个数为 `k`"，反求 `front`／`rear` 的取值，答案可能是**多个**（因为环上对称），要看选项来判断。
  - 顺序队列与循环队列要分清：**顺序队列存在假溢出，循环队列不存在假溢出**。

### 3.5 队列的链式存储结构（链队列）

- **是什么/为什么**：队列用单链表实现，需要**两个指针**：队头 `front` 和队尾 `rear`。之所以要维护 `rear`，是因为出队发生在头部（`O(1)`），而如果只在头部维护一个指针，入队就要遍历到尾部变成 `O(n)`。
- **关键点（带头结点）**：
  - `front` 指向**头结点**（不是第一个数据结点！），`rear` 指向**队尾结点**（即最后一个数据结点）。
  - 判空：`front == rear`（此时两者都指向头结点）。
  - 入队：在 `rear` 后面插入新结点，`rear` 后移。**队满只在内存耗尽时发生。**
  - 出队：删除 `front->next` 所指结点，`front->next` 后移。
  - **最高频的坑**：当出队的是**最后一个数据结点**时，必须把 `rear` 重新指回 `front`（`rear = front`），否则 `rear` 会指向已被 `free` 掉的结点，成为悬空指针。

```c
typedef struct LinkNode {
    int data;
    struct LinkNode *next;
} LinkNode;

typedef struct {
    LinkNode *front, *rear;    /* 带头结点：front 指头结点，rear 指队尾结点 */
} LinkQueue;

void InitQueue(LinkQueue *Q) {                 /* 初始化为空队列 */
    Q->front = Q->rear = (LinkNode *)malloc(sizeof(LinkNode));
    Q->front->next = NULL;
}

void EnQueue(LinkQueue *Q, int x) {            /* 入队：尾插 */
    LinkNode *s = (LinkNode *)malloc(sizeof(LinkNode));
    s->data = x;
    s->next = NULL;
    Q->rear->next = s;
    Q->rear = s;
}

int DeQueue(LinkQueue *Q, int *x) {            /* 出队：头删 */
    if (Q->front == Q->rear)                   /* 队空 */
        return 0;
    LinkNode *p = Q->front->next;
    *x = p->data;
    Q->front->next = p->next;
    if (Q->rear == p)                          /* 关键：删的是最后一个结点 */
        Q->rear = Q->front;
    free(p);
    return 1;
}
```

- **不带头结点的链队列**：判空为 `front == NULL`（等价于 `rear == NULL`）；入队第一个元素时 `front = rear = s`；出队最后一个元素时 `front = rear = NULL`。这两种写法都要能读懂，题目给哪种就用哪种。
- **408 怎么考 / 常见坑**：
  - 选择题常问："链队列出队时 `rear` 指针是否需要修改"——**需要，仅当出队的是最后一个元素时**。
  - 对比题：链队列"适合元素个数变化大、无法预估最大长度"的场景；顺序队列（循环队列）"需要预先分配固定空间"。
  - 判断"队空"条件：带头结点是 `front == rear`，不带头结点是 `front == NULL`，**看清头结点有无**。

### 3.6 双端队列 `Deque`

- **是什么**：`Double-Ended Queue`，两端都可以插入和删除的线性表。它是栈和队列的推广：
  - 只允许一端插入删除 → 退化成**栈**；
  - 一端只插入、另一端只删除 → 退化成**队列**。
- **两种受限形式**：
  - **输入受限的双端队列**：只允许在一端插入，但两端都可以删除。
  - **输出受限的双端队列**：只允许在一端删除，但两端都可以插入。
- **判断某输出序列是否合法（方法）**：
  1. 画一个两端开口的"通道"，输入序列按顺序从**允许插入的那端**依次放入；
  2. 对目标输出序列的每一个元素，判断此刻它是否在某一端（只有端点的元素才能被取出）；
  3. 若某一步目标元素既不在左端也不在右端、或该端不允许删除，则序列非法；
  4. 技巧：**先把「栈能产生的序列」筛一遍**——栈合法的序列，输出受限的双端队列一定也能产生（因为双端队列能力更强）；只有"栈得不到"的序列才需要用双端队列单独模拟。
- **自编小例（验证方法）**：输入受限的双端队列（只允许在右端插入，两端都可删除），输入序列 `1, 2, 3, 4`。判断 `4, 2, 3, 1` 是否合法？
  - 要第一个输出 `4`，必须先把 `1, 2, 3, 4` 全部从右端插入，此时队列左右排列为 `1, 2, 3, 4`；
  - 从右端删除 `4` 后，剩下的排列是 `1, 2, 3`；
  - 第二个要输出 `2`，但 `2` 在中间，只能先从左端删除 `1`（那就先输出了 `1`）或从右端删除 `3`（输出了 `3`）——矛盾；
  - 所以 `4, 2, 3, 1` **不合法**。
- **408 怎么考 / 常见坑**：
  - 考法是"下列哪个序列不能由输入受限（或输出受限）的双端队列得到"，本质是**模拟 + 排除**，没有公式，别硬套卡特兰数。
  - 常见结论：栈能产生的所有序列，输出受限双端队列都能产生；但输入受限双端队列**不一定**能产生栈的全部序列，要具体模拟。
  - 也别把"双端队列"当成"两个栈"或"两个队列"——它是**一段两端开口的连续空间**。

### 3.7 栈和队列的应用

#### （1）括号匹配

- **为什么用栈**：括号的嵌套是"最后出现的左括号最先被匹配上"，天然是 `LIFO`。
- **算法**：扫描字符序列；遇左括号入栈；遇右括号则弹出栈顶并检查是否配对（不配或栈已空则失败）；扫描结束后**栈必须为空**，否则左括号多余。
- **408 怎么考 / 常见坑**：只支持一种括号时判断简单；支持 `()[]{}` 三种时必须**逐个配对判断**，最容易漏掉"栈空时来右括号"和"扫描完栈不空"这两种失败情形。

#### （2）表达式求值

- **三种表示法**：
  - **中缀表达式**：运算符在两个操作数中间，如 `A + B * (C - D) - E / F`。
  - **后缀表达式（逆波兰式）**：运算符在操作数之后，如 `A B C D - * + E F / -`。
  - **前缀表达式（波兰式）**：运算符在操作数之前。
- **中缀 → 后缀（手算：加括号法）**：
  1. 按运算符优先级和结合性给每个运算加括号，使每个括号内只有一个运算符；
  2. 把每个运算符移到其所在括号的**右括号之前**（前缀则移到左括号之前）；
  3. 去掉所有括号，得到后缀表达式。
  - 例：`A + B * (C - D) - E / F`
    - 加括号：`((A + (B * (C - D))) - (E / F))`
    - 移运算符到右括号前：`((A (B (C D) -) *) + (E F) /) -`
    - 去括号：`A B C D - * + E F / -`
- **中缀 → 后缀（计算机算法：一个栈）**：从左到右扫描：
  - 遇**操作数**：直接输出；
  - 遇**运算符** `op`：栈空或栈顶是 `(` 时 `op` 入栈；否则当栈顶运算符优先级 `>= op` 时不断弹出并输出，然后把 `op` 入栈；
  - 遇 `(`：直接入栈；
  - 遇 `)`：不断弹出并输出，直到弹出 `(` 并把它丢弃；
  - 扫描结束后，把栈中剩余运算符依次弹出输出。
  - **优先级**：`*` `/` 高于 `+` `-`；栈内的 `(` 视为**最低**优先级（保证它不被提前弹出）。
- **后缀表达式求值（一个栈）**：从左到右扫描：
  - 遇**操作数**：入栈；
  - 遇**运算符**：从栈中弹出**两个**操作数，**先弹出的是右操作数、后弹出的是左操作数**，运算后把结果压回栈；
  - 扫描结束时，栈顶元素就是结果。
- **408 怎么考 / 常见坑**：
  - 手算中缀转后缀是高频小计算题，**务必用"加括号法"自己练到不出错**；选择题常给 4 个后缀表达式让你挑正确的。
  - 最经典的坑：**后缀求值时两个操作数的顺序容易颠倒**。记住"先弹出的是右操作数"，减法与除法尤其致命。
  - 单目运算符（如 `-x`）与常数要以题意为准，不要自己加戏。
  - 注意区分"栈内优先级"与"栈外优先级"：手算时不必区分，写算法代码时必须区分。

#### （3）递归与函数调用栈

- **怎么来的**：递归函数每次调用都要保存"返回地址 + 参数 + 局部变量 + 部分寄存器"，这些信息打包成一个**栈帧 `stack frame`** 压入系统栈。因为最后调用的函数最先返回，所以用栈管理。
- **关键点**：递归深度 = 系统栈中同时存在的栈帧数；递归调用次数 ≠ 递归深度。**递归必须能转化为用栈模拟的非递归形式**，这正是"栈的应用"在大题里的落点（如二叉树遍历的非递归写法）。
- **408 怎么考 / 常见坑**：常问"递归调用过程中栈的变化"或"递归深度是多少"；也常与"函数调用栈可能溢出（栈溢出）"结合考。

#### （4）进制转换

- **为什么用栈**：十进制数 `N` 转 `r` 进制用"**除 `r` 取余、逆序排列**"——余数是**从低位到高位**产生的，而输出需要**从高位到低位**，于是正好把余数依次入栈、再依次出栈。
- **例子**：`N = 1348` 转八进制 → 依次得余数 `4, 0, 5, 2`，逆序即 `2504`。

#### （5）迷宫求解

- **思想**：从入口出发，按某方向试探；能走就前进一步并记入路径（压栈），走不通就回退一步（弹栈）换方向——这是**回溯法**，用栈保存当前路径。

#### （6）其他应用（408 常考的"场景题"）

| 场景 | 用栈还是队列 | 原因 |
| --- | --- | --- |
| 树的层次遍历 | 队列 | 按"层"的先后顺序处理，先来的先展开 |
| 图的 `BFS`（广度优先搜索） | 队列 | 按距源点的距离递增访问 |
| 图的 `DFS`（深度优先搜索） | 栈（或递归） | 一条路走到底再回退 |
| 括号匹配、表达式求值 | 栈 | 嵌套与后进先出 |
| 打印机任务队列、缓冲区、键盘输入缓冲 | 队列 | 先到先服务，保证公平与顺序 |
| 操作系统中的作业/进程调度 | 队列 | 一般按到达顺序排队 |
| 中缀转后缀、函数调用、进制转换 | 栈 | 逆序处理 |

- **408 怎么考 / 常见坑**：这类"某场景该用什么结构"的判断题几乎每年都有；判别关键只有一句：**需要"后来先处理"就用栈，需要"先来先处理"就用队列**。

### 3.8 多维数组的存储

- **数组与线性表的关系**：
  - 一维数组就是线性表；
  - `m` 维数组可以看作"每个数据元素是一个 `m-1` 维数组"的线性表（递归定义）；
  - 数组一旦定义，**维数与各维的长度不再改变**，所以除初始化和销毁外，只有「存取元素」和「修改元素」两种操作，**不进行插入和删除** → 因此**必然采用顺序存储**（顺序存储才支持随机存取）。
- **一维数组地址**：设每个元素占 `L` 个字节，`LOC` 表示存储地址，则
  - `LOC(a_i) = LOC(a_0) + i * L`（下标从 `0` 开始）
  - `LOC(a_i) = LOC(a_1) + (i - 1) * L`（下标从 `1` 开始）
- **二维数组（`m` 行 `n` 列，下标从 `0` 开始）**：
  - **行优先**（`Row Major`，C/C++、Pascal 采用）：先存第 `0` 行，再存第 `1` 行……
    - `LOC(a[i][j]) = LOC(a[0][0]) + (i * n + j) * L`
    - 含义：前面有 `i` 个整行（每行 `n` 个）加上本行前面的 `j` 个。
  - **列优先**（`Column Major`，Fortran、MATLAB 采用）：先存第 `0` 列，再存第 `1` 列……
    - `LOC(a[i][j]) = LOC(a[0][0]) + (j * m + i) * L`
    - 含义：前面有 `j` 个整列（每列 `m` 个）加上本列前面的 `i` 个。
- **下标从 `1` 开始时（`A[1..m][1..n]`）**：
  - 行优先：`LOC(a[i][j]) = LOC(a[1][1]) + ((i - 1) * n + (j - 1)) * L`
  - 列优先：`LOC(a[i][j]) = LOC(a[1][1]) + ((j - 1) * m + (i - 1)) * L`
- **记忆的核心思想（比背公式可靠）**：**"前面有多少个元素" + 起始地址**。
  - 行优先数"整行 + 本行前几个"；列优先数"整列 + 本列前几个"。
  - 每行有 `n` 个元素，每列有 `m` 个元素——**行优先乘的是列数 `n`，列优先乘的是行数 `m`**，这是最容易记反的地方。
- **408 怎么考 / 常见坑**：
  - 三类坑，全在"约定"上：**（a）行优先还是列优先？（b）下标从 `0` 还是从 `1` 开始？（c）每个元素占几个字节 `L`？**
  - 题目里的 `A[3][5]` 有时表示"3 行 5 列"、有时表示"下标为 `3` 和 `5` 的元素"，必须结合上下文判断。**若题中说"`A` 的行下标为 `0..m-1`，列下标为 `0..n-1`"，则行列数就明确了。**
  - 求"元素个数"时别忘了乘 `L` 换算成字节数；求"地址"时注意最终要加偏移 `* L`，许多错误都是忘了乘 `L` 或忘了加基址。
  - 三维及以上数组的地址计算：仍是"前面有多少个元素"的思路，按维依次展开，例如 `A[m1][m2][m3]`（下标从 `0` 开始、行优先）有 `LOC(a[i][j][k]) = LOC(a[0][0][0]) + (i * m2 * m3 + j * m3 + k) * L`。

### 3.9 特殊矩阵的压缩存储

- **为什么要压缩**：矩阵中若有很多**相同元素或零元素**，把它们全部存下来是浪费。压缩存储的思想是：**多个相同的元素只分配一个存储空间；零元素不分配空间**。代价是失去"按下标直接定位"的简单性，需要一套**下标映射公式**把二维下标 `(i, j)` 换算成一维下标 `k`。
- **总思路（对所有矩阵通用）**：先确定"**存哪些元素**"、"**按什么次序存**"、"**一维数组下标从几开始**"，然后**数清楚排在该元素前面的元素个数**，就是 `k`。下面的公式统一采用**矩阵下标从 `1` 开始、一维数组 `B` 下标从 `0` 开始**（王道教材的约定）。

#### （1）对称矩阵

- **定义**：`n` 阶方阵满足 `a[i][j] == a[j][i]`（`1 <= i, j <= n`）。
- **存法**：只存**下三角（含主对角线）**，共 `n(n+1)/2` 个元素，按**行优先**放入一维数组 `B[0 .. n(n+1)/2 - 1]`。
- **映射公式**：
  - 当 `i >= j`（元素在下三角）：`k = i * (i - 1) / 2 + j - 1`
    - 含义：前 `i - 1` 行共有 `1 + 2 + ... + (i - 1) = i(i-1)/2` 个元素，本行前面有 `j - 1` 个。
  - 当 `i < j`（元素在上三角）：利用对称性 `a[i][j] = a[j][i]`，把 `i`、`j` **交换后**代入上式：`k = j * (j - 1) / 2 + i - 1`
  - **反向求值**：给定 `k` 求 `(i, j)` 时，先求满足 `i(i-1)/2 <= k < (i+1)i/2` 的 `i`，即 `i = ⌈(sqrt(8k + 1) - 1) / 2⌉`，再算 `j = k - i(i-1)/2 + 1`，然后按 `k` 是否落在下三角判断要不要交换 `i`、`j`。
- **若矩阵下标从 `0` 开始**（`0 <= i, j <= n-1`），下三角公式变为 `k = i * (i + 1) / 2 + j`。**两套公式差一个偏移，做题先看下标起点。**

#### （2）三角矩阵

- **下三角矩阵**：上三角（不含主对角线）的元素全是同一个常数 `c`。存**下三角**的全部元素，再**额外加 1 个单元**存常数 `c`，共 `n(n+1)/2 + 1` 个存储单元。
  - 下三角元素映射与对称矩阵的 `i >= j` 情形**完全相同**：`k = i(i-1)/2 + j - 1`；
  - 上三角元素一律映射到最后一个单元：`k = n(n+1)/2`。
- **上三角矩阵**：下三角元素全是同一常数。存**上三角**全部元素 + 1 个常数单元，按**行优先**：
  - 当 `i <= j`：`k = (i - 1) * n - (i - 1)(i - 2) / 2 + (j - i)`
    - 含义：前 `i - 1` 行元素个数为 `n + (n-1) + ... + (n-i+2)`，本行前面有 `j - i` 个；
  - 当 `i > j`：`k = n(n+1)/2`（常数单元）。
  - 也可记为 `k = (i - 1)(2n - i + 2) / 2 + (j - i)`（与上式等价）。
- **408 怎么考 / 常见坑**：三角矩阵与对称矩阵最容易混。**区别只有一句：对称矩阵上三角"不用存"（靠对称性算出），三角矩阵上三角"存一个常数"（多占 1 个单元，总数是 `n(n+1)/2 + 1`）。**

#### （3）三对角矩阵（带状矩阵）

- **定义**：所有非零元素都集中在以主对角线为中心的带状区域，即 `|i - j| <= 1` 时 `a[i][j]` 可能非零，其余为 `0`。
- **元素个数**：第 `1` 行和第 `n` 行各 `2` 个，其余每行 `3` 个 → 共 `2 + 2 + 3(n - 2) = 3n - 2` 个非零元素。
- **存法**：按**行优先**把非零元素存入 `B[0 .. 3n - 3]`。
- **映射公式**（`1 <= i, j <= n`，`|i - j| <= 1`）：`k = 2i + j - 3`
  - 含义：前 `i - 1` 行共 `3(i - 1) - 1 = 3i - 4` 个元素，本行前面有 `j - i + 1` 个，相加即得。
  - 验证：`(1,1) → 0`，`(1,2) → 1`，`(2,1) → 2`，`(2,2) → 3`，`(2,3) → 4`。
- **反向求值**（给 `k` 求 `(i, j)`）：`i = (k + 1) / 3 + 1`（整除），`j = k - 2i + 3`。
  - 验证：`k = 0 → i = 1, j = 1`；`k = 4 → i = 2, j = 3`；`k = 5 → i = 3, j = 2`。

#### （4）稀疏矩阵

- **定义**：非零元素个数 `t` 远小于矩阵元素总数 `m * n`（一般 `t / (m*n) <= 0.05` 时称稀疏）。**稀疏是"非零元素比例很低"的意思，不是"矩阵很小"。**
- **顺序存储：三元组表**。把每个非零元素存成 `(行下标, 列下标, 值)` 三元组，并额外记录总行数、总列数、非零元素个数。三元组通常**按行优先（行下标递增，同行列下标递增）排列**，这样才便于处理。
- **三元组表的转置思想**：
  - **普通转置（按列扫描）**：对原矩阵的每一列 `col`（`0 <= col < n`），扫描全部 `t` 个三元组，把列下标等于 `col` 的取出、行列互换后依次存入新三元组表。时间复杂度 `O(n * t)`。
  - **快速转置（列计数 + 起始位置）**：先用一趟扫描统计每一列的非零元素个数 `num[col]`，再算每列在转置结果中的起始位置 `cpos[col]`（`cpos[0] = 0`，`cpos[col] = cpos[col-1] + num[col-1]`），然后一趟扫描原三元组表，按 `cpos` 把元素直接放到目标位置并让 `cpos` 自增。时间复杂度 `O(n + t)`，代价是需要两个辅助数组 `num` 和 `cpos`。
- **链式存储：十字链表 `Orthogonal List`**。
  - 每个非零元素是一个结点，含 `(行, 列, 值, right, down)` 五个域：`right` 指向同行下一个非零元素，`down` 指向同列下一个非零元素。
  - 再为每一行设一个行头结点、每一列设一个列头结点（通常把两类头结点也链成两个循环链表）。
  - **优点**：插入、删除非零元素时不必大量移动元素，适合"非零元素个数经常变化"的矩阵运算（如矩阵加法）。
- **408 怎么考 / 常见坑**：
  - 对称/三角/三对角矩阵考**计算**（给 `(i, j)` 求 `k` 或反过来）；稀疏矩阵考**概念与结构对比**（三元组表 vs 十字链表、两种转置的时间复杂度）。
  - "压缩存储后还能随机存取吗？"——**能随机存取（可以下标换算），但只对能建立映射公式的规则矩阵成立**；稀疏矩阵的三元组表**不能**随机存取，查找某个元素需要顺序扫描。
  - 十字链表是"链式存储"，三元组表是"顺序存储"，别把两者混为一谈。
  - 计算压缩后的数组大小时，别忘了对称矩阵的 `n(n+1)/2`、三角矩阵的 `n(n+1)/2 + 1`、三对角的 `3n - 2` 这些精确数字。

## 三、易混对比表

### 表 1　顺序栈 `top` 的两种约定

| 项目 | 约定甲：`top` 指栈顶元素 | 约定乙：`top` 指栈顶元素的下一个位置 |
| --- | --- | --- |
| `top` 初值 | `-1` | `0` |
| 判空 | `top == -1` | `top == 0` |
| 判满 | `top == MaxSize - 1` | `top == MaxSize` |
| 入栈 | `data[++top] = x` | `data[top++] = x` |
| 出栈 | `x = data[top--]` | `x = data[--top]` |
| 元素个数 | `top + 1` | `top` |
| 取栈顶 | `data[top]` | `data[top - 1]` |

### 表 2　循环队列队满判定的三种方案

| 方案 | 队空 | 队满 | 最多元素个数 | 需要额外变量 | 代价 |
| --- | --- | --- | --- | --- | --- |
| 牺牲一个存储单元 | `front == rear` | `(rear + 1) % MaxSize == front` | `MaxSize - 1` | 无 | 浪费 1 个单元 |
| 设 `size` 计数器 | `size == 0` | `size == MaxSize` | `MaxSize` | `size` | 每次入队/出队多一次维护 |
| 设 `tag` 标记 | `front == rear && tag == 0` | `front == rear && tag == 1` | `MaxSize` | `tag` | 需在两种操作中分别置位 |

> 三种方案的**元素个数公式都是** `(rear - front + MaxSize) % MaxSize`。

### 表 3　顺序存储 vs 链式存储

| 项目 | 顺序栈 | 链栈 | 循环队列 | 链队列 |
| --- | --- | --- | --- | --- |
| 空间 | 预先固定 `MaxSize` | 动态分配 | 预先固定 `MaxSize` | 动态分配 |
| 上溢 | 会（栈满） | 不会（除非内存耗尽） | 会（队满） | 不会（除非内存耗尽） |
| 随机存取 | 支持 | 不支持 | 支持 | 不支持 |

## 四、例题精练（3 道）

### 例题 1（选择题）

> **题目**（自编，408 风格）：元素 `1, 2, 3, 4` 依次入栈，入栈过程中允许随时出栈。下列序列中，**不可能**是出栈序列的是（　　）
>
> A. `1, 4, 3, 2`
> B. `2, 3, 4, 1`
> C. `3, 1, 2, 4`
> D. `4, 3, 2, 1`

**答案：C**

**逐项解析**（用模拟法：按目标序列依次取元素，栈顶不是它就让还没入栈的元素继续入栈）：

- **A. `1, 4, 3, 2` —— 合法。**
  `1` 入栈后立即出栈（得 `1`）；`2`、`3`、`4` 依次入栈；此时栈内自底向上为 `2, 3, 4`，栈顶是 `4`，连续出栈得 `4, 3, 2`。完整出栈序列 `1, 4, 3, 2`。✔
- **B. `2, 3, 4, 1` —— 合法。**
  `1` 入栈；`2` 入栈后出栈（得 `2`）；`3` 入栈后出栈（得 `3`）；`4` 入栈后出栈（得 `4`）；最后 `1` 出栈。序列 `2, 3, 4, 1`。✔
- **C. `3, 1, 2, 4` —— 不可能。**
  要第一个输出 `3`，必须把 `1`、`2`、`3` 依次入栈，此时栈内自底向上为 `1, 2, 3`，`3` 出栈后剩下的栈内自底向上是 `1, 2`。
  接着要输出 `1`，但栈顶是 `2`——`2` 压在 `1` 上面，**必须先把 `2` 弹出才能弹出 `1`**，所以 `1` 不可能紧跟在 `3` 之后输出。✘
- **D. `4, 3, 2, 1` —— 合法。**
  `1, 2, 3, 4` 全部入栈后依次出栈即可。✔

**用"禁止模式法"快速验证 C**：入栈序列为 `1, 2, 3, 4`，合法出栈序列中不允许出现位置 `p < q < r` 使 `value[r] < value[p] < value[q]`。C 中取 `p = 1`（值 `3`）、`q = 2`（值 `1`）……值满足 `1 < 3`，再取 `r = 3`（值 `2`）：`value[r] = 2 < value[p] = 3` 不成立。换一个取法：`p = 1`（`3`）、`q = 3`（`2`）？需要 `value[r] < value[p] < value[q]`，即 `value[r] < 3 < 2` 不可能。直接看：C 的前三个是 `3, 1, 2`，正好是"`3` 在 `1` 前、`2` 在最后且 `2 > 1`"的形状 —— 这就是典型的"禁止模式"。

**408 采分点与常见坑**：
- 判断**唯一可靠的方法是模拟**，不要凭感觉。模拟时记住一句话：「**栈顶不是目标元素，就把下一个还没入栈的元素压进来**」。
- 若题目问"共有多少种可能的出栈序列"，答案是卡特兰数 `C(8,4) / 5 = 70 / 5 = 14`（`n = 4`）；**元素互不相同**才能这么算。
- 别把"入栈序列"当成必须是递增的：题目可以给 `A, B, C, D` 或其他顺序，方法与本题完全一样。

### 例题 2（计算题）

> **题目**（自编）：本题综合训练本章两类高频小计算。
>
> **（1）数组地址计算。** 二维数组 `A` 的行下标范围是 `0..8`，列下标范围是 `0..9`，每个元素占 `3` 个字节，`A[0][0]` 的存储地址为 `1000`。求：
> ① 按**行优先**存储时 `A[5][6]` 的地址；
> ② 按**列优先**存储时 `A[5][6]` 的地址；
> ③ 数组 `A` 总共占多少字节。
>
> **（2）循环队列计算。** 设循环队列 `Q` 的 `MaxSize = 50`，采用"牺牲一个存储单元"法判满，`front` 指向队头元素、`rear` 指向队尾元素的下一个位置，初始时 `front = rear = 0`。依次执行：入队 `10` 个元素 → 出队 `3` 个元素 → 再入队 `5` 个元素。求：
> ① 此时 `front` 与 `rear` 的值；
> ② 队列中当前的元素个数；
> ③ 该队列还能再入队多少个元素（假设不再出队）。

**解答**

**（1）数组地址计算**

先明确：行数 `m = 9`（`0..8`），列数 `n = 10`（`0..9`），元素大小 `L = 3` 字节，基址 `LOC(a[0][0]) = 1000`。

① **行优先**：
```
LOC(a[5][6]) = LOC(a[0][0]) + (i * n + j) * L
             = 1000 + (5 * 10 + 6) * 3
             = 1000 + 56 * 3
             = 1000 + 168
             = 1168
```
（含义：`A[5][6]` 前面有 `5` 个完整行共 `50` 个元素，本行前面有 `6` 个元素，合计 `56` 个，每个 `3` 字节。）

② **列优先**：
```
LOC(a[5][6]) = LOC(a[0][0]) + (j * m + i) * L
             = 1000 + (6 * 9 + 5) * 3
             = 1000 + 59 * 3
             = 1000 + 177
             = 1177
```
（含义：前面有 `6` 个完整列共 `54` 个元素，本列前面有 `5` 个元素，合计 `59` 个。注意列优先乘的是**行数 `m = 9`**。）

③ **总字节数**：
```
总字节数 = m * n * L = 9 * 10 * 3 = 270 字节
```

**（2）循环队列计算**

① **指针值**：初始 `front = rear = 0`。
- 入队 `10` 个：每入队一个 `rear = (rear + 1) % 50`，`rear` 从 `0` 变到 `10`，`front` 不变；
- 出队 `3` 个：每出队一个 `front = (front + 1) % 50`，`front` 从 `0` 变到 `3`，`rear` 不变；
- 再入队 `5` 个：`rear` 从 `10` 变到 `15`。

所以此时 `front = 3`，`rear = 15`。

② **元素个数**：
```
元素个数 = (rear - front + MaxSize) % MaxSize
        = (15 - 3 + 50) % 50
        = 62 % 50
        = 12
```
（`12` 也符合手算：入队 `10 + 5 = 15` 个，出队 `3` 个，净剩 `12` 个。）

③ **还能入队多少个**：牺牲一个单元法下队列**最多存 `MaxSize - 1 = 49` 个**元素，当前已有 `12` 个，所以还能再入队：
```
49 - 12 = 37 个
```
也可以从指针角度验证：队满时要求 `(rear + 1) % 50 == front`，即 `rear` 应停在 `front - 1 = 2` 处；从 `rear = 15` 走到 `2` 需要 `(2 - 15 + 50) % 50 = 37` 步，与上面的结果一致。

**408 采分点与常见坑**：
- 数组题的三问是"行优先 / 列优先 / 总大小"，**先写下 `m`、`n`、`L`、基址四个量再套公式**，不要一上来就动笔算。
- **行优先乘列数 `n`，列优先乘行数 `m`** —— 这是每题都会出现的陷阱；本题 `A[5][6]` 行优先是 `1168`、列优先是 `1177`，两者很近，专门用来检验你是否真的知道在乘谁。
- 循环队列的"还能入队几个"**必须先想到牺牲了一个单元**，即容量是 `MaxSize - 1` 而不是 `MaxSize`；直接答 `50 - 12 = 38` 就错了。
- 计算指针时**不要真的绕圈数**，用公式一步到位；出队只动 `front`、入队只动 `rear`，两者互不干扰。

### 例题 3（综合应用题）

> **题目**（自编，408 数据结构算法设计题风格）：设计一个算法，判断一个仅由字符 `(`、`)`、`[`、`]`、`{`、`}` 以及若干普通字符（视为操作数）组成的字符串 `str` 中的**括号是否配对**。要求：
> （1）写出算法的基本思想；
> （2）用 C 语言写出完整函数（顺序栈实现，给出类型定义与基本操作）；
> （3）分析时间复杂度和空间复杂度；
> （4）指出实现中最容易出错的地方。

**（1）算法基本思想**

括号的嵌套关系具有"后出现的左括号先被匹配"的特点，与栈的 `LIFO` 特性一致，因此用**栈**解决：

1. 从左到右扫描字符串；
2. 遇到**左括号**（`(`、`[`、`{`）就压入栈；
3. 遇到**右括号**就弹出栈顶元素，检查它与当前右括号是否为同一种括号：
   - 若弹出时栈已空 → 右括号多余，立即返回"不匹配"；
   - 若类型不同 → 交叉嵌套（如 `( [ ) ]`），返回"不匹配"；
4. 扫描结束后，若栈**为空**则说明所有左括号都被正确匹配，返回"匹配"；否则说明左括号多余，返回"不匹配"。

**（2）C 语言实现**

```c
#include <stdio.h>
#define MaxSize 100

/* ---------- 顺序栈的类型定义 ---------- */
typedef struct {
    char data[MaxSize];
    int top;                 /* 约定：top 指向栈顶元素，初值 -1 */
} SqStack;

/* ---------- 基本操作 ---------- */
void InitStack(SqStack *S) {
    S->top = -1;
}

int StackEmpty(SqStack *S) {
    return (S->top == -1);
}

/* 入栈：成功返回 1；栈满（上溢）返回 0 */
int Push(SqStack *S, char x) {
    if (S->top == MaxSize - 1)
        return 0;
    S->data[++S->top] = x;
    return 1;
}

/* 出栈：成功返回 1 并由 *x 带回栈顶元素；栈空（下溢）返回 0 */
int Pop(SqStack *S, char *x) {
    if (S->top == -1)
        return 0;
    *x = S->data[S->top--];
    return 1;
}

/* ---------- 括号匹配算法 ---------- */
/* 匹配返回 1，不匹配返回 0 */
int BracketCheck(char str[]) {
    SqStack S;
    char ch, top;
    int i = 0;

    InitStack(&S);

    while (str[i] != '\0') {
        ch = str[i];

        if (ch == '(' || ch == '[' || ch == '{') {
            /* 左括号一律入栈；顺序栈上溢时按"不匹配"处理
               （实际工程中应改为动态扩容） */
            if (!Push(&S, ch))
                return 0;
        }
        else if (ch == ')' || ch == ']' || ch == '}') {
            /* 右括号：栈空则右括号多余 */
            if (!Pop(&S, &top))
                return 0;
            /* 检查括号种类是否对应 */
            if (ch == ')' && top != '(')
                return 0;
            if (ch == ']' && top != '[')
                return 0;
            if (ch == '}' && top != '{')
                return 0;
        }
        /* 其他普通字符：直接跳过，不作处理 */

        i++;
    }

    /* 扫描结束后栈必须为空，否则左括号多余 */
    return StackEmpty(&S);
}

/* ---------- 测试 ---------- */
int main(void) {
    char s1[] = "a*(b+[c-{d/e}])";   /* 匹配 */
    char s2[] = "a*(b+[c-{d/e]}";    /* 左括号多余 */
    char s3[] = "a*(b+[c-{d/e}]))";  /* 右括号多余 */

    printf("%d\n", BracketCheck(s1));   /* 输出 1 */
    printf("%d\n", BracketCheck(s2));   /* 输出 0 */
    printf("%d\n", BracketCheck(s3));   /* 输出 0 */
    return 0;
}
```

**（3）复杂度分析**

- **时间复杂度**：`O(n)`，`n` 为字符串长度。每个字符只被扫描一次，每个括号最多入栈一次、出栈一次，入栈与出栈均为 `O(1)`。
- **空间复杂度**：`O(n)`，最坏情况（字符串全是左括号，如 `((((...`）栈中需要同时保存所有左括号；若字符串中括号种类只有一种且题目说明括号层数不超过常数，可视为 `O(1)`，但**按最坏情况应写 `O(n)`**。

**（4）最容易出错的地方（408 采分点）**

1. **忘记检查"右括号多余"**：遇到右括号时不先判断栈空就弹栈，会读到 `top == -1` 的非法位置。必须先 `Pop`（或判空）再比较。
2. **忘记检查"左括号多余"**：扫描结束后漏掉 `StackEmpty(&S)` 这一步。`((a+b)` 这类字符串就会漏判。
3. **只比数量不比类型**：只统计左括号和右括号的个数会放过 `([)]` 这种交叉嵌套，所以**必须逐个比对括号种类**。
4. **顺序栈上溢的处理**：静态数组容量固定，若串长超过 `MaxSize` 会误判为"不匹配"。正确做法是加大容量或改链栈，答题时最好在注释里说明。
5. **`Pop` 的返回值设计**：用返回值表示成功/失败，用指针参数带回元素，比"直接返回栈顶元素"更安全（因为空栈时无法用普通 `char` 表示错误）。
6. **数组越界**：字符串以 `'\0'` 结尾，循环条件写 `str[i] != '\0'`，不要用 `str[i] != 0` 之外的固定长度。

**变式（同样高频，思路相通）**：
- **用栈实现中缀表达式转后缀**：把"遇右括号弹到左括号"改成"遇运算符按优先级弹栈"，其余框架一致（见 3.7 节算法）。
- **用两个栈模拟一个队列**：入队压入栈 1；出队时若栈 2 为空，就把栈 1 全部弹出并压入栈 2，再从栈 2 弹出。均摊时间复杂度 `O(1)`。
- **判断单链表 / 字符串是否中心对称（回文）**：把前半部分压栈，再与后半部分逐个比较，是 408 真题中出现过的经典考法（本题的框架可直接改造成这类题）。

## 六、简便方法与易错口诀（速算 · 防错）

> 本节把本章能"省时间"和"防掉坑"的招集中在一处：二轮复习与考前只看这一节。每条都写清**适用条件**。

### 6.1 速算招式

| 场景 | 常规做法（慢/繁） | 简便做法（快/稳） | 为什么成立 / 适用条件 |
| --- | --- | --- | --- |
| 循环队列求元素个数 | 分"队空 / 队满 / 已绕圈"三类讨论，逐类写式子 | 一个式子通吃：`个数 = (rear - front + MaxSize) % MaxSize` | 先加 `MaxSize` 再取模，负数被折回正区间，"绕圈"自动处理，不必分类。**适用条件**：`front` 指向队头、`rear` 指向队尾的下一个位置。注意此式给的是**当前元素个数**，不是容量 |
| 判断出栈序列是否合法 | 逐个元素模拟压栈 / 弹栈 | 不模拟，找"禁止模式"：在待判序列里任取三个元素，若它们的相对大小呈 **大 … 小 … 中**（按秩写出就是 `3-1-2` 模式，如 `3,1,2`、`4,1,3`、`3,4,1,2` 的出现次序）即非法 | 输入按 `1..n` 顺序入栈（允许边入边出）时，合法出栈序列恰是**不含 `3-1-2` 模式**的排列。**订正提示**：若见到"中…大…小就非法"的说法，那是按秩的 `2-3-1` 模式，它**是合法的**（`2,3,1` 可为出栈序列），别记反——非法的是"大的先出，接着小的跑出来，中间的还压在栈里"这种次序 |
| 数合法出栈序列 / 二叉树形态的种数 | 写递推、现场枚举 | 直接代卡特兰数 `C(2n, n) / (n + 1)`；记住前几项 `n = 1..6`：`1, 2, 5, 14, 42, 132` | **适用条件**：`n` 个元素**互不相同**（树形态题为 `n` 个结点）。`n = 3` 是 5 个、`n = 4` 是 14 个，选择题常直接问"共有多少种"，用阶乘展开算比推递推快 |
| 二维数组元素地址 | 逐行累加偏移，一行一行数 | 两条口诀定位：**行优先乘列数 `n`，列优先乘行数 `m`**，即行优先 `LOC = 基址 + (i * n + j) * L`、列优先 `LOC = 基址 + (j * m + i) * L` | 上面两式**只在下标从 0 开始**时成立；题目写"从 1 开始"就先做 `i -> i - 1`、`j -> j - 1` 再代入。`L` 是每个元素的字节数。做题第一步永远是写清三件事：行/列优先、下标起点、`L` |
| 对称矩阵 / 三对角矩阵压缩存储换算 | 画图数元素、逐个累加 | 下三角存法 `k = i(i-1)/2 + j - 1`（`i >= j`，下标从 1 起，`k` 从 0 起）；遇 `i < j` **先交换 `i`、`j`** 再代入；三对角矩阵共 `3n - 2` 个元素，映射 `k = 2i + j - 3` | `i(i-1)/2` 是"前 `i-1` 行的元素总数"，`j - 1` 是"本行前面的偏移"，两项一拼就是 0 起下标。若一维数组下标从 1 起，则整体加 1 写成 `k = i(i-1)/2 + j`。对称矩阵只存 `n(n+1)/2` 个，三角矩阵还要多一个常数项 |
| 中缀表达式转后缀 | 逐字符扫描、反复比较栈内栈外优先级 | **加括号法**：按优先级（同级按结合性）给每个运算加一对括号，再把每个运算符移到**它自己那对括号的外面**，去括号后即得后缀式 | 一次成串、几乎不出错，比手推栈快得多。**例外（必看）**：补括号要按结合性——左结合 `a - b - c` 补成 `((a - b) - c)`；右结合的幂 `a^b^c` 补成 `(a^(b^c))`，补错括号结果就错 |
| 后缀表达式求值 | 只记"弹两个数再算" | 从左到右扫：操作数入栈，遇运算符连弹两个，**先弹出的是右操作数**，后弹出的是左操作数 | **适用条件**：二目运算符。减法、除法是"反"的：`2 3 4 * -` 得 `2 - 12 = -10`。单目运算符（如取负号）不适用此条，需按题目自定义规则 |
| 判断"该用栈还是队列" | 逐题分析语义 | 关键词速判：`BFS` / 缓冲区 / 打印任务 / 层次遍历 → **队列**；`DFS` / 递归 / 括号匹配 / 表达式求值 / 进制转换的逆序输出 → **栈** | 判据只有一句："先来先服务用队列，后来先服务用栈"。这条钩子在树、图章节同样通用 |

### 6.2 口诀与记忆钩子

- **口诀**：「**尾减头，加容量，再取模**」——循环队列元素个数一步到位；"加容量"专治负数取模，别写成 `(rear - front) % MaxSize`。
- **口诀**：「**大 小 中，见就否**」——出栈序列里三个元素的相对次序只要呈"大…小…中"（秩 `3-1-2`）就非法；配一句解释"大的先出去了，小的也跑出来了，中间那个还压在栈里翻不出来"。
- **口诀**：「**行优先乘列数，列优先乘行数；动手先问 0 还是 1**」——数组地址题三约定（优先次序、下标起点、`L`）一次背全。
- **口诀**：「**前几行整行加，本行偏移减一**」——压缩存储 `k = i(i-1)/2 + j - 1`：`i(i-1)/2` 是前面整行，`j - 1` 是本行偏移；上三角先交换 `i`、`j`。
- **口诀**：「**先出来的是右边那个**」——后缀求值只背这一句，`-` 和 `/` 就不会算反。
- **口诀**：「**加括号、运算符出括号、去括号**」——中缀转后缀三步走；幂运算记得按右结合补括号。

### 6.3 反例黑名单（这些"简便法"是错的）

- ❌ **把"禁止 `3-1-2` 模式"搬去判双端队列的输出序列**：正确做法是老老实实模拟。栈产不出 `3,1,2`，但输入受限的双端队列可以——`1、2、3` 依次从右端入，`3` 从右端出、`1` 从左端出、`2` 再从左端出，就得到 `3,1,2`。禁止模式法**只对栈（含边入边出）成立**。
- ❌ **把卡特兰数公式套到"元素有重复"的输入上**：正确做法是按重复情况去重或直接枚举。`C(2n, n) / (n + 1)` 只数 **`n` 个互异元素**的合法出栈序列；像 `1, 1, 2` 这类含相同元素的输入，不同操作次序会得到相同的结果序列，个数并不等于卡特兰数。
- ❌ **用 `(rear - front + MaxSize) % MaxSize` 当"容量"用**：正确做法是记住两种约定——**牺牲一个单元**方案容量上限是 `MaxSize - 1`（判满 `(rear + 1) % MaxSize == front`），用 `size` 计数或 `tag` 标记的方案容量上限才是 `MaxSize`。把元素个数当容量，会在"刚好塞满"时多算或少算一个位置。
- ❌ **后缀求值时按"弹出的先后顺序"直接算**：正确做法是把**先弹出**的当右操作数、后弹出的当左操作数。`-` 与 `/` 反着算必错：`2 3 4 * -` 正确答案是 `-10`，不是 `10`。
- ❌ **对称矩阵题目里对 `i < j` 的元素不交换 `i`、`j` 就代入**：正确做法是**先交换再代** `k = i(i-1)/2 + j - 1`。直接代入会算出超过 `n(n+1)/2 - 1` 的下标，属于越界，而不是"也能凑出答案"。
- ❌ **中缀转后缀补括号时同级运算一律"从左到右"**：正确做法是先看结合性。左结合的 `a - b - c` 才是 `((a - b) - c)`；右结合的幂 `a^b^c` 必须补成 `(a^(b^c))`，按从左到右补会错写成 `(a^b)^c`，后缀式随之全错。
