### 2. 按「思想」归类的记忆线索

| 思想 | 算法 | 一句话本质 |
| --- | --- | --- |
| 插入 | 直接插入、折半插入、希尔 | 把待排元素**插入到已排好的有序区** |
| 交换 | 起泡、快速 | 通过**元素交换**消除逆序 |
| 选择 | 简单选择、堆排序 | **每趟选出最值**放到最终位置 |
| 归并 | 二路归并 | 把两个有序表**合并**成一个有序表 |
| 分配 | 基数排序 | **按位分配再收集**，不比较关键字 |

### 3. 全章最重要的 6 个结论（先记住，后面逐个验证）

1. **稳定的**：直接插入、折半插入、起泡、归并、基数（口诀：**插冒归基稳**）。
2. **不稳定的**：希尔、快速、简单选择、堆（口诀：**快的选希堆不稳**）。
3. **每趟能确定一个元素最终位置**：起泡、简单选择、快速、堆。
4. **比较次数与初始序列无关**：折半插入（比较次数只由 `n` 决定）、简单选择（恒为 `n(n-1)/2`）；基数排序不做关键字比较。**注意**：堆排序的比较次数**随初始序列变化**，不属于这一条 —— 它属于「**时间复杂度**与初始序列无关」（最好/最坏/平均恒 `O(n log n)`，与归并排序同类）。
5. **平均 `O(n log n)` 且不稳定**：快速、堆（归并稳定但与初始序列无关）。
6. **空间 `O(n)`**：二路归并（辅助数组）、基数排序（`O(r)` 个队列）；快速排序 `O(log n)`~`O(n)` 栈空间。

> **408 怎么考**：这一节内容几乎每年在选择题里以「下列排序算法中，稳定的是 / 时间复杂度与初始序列有关的是 / 一趟结束后能确定某元素位置的是」的形式出现，属于**纯记忆题**，必须零失误。

## 二、概念详解

### 8.1 排序的基本概念

#### 1. 什么是排序

**排序**：重新排列表中的元素，使它们按关键字**递增**（或递减）有序。数学化地说，把 `{R1, R2, ..., Rn}` 重排为 `{R1', R2', ..., Rn'}`，使得关键字满足 `k1' ≤ k2' ≤ ... ≤ kn'`。

关键在于：如果关键字相等，排序前后的**相对次序**是否保持 —— 这就是稳定性的来源。

#### 2. 稳定性（本章第一大考点）

**定义**：对任意两个关键字相等的记录 `Ri` 和 `Rj`（排序前 `Ri` 在 `Rj` 之前），若排序后 `Ri` 仍在 `Rj` 之前，则该算法**稳定**；否则**不稳定**。

**怎么判断**（不要死背，用「跨步交换」判据）：

> 算法在做「相距较远的两个元素交换 / 跳跃式移动」时，如果有机会把两个相等元素的前后顺序颠倒，就不稳定。

- 起泡只看相邻元素，相等时不交换 → 稳定。
- 直接插入找到一个「不大于当前元素」的位置就停下（即插在相等元素后面）→ 稳定。
- 希尔排序中，同一元素在不同增量下与相距 `d` 的元素交换 → 不稳定。
- 快速排序中，`Partition` 会把远处元素挖过来填坑 → 不稳定。
- 简单选择排序中，选出最小值与第 `i` 位交换，可能把前面的相等元素甩到后面 → 不稳定。
- 堆排序中，堆顶与堆尾交换后 `SiftDown` 长距离下移 → 不稳定。
- 归并 `Merge` 时若取 `L[i] <= R[j]` 取左边（相等时优先左）→ 稳定。
- 基数排序按位「先进先出」收集 → 稳定。

> **408 怎么考 / 常见坑**：
> ① 题干问「排序前后相对位置不变」，考查的**只有关键字相等的元素**，不要拿不同关键字的元素去比。
> ② 稳定性与时间复杂度无关，别因为「快排快」就以为它稳定。
> ③ 一次排序**可能不破坏**稳定性（比如本来就有序），但算法本身的性质不变 —— 判断的是算法，不是某次运行结果。

#### 3. 内部排序与外部排序

| 类型 | 数据存放 | 关键瓶颈 | 代表算法 |
| --- | --- | --- | --- |
| 内部排序 | 全部在内存 | **比较次数与移动次数** | 插入/交换/选择/归并/基数 |
| 外部排序 | 部分在外存，需多次内外存交换 | **`I/O` 次数**（磁盘读写） | 多路平衡归并 + 败者树 + 置换-选择 |

> **408 怎么考**：问「外部排序的时间主要取决于什么」→ 答案是 `I/O` 次数（即归并趟数 × 每趟读写量），不是比较次数。这是外部排序所有计算题的出发点。

#### 4. 比较次数与移动次数

内部排序的时间开销 = **关键字比较次数** + **记录移动次数**。要注意这两种次数**经常被分开考**：

- 折半插入排序：比较次数减少到 `O(n log n)`，但**移动次数不变**（仍是 `O(n^2)`），所以总时间仍是 `O(n^2)`。
- 简单选择排序：比较次数**固定**为 `n(n-1)/2`，但移动次数最多 `n-1` 次（每趟至多一次交换，一次交换算 3 次移动）。

> **408 怎么考**：题干常问「比较次数与初始序列无关的是」「移动次数与初始序列无关的是」。前者：折半插入、简单选择（外加根本不比较的基数排序）；后者几乎都不固定（简单选择比较固定、移动仍与序列有关，只是很少）。**注意：堆排序的比较次数与初始序列有关**（随堆的形态与元素关系变化），它只是「**时间**与初始序列无关」，不要混进前者。

#### 5. 原地排序（就地排序）

**原地排序**：空间复杂度为 `O(1)`（只用到常数个辅助单元）。满足的有：直接插入、折半插入、起泡、简单选择、希尔、快速（不计递归栈）、堆。**不满足**的：二路归并（`O(n)`）、基数排序（`O(r)`）。

> **408 怎么考**：注意「快速排序」的坑 —— 辅助空间 `O(log n)` 是**递归工作栈**，不算额外数组，通常仍被归为「原地/就地」但空间复杂度写 `O(log n)`。「二路归并需要 `O(n)` 辅助空间」是高频填空点。

### 8.2 直接插入排序

#### 1. 思路（怎么来的）

把序列看成两部分：左边是**已排好序的有序区**，右边是**待插入的无序区**。每趟从无序区取第一个元素 `L[i]`，在有序区 `L[1..i-1]` 中**从后往前**找位置，一边比较一边把比它大的元素后移，找到位置后插入。

为什么从后往前找？因为从后往前可以在比较的同时**顺便后移**，一趟搞定，代码最省。

```c
// 对 L[1..n] 做直接插入排序（下标从 1 开始，L[0] 作哨兵/暂存）
void InsertSort(int L[], int n) {
    for (int i = 2; i <= n; i++) {
        if (L[i] < L[i - 1]) {          // 只有逆序才需要插入，否则直接跳过
            L[0] = L[i];                // 暂存待插入元素（哨兵）
            int j;
            for (j = i - 1; L[0] < L[j]; j--)
                L[j + 1] = L[j];        // 后移
            L[j + 1] = L[0];            // 插入
        }
    }
}
```

#### 2. 复杂度分析

- **最好情况**：序列已经有序。每次 `L[i] < L[i-1]` 不成立，只比较 1 次，共 `n-1` 次比较，移动 0 次。`O(n)`。
- **最坏情况**：序列逆序。第 `i` 趟比较 `i` 次、移动 `i+1` 次，累加得比较次数与移动次数都约为 `n^2/2`。`O(n^2)`。
- **平均情况**：`O(n^2)`。
- **空间**：`O(1)`。
- **稳定**：稳定（`L[0] < L[j]` 用严格小于，相等时停止后移，插在相等元素之后）。

#### 3. 适用场景与「哨兵」的作用

- 适合 `n` 较小、或序列**基本有序**的场合（此时接近 `O(n)`）。
- 哨兵 `L[0]` 的两个作用：① 暂存待插入元素，省去在移动中丢失数据；② 作为**循环边界**，避免 `j >= 1` 的判断，减少比较次数。

> **408 怎么考 / 常见坑**：
> ① 常考「对基本有序的序列，下列哪个算法最快」→ 直接插入排序（`O(n)`）。
> ② 「直接插入排序一趟结束后能否确定一个元素的最终位置？」→ **不能**。它只保证有序区扩大一个，元素位置在后续趟中仍可能被挤走。
> ③ 移动次数的最坏值是 `n(n+1)/2 - 1` 量级，代入 `n=6` 之类的小规模，选择题会让你数具体次数。

### 8.3 折半插入排序

#### 1. 思路（改进了什么）

直接插入排序的「找位置」是**顺序查找**，比较次数多。既然有序区已经有序，自然可以**折半查找**找插入位置，这就是折半插入排序。

```c
void BinInsertSort(int L[], int n) {
    for (int i = 2; i <= n; i++) {
        L[0] = L[i];                    // 暂存
        int low = 1, high = i - 1;
        while (low <= high) {           // 折半找插入位置
            int mid = (low + high) / 2;
            if (L[mid] > L[0]) high = mid - 1;
            else low = mid + 1;         // 相等时往右走 → 保证稳定
        }
        for (int j = i - 1; j >= high + 1; j--)
            L[j + 1] = L[j];            // 统一后移
        L[high + 1] = L[0];
    }
}
```

#### 2. 关键结论（必背）

| 指标 | 直接插入 | 折半插入 |
| --- | --- | --- |
| 比较次数 | 与初始序列有关，最好 `n-1`、最坏 `~n^2/2` | **与初始序列无关**，固定 `O(n log n)` |
| 移动次数 | 与初始序列有关 | **与直接插入完全相同**（没有改善） |
| 时间复杂度 | `O(n^2)` | **仍为 `O(n^2)`**（瓶颈是移动） |
| 空间 | `O(1)` | `O(1)` |
| 稳定性 | 稳定 | 稳定 |

**为什么比较次数与初始序列无关？** 因为无论数据怎么排，第 `i` 趟的折半查找都在长度 `i-1` 的有序区里做，查找长度只取决于区间长度，不取决于元素值。

**为什么总时间没降下来？** 因为折半只优化了「比较」这一半代价，而「移动」仍是 `O(n^2)`，是瓶颈。

> **408 怎么考 / 常见坑**：
> ① 高频原话：「折半插入排序减少了比较次数，但移动次数不变，时间复杂度仍为 `O(n^2)`」，缺哪半句都可能被扣分。
> ② 折半插入的**稳定性**：折半查找在 `L[mid] == L[0]` 时必须让 `low = mid + 1`（往右半区走），这样插入位置在相等元素之后 → 稳定。若写成 `high = mid - 1` 就不稳定了。

### 8.4 起泡排序（Bubble Sort）

#### 1. 思路

从前往后（或从后往前）**两两比较相邻元素**，逆序则交换。一趟下来，最大（或最小）的元素像气泡一样「浮」到序列一端，即**该元素的最终位置被确定**。对 `n` 个元素最多做 `n-1` 趟。

```c
void BubbleSort(int L[], int n) {
    for (int i = 0; i < n - 1; i++) {
        int flag = 0;                       // 本趟是否发生交换
        for (int j = n - 1; j > i; j--) {   // 从后往前冒，小的往上浮
            if (L[j - 1] > L[j]) {
                int t = L[j - 1]; L[j - 1] = L[j]; L[j] = t;
                flag = 1;
            }
        }
        if (flag == 0) return;              // 本趟无交换 → 已有序，提前结束
    }
}
```

#### 2. 关键结论

- **最好情况**：序列有序，1 趟 + `n-1` 次比较 + 0 次移动 → `O(n)`。**这个 `O(n)` 完全依赖标志位**，没有标志位则最好也是 `O(n^2)`。
- **最坏情况**：逆序，比较 `n(n-1)/2` 次，移动 `3n(n-1)/2` 次 → `O(n^2)`。
- **平均**：`O(n^2)`。**空间**：`O(1)`。**稳定**：稳定。
- **每趟至少能确定一个元素（最大或最小）的最终位置**；反过来，若某趟无交换，说明整个序列已有序，可提前终止。
- 一个常考小结论：起泡排序过程中，一趟结束后**有序区**在序列的一端（通常最右），且这个有序区里的元素都 ≥（或 ≤）无序区里的所有元素。

> **408 怎么考 / 常见坑**：
> ① 「起泡排序最好时间复杂度」必须是**带标志位**的 `O(n)`，这是明确写在王道书上的结论，常与「不带标志位」对比设陷阱。
> ② 交换一次算 **3 次移动**（`t=a; a=b; b=t`），做移动次数计算题时不要算成 1 次。
> ③ 「能否提前结束」是起泡排序区别于简单选择排序的显著特征（后者无论数据如何都要跑满 `n-1` 趟）。

### 8.5 简单选择排序

#### 1. 思路

每趟从**未排序区**中选出关键字最小（大）的元素，与未排序区的**第一个位置**交换，从而把该位置变成已排序区的末尾。`n-1` 趟后全部有序。

```c
void SelectSort(int L[], int n) {
    for (int i = 0; i < n - 1; i++) {
        int min = i;
        for (int j = i + 1; j < n; j++)
            if (L[j] < L[min]) min = j;     // 找最小值下标
        if (min != i) {                     // 每趟至多一次交换
            int t = L[i]; L[i] = L[min]; L[min] = t;
        }
    }
}
```

#### 2. 关键结论

- **比较次数固定**：`(n-1) + (n-2) + ... + 1 = n(n-1)/2`，**与初始序列无关**。
- **移动次数很少**：最多 `n-1` 次交换 = 最多 `3(n-1)` 次移动；最好 0 次。这一点使它适合**元素很大、移动代价高**的场景（如记录体积大的结构体）。
- 时间：最好 = 最坏 = 平均 = `O(n^2)`。空间 `O(1)`。
- **不稳定**：交换是「远距离」的，例：`{5, 5, 2}`，第一趟把 `2` 与第一个 `5` 交换，得到 `{2, 5, 5}` —— 看起来没变？换成 `{2, 2, 1}` 看更清楚，或经典反例 `{5a, 5b, 2}` → `{2, 5b, 5a}`，两个 5 的相对次序被颠倒。
- **每趟能确定一个元素的最终位置**（与起泡相同）。

> **408 怎么考 / 常见坑**：
> ① 「比较次数与初始序列无关」的排序算法：**简单选择排序（恒 `n(n-1)/2`）、折半插入排序**（外加按位处理、根本不比较的基数排序）。**堆排序不在其列** —— 它的比较次数随初始序列变化，只有**时间**恒 `O(n log n)`。这条几乎年年出现，而堆排序正是最大的干扰项。
> ② 简单选择排序**不能**因为「某趟没交换」就判断序列已有序 —— 没交换只说明当前最小值恰好在它该在的位置，后面还可能乱。所以它没有「提前结束」的优化，这是与起泡排序的关键区别。
> ③ 稳定性反例要能当场举出来，别只背结论。

### 8.6 希尔排序（Shell Sort）

#### 1. 思路（为什么想到分组）

直接插入排序有两个特点：**对基本有序的序列很快**（接近 `O(n)`）、**对 `n` 小的序列很快**。希尔排序就想办法**同时制造这两个条件**：

1. 取一个增量 `d`（如 `d = n/2`），把下标相隔 `d` 的元素分成一组，共 `d` 组；
2. 对**每组内部**做直接插入排序（组内元素少，且一次移动跨 `d` 步，可以消除远距离的逆序）；
3. 缩小增量（如 `d = d/2`）重复，直到 `d = 1`，此时整表做一次直接插入排序 —— 但因为序列已基本有序，这一趟很快。

**为什么最后必须 `d = 1`？** 只有 `d = 1` 才是全体元素一组，才能保证整体有序。前面的趟都是「预处理」，让序列逐渐变「基本有序」。

```c
void ShellSort(int L[], int n) {
    for (int d = n / 2; d >= 1; d /= 2) {          // 增量序列：n/2, n/4, ..., 1
        for (int i = d + 1; i <= n; i++) {         // 各组交替做直接插入
            if (L[i] < L[i - d]) {
                L[0] = L[i];
                int j;
                for (j = i - d; j > 0 && L[0] < L[j]; j -= d)
                    L[j + d] = L[j];
                L[j + d] = L[0];
            }
        }
    }
}
```

#### 2. 关键结论

- **时间复杂度与增量序列的选取有关**，这是本章少有的「不唯一答案」：
  - 希尔本人增量 `n/2, n/4, ..., 1`：最坏 `O(n^2)`。
  - Hibbard 增量 `2^k - 1`：最坏 `O(n^1.5)`。
  - 目前最好的增量序列可做到约 `O(n^1.3)`。
  - **任何增量序列的最坏情况都不低于 `O(n log n)`** 这个下界（比较排序下界）。
- **空间**：`O(1)`。
- **不稳定**：同一元素在不同增量的分组里被跳过交换，相等元素次序可能颠倒。
- **适用**：`n` 中等规模、且**不要求稳定性**的场合；比直接插入快，但不如快排。

> **408 怎么考 / 常见坑**：
> ① 时间复杂度的标准答法：「**依赖于增量序列**，约为 `O(n^1.3)`，最坏 `O(n^2)`」，不要只写 `O(n log n)`。
> ② 常考「希尔排序的一趟是指**同一个增量下所有组都做完**」，不是只做一组。手算题会给 `d = 5, 3, 1` 让你写每趟结果。
> ③ 希尔排序是**插入类**排序，不是交换类 —— 别把它归错类。
> ④ 增量序列的要求：逐渐减小且**最后一趟必须为 1**；此外各增量之间最好**互质**（不互质时前面趟的效果可能被后面的趟破坏）。

### 8.7 快速排序

本章第一大重点，几乎每年必考（选择或大题）。

#### 1. 思路：分治

在待排序列 `L[low..high]` 中取一个元素作**枢轴（pivot）**，通过一次 `Partition`（划分）把序列分成两部分，使得：

- 左半部分所有元素 `<` 枢轴；
- 右半部分所有元素 `>=` 枢轴；
- 枢轴落到**最终位置**上（`pivotpos`）。

然后对左右两部分**递归**做同样的事。这就是分治法：`Divide`（划分） + `Conquer`（递归） + 无需 `Combine`。

#### 2. `Partition` 的两种实现

**实现 A：挖坑法（王道书主流写法）**

```c
// 以 L[low] 为枢轴，返回枢轴最终位置
int Partition(int L[], int low, int high) {
    int pivot = L[low];                 // 1. 挖出 L[low]，形成一个"坑"
    while (low < high) {
        while (low < high && L[high] >= pivot) high--;
        L[low] = L[high];               // 2. 右边找小的填左坑，high 处变成新坑
        while (low < high && L[low] <= pivot) low++;
        L[high] = L[low];               // 3. 左边找大的填右坑，low 处变成新坑
    }
    L[low] = pivot;                     // 4. 枢轴归位（low == high）
    return low;
}
```

**实现 B：交换法**

```c
int PartitionSwap(int L[], int low, int high) {
    int pivot = L[low], i = low;        // i 记录"小于枢轴区"的最后一个位置
    for (int j = low + 1; j <= high; j++)
        if (L[j] < pivot) {             // 严格小于才交换 → 保证稳定性的写法
            i++;
            int t = L[i]; L[i] = L[j]; L[j] = t;
        }
    int t = L[low]; L[low] = L[i]; L[i] = t;   // 枢轴换到分界处
    return i;
}
```

两种实现**划分结果（元素集合归属）是相同的**，但**中间过程与枢轴最终位置可能不同**；408 手算题一般以王道书的挖坑法为准。

#### 3. 手算「一趟划分结果」的标准方法（必练）

题目给 `{49, 38, 65, 97, 76, 13, 27, 49'}` 之类的序列，要求写出一趟快排（以第一个元素为枢轴）后的结果。**按挖坑法逐句模拟**：

设 `L = {49, 38, 65, 97, 76, 13, 27, 49'}`，`low = 1, high = 8`，`pivot = 49`。

1. 从 `high` 往左找 `< 49` 的：`49'` 不小于，`27 < 49` → 停下。把 `27` 填到 `low` 位：`{27, 38, 65, 97, 76, 13, [27], 49'}`（`high = 7` 成为新坑）。
2. 从 `low` 往右找 `> 49` 的：`38` 不大于，`65 > 49` → 停下。把 `65` 填到 `high` 位：`{27, 38, [65], 97, 76, 13, 65, 49'}`（`low = 3` 成为新坑）。
3. 从 `high` 往左找 `< 49` 的：`13 < 49` → 停下。填入 `low`：`{27, 38, 13, 97, 76, [13], 65, 49'}`（`high = 6` 成为新坑）。
4. 从 `low` 往右找 `> 49` 的：`97 > 49` → 停下。填入 `high`：`{27, 38, 13, [97], 76, 97, 65, 49'}`（`low = 4` 成为新坑）。
5. `high` 往左找 `< 49`：经过 `76`、`97` 都大于，`high` 减到 4 与 `low` 相遇 → 循环结束。
6. 枢轴归位：`L[4] = 49`。

**结果：`{27, 38, 13, 49, 76, 97, 65, 49'}`**，枢轴 `49` 位于第 4 位（最终位置），左边三个都 `< 49`，右边四个都 `>= 49`。

> 手算要点：**永远从枢轴的另一端开始找**（枢轴在 `low` 就先从 `high` 走）；两个「坑」交替出现；相遇位置就是枢轴最终位置；最后检查「左 < 枢轴 ≤ 右」。

#### 4. 复杂度与空间

| 情形 | 出现条件 | 递归深度 | 时间 |
| --- | --- | --- | --- |
| 最好 | 每次划分接近均分 | `O(log n)` | `O(n log n)` |
| 平均 | 随机序列 | `O(log n)` | `O(n log n)` |
| 最坏 | 序列**基本有序/逆序**，且取首元素为枢轴 | `O(n)` | `O(n^2)` |

- **空间**：递归工作栈，最好/平均 `O(log n)`，最坏 `O(n)`。
- **不稳定**：`Partition` 中元素跨距离移动。反例 `{3a, 3b, 1}` 一趟后可能变成 `{1, 3b, 3a}`。
- 快速排序在**平均情况**下是内部排序中**平均性能最好**的算法，其平均时间常数比归并和堆排序都小。

#### 5. 枢轴的选择与优化

- **固定取首元素**：实现最简单，但对**基本有序**的输入退化为 `O(n^2)`（每次划分一边空、一边 `n-1`）。这是 408 最爱考的「最坏情况」触发条件。
- **随机选取**（`rand` 后与首元素交换）：使最坏情况出现的概率极低，**但不改变最坏复杂度**（仍是 `O(n^2)`）。
- **三数取中**：取 `L[low]`、`L[mid]`、`L[high]` 三者的中位数作枢轴，能有效避免有序输入退化。
- **小区间优化**：递归到区间长度较小时改用直接插入排序，减少递归开销。

> **408 怎么考 / 常见坑**：
> ① 「快速排序在什么情况下最坏？」→ **待排序列基本有序或基本逆序**（且枢轴取首元素）。反过来，「对基本有序的序列，快排最慢、直接插入最快」是经典对比结论。
> ② 空间复杂度的 `O(n)` 最坏值来自**递归深度 `n`**，一定要说清是**栈空间**，不是辅助数组。
> ③ 手算一趟划分时，**中间结果写不写不影响得分，但最终结果必须对**；同时注意枢轴元素的最终位置要标出来。
> ④ 「快排一趟能不能确定一个元素的最终位置？」→ **能**（枢轴），与其他「交换类」算法区分开。

### 8.8 堆排序

#### 1. 堆的定义（先分清大小根堆）

`n` 个元素的序列 `{k1, k2, ..., kn}` 满足：

- **大根堆（大顶堆）**：`ki >= k2i` 且 `ki >= k2i+1`（`1 <= i <= ⌊n/2⌋`），即**每个结点都 ≥ 其孩子**，堆顶是全局最大值。
- **小根堆（小顶堆）**：`ki <= k2i` 且 `ki <= k2i+1`，堆顶是全局最小值。

因为下标关系 `2i`、`2i+1` 与完全二叉树一致，所以堆的逻辑结构是一棵**完全二叉树**，且 **`i <= ⌊n/2⌋` 的结点才是分支结点（非叶结点）**，其余都是叶子。

> 重要区分：堆是「**父子有序**」—— 只保证双亲和孩子的大小关系，**并不保证左右孩子之间有序**。因此堆**不是** `BST`（`BST` 要求左子树全部小于根、右子树全部大于根，是更强也更"贵"的约束）。这是本章高频易混点。

#### 2. `SiftDown`：向下调整（堆的核心操作）

把下标 `k` 的结点不断与**较大的那个孩子**交换，直到满足堆性质或到达叶子。

```c
// 大根堆的向下调整：把 L[k] 调到合适位置
void SiftDown(int L[], int k, int n) {
    L[0] = L[k];                            // 暂存（L[0] 作哨兵）
    for (int i = 2 * k; i <= n; i *= 2) {   // 沿较大的孩子往下
        if (i < n && L[i] < L[i + 1]) i++;  // i 指向较大的孩子
        if (L[0] >= L[i]) break;            // 已满足堆性质，停止
        L[k] = L[i];                        // 孩子上移
        k = i;                              // k 下移到孩子位置
    }
    L[k] = L[0];                            // 归位
}
```

**为什么每次都挑「较大的孩子」？** 因为上移的孩子将成为新的双亲，必须 ≥ 另一个孩子，否则交换后立即违反堆性质。

#### 3. 建初堆：自下而上 `O(n)`

从**最后一个分支结点** `⌊n/2⌋` 开始，依次对 `⌊n/2⌋, ⌊n/2⌋-1, ..., 1` 做 `SiftDown`。

```c
void BuildHeap(int L[], int n) {
    for (int i = n / 2; i >= 1; i--)
        SiftDown(L, i, n);
}
```

**为什么建堆是 `O(n)` 而不是 `O(n log n)`？** 注意区分：

- 若从根往下、每个结点都 `SiftDown` 一次，是 `O(n log n)`。
- 但**自下而上**建堆时，越靠近底层的结点越多、下沉高度越小：高度为 `h` 的结点最多 `⌈n/2^(h+1)⌉` 个，每个只需下移 `h` 层，总代价 `Σ n·h/2^(h+1) = O(n)`。

**这就是「初始建堆 `O(n)`」的由来，是本章最经典的复杂度推导题。**

#### 4. 堆排序：反复「取堆顶 + 重建」

1. 先建**大根堆**（升序排序用大根堆，降序用小根堆 —— 因为要把最大的换到末尾）；
2. 堆顶 `L[1]` 是当前最大值，与堆的**最后一个元素** `L[i]` 交换 → 最大值归位到最终位置；
3. 堆的有效范围缩小为 `1..i-1`，对新堆顶做一次 `SiftDown`（`O(log n)`）；
4. 重复 `n-1` 次。

```c
void HeapSort(int L[], int n) {
    BuildHeap(L, n);                        // 建初堆 O(n)
    for (int i = n; i > 1; i--) {
        int t = L[1]; L[1] = L[i]; L[i] = t; // 堆顶（最大）换到末尾
        SiftDown(L, 1, i - 1);               // 调整剩余堆，O(log n)
    }
}
```

#### 5. 关键结论

- **时间**：建堆 `O(n)` + `n-1` 次调整各 `O(log n)` = **`O(n log n)`**；且**最好、最坏、平均都是 `O(n log n)`**（这点与快排不同，是堆排序最大的优点）。
- **空间**：`O(1)`，原地排序。
- **不稳定**：堆顶与末尾的远距离交换会打乱相等元素次序。
- **比较次数与初始序列无关吗？** **不是** —— 建堆与每趟 `SiftDown` 的比较次数取决于堆的形态与元素关系，**会随初始序列变化**（实测 `n = 4` 时：输入 `{1,2,3,4}` 建堆 + 排序共比较 7 次，输入 `{4,3,2,1}` 共 6 次），所以堆排序**不属于**「比较次数与初始序列无关」的一类。它属于**「时间复杂度（最好/最坏/平均）与初始序列无关」**（恒 `O(n log n)`），与归并排序同类。答题时务必把「**时间**无关」与「**比较次数**无关」分开写。

#### 6. 应用：`TopK` 问题

求 `n` 个数中最大的 `k` 个：建立**大小为 `k` 的小根堆**，扫描剩余元素，若大于堆顶则替换堆顶并 `SiftDown`。时间 `O(n log k)`，空间 `O(k)`。
（若要找最小的 `k` 个，则用大小为 `k` 的大根堆。**方向别搞反**：堆顶永远是「当前候选集合里最差的那个」。）

> **408 怎么考 / 常见坑**：
> ① 手算题：给序列，写「建初堆过程」和「每趟堆排序后的结果」。注意**建堆是从 `⌊n/2⌋` 往 1 走**，不是从 1 往 `n/2` 走 —— 方向写反全错。
> ② 堆排序**一趟**能确定一个元素的最终位置，且确定的是**当前最大值（大根堆）**，位置在**序列末尾**（从前向后逐步确定）。与简单选择排序的「从前向后确定」方向不同。
> ③ 千万别把堆和 `BST` 混淆：堆不保证左右子树有序，因此**中序遍历堆得不到有序序列**。
> ④ 判断题：「堆排序的空间复杂度是 `O(n)`」→ 错，是 `O(1)`；「初始建堆是 `O(n log n)`」→ 错，是 `O(n)`。

### 8.9 二路归并排序（Merge Sort）

#### 1. 思路：分治 + `Merge`

把长度为 `n` 的序列分成两个长度约 `n/2` 的子序列，分别递归排序，再把两个**有序子序列归并**成一个有序序列。

**`Merge` 是核心**：两个有序表各设一个指针 `i`、`j`，比较 `L[i]` 与 `R[j]`，取较小者放入辅助数组 `T`，直到一方取完，再把另一方剩余全部接上。

```c
// 归并 L[low..mid] 和 L[mid+1..high] 到辅助数组 T，再拷回 L
void Merge(int L[], int T[], int low, int mid, int high) {
    int i = low, j = mid + 1, k = low;
    while (i <= mid && j <= high) {
        if (L[i] <= L[j]) T[k++] = L[i++];   // 相等时优先取左 → 稳定
        else              T[k++] = L[j++];
    }
    while (i <= mid)  T[k++] = L[i++];
    while (j <= high) T[k++] = L[j++];
    for (k = low; k <= high; k++) L[k] = T[k];
}

void MSort(int L[], int T[], int low, int high) {
    if (low < high) {
        int mid = (low + high) / 2;
        MSort(L, T, low, mid);           // 排左半
        MSort(L, T, mid + 1, high);      // 排右半
        Merge(L, T, low, mid, high);     // 归并
    }
}
```

#### 2. 复杂度推导

归并趟数 = 递归树高度 = `⌈log2 n⌉`；每趟归并都要遍历全部 `n` 个元素，代价 `O(n)`。

即 `T(n) = 2T(n/2) + O(n)`，由主定理（或递归树）得 `T(n) = O(n log n)`。

- **最好、最坏、平均都是 `O(n log n)`**，与初始序列**无关**（划分方式只由下标决定）。
- **空间**：`O(n)`（辅助数组 `T`）。这是归并排序最大的缺点。
- **稳定**：`L[i] <= L[j]` 时优先取左边即可保证稳定。
- 归并排序是**唯一**在「稳定 + `O(n log n)` + 与初始序列无关」三项上同时满足的比较排序。

#### 3. 为什么归并排序特别适合外部排序

外部排序的瓶颈是 `I/O`。归并排序的**访问模式是顺序的**（每个归并段顺序读完），而快排、堆排序都要随机访问，在外存上会引发大量随机寻道。所以外部排序以「归并」为核心，只是把「二路」升级成「多路」。

> **408 怎么考 / 常见坑**：
> ① 「二路归并排序需要多少辅助空间？」→ `O(n)`，必答点。
> ② 手算题：写「每趟归并后的结果」。注意先**两两分组归并**（长度为 1 归成长度 2，再归成长度 4……），而不是像快排那样先划分。
> ③ 「归并的趟数」与「递归深度」都是 `⌈log2 n⌉`，但**归并排序不是原地排序**。
> ④ 完成「一趟归并」的含义：把相邻的长度为 `len` 的有序段两两合并成长度 `2*len`，最后可能剩一个落单段直接保留。

### 8.10 基数排序

#### 1. 思路：不比较关键字，靠「分配 + 收集」

基数排序（Radix Sort）属于**分配类排序**，全程**不做关键字比较**。以 `LSD`（最低位优先）为例，对关键字（或关键字组合）从**最低位到最高位**依次处理：

1. **分配**：按当前位的值（`0~r-1`），把元素依次放入 `r` 个队列中；
2. **收集**：按队列 `0, 1, ..., r-1` 的顺序把元素串起来，形成新的序列；
3. 对更高一位重复，共 `d` 趟（`d` 为关键字位数，`r` 为基数）。

**为什么 LSD 必须从最低位开始？** 因为后一趟的处理必须建立在「前一趟已按低位有序」的基础上，且**收集时采用先进先出**，才能保证高位相同的元素保持低位有序 —— 这也是基数排序**稳定**的原因。

#### 2. 例子

序列 `{278, 109, 63, 930, 589, 184, 505, 269, 8, 83}`，基数 `r = 10`，`d = 3`：

| 趟次 | 处理位 | 处理后的序列 |
| --- | --- | --- |
| 第 1 趟 | 个位 | `930, 63, 83, 184, 505, 278, 8, 109, 589, 269` |
| 第 2 趟 | 十位 | `505, 8, 109, 930, 63, 269, 278, 83, 184, 589` |
| 第 3 趟 | 百位 | `8, 63, 83, 109, 184, 269, 278, 505, 589, 930` |

#### 3. 关键结论

- **时间**：`O(d(n + r))`。一趟分配 `O(n)`、一趟收集 `O(n + r)`，共 `d` 趟。
- **空间**：`O(r)`（`r` 个队列的头尾指针等；若每个队列都用链式存储，则还需要 `n` 个结点空间）。
- **稳定**：稳定（收集保持先进先出）。
- **不比较**：基数排序不是比较排序，因此**不受 `O(n log n)` 下界约束**。
- **适用**：关键字的**位数少、取值范围小（`r` 小）**而 `n` 很大时（如身份证号、手机号分桶），效率极高。
- **`LSD` 与 `MSD`**：`LSD`（最低位优先）是自底向上逐位进行，**不需要递归**，实现简单，是 408 的标准考法；`MSD`（最高位优先）是自顶向下按位分组后**对每组递归**，实现复杂。

| 对比项 | `LSD`（最低位优先） | `MSD`（最高位优先） |
| --- | --- | --- |
| 处理顺序 | 个位 → 十位 → ... → 最高位 | 最高位 → 次高位 → ... |
| 实现方式 | 循环 `d` 趟，配 `r` 个队列 | 递归，按位分桶后组内递归 |
| 稳定性 | 稳定 | 稳定 |
| 408 考法 | 主流，手算题基本都是它 | 概念辨识题 |

> **408 怎么考 / 常见坑**：
> ① 复杂度写成 `O(d(n+r))` 而不是 `O(n)`，`d`、`r` 的含义要说清（`d` 位数、`r` 基数）。
> ② 基数排序是**唯一不通过比较**的常见内部排序，常考「下列哪种排序算法不需要比较关键字」。
> ③ 手算题要写清每一趟分配、收集后的序列，注意**收集时同一个队列内部保持原序**。

### 8.11 外部排序

#### 1. 为什么需要外部排序

当记录数 `n` 极大（文件放不进内存）时，必须把数据分批读入内存排序，再写回外存，最后把多个**有序子文件（归并段）**合并。这就是外部排序。

**时间组成**：外部排序总时间 = **内部排序时间**（生成初始归并段） + **`I/O` 时间**（读写外存） + **内部归并时间**（比较）。其中 **`I/O` 时间占绝对主导**，所以外部排序的一切优化都围绕「减少 `I/O` 次数」。注意：外部排序的优化目标不是减少比较次数。

#### 2. 多路平衡归并与归并趟数

设初始归并段有 `m` 个，做 `k` 路归并（一次合并 `k` 个归并段），则**归并趟数**：

```
S = ⌈log_k m⌉
```

- 增大 `k`（路数）→ `S` 减少 → `I/O` 次数减少。
- 但 `k` 增大后，从 `k` 个归并段中选最小元素的**内部比较次数**增大：朴素做法每输出一个元素需 `k-1` 次比较，一趟内部比较共 `(k-1)·n` 次，总内部比较达 `(k-1)·n·⌈log_k m⌉`，随 `k` 增大而增大。
- **败者树**就是为解决这个矛盾而生的：它把「从 `k` 个元素中选最小」的代价从 `O(k)` 降到 `O(log2 k)`，使得增大 `k` 时内部比较次数不再显著膨胀，于是「增大 `k` 减少 `I/O`」这条优化路才真正走通。

> 关键：**败者树不减少 `I/O` 次数，它减少的是内部比较次数。**「增大 `k` 减少 `I/O`、败者树抵消其副作用」这句话要背下来。

#### 3. 败者树的结构与工作方式

- 败者树是一棵**完全二叉树**，`k` 个归并段对应 **`k` 个叶子**结点，内部结点数为 **`k-1`**（整棵树共 `2k-1` 个结点）。
- 每个**内部结点记录「刚刚比较的败者」**，胜者继续向上传，最终在根的上方（`ls[0]`）保存**冠军**（当前最小元素所在归并段）。
- 当冠军段输出一个元素后，只需**沿从该叶子到根的路径**重新比较 `⌈log2 k⌉` 次，即可得到新的最小值 —— 这就是 `O(log2 k)` 的来源。
- 相比朴素的「每次遍历 `k` 个段找最小」（`O(k)`），败者树在 `k` 较大时优势明显。

**为什么叫「败者树」而胜者树？** 因为内部结点存的是**败者**，好处是：当叶子值变化时，只需把新值与父结点存的败者比较即可继续上升，**不必回溯兄弟结点**，实现更简洁（胜者树需要访问兄弟）。

#### 4. 置换-选择排序：生成更长的初始归并段

普通做法生成的初始归并段长度受内存工作区大小 `w` 限制（每段约 `w` 个记录），段数 `m` 就大，`S` 也大。

**置换-选择排序**用一个大小为 `w` 的内存工作区 + 一个输出缓冲，配合「**选择当前工作区中 ≥ 上次输出值的最小元素**」的规则，可以生成**平均长度为 `2w`** 的初始归并段（树形选择/败者树实现时），从而**减少归并段个数 `m`**，进而减少归并趟数。

关键机制：被输出元素留下的空位由输入文件补入新元素；若新元素**小于**刚输出的值（即属于下一段），则暂不参与当前段的选择，留到下一段使用。这样一段可以「跨过」工作区容量继续增长。

> 一句话：**置换-选择排序不减少 `I/O` 的直接次数，而是通过减少归并段个数 `m` 来减少归并趟数 `S`。**

#### 5. 最佳归并树（哈夫曼思想）

各初始归并段的长度不同，不同的**归并顺序（归并树形状）**会导致不同的总 `I/O` 量。要让总 `I/O` 最小，就应让**短的归并段先归并、长的归并段后归并** —— 这正是**哈夫曼树**的思想：把归并段长度当权值，构造**带权路径长度 `WPL` 最小**的 `k` 叉哈夫曼树。

- **`k` 叉哈夫曼树的存在条件**：设归并段个数为 `m`，则必须满足 `(m - 1) mod (k - 1) == 0`。若不满足，需要**补充 `(k-1) - (m-1) mod (k-1)` 个长度为 0 的「虚段」（空归并段）**，它们不产生实际 `I/O`，只是为了让树成为严格的 `k` 叉树。
- `WPL` = 每个叶子权值 × 其到根的路径长度之和 = **总 `I/O` 记录数**（把根到叶路径长度理解为该段被读写的次数）。

**例**：`m = 8`，`k = 3`。`(8-1) mod (3-1) = 7 mod 2 = 1 ≠ 0`，需补 `2 - 1 = 1` 个虚段，得到 9 个叶子，`(9-1)/2 = 4` 个内部结点，是满三叉树。

#### 6. `I/O` 次数的计算方法（大题核心）

**基本公式**：

```
每趟归并的 I/O 次数 = 读入全部记录 + 写出全部记录 = 2 × n 次记录读写
                    （若按"块"计，则为 2 × 总块数）
总 I/O 次数 = 生成初始归并段的 I/O + 归并过程的总 I/O
归并过程总 I/O = 2 × (S + 1) × n   ← 用"归并树根到叶路径长度"理解更本质
```

更实用的两个视角：

**视角 A（趟数法）**：设文件共 `n` 个记录、`b` 个物理块。

1. 生成初始归并段：读全部 ∪ 写全部 = `2b` 次块 `I/O`（往返各一次）。
2. 每趟归并：读 `b` 块 + 写 `b` 块 = `2b` 次。
3. 共 `S = ⌈log_k m⌉` 趟。

```
总块 I/O 次数 = 2b × (1 + S)          （生成段 1 次 + 归并 S 趟）
```

**视角 B（最佳归并树法）**：用 `WPL` 直接算。叶子权值取「该段的记录数」，则 `WPL` 就是归并阶段读+写的记录总数；再加生成初始归并段的 `2n`。

**例**：文件有 10000 个记录，每个物理块 100 个记录（`b = 100`），初始归并段 `m = 100` 个，做 4 路平衡归并，则 `S = ⌈log_4 100⌉ = 4`（因为 `4^3 = 64 < 100 <= 256 = 4^4`）。总块 `I/O` = `2 × 100 × (1 + 4) = 1000` 次。

> **408 怎么考 / 常见坑**：
> ① `S = ⌈log_k m⌉` 里的 `m` 是**初始归并段个数**，不是记录数；`k` 是**归并路数**。两者别混。
> ② 「增大 `k` 能否无限优化？」→ 不能。`I/O` 次数虽减少，但内存需容纳 `k` 个输入缓冲 + 1 个输出缓冲，硬件成本上升；且内部比较开销增大（用败者树缓解）。
> ③ 补充虚段的条件 `(m-1) mod (k-1) == 0` 是必背，考试常给 `m = 8, k = 3` 这种需要补 1 个虚段的例子。
> ④ 「败者树减少的是什么？」→ **内部比较次数**，不是 `I/O` 次数。这是最经典的偷换概念陷阱。

### 8.12 排序算法的分析与应用

#### 1. 怎么选排序算法（决策顺序）

1. **`n` 很小（如 `n <= 50`）**：用直接插入或简单选择。数据基本有序 → 直接插入（接近 `O(n)`）；元素移动代价大 → 简单选择（移动次数少）。
2. **`n` 很大**：看要求。
   - 要求**稳定** → 二路归并（`O(n log n)`，但 `O(n)` 空间）；若空间紧张，考虑基数排序（数据适合时）。
   - 不要求稳定、要求**平均最快** → 快速排序。
   - 不要求稳定、要求**最坏也保证 `O(n log n)`**、或空间要 `O(1)` → 堆排序。
   - 关键字**位数少、`n` 极大** → 基数排序。
3. **数据规模大到内存放不下** → 外部排序（多路平衡归并 + 败者树 + 置换-选择 + 最佳归并树）。
4. **`n` 中等规模，不在意稳定性** → 希尔排序。

#### 2. 排序算法总对比表（本章最重要的表，必须完整记牢）

| 算法 | 最好时间 | 平均时间 | 最坏时间 | 空间 | 稳定性 | 是否原地 | 比较次数与初始序列有关 | 每趟能否确定最终位置 | 适用场景 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 直接插入排序 | `O(n)` | `O(n^2)` | `O(n^2)` | `O(1)` | **稳定** | 是 | 有关 | 否 | `n` 小、基本有序 |
| 折半插入排序 | `O(n log n)`（比较） | `O(n^2)` | `O(n^2)` | `O(1)` | **稳定** | 是 | **无关**（比较次数） | 否 | `n` 小；比较代价高时 |
| 起泡排序 | `O(n)`（带标志位） | `O(n^2)` | `O(n^2)` | `O(1)` | **稳定** | 是 | 有关 | 能（每趟定最值） | `n` 小；教学/入门 |
| 简单选择排序 | `O(n^2)` | `O(n^2)` | `O(n^2)` | `O(1)` | 不稳定 | 是 | **无关**（比较次数固定） | 能（每趟定最小值） | `n` 小；移动代价大 |
| 希尔排序 | 与增量有关 | 与增量有关 | `O(n^2)`（`n/2` 增量） | `O(1)` | 不稳定 | 是 | 有关 | 否 | `n` 中等、不需稳定 |
| 快速排序 | `O(n log n)` | `O(n log n)` | `O(n^2)` | `O(log n)`~`O(n)` | 不稳定 | 是（不计栈） | 有关（最坏在基本有序） | 能（枢轴归位） | 大规模、平均最快 |
| 堆排序 | `O(n log n)` | `O(n log n)` | `O(n log n)` | `O(1)` | 不稳定 | 是 | **有关**（比较次数随堆形态变；**时间**恒 `O(n log n)`） | 能（每趟定最值） | 要求最坏也 `O(n log n)`；`TopK` |
| 二路归并排序 | `O(n log n)` | `O(n log n)` | `O(n log n)` | **`O(n)`** | **稳定** | 否 | **无关** | 否 | 要求稳定；**外部排序** |
| 基数排序 | `O(d(n+r))` | `O(d(n+r))` | `O(d(n+r))` | `O(r)` | **稳定** | 否 | 无关（不比较） | 否 | 位数少、`n` 极大 |

**记忆口诀**：

- 时间下界三兄弟（`O(n log n)` 平均）：**快、堆、归**。
- 稳定五兄弟：**插、冒、归、基**（外加折半插入）。
- 不稳四兄弟：**快、希、选、堆**。
- 空间两例外：**归并 `O(n)`、基数 `O(r)`**。
- 「无关」分两种：**比较次数无关** = 折半插入、简单选择（基数不比较）；**时间无关** = 堆、归并、简单选择 —— 表中「比较次数与初始序列有关」这一列只问**比较次数**，堆排序在这一列填「**有关**」。

> **408 怎么考**：这张表直接对应选择题，考试形式通常是「给出四个算法判断其稳定性/复杂度/是否与初始序列有关」。建议合上书默写整张表，一遍不对就再来一遍。

#### 3. 应用型考点

- **求逆序对个数**：可用归并排序（`Merge` 时若取右边元素，则左边剩余元素都与之构成逆序对，累加 `mid - i + 1`）、也可用树状数组 / `BST`。归并做法时间 `O(n log n)`。
- **求第 `k` 小**：可用快排的 `Partition` 做「快速选择」，平均 `O(n)`。
- **`TopK`**：堆（见 8.8）。
- **外部排序的优化链路**：置换-选择排序（减 `m`）→ 多路归并 + 败者树（减 `S` 与内部比较）→ 最佳归并树（减总 `WPL`）。

## 四、例题精练（3 道）

### 例题 1（选择题）

**题目**：下列关于排序算法的叙述中，**正确**的是（　　）

A. 快速排序是不稳定的排序算法，其最坏情况下的时间复杂度为 `O(n log n)`
B. 二路归并排序是稳定的排序算法，其空间复杂度为 `O(1)`
C. 简单选择排序的比较次数与初始序列无关，且其空间复杂度为 `O(1)`
D. 堆排序在最坏情况下的时间复杂度为 `O(n^2)`，因此不适合处理大规模数据

**答案：C**

**逐项解析**：

- **A 错**。前半句对（快排确实不稳定），后半句错。快排**最坏**为 `O(n^2)`（当序列基本有序或基本逆序、枢轴固定取首元素时，每次划分严重不均，递归深度退化为 `n`）。只有**平均**和**最好**才是 `O(n log n)`。这是最常见的偷换与拼接陷阱：把两个正确但互不匹配的半句拼起来。
- **B 错**。前半句对（归并稳定），后半句错。二路归并需要**长度为 `n` 的辅助数组**，空间复杂度为 `O(n)`，这也是它相对于快排、堆排序的主要劣势。堆排序的空间才是 `O(1)`。
- **C 对**。简单选择排序第 `i` 趟在 `n-i` 个元素中找最小值，比较次数为 `(n-1)+(n-2)+...+1 = n(n-1)/2`，**只取决于 `n`，与初始序列完全无关**；同时它只用了几个临时变量，空间复杂度 `O(1)`（注意它的**移动**次数与序列有关，但题干说的是比较次数，正确）。
- **D 错**。堆排序的最好、平均、最坏都是 `O(n log n)`，正是它「最坏情况有保证」的优点，恰恰**适合**大规模数据。前半句就是错的。

> **本题采分点**：把「时间复杂度」拆成最好/平均/最坏三个值分别核对，警惕「前半句对、后半句错」的拼接选项。

### 例题 2（计算题：三小问）

#### (1) 一趟快速排序划分

**题目**：对序列 `{49, 38, 65, 97, 76, 13, 27, 49}` 进行快速排序，取第一个元素为枢轴，写出**第一趟划分**后的结果。

**解**（挖坑法）：`pivot = 49`，`low = 1`，`high = 8`。

| 步骤 | 操作 | 当前序列 |
| --- | --- | --- |
| 初始 | — | `49, 38, 65, 97, 76, 13, 27, 49` |
| 1 | `high` 左移找到 `27 < 49`，填左坑 | `27, 38, 65, 97, 76, 13, [ ], 49` |
| 2 | `low` 右移找到 `65 > 49`，填右坑 | `27, 38, [ ], 97, 76, 13, 65, 49` |
| 3 | `high` 左移找到 `13 < 49`，填左坑 | `27, 38, 13, 97, 76, [ ], 65, 49` |
| 4 | `low` 右移找到 `97 > 49`，填右坑 | `27, 38, 13, [ ], 76, 97, 65, 49` |
| 5 | `high` 继续左移，与 `low` 在位置 4 相遇 | `27, 38, 13, [ ], 76, 97, 65, 49` |
| 6 | 枢轴归位 `L[4] = 49` | **`27, 38, 13, 49, 76, 97, 65, 49`** |

**结果：`{27, 38, 13, 49, 76, 97, 65, 49}`**，枢轴 `49` 位于第 4 个位置（已是最终位置）。左子表 `{27, 38, 13}` 全部 `< 49`，右子表 `{76, 97, 65, 49}` 全部 `>= 49`。

#### (2) 初始建堆 + 堆排序过程

**题目**：对序列 `{49, 38, 65, 97, 76, 13, 27, 49}` 建立**大根堆**，写出建堆过程；然后写出堆排序前两趟的结果。

**解**：`n = 8`，最后一个分支结点为 `⌊8/2⌋ = 4`。从 `i = 4` 递减到 `1` 依次 `SiftDown`。

| 步骤 | 调整结点 | 说明 | 序列 |
| --- | --- | --- | --- |
| 初始 | — | 完全二叉树层序 | `49, 38, 65, 97, 76, 13, 27, 49` |
| 1 | `i=4`（值 97） | 孩子为位置 8 的 `49`，`97 > 49`，无需调整 | `49, 38, 65, 97, 76, 13, 27, 49` |
| 2 | `i=3`（值 65） | 孩子为位置 6 的 `13`、位置 7 的 `27`，较大者是 `27`；`65 > 27`，无需调整 | `49, 38, 65, 97, 76, 13, 27, 49` |
| 3 | `i=2`（值 38） | 孩子为位置 4 的 `97`、位置 5 的 `76`，较大者是 `97`；`38 < 97` → 交换 | `49, 97, 65, 38, 76, 13, 27, 49` |
| 3' | 继续下沉到 `i=4` | 位置 4 的孩子为位置 8 的 `49`；`38 < 49` → 交换 | `49, 97, 65, 49, 76, 13, 27, 38` |
| 4 | `i=1`（值 49） | 孩子为位置 2 的 `97`、位置 3 的 `65`，较大者是 `97`；`49 < 97` → 交换 | `97, 49, 65, 49, 76, 13, 27, 38` |
| 4' | 继续下沉到 `i=2` | 位置 2 的孩子为位置 4 的 `49`、位置 5 的 `76`，较大者是 `76`；`49 < 76` → 交换 | `97, 76, 65, 49, 49, 13, 27, 38` |
| 4'' | 继续下沉到 `i=5` | 位置 5 无孩子（`2*5 = 10 > 8`），停止 | **`97, 76, 65, 49, 49, 13, 27, 38`** |

**初始大根堆：`{97, 76, 65, 49, 49, 13, 27, 38}`**（堆顶 `97` 为最大值）。

**堆排序第 1 趟**：堆顶 `97` 与末尾 `38` 交换 → `{38, 76, 65, 49, 49, 13, 27 | 97}`，堆范围缩为前 7 个，对堆顶 `38` 做 `SiftDown`：
- `38` 的孩子 `76`、`65`，较大者 `76` → 交换 → `{76, 38, 65, 49, 49, 13, 27}`；
- `38` 到位置 2，孩子 `49`、`49`，较大者 `49` → 交换 → `{76, 49, 65, 38, 49, 13, 27}`；
- `38` 到位置 4，无孩子，停止。

第 1 趟后：**`{76, 49, 65, 38, 49, 13, 27, 97}`**（`97` 就位）。

**堆排序第 2 趟**：堆顶 `76` 与当前堆末尾 `27` 交换 → `{27, 49, 65, 38, 49, 13 | 76, 97}`，堆范围缩为前 6 个，对堆顶 `27` 做 `SiftDown`：
- 孩子 `49`、`65`，较大者 `65` → 交换 → `{65, 49, 27, 38, 49, 13}`；
- `27` 到位置 3，孩子 `13`（位置 6），`27 > 13`，停止。

第 2 趟后：**`{65, 49, 27, 38, 49, 13, 76, 97}`**。

> **本题采分点**：① 建堆必须**从 `⌊n/2⌋` 递减到 1**；② 每次交换后要**继续沿路径下沉到底**，不能只换一层；③ 堆排序每趟交换后要**缩小堆的有效范围**（已就位元素不再参与调整），这一步漏了整题全错；④ 升序排序用**大根堆**。

#### (3) 外部排序归并趟数与 `I/O` 次数

**题目**：某文件共 `10000` 个记录，每个物理块可存 `100` 个记录，经内部排序后得到 `100` 个初始归并段。现采用 **4 路平衡归并**，求归并趟数与总 `I/O` 次数（以块为单位）。

**解**：

1. 块数 `b = 10000 / 100 = 100` 块。
2. 初始归并段个数 `m = 100`，归并路数 `k = 4`。
3. 归并趟数 `S = ⌈log_4 100⌉`。因 `4^3 = 64 < 100 <= 256 = 4^4`，所以 `S = 4`。
4. 生成初始归并段：读 `b` 块 + 写 `b` 块 = `2b = 200` 次块 `I/O`。
5. 每趟归并：读 `100` 块 + 写 `100` 块 = `200` 次；共 `4` 趟 = `800` 次。
6. 总 `I/O` 次数 = `200 + 800 = 1000` 次块读写。

**若改用 8 路平衡归并**：`S = ⌈log_8 100⌉ = 3`（`8^2 = 64 < 100 <= 512 = 8^3`），总 `I/O` = `2 × 100 × (1 + 3) = 800` 次。

**结论**：路数由 4 增到 8，`I/O` 次数由 `1000` 降到 `800`，约减少 `20%`；但代价是内存中需要 `8` 个输入缓冲 + `1` 个输出缓冲，且内部比较开销增大（**用败者树**把每次选最小的代价从 `O(k)` 降到 `O(log2 k)`）。

> **本题采分点**：① `S = ⌈log_k m⌉` 中 `m` 是**归并段个数** `100`，不是记录数 `10000`；② 别忘「生成初始归并段」也要算一趟读写（`2b`）；③ `I/O` 次数要**以块为单位**（题干给的是「每个物理块可存 100 个记录」，必须先换算成 `b` 块）。

### 例题 3（算法设计题）

#### 题目一：实现 `Partition`（快速排序的一趟划分）

**要求**：以顺序表 `L[1..n]` 存储记录，写出函数 `Partition(L, low, high)`，以 `L[low]` 为枢轴完成一趟划分，返回枢轴最终位置，并说明时间与空间复杂度。

```c
// 一趟划分：挖坑法。返回枢轴最终所在下标
int Partition(int L[], int low, int high) {
    int pivot = L[low];                 // 暂存枢轴，L[low] 成为"坑"
    while (low < high) {
        // 从右往左找第一个 < pivot 的元素，填到左坑
        while (low < high && L[high] >= pivot)
            high--;
        L[low] = L[high];
        // 从左往右找第一个 > pivot 的元素，填到右坑
        while (low < high && L[low] <= pivot)
            low++;
        L[high] = L[low];
    }
    L[low] = pivot;                     // 枢轴归位（此时 low == high）
    return low;
}
```

**思路**：枢轴挖出后形成「坑」，用两个指针从两端向中间夹逼，交替用「从另一端找到的越界元素」填当前坑，坑的位置随之转移。指针相遇处即枢轴最终位置。

**复杂度**：时间 `O(high - low + 1)`，即一趟划分 `O(n)`；空间 `O(1)`（只用常数个辅助变量）。**不稳定**（`>=`、`<=` 的比较使相等元素可能跨距离交换）。

**408 采分点**：① 循环条件必须写 `low < high &&`，否则数组越界；② `L[high] >= pivot` 和 `L[low] <= pivot` 中的等号不能丢，否则相等元素会导致死循环；③ 最后一定要把 `pivot` 写回 `L[low]`。

#### 题目二：实现 `SiftDown` 并建堆

**要求**：写出大根堆的向下调整函数 `SiftDown(L, k, n)` 和建初堆函数 `BuildHeap(L, n)`，并分析建堆的时间复杂度。

```c
// 向下调整：把 L[k] 调整到合适位置，堆的有效范围为 L[1..n]
void SiftDown(int L[], int k, int n) {
    L[0] = L[k];                             // 暂存到哨兵位
    for (int i = 2 * k; i <= n; i *= 2) {    // 沿孩子链向下
        if (i < n && L[i] < L[i + 1]) i++;   // i 指向较大的孩子
        if (L[0] >= L[i]) break;             // 已满足堆性质，结束
        L[k] = L[i];                         // 较大孩子上移
        k = i;                               // 继续向下检查
    }
    L[k] = L[0];                             // 归位
}

// 建初堆：自下而上，从最后一个分支结点开始
void BuildHeap(int L[], int n) {
    for (int i = n / 2; i >= 1; i--)
        SiftDown(L, i, n);
}
```

**思路**：`SiftDown` 每次都把当前结点与**较大的那个孩子**比较，小则交换并继续下沉（代码中改为「孩子上移、目标位置下移」，最后一次写入，减少移动次数）。`BuildHeap` 必须**自下而上**，因为 `SiftDown` 要求被调整结点的子树已经是堆。

**建堆的时间复杂度**：`O(n)`。推导：高度为 `h` 的结点最多有 `⌈n / 2^(h+1)⌉` 个，每个最多下移 `h` 层，总代价为

```
Σ(h 从 0 到 ⌊log2 n⌋) ⌈n / 2^(h+1)⌉ × h  =  O(n × Σ h/2^h)  =  O(n)
```

（级数 `Σ h/2^h` 收敛于 2。）**这就是「初始建堆是 `O(n)` 而非 `O(n log n)`」的原因。**

**408 采分点**：① `i = 2*k` 起始、`i *= 2` 递增，是「沿孩子链」的关键；② `if (i < n && L[i] < L[i+1]) i++;` 中先判 `i < n` 防止越界，取的是**较大**孩子；③ 建堆必须**从 `n/2` 递减到 `1`**（方向错则结果不是堆）；④ 空间 `O(1)`，不稳定。

#### 题目三：用归并思想求逆序对个数

**要求**：给定数组 `L[1..n]`，用归并排序的思想统计逆序对个数（若 `i < j` 且 `L[i] > L[j]`，则 `(L[i], L[j])` 是一个逆序对），要求时间 `O(n log n)`。

```c
int cnt = 0;    // 逆序对总数（全局变量）

void MergeCount(int L[], int T[], int low, int mid, int high) {
    int i = low, j = mid + 1, k = low;
    while (i <= mid && j <= high) {
        if (L[i] <= L[j]) {
            T[k++] = L[i++];
        } else {
            // L[j] 比左半部剩下的 (mid - i + 1) 个元素都小
            // 这 (mid - i + 1) 个元素每个都与 L[j] 构成一个逆序对
            cnt += (mid - i + 1);
            T[k++] = L[j++];
        }
    }
    while (i <= mid)  T[k++] = L[i++];
    while (j <= high) T[k++] = L[j++];
    for (k = low; k <= high; k++) L[k] = T[k];
}

void MergeSortCount(int L[], int T[], int low, int high) {
    if (low < high) {
        int mid = (low + high) / 2;
        MergeSortCount(L, T, low, mid);         // 左半部的逆序对
        MergeSortCount(L, T, mid + 1, high);    // 右半部的逆序对
        MergeCount(L, T, low, mid, high);       // 跨越左右两半的逆序对
    }
}
```

**思路**：逆序对分三类 —— 全在左半部、全在右半部、跨越左右。前两类由递归解决，第三类在 `Merge` 时顺手统计：当取右半部的 `L[j]` 时，说明 `L[j]` 小于左半部剩余的所有元素 `L[i..mid]`，因此一次性贡献 `mid - i + 1` 个逆序对。

**复杂度**：时间 `O(n log n)`（与归并排序同阶），空间 `O(n)`（辅助数组 `T`）。**稳定**（用的是 `L[i] <= L[j]` 优先取左）。

**408 采分点**：① 核心是 `cnt += mid - i + 1` 这一句，必须解释清楚「为什么一次能加一批」；② 统计的是**左半部剩余元素与右半部当前元素**构成的逆序对，别与「左半部与右半部已输出元素」搞混；③ 只需在归并排序的 `Merge` 里加一行，不能改变原有的 `O(n log n)` 复杂度。

## 六、简便方法与易错口诀（速算 · 防错）

> 本节把本章能"省时间"和"防掉坑"的招集中在一处：二轮复习与考前只看这一节。每条都写清**适用条件**。

### 6.1 速算招式

| 场景 | 常规做法（慢/繁） | 简便做法（快/稳） | 为什么成立 / 适用条件 |
| --- | --- | --- | --- |
| 判断稳定性 | 逐个算法回忆代码细节 | 背口诀「**快选希堆不稳**」，其余（直接插入、折半插入、起泡、归并、基数）稳定 | 不稳定的只有快速、简单选择、希尔、堆这 4 个。**适用条件**：判的是算法固有性质，与某次输入的运行结果无关（本来就有序的序列可能"看不出"不稳定） |
| 问「第 `k` 趟后哪些元素已到位」 | 完整模拟整趟过程 | 只有**起泡、简单选择、堆排序、快速排序**能每趟确定 1 个元素的最终位置；插入类、归并、基数、希尔都不能 | 快排每趟确定的是**枢轴**的最终位置（不是最大/最小值）。`k` 趟最多累计 `k` 个元素到位，别把「有序段变长」当成「元素到位」 |
| 手算快排一趟划分 | 逐对元素两两比较 | **挖坑法**：枢轴取第一个元素并"挖坑"；**从枢轴的另一端（`high`）开始**找 `< 枢轴` 的填左坑，再从 `low` 找 `> 枢轴` 的填右坑，两边交替换手，指针相遇处填入枢轴 | 相遇位置就是枢轴的最终位置。**收尾必须自检**「左边全 `< 枢轴` ≤ 右边」。`Partition` 两种实现在「元素集合归属」上结果相同，中间过程可不同 |
| 初始建堆 | 把元素逐个插入堆，`O(n log n)` | 从**最后一个非叶结点 `⌊n/2⌋`** 开始，自下而上对每个结点做 `SiftDown`，总代价 `O(n)` | 只有 `⌊n/2⌋` 及其之前的结点有孩子；越靠下的结点调整高度越小，求和后是 `O(n)`。这就是「为什么建堆不是 `O(n log n)`」的标准答案 |
| 手算堆排序全过程 | 每趟重画整棵树 | 先建大根堆；每趟只做三步：**堆顶 ↔ 当前末尾**交换（该元素即到位，退出堆）、堆长度减 1、对**堆顶**做一次 `SiftDown` | 已到位的尾部元素不再参与。每趟 1 次交换 = 3 次移动，**时间**恒 `O(n log n)`、与初始序列无关（但**比较次数**随初始序列变化） |
| 问「比较次数与初始序列无关」的算法 | 逐个算法试算 | **只有折半插入**（比较次数只由 `n` 决定）、**简单选择**（恒 `n(n-1)/2`）；基数排序不比较 | **堆排序不能选**：它的比较次数随初始序列变化（随堆的形态与元素关系而变，实测 `n = 4` 时 `{1,2,3,4}` 为 7 次、`{4,3,2,1}` 为 6 次）。折半插入只优化了比较，移动次数与直接插入完全相同 |
| 问「时间复杂度与初始序列无关」的算法 | 逐个算法试算 | **堆排序**（恒 `O(n log n)`）、**归并排序**（恒 `O(n log n)`）、**简单选择排序**（恒 `O(n^2)`） | 「时间无关」指最好/平均/最坏三者的阶相同，**不等于比较次数恒定**；快排、直接插入、起泡的时间都与初始序列有关 |
| 比较/移动次数数值速算 | 现场重新推导 | 简单选择比较恒为 `n(n-1)/2`；起泡最坏比较 `n(n-1)/2`、最坏移动 `3n(n-1)/2`；直接插入最坏比较与移动都约 `n^2/2`；折半插入移动次数与直接插入完全相同 | 统一口径：**一次交换 = 3 次移动**（`temp` 存、写、再写）。简单选择移动最多 `3(n-1)`、最少 0，是移动次数最少的一类 |
| 归并排序秒答 | 画递归树逐层算 | 时间**恒** `O(n log n)`（最好 = 平均 = 最坏）、空间 `O(n)`、**稳定**、**不是原地**；二路归并的趟数（= 递归深度）= `⌈log2 n⌉` | 段长按 1 → 2 → 4 → ... 翻倍。注意「时间与初始序列无关」≠「比较次数恒定」，见 6.1 下方的口径提醒与订正提示 |
| 基数排序秒答 | 背一长串成立条件 | `d` 趟「分配 + 收集」，时间 `O(d(n+r))`、空间 `O(r)`、**稳定**、**不比较**，故不受 `O(n log n)` 下界约束 | `d` = 关键字位数、`r` = 基数（十进制 `r = 10`）。适用条件是**位数少、`r` 小、`n` 极大**；趟数与比较都只由 `d`、`r` 决定，与初始序列无关 |
| 快排最坏情形 | 背一句结论 | **基本有序或基本逆序 + 取首元素为枢轴** → 每次划分一边空、一边 `n-1`，递归深度 `n`，时间 `O(n^2)`、栈空间 `O(n)` | 随机枢轴把最坏情况出现概率压到极低，三数取中能避开有序退化，但**两者都不改变最坏界仍是 `O(n^2)`** |
| 外部排序三公式 | 逐趟数块 | 归并趟数 `S = ⌈log_k m⌉`；总块 `I/O` 次数 = `2b × (1 + S)`；补虚段条件 `(m-1) mod (k-1) == 0`，不满足则补 `(k-1) - (m-1) mod (k-1)` 个虚段 | `m` 是**初始归并段个数**不是记录数，`k` 是**归并路数**，`b` 是文件总块数（`1` 指生成初始归并段那一趟）。优化链路：置换-选择（减 `m`）→ 多路归并 + 败者树（减 `S` 与内部比较）→ 最佳归并树（哈夫曼思想，减 `WPL`） |
| 逆序对 / 第 `k` 小 / `TopK` | 暴力枚举 `O(n^2)` | 逆序对用归并：`Merge` 中取右段元素时 `cnt += mid - i + 1`；第 `k` 小用 `Partition` 做**快速选择**（平均 `O(n)`）；`TopK` 用堆 | 归并求逆序对时间 `O(n log n)`、空间 `O(n)`、稳定；快速选择平均 `O(n)`、最坏 `O(n^2)`。这三招都要求"只求局部信息、不求全局有序" |

> **口径提醒**：
> - **考场判别**：题目问「比较次数与初始序列无关的是」，答案取 `折半插入排序`（比较次数只由 `n` 决定）与 `简单选择排序`（恒为 `n(n-1)/2`）；若选项里**同时出现 `堆排序` 与 `简单选择排序`**，选 `简单选择排序` —— 它恒为 `n(n-1)/2`，是没有争议的那个，而 `堆排序` 的比较次数会随初始序列变化。
> - **最容易的张冠李戴**：很多资料把「堆排序**时间**与初始序列无关（恒 `O(n log n)`）」误记成「堆排序**比较次数**与初始序列无关」，这两句必须分开说。实测反例：`n = 4` 时输入 `{1,2,3,4}` 建堆 + 排序共比较 7 次，输入 `{4,3,2,1}` 共 6 次。
> - **一句话记忆**：**「比较次数无关」看简单选择与折半插入；「时间无关」看堆与归并。**

> **订正提示（针对候选招式 5「比较次数与初始序列无关：折半插入、简单选择、归并」）**：把「归并」放进这一条并不准确，需分两层看。
> ① **时间与趟数**这一层确实与初始序列无关：二路归并时间恒 `O(n log n)`、趟数恒 `⌈log2 n⌉`，这也是正文总对比表与表 2 记的口径，考场上按「与初始序列无关」作答不会错。
> ② 但严格的**比较次数**会随初始序列浮动：合并两个长度为 `a`、`b` 的有序段需要 `min(a, b)` ~ `a + b - 1` 次比较（一段先耗尽就停止比较，两段交替耗尽则比较最多），序列不同总比较数就不同，所以**不能写成「比较次数恒为定值」**。
> ③ 要挑「比较次数与初始序列无关」的算法，标准答案是**折半插入、简单选择（恒 `n(n-1)/2`）**（外加"根本不比较"的基数排序）；**堆排序不能算进来** —— 它的比较次数随初始序列变化，堆排序属于「**时间**与初始序列无关」那一类。

### 6.2 口诀与记忆钩子

- **稳定性**：**「插冒归基稳，快的选希堆不稳」** —— 稳定 = 直接插入、折半插入、起泡、归并、基数；不稳定 = 快速、简单选择、希尔、堆。
- **复杂度与空间例外**：**「快、堆、归是平均 `O(n log n)` 三兄弟；空间两例外 —— 归并 `O(n)`、基数 `O(r)`」**（快排空间是递归栈 `O(log n)` ~ `O(n)`，不算例外）。
- **每趟定位**：**「冒、选、堆、快，一箭一雕」** —— 每趟能确定一个元素最终位置的就这 4 个；快排那"一箭"射中的是**枢轴**。
- **比较次数不随序列变**：**「折、选，比数不随序」**（折半插入、简单选择），再加一句**「基数根本不算比」**；**堆排序不进这一组** —— 它的比较次数随序列变，只进下面那条「时间无关」。
- **两种「无关」分清**：**「比较次数无关」看简单选择与折半插入；「时间无关」看堆与归并** —— 考场上先看清题干问的是"比较次数"还是"时间复杂度"。
- **建堆**：**「从尾往前，非叶起手」** —— 起点 `⌊n/2⌋`，自下而上，代价 `O(n)`。
- **快排**：**「有序反而最慢」** —— 基本有序 + 首元素枢轴 → `O(n^2)`；救场招是**随机枢轴 / 三数取中**（只降概率，不改最坏界）。
- **外部排序**：**「置换选择减 `m`，败者树减比较，最佳归并树（哈夫曼）减 `WPL`；趟数看 `⌈log_k m⌉`，`I/O` 看 `2b(1+S)`」**。
- **移动次数口径**：**「一次交换三次移」** —— 交换要经 `temp`，算 3 次移动；简单选择是"比较最多、移动最少"的典型。

### 6.3 反例黑名单（这些"简便法"是错的）

- ❌ **「快排平均 `O(n log n)`，所以最坏也是 `O(n log n)`」**：正确做法是记住最坏 `O(n^2)`，触发条件是**基本有序或基本逆序 + 首元素枢轴**；平均最快 ≠ 最坏也快。
- ❌ **「快速排序辅助空间是 `O(1)`」**：正确做法是写**递归工作栈 `O(log n)` ~ `O(n)`**（最坏来自递归深度 `n`）；`O(1)` 只是"原地挪动、不开辅助数组"的意思，两者别混。
- ❌ **「归并排序原地、空间 `O(1)`」**：正确做法是二路归并需要 **`O(n)` 辅助数组**，它是本章唯一"时间 `O(n log n)` + 稳定 + 不原地"的算法。
- ❌ **「堆排序稳定」或「堆排序空间是 `O(n)`」**：正确做法是堆排序**不稳定**、空间 `O(1)`（原地）；堆顶与末尾**长距离交换**会打乱相等元素次序（反例 `{5a, 5b, 3}`）。
- ❌ **「基数排序时间是 `O(n)`」**：正确做法是 `O(d(n+r))`，必须写清 `d` = 位数、`r` = 基数；它是**非比较**排序，但复杂度不是线性的 `O(n)`。
- ❌ **「败者树减少的是 `I/O` 次数」**：正确做法是败者树只把"从 `k` 个段中选最小"的内部比较从 `O(k)` 降到 `O(log2 k)`，`I/O` 次数由趟数 `S` 决定；**置换-选择排序也不直接减少 `I/O` 次数**，它靠加长初始归并段来减少 `m`，从而减少 `S`。
- ❌ **「建堆是逐个插入，代价 `O(n log n)`」**：正确做法是自下而上从 `⌊n/2⌋` 起 `SiftDown`，总代价 `O(n)`；`O(n log n)` 是"逐个插入建堆"的代价。
- ❌ **「希尔排序的增量只要递减就行，最后一趟不必为 1」**：正确做法是增量必须递减且**最后一趟增量必须为 1**（否则不能保证整体有序），且其时间复杂度依赖增量序列。
- ❌ **「外部排序的优化目标是减少比较次数」**：正确做法是外部排序时间由 **`I/O` 次数主导**，一切优化都为减少 `I/O`；比较次数只是"增大 `k`"带来的副作用，靠败者树抵消。
- ❌ **「由稳定性或"是否与初始序列有关"能推出时间复杂度高低」**：正确做法是把三条分开判：快排平均最快却不稳定；折半插入稳定、比较次数与序列无关，但总时间仍是 `O(n^2)` —— 三者互不推导。
