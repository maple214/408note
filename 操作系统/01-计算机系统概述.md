## 一、本章知识框架

- 计算机系统概述
  - 操作系统的基本概念
    - 定义：管理硬件与软件资源、为用户和应用程序提供服务的**系统软件**
    - 三种观点：资源管理者 / 用户与硬件的接口 / 虚拟机（对硬件的第一层扩充）
    - 目标：方便性、有效性、可扩充性、开放性
    - 作用：`OS` 是"管理机构 + 服务窗口"，把裸机改造成可用的"扩充机器"
    - 四个基本特征：并发、共享、虚拟、异步（并发与共享互为存在条件）
  - 操作系统的发展历程
    - 手工操作阶段：`I/O` 慢、`CPU` 空转，人机矛盾 + 速度矛盾
    - 批处理阶段：单道批处理（解决人机矛盾，`CPU` 仍等 `I/O`）→ 多道批处理（解决 `CPU` 等待，但无交互、响应慢）
    - 分时操作系统：解决交互问题，时间片轮转，多用户同时使用
    - 实时操作系统：硬实时 / 软实时，把"及时性 + 可靠性"放在效率之前
    - 网络操作系统、分布式操作系统、个人计算机操作系统、嵌入式操作系统（大纲未单列，了解即可）
  - 程序运行环境
    - `CPU` 运行模式：内核模式（核心态/管态）与用户模式（用户态/目态）
      - 划分依据：指令的执行权限
      - 特权指令 / 非特权指令
      - 状态切换的唯一方向：用户态 → 内核态靠**中断或异常**；内核态 → 用户态靠**特权指令修改 `PSW`**
      - 内核的组成：时钟管理、中断处理、原语、进程管理（以及存储管理、设备管理）
    - 中断和异常的处理
      - 外中断（中断）：时钟中断、`I/O` 中断、键盘中断
      - 内中断（异常）：故障 `fault`、自陷 `trap`、终止 `abort`
      - 中断处理过程：中断隐指令（硬件自动完成）→ 中断服务程序
      - "操作系统是中断驱动的"：所有要求内核介入的事件都靠中断通知 `CPU`
    - 系统调用
      - 概念：内核提供给用户程序的、在用户态用 `trap` 指令进入内核态执行的服务
      - 库函数与系统调用的区别（有的库函数不涉及系统调用）
      - 分类：设备管理、文件管理、进程控制、进程通信、内存管理
      - 执行过程：用户态传参 → `trap` 陷入 → 内核态查系统调用号、执行服务例程 → 返回用户态
    - 程序的链接与装入
      - 三步：编译 → 链接 → 装入
      - 装入方式：绝对装入、静态重定位（可重定位装入）、动态重定位（动态运行时装入）
      - 链接方式：静态链接、装入时动态链接、运行时动态链接
    - 程序运行时的内存映像与地址空间
      - 从高到低：内核空间 / 栈 / 共享库 / 堆 / `BSS` 段 / 数据段 / 代码段（典型 `Linux` 用户进程布局）
      - 逻辑地址（相对地址、虚拟地址）与物理地址
      - 地址空间：每个进程有独立的逻辑地址空间
  - 操作系统结构
    - 分层结构、模块化结构（大纲未单列模块化以外的细节，了解即可）
    - 宏内核（单内核）、微内核、外核
    - 取舍主线：**性能 ↔ 可靠性/可维护性**
  - 操作系统引导（大纲未单列细节，了解即可，但"引导块在硬盘哪个位置"是常考小点）

## 二、概念详解

### 1.1 操作系统的基本概念

- **是什么/为什么**：早期计算机没有操作系统，程序员直接操作硬件（插线板、纸带），效率极低。**操作系统的出现是为了"管起来"**：机器越来越快、部件越来越多，必须有个程序专门负责"谁用 `CPU`、谁占内存、谁读磁盘"，于是 `OS` 成为第一层系统软件。
- **定义（三段式，答题可套）**：操作系统是**管理和控制计算机硬件与软件资源的系统软件**，它**合理地组织、调度计算机的工作与资源的分配**，并**为用户和其他软件提供方便、有效的接口与环境**。
- **三种观点**（考试爱考"下列不属于…的是"）：
  1. **资源管理者**：管理处理机、存储器、`I/O` 设备、文件。体现为处理机管理、存储管理、设备管理、文件管理。
  2. **用户与硬件的接口**：向上提供两类接口——**命令接口**（联机命令/脱机命令，给人用）和**程序接口**（即系统调用，给程序用）。
  3. **虚拟机观点**：`OS` 是在裸机上安装的第一层软件，它把裸机"扩充"成一台功能更强、更好用的**虚拟机（扩充机器）**。注意这里的"虚拟机"是**逻辑上的扩充机器**，与第 1.6 节虚拟化技术的 `VM` 不是同一个概念，别混。
- **目标**：方便性（易用）、有效性（提高资源利用率与系统吞吐量）、可扩充性（易增改功能）、开放性（可移植、可互操作）。其中**方便性**靠"接口"实现，**有效性**靠"资源管理"实现——目标与作用是对应的。
- **408 提示**：常考"`OS` 是系统软件还是应用软件"→ **系统软件**，且是**最基本的系统软件**，是硬件之上的第一层。也常考"`OS` 的目标中，方便性和有效性哪个是主要目标"→ 现代 `OS` 把**有效性（资源利用率）**放在首位，方便性服务于它。**坑**：把"`OS` 是硬件与软件的接口"说成"`OS` 是软件与硬件的接口"时是对的，但说成"`OS` 就是一台真实机器"就错了——它是**扩充机器（虚拟机）**。

### 1.2 操作系统的四个基本特征

- **是什么/为什么**：这四个特征不是并列罗列，而是有因果链的：**先有并发，才需要共享与虚拟，而共享与虚拟又因资源竞争导致异步**。答题时能说出这条链，比死背四个词得分高。
- **关键点**：
  - **并发 `Concurrence`**：两个或多个事件在**同一时间间隔内**发生。宏观上同时，微观上交替。**单处理机同一时刻只能有一道程序占用 `CPU`**，所以并发是"宏观并行、微观串行"。
  - **共享 `Sharing`**：系统中的资源可供内存中多个并发执行的进程**共同使用**。两种方式：
    - **互斥共享**：一段时间内只允许一个进程访问（如打印机、临界资源）。
    - **同时共享**（宏观同时、微观交替）：如磁盘文件可被多个进程"同时"读。
  - **虚拟 `Virtual`**：把**一个物理实体变成多个逻辑对应物**（如虚拟处理机、虚拟存储器、虚拟设备 `SPOOLing`）；或反过来**把多个物理实体变成一个逻辑实体**（如虚拟存储器把主存+外存变成一个大逻辑内存）。
  - **异步 `Asynchronism`**：进程以**不可预知的速度**向前推进。因为资源有限，进程走走停停。**异步是并发的必然结果**，`OS` 必须保证"无论推进顺序如何，结果都一致"。
- **四个特征的关系（易考）**：**并发和共享互为存在条件**（没有并发就没有共享的必要；没有共享，并发无法进行）；**并发是共享的前提，虚拟以并发为前提，异步是并发的必然结果**。所以**并发是最基本的特征**。
- **408 提示**：几乎年年有一道关于"并发/并行"或"共享方式"的辨析题。**最容易错的表述**："单处理机系统中，进程可以并行执行"（错，只能并发）；"共享就是多个进程同时使用同一个资源"（不严谨，互斥共享是交替使用）；"没有并发就没有虚拟"（对）。判断通用技巧：出现"**同时（同一时刻）**"要立刻警觉——**并行**才要求同一时刻。

### 1.3 操作系统的发展历程

- **是什么/为什么**：发展史不是背年份，而是**背"每个阶段解决了什么矛盾"**。矛盾主线只有两条：**人机矛盾**（人操作太慢，机器闲置）和**`CPU` 与 `I/O` 设备速度不匹配的矛盾**（`CPU` 等 `I/O`）。
- **关键点**：

| 阶段 | 解决的核心矛盾 | 关键技术 | 遗留的问题 |
| --- | --- | --- | --- |
| 手工操作 | —（无 `OS`） | 纸带/插线板、人工装卡 | 用户独占全机；`CPU` 等人工操作，利用率极低 |
| 单道批处理 | **人机矛盾**（人工操作与机器速度的矛盾） | 监督程序、脱机输入输出 | 内存中只有一道程序，`CPU` 仍需等 `I/O`，利用率仍低 |
| 多道批处理 | **`CPU` 与 `I/O` 速度不匹配**（`CPU` 空等） | **多道程序设计**：内存同时放多道程序，交替运行 | **无交互能力、响应时间长**，用户不能干预 |
| 分时 | **交互问题**（用户需要人机对话） | **时间片轮转**、多用户同时使用一台主机 | 不能保证在严格期限内响应 |
| 实时 | **及时性与可靠性**（必须在截止时间内响应） | 优先级调度、抢占、硬实时/软实时 | 资源利用率让位于及时性 |

- **两个必须理解的名词**：
  - **多道程序设计**：内存中同时存放多道相互独立的程序，`CPU` 在它们之间**交替执行**。它带来三个结果：**提高了 `CPU` 与设备利用率、提高了系统吞吐量、但使系统变得复杂（要解决同步、互斥、安全问题）**。这是整个操作系统的**技术起点**。
  - **分时系统的四个特点**：**多路性**（多用户同时用）、**独立性**（各自操作互不干扰）、**及时性**（用户能在可接受时间内得到响应）、**交互性**（人机对话）。其中**交互性是分时系统最重要的特征**，也是它与批处理系统的分水岭。
- **408 提示**：常考"多道批处理的优点/缺点""分时系统的时间片是固定的还是可变的"。**坑 1**：把"批处理系统提高了资源利用率"篡改成"批处理系统提高了响应速度"（错，批处理响应最慢）。**坑 2**：把"分时系统的时间片"说成"动态调整"（错，**时间片固定**，是**多级反馈队列**才动态调整，属于第 2 章内容）。**坑 3**：实时系统的首要目标是**及时性和可靠性**，不是资源利用率。**坑 4**：网络操作系统 = 各机器有独立 `OS`、通过通信实现资源共享；分布式操作系统 = 统一 `OS`、各机器协同完成同一任务——这两者常被换位设错。

### 1.4 `CPU` 运行模式（核心态与用户态）

- **是什么/为什么**：如果用户程序能随便执行"关机中断""修改页表基址寄存器""直接读写磁盘"这类指令，系统会被瞬间破坏，也无法防止一个进程干扰另一个进程。所以硬件在 `PSW`（程序状态字）中设一个**模式位**，把 `CPU` 的指令执行权限分成两档。这就是"**两种运行模式**"的由来——本质是**保护机制**。
- **关键点**：
  - **用户态（目态）**：只能执行**非特权指令**，不能直接访问 `OS` 内核的数据结构与硬件资源。用户程序运行于此。
  - **核心态（内核态、管态）**：可执行**全部指令（含特权指令）**，可访问所有寄存器和存储区。`OS` 内核运行于此。
  - **状态位在 `PSW` 中**：`CPU` 每执行一条指令前先"看状态位"，据此决定该指令是否合法。所以**状态切换 = 修改 `PSW` 中的模式位**。
  - **切换的时机（必背）**：
    - **用户态 → 核心态**：**唯一途径是中断或异常**（含**系统调用**）。也就是必须由**硬件**在这次切换中起作用，因为用户程序无权改 `PSW`。常见触发事件：`trap` 指令（系统调用）、缺页异常、时钟中断、`I/O` 中断。
    - **核心态 → 用户态**：由内核执行**特权指令修改 `PSW`** 后返回。典型是中断服务程序末尾执行"返回"指令（如 `x86` 的 `iret`）。
    - **重要结论**：**中断/异常是 `CPU` 从用户态进入核心态的唯一入口**。没有中断机制，`OS` 就无法从用户程序手里"夺回"控制权。
  - **内核的组成**（哪些东西必须放在核心态运行）：
    - **时钟管理**：计时、时间片到、提供系统时间。
    - **中断处理**：`OS` 的"神经中枢"，是内核最核心的部分。
    - **原语**：**原子操作**，执行期间不可被中断（用**关中断**实现），如进程创建、`P`/`V` 操作的底层实现。
    - **进程管理**（以及存储管理、设备管理）：都在核心态。
  - **内核的划分方式（大纲未单列，了解即可）**：**大内核（宏内核）**——把时钟、中断、原语、进程/存储/设备管理全部放内核；**微内核**——只保留时钟、中断、原语等最基本功能，其余移到用户态。
- **408 提示**：这是本章**最高频**的考点，判断口诀是"**想做坏事必须先陷入内核**"。
  - 常考"下列事件中，会导致用户态转为核心态的是"→ 只要含**中断/异常/系统调用**就对；"用户程序调用库函数求平方根"**不会**切换（纯用户态计算）。
  - 常考"**从用户态到核心态的转换是由硬件完成的还是软件完成的**"→ **由硬件完成**（保存断点、切换 `PSW` 由中断隐指令完成）。而"从核心态到用户态"是由内核用特权指令完成的。
  - **坑 1**：把"进程切换"当成"模式切换"。进程切换（换 `PCB`、换页表）**必然发生在核心态**，但**不一定引起模式切换**（核心态线程切换仍在内核态）；反过来，**模式切换也不一定引起进程切换**（如一次系统调用处理完直接返回）。这两个概念在第 2 章还会考。
  - **坑 2**：**中断是让 `OS` 获得控制权的唯一方式，但不是唯一的进入核心态方式**——**异常**同样可以（如缺页、除零、`trap`）。选项里只写"中断"而漏掉"异常"时，要看题干是否把 `trap`/异常也归入"中断"的广义含义。

### 1.5 特权指令与非特权指令

- **是什么/为什么**：既然有两种模式，就必须规定"哪些指令只准在内核态执行"，否则模式划分形同虚设。这一条"准用清单"就是特权指令集合。
- **关键点**：
  - **特权指令**：**只允许 `OS` 内核使用**，用户程序无权执行。典型的有：
    - `I/O` 指令（启动/控制外部设备）
    - 设置时钟、清内存
    - **关中断 / 开中断**指令
    - 修改 `PSW`（含模式位）的指令
    - 设置中断屏蔽字、设置页表基址寄存器、修改栈指针（部分架构）
    - 停机指令（`halt`）
  - **非特权指令**：用户程序与内核都可执行。典型的有：算术/逻辑运算指令、数据传送指令（`MOV`）、访存指令、**陷入指令 `trap`**（也叫访管指令）、跳转指令。
  - **最反直觉、最容易考的一条**：**`trap`（访管）指令本身是非特权指令**。因为它的作用就是"让用户程序**主动请求**进入内核态"，如果它被划成特权指令，用户程序就无法进入内核，系统调用根本无法实现。`trap` 在用户态执行，执行后 `CPU` 进入核心态。
  - **另一个常考陷阱**：**`trap` 不是特权指令，但"执行 `trap` 之后的动作"是特权行为**。也就是说用户程序只能"敲门"，门里的活由内核干。
- **408 提示**：
  - 常见问法："下列指令中，**不属于**特权指令的是"→ 答案往往落在"算术运算""取数""`trap`""转移"上；"属于特权指令的是"→ 答案往往落在"关中断""设置时钟""`I/O` 指令""修改 `PSW`"上。
  - **坑 1**：把"设置时钟"和"读时钟"混淆——**设置**时钟是特权指令，**读**时钟（`RDTSC` 之类）通常不是，做题按"能改变系统全局状态的是特权指令"这一标准判断。
  - **坑 2**：**用户态可以直接执行 `trap`，但不能直接执行 `I/O` 指令**。所以"用户程序可以直接读写磁盘"必然错，正确路径是"用户程序调用系统调用 → 内核态执行 `I/O` 指令"。
  - **坑 3**："特权指令"是**硬件层面的权限划分**，与"这条指令是系统调用"不同——很多系统调用并不对应一条单独的特权指令，而是由一段内核代码完成。

### 1.6 中断和异常的处理

- **是什么/为什么**：`CPU` 跑用户程序时，`OS` 想知道"时间片到了没""磁盘读完没""用户是不是想调用内核"，就必须有个机制让**外部事件能打断 `CPU`、把控制权交给内核**。这个机制就是中断。**没有中断，多道程序无法并发，系统调用无法实现，`OS` 根本无法运行**——所以教材说"**操作系统是中断驱动的**"。
- **关键点（分类）**：
  - **外中断（狭义"中断"）**：来自 `CPU` **外部**、与当前执行指令**无关**的事件。包括：
    - **时钟中断**（时间片到、定时）
    - **`I/O` 中断**（设备完成、出错）
    - 控制台（键盘/鼠标）中断、硬件故障引起的中断
    - 外中断**是异步的**（不知何时到来），通常**在一条指令执行结束后**被检测并响应。
  - **内中断（异常 `Exception`）**：来自 `CPU` **内部**、由**当前正在执行的指令**引起的事件。分三类：
    - **故障 `fault`**：**可修复**，处理后**重新执行**引发故障的那条指令。典型：**缺页异常**、除零、地址越界、非法操作码。缺页处理完返回后要重执行该指令（这一点第 3 章会用到）。
    - **自陷 `trap`**：**有意安排**的、用于实现**系统调用**或调试的"陷阱"。处理后**返回下一条指令**（因为 `trap` 本身已执行完）。系统调用的入口就是 `trap` 指令。
    - **终止 `abort`**：**不可恢复**的致命错误（如硬件故障、电源掉电、控制器出错），只能中止程序。
- **中断处理过程（必背的"两段式"）**：
  1. **中断隐指令（由硬件自动完成，不是一条真正的指令）**：
     - **关中断**：防止本次处理被打断（保证保存断点、取入口地址的过程原子）。
     - **保存断点**：把 `PC`（有时含 `PSW`）压入内核栈或存入固定单元。
     - **引出中断服务程序**：根据**中断类型号**查**中断向量表**，取出服务程序的入口地址送 `PC`。
  2. **中断服务程序（软件完成）**：
     - **保存现场**（通用寄存器等）→ **分析中断原因**（判明是哪类中断）→ **执行具体处理**（如 `I/O` 完成唤醒进程）→ **恢复现场** → **开中断** → **返回**（`iret` 等）。
  - **为什么"关中断"要放在最前面**：中断隐指令保存断点的过程如果不原子，新来的中断会覆盖 `PC`，断点丢失，无法正确返回。所以硬件在进入处理程序前先关中断。
  - **多重中断（中断嵌套）**：若在中断服务程序中**提前开中断**，则允许更高优先级的中断打断当前服务程序，形成嵌套。**嵌套的前提是有优先级机制 + 服务程序中开中断**；隐指令里是关中断的，所以默认不嵌套。
- **中断在操作系统中的地位（高频原话）**：
  - **中断是 `OS` 获得 `CPU` 控制权、从用户态进入核心态的唯一途径**（含异常）。
  - **中断是并发的前提**：没有中断，一个程序会一直占用 `CPU`（除非它自愿 `trap`），多道程序无法交替。
  - **`OS` 是中断驱动的**：`OS` 的大部分工作是"事件驱动"的——中断来了才干活（时钟中断触发调度、`I/O` 中断触发唤醒、`trap` 触发系统调用）。
- **408 提示**：
  - 常考"下列事件中，属于内中断（异常）的是"→ 缺页、除零、`trap`（系统调用）、地址越界、非法指令；"属于外中断的是"→ 时钟中断、`I/O` 中断、键盘中断。**判别技巧：事件由当前指令引起 → 内中断；与当前指令无关、外部设备/定时器引起 → 外中断。** 系统调用由 `trap` 指令引起，所以**系统调用属于内中断**（这点极易错）。
  - 常考"中断处理程序必须在内核态执行"→ **对**；"中断处理程序可以在用户态执行"→ **错**。
  - **坑 1**：把"`trap` 属于外中断"（错，`trap` 是内中断中的自陷）。**坑 2**：把"缺页处理后返回到下一条指令"（错，`fault` 要**重新执行**原指令）。**坑 3**：把"中断隐指令"当成一条特权指令（错，它**不是指令**，是硬件自动完成的一串微操作）。**坑 4**：把"保存现场"和"保存断点"混为一谈（**保存断点**由硬件在隐指令中做，**保存现场**由中断服务程序用软件指令做）。

### 1.7 系统调用

- **是什么/为什么**：用户程序不能直接访问内核代码与硬件（否则无安全性可言），但它又必须使用文件、屏幕、键盘、网络等资源。于是内核在"用户态与核心态的边界"上开一组**受控入口**，用户程序只能通过这些入口请内核代劳。这组入口就是**系统调用**。它既是 `OS` 向程序提供的**程序接口**，也是**保护机制的必然产物**。
- **关键点**：
  - **概念**：系统调用是**操作系统提供给应用程序使用内核服务的接口**，本质是内核中的一段**可被用户程序请求执行的代码（服务例程）**。它运行在**核心态**。
  - **为什么不能让用户直接访问内核代码**：
    1. **安全性**：用户程序不可信，直接操作硬件/内核数据结构会破坏系统。
    2. **权限**：`I/O`、改 `PSW`、改页表都要用特权指令，用户态根本没有执行权。
    3. **一致性与可管理性**：内核要统一记账（谁用了多少资源）、统一同步互斥，自己实现等于绕开管理。
  - **分类（五类，必背）**：
    | 类别 | 典型系统调用 |
    | --- | --- |
    | 设备管理 | 请求设备、释放设备、启动设备、`I/O` 操作 |
    | 文件管理 | `open`、`close`、`read`、`write`、`create`、`delete` |
    | 进程控制 | `fork`、`exec`、`exit`、`wait`、阻塞/唤醒 |
    | 进程通信 | 消息传递 `send`/`receive`、共享内存的建立与映射 |
    | 内存管理 | `brk`/`mmap` 申请与释放内存、内存映射 |
    （注：也常把"进程通信"并入"进程控制"，答题时按题目给的分法。）
  - **执行过程（五步，答题模板）**：
    1. 用户程序在**用户态**准备参数（把系统调用号、参数放入约定寄存器或用户栈），并执行**陷入指令 `trap`**（也叫访管指令）。
    2. `trap` 触发**内中断（自陷）**，硬件执行**中断隐指令**：切到核心态、保存断点与 `PSW`、按中断向量进入**系统调用入口程序**。
    3. 内核在**核心态**根据**系统调用号**查**系统调用表**，找到对应的**服务例程**并执行（如 `read` 会去驱动磁盘）。
    4. 服务例程把返回值放入约定寄存器，内核执行**特权指令修改 `PSW`** 切回用户态。
    5. 返回用户程序**下一条指令**继续执行（因为 `trap` 已执行完，这点与 `fault` 要重执行原指令不同）。
  - **库函数与系统调用的区别（高频）**：
    - **库函数**是语言/`C` 运行库提供的**用户态函数**（如 `printf`、`malloc`、`strlen`）。
    - 有的库函数**内部会调用系统调用**（如 `printf` 最终调用 `write`、`malloc` 底层用 `brk`/`mmap`），此时发生模式切换。
    - 有的库函数**完全在用户态**完成，不涉及系统调用（如 `strlen`、`sin`、纯字符串/数学运算），**不会引起模式切换**。
    - 因此不能说"库函数就是系统调用"，也不能说"调用库函数一定陷入内核"。
    - 另一条区别：**库函数可跨 `OS` 移植（同一套 `C` 库在不同系统上重新实现即可），系统调用与具体 `OS` 强绑定**。
- **408 提示**：
  - 常考"系统调用是 `OS` 提供给用户的接口，它运行在核心态"（对）；"系统调用由用户程序直接执行内核代码"（错）；"系统调用**必须**通过 `trap` 指令进入内核"（对）。
  - 常考"下列哪个操作**不需要**系统调用"→ 典型答案是"两个数相加""字符串求长度""局部变量的赋值"这类纯用户态运算；"读取文件内容""创建进程""申请内存"都需要。
  - **坑 1**：把"库函数调用"等同于"系统调用"。**坑 2**：以为系统调用可以像普通函数那样"被调用后直接返回内核里"——它必须**先陷入（`trap`）**。**坑 3**：以为系统调用完成后返回到 `trap` 指令本身（错，返回**下一条指令**）。**坑 4**：把系统调用归入**外中断**（错，它是**内中断（自陷）**）。**坑 5**：混淆"系统调用的**分类**"与"`OS` 的**功能模块**"——分类是接口视角，功能模块是管理视角，二者常常一一对应但不要混答。

### 1.8 程序的链接与装入

- **是什么/为什么**：源程序要变成内存里能跑的指令，必须经过"翻译 → 合并 → 定位"三关。**翻译**解决"人写的符号 → 机器码"；**链接**解决"多个模块的符号引用 → 统一地址"；**装入**解决"逻辑地址 → 物理地址"。每一步都可能因为"为了提高效率或灵活性"而出现不同方案，这就是本节各种方式存在的原因。
- **关键点（三步）**：
  1. **编译**：源程序 `.c` → 目标模块 `.o`（可重定位目标文件）。
  2. **链接**：把多个目标模块 + 库函数合并成一个**完整装入模块** `.exe`。
  3. **装入**：把装入模块放进内存并**建立逻辑地址到物理地址的映射**。
- **装入的三种方式**：

| 装入方式 | 地址转换时机 | 是否需要硬件支持 | 能否在内存中移动 | 特点与适用 |
| --- | --- | --- | --- | --- |
| **绝对装入** | 编译时 | 不需要 | 不能 | 编译时已知程序驻留在内存何处，直接生成**绝对地址**；只适用于**单道环境**，程序换位置就得重新编译 |
| **静态重定位**（可重定位装入） | **装入时**一次性完成 | 不需要（由装入程序做） | 不能 | 装入时把逻辑地址**统一加上**一个偏移量改成物理地址；**程序一旦装入就不能再移动**，且要求**连续分配**内存 |
| **动态重定位**（动态运行时装入） | **运行时**每次访存时 | **需要**（重定位寄存器 + 地址变换硬件） | 可以移动 | 装入时保持逻辑地址不变，运行时由 `重定位寄存器` 的值与逻辑地址相加得到物理地址；支持**不连续分配**与**程序在内存中移动**，是**现代 `OS` 的做法** |

  - **为什么现代 `OS` 用动态重定位**：因为它把"地址转换"从一次性动作变成了"每次访存都做一次"的动作，代价是有硬件开销（多一次加法），收益是**程序可以被换出到外存、可以移动、可以不连续存放**——这正是**虚拟内存**（第 3 章）的物理基础。
  - **重定位寄存器**（基址寄存器）存放"该程序在内存中的起始物理地址"；**静态重定位里没有这个寄存器**，地址在装入时就被改死了。
- **链接的三种方式**：

| 链接方式 | 何时链接 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **静态链接** | 装入**之前** | 运行时不再需要库，执行效率高、独立 | 库代码被**重复复制**进每个可执行文件，占用空间大；库更新后必须**重新链接** |
| **装入时动态链接** | **装入内存时**边装入边链接 | 便于**修改和更新**库（改库不用重链接所有程序）；便于**共享**库代码 | 链接在装入时完成，仍不够灵活；**未用到的模块也会被链接进来** |
| **运行时动态链接** | **程序执行到调用时**才链接 | 只链接**真正用到**的模块，**加快装入、节省内存**；最适合大型程序与库 | 实现复杂，第一次调用时有额外开销 |

  - **三者关系的关键**：**动态链接的核心价值是"共享库"与"按需链接"**。静态链接把 `printf` 的代码抄进每个 `.exe`；动态链接下所有进程共享同一份 `libc.so`。
- **408 提示**：
  - 常考"静态重定位与动态重定位的区别"→ 抓住三点：**转换时机（装入时 vs 运行时）、是否需要硬件支持、能否移动**。
  - 常考"程序在内存中被移动后，需要修改什么"→ 动态重定位下**只需修改重定位寄存器的值**；静态重定位下**不可能移动**（必须重新装入）。
  - **坑 1**：把"动态重定位"和"动态链接"混为一谈。**一个解决地址问题（装入阶段），一个解决模块合并问题（链接阶段）**，互不替代。**坑 2**：以为"静态重定位不需要硬件支持所以更好"——错，正因为它改死了地址，才无法支持虚拟内存。**坑 3**：把"装入时动态链接"的缺点说成"必须重新链接"（那是**静态链接**的缺点）。

### 1.9 程序运行时的内存映像与地址空间

- **是什么/为什么**：编译链接后的程序在逻辑上被划分成若干**段**，每段有不同的用途与访问属性（可执行 / 可写 / 只读）。这样划分的好处是：可以让**代码段被多个进程共享**、让**只读段共享**、让**未初始化的数据不占磁盘空间**，这正是 `OS` 需要的。
- **关键点（典型 `Linux` 用户进程逻辑地址空间，从高地址到低地址）**：
  1. **内核空间**：地址空间最高处，用户程序**不可访问**（访问即出错）。它让"用户态切到核心态"时不必切换页表，提高效率。
  2. **栈 `Stack`**：存放函数调用时的**局部变量、返回地址、参数、函数调用框架**。**向低地址方向增长**（压栈是地址减小）。由编译器自动管理。
  3. **共享库映射区**：`libc` 等动态库的映射位置（典型 `Linux` 在栈下方）。
  4. **堆 `Heap`**：**向高地址方向增长**，用于 `malloc`/`new` 动态申请的内存，由程序员管理（忘了释放就内存泄漏）。
  5. **`BSS` 段**：存放**未初始化（或初始化为 0）的全局变量和静态变量**。**不占用目标文件空间**，装入时才在内存中分配并被清零——这是 `BSS` 存在的意义。
  6. **数据段 `Data`**：存放**已初始化的全局变量和静态变量**（有初值，必须存在目标文件里）。
  7. **代码段 `Text`**：存放**机器指令**，通常是**只读、可共享**的。
  - **记忆口诀**：**"栈在高处往下长，堆在低处往上长，中间夹着库；数据段有初值，`BSS` 段无初值不占文件，代码段只读可共享。"**
- **地址与地址空间**：
  - **逻辑地址（相对地址、虚拟地址）**：程序**编译后**使用的地址，从 0 开始编址。**每个进程都有自己独立的逻辑地址空间**，所以两个进程可以有相同的逻辑地址。
  - **物理地址**：内存单元在内存条上的真实地址。
  - **地址空间**：逻辑地址的集合；**地址重定位**就是把逻辑地址映射到物理地址的过程。
  - **内存映像**：程序装入内存后在各段的实际分布（各段起始物理地址与长度）。
- **408 提示**：
  - 常考"堆和栈的增长方向"→ **栈向低地址、堆向高地址**（可画图，是标准考点）。
  - 常考"`BSS` 段的作用"→ 存放未初始化全局/静态变量，**不占磁盘上的目标文件空间**，只占内存。
  - 常考"进程的逻辑地址空间是否独立"→ **独立**；"两个不同进程能否有相同逻辑地址"→ **能**（这正是虚拟内存要解决的问题）。
  - **坑 1**：把"局部变量"放到堆里（错，局部变量在**栈**上；`malloc` 出来的才在堆上）。**坑 2**：把"未初始化全局变量"放到数据段（错，在 `BSS`）。**坑 3**：把"逻辑地址连续"等同于"物理地址连续"——动态重定位/分页之后**物理上可以不连续**。

### 1.10 操作系统结构（分层、模块化、宏内核、微内核、外核）

- **是什么/为什么**：`OS` 从几万行涨到几千万行后，"怎么组织代码"直接决定**可靠性、性能、可维护性**。核心矛盾是：**把功能放进内核（性能好、但一处出错全盘崩溃）还是放到用户态（可靠、但每次服务都要切换模式，性能差）**。各种结构都是这条主线上的不同取舍点。
- **关键点**：
  - **分层结构**：把 `OS` 分成若干层，**第 n 层只能调用第 n−1 层**（单向依赖）。优点：**易于调试与验证**（自下而上逐层调通）、易扩充、易维护。缺点：**层次划分困难**（很多功能互相纠缠，难以严格分层）、**效率低**（跨层调用层层传递，参数与数据要反复拷贝）。
  - **模块化结构**：把 `OS` 按功能拆成若干**模块**（进程管理、存储管理、文件管理…），模块间通过**接口**调用。优点：**提高了设计的正确性、可理解性与可维护性**，模块可独立开发。缺点：**模块间接口定义困难**，且模块间**仍可能相互依赖**，难以做到真正的"高内聚、低耦合"。
  - **宏内核（单内核）**：**把 `OS` 的主要功能模块（进程、存储、设备、文件、网络…）全部放在内核态**，模块之间可直接互相调用（如 `Linux`）。优点：**模块间调用只是函数调用，性能高、效率高**。缺点：**内核庞大、结构混乱、可靠性差**——任何一个模块（如某个设备驱动）出错都可能导致**整个系统崩溃**，且难以维护与移植。
  - **微内核**：**只把最基本的功能（时钟管理、中断处理、原语、进程间通信 `IPC`）留在内核态**，把文件系统、设备驱动、内存管理等**移到用户态作为服务器进程**，客户与服务器之间通过**消息传递（`IPC`）**通信。优点：**可靠性高**（一个服务器崩了不影响内核）、**可扩展性与可移植性好**、**适合分布式系统**。缺点：**性能差**——一次服务请求要经历"用户态 → 内核态 → 另一个用户态服务器 → 内核态 → 用户态"多次**模式切换与消息拷贝**，开销大。
  - **外核 `Exokernel`**：**内核只负责"资源的分配与保护"，不负责资源的抽象与管理**，把抽象留给用户态库 `OS`（`libOS`）自己决定。比如内核只保证"这段磁盘块归你且别人不能用"，至于"这些块按什么文件系统组织"由应用程序自己定。优点：**灵活性极高、减少了抽象层次带来的开销**（应用可按需自己实现最合适的抽象）；缺点：**设计复杂**，应用开发者负担重。
- **408 提示**：
  - 常考"微内核相比宏内核的优点/缺点"→ 优点写**可靠性、可扩展性、可移植性、适合分布式**；缺点写**性能开销大（模式切换与消息传递）**。**这两句几乎是标准答案，务必背住。**
  - 常考"哪种结构效率最高""哪种结构最可靠"→ **效率：宏内核（外核理论上有优势）> 微内核；可靠性/可维护性：微内核 > 宏内核**。
  - **坑 1**：说"微内核把进程管理移到用户态"——错，**进程管理（调度）必须在核心态**，移到用户态的是文件系统、设备驱动等**服务**。**坑 2**：把"分层结构易调试"的优点安到"模块化"上（模块化的优点是**可独立开发、易维护**；分层的优点是**易验证、单向依赖**）。**坑 3**：把外核说成"一种微内核"——外核与微内核理念不同：微内核**保留抽象**，外核**拒绝提供抽象**。

### 1.11 操作系统引导

- **是什么/为什么**：断电后内存里什么都没有，`CPU` 也不知道 `OS` 在哪。可 `OS` 本身是一个程序，需要"被装入内存"才能运行——这就是"鸡生蛋"问题。解决办法：把一段**固化在 `ROM`（只读、断电不丢）里的小程序**作为起点，由它去把 `OS` 从磁盘搬进内存。这段起点就是 `BIOS`/`UEFI`。
- **关键点（引导流程）**：
  1. `CPU` 加电复位，`PC` 被硬件置为**固定地址**（指向 `ROM` 中的 `BIOS`）。
  2. 执行 `BIOS`/`UEFI`：进行**加电自检 `POST`**（检测内存、显卡等）、初始化硬件、建立中断向量表。
  3. `BIOS` 按**启动顺序**读启动盘的**第一个扇区**——**主引导记录 `MBR`**（`512 B`，含引导代码 + 分区表）。
  4. 执行 `MBR` 中的**引导加载程序**（如 `GRUB`、`LILO`、`Windows Boot Manager`），它根据分区表找到**活动分区**，读取该分区的**引导块（分区引导扇区）**。
  5. 引导加载程序把**操作系统内核**从磁盘装入内存的固定位置（或按内核格式装入），并把控制权交给内核入口。
  6. 内核初始化（建立页表、初始化各子系统、启动第一个进程），`OS` 开始运行。
  - **硬盘分区中的引导块（常考小点）**：一个磁盘分区中，**第一个扇区称为引导块（分区引导扇区）**，用于存放该分区的引导程序；`OS` 的引导程序通常就放在**活动分区的引导块**中。`MBR` 位于**整个磁盘的第 0 号扇区**，不是分区内的。
  - `UEFI` 相对 `BIOS` 的改进（了解即可）：支持 `GPT` 分区、支持大于 `2 TB` 磁盘、图形界面、安全启动、更快的启动速度。
- **408 提示**：本章考"引导"通常只考**顺序**与**位置**，不深究细节。
  - 常考排序题："`BIOS` → `MBR` → 引导加载程序 → 装入内核"，注意 **`MBR` 在 `BIOS` 之后、引导加载程序之前**。
  - **坑 1**：把 `OS` 内核说成"由 `BIOS` 直接装入内存"（不严谨，通常由**引导加载程序**装入，`BIOS` 只负责把 `MBR` 读进来）。**坑 2**：把"引导块"和"主引导记录"当成同一个东西（`MBR` 在**磁盘**第 0 扇区，引导块在**分区**的第 0 扇区）。

### 1.12 虚拟机

- **是什么/为什么**：一台物理机只跑一个 `OS` 很浪费，且不同 `OS` 的应用无法共存。于是加一层**虚拟机管理程序 `VMM`（`Hypervisor`）**，把物理资源**虚拟化**成多套，每套上装一个客户 `OS`。关键问题是：客户 `OS` 以为自己在核心态，但它执行的**特权指令**怎么办？答案是 `VMM` 把它**截获并模拟**（陷入 `VMM` 处理）。
- **关键点**：
  - **虚拟化的本质**：`VMM` 运行在**最高特权级**，客户 `OS` 运行在**较低特权级**。客户 `OS` 执行**特权指令**时会被 `VMM` 截获（陷入），由 `VMM` 代为完成或模拟——这叫**特权指令的陷入与模拟**。而**非特权指令**仍由硬件**直接执行**（这是虚拟化性能损失小的原因）。
  - **第一类 `VMM`（`Type-1`，裸机型 / 原生型）**：`VMM` **直接运行在裸机硬件上**，本身就是一层"精简 `OS`"，客户 `OS` 运行在它之上。例：`Xen`、`VMware ESXi`、`Microsoft Hyper-V`。特点：**性能好、安全性高**，多用于服务器/数据中心。
  - **第二类 `VMM`（`Type-2`，宿主型）**：`VMM` **运行在宿主操作系统之上**，作为宿主机的一个应用程序。例：`VMware Workstation`、`VirtualBox`、`QEMU`。特点：**安装使用方便、性能较差**（多经过一层宿主 `OS`），多用于个人开发测试。
  - **虚拟化与模拟的区别**：
    - **虚拟化**：客户 `OS` 与宿主机**指令集（体系结构）相同**，绝大多数指令**直接在真实硬件上执行**，只把特权指令截获处理。性能损失小（通常几个百分点到几十个百分点）。
    - **模拟 `Emulation`**：客户与宿主机**体系结构不同**（如在 `x86` 上跑 `ARM` 程序），必须**逐条解释执行**客户指令，用软件模拟出另一套硬件。**性能损失可达几个数量级**。
    - 一句话记忆：**虚拟化是"分权"（资源切分 + 特权截获），模拟是"翻译"（指令逐条转换）。**
  - **按虚拟化对象分类（了解即可）**：`CPU` 虚拟化、内存虚拟化、`I/O` 设备虚拟化（全虚拟化 / 半虚拟化 / 硬件辅助虚拟化）。
- **408 提示**：本章对虚拟机通常只考**概念辨析**。
  - 常考"第一类 `VMM` 与第二类 `VMM` 的区别"→ **看 `VMM` 是否直接运行在硬件上：是 → 第一类；运行在宿主 `OS` 上 → 第二类**。
  - 常考"虚拟化与模拟的区别"→ **指令集是否相同、指令是直接执行还是逐条解释**。
  - **坑 1**：把"虚拟机"与 1.1 节里 `OS` 作为"扩充机器（虚拟机）"的概念混为一谈。**前者的 `VM` 是真实可运行客户 `OS` 的软件系统，后者是抽象的"逻辑机器"，两者同名不同义。** **坑 2**：说"第二类 `VMM` 性能更高"（错，第一类更高，因为它少了宿主 `OS` 这一层）。**坑 3**：说"虚拟化下客户 `OS` 执行特权指令时由硬件直接执行"（错，被 `VMM` 截获）。

### 表 1　并发与并行

| 对比项 | 并发 `Concurrence` | 并行 `Parallelism` |
| --- | --- | --- |
| 时间尺度 | **同一时间间隔内**（宏观同时，微观交替） | **同一时刻**（真正同时） |

## 四、例题精练（3 道）

### 例 1（选择题，考点：特权指令与 `CPU` 状态）（真题风格改编）

**题目**：下列关于 `CPU` 运行模式和指令的叙述中，**正确**的是（　　）

A. 关中断指令和设置时钟指令都是特权指令，只能在内核态执行
B. 陷入指令（`trap`）是特权指令，用户程序执行它会由用户态切换到核心态
C. 用户程序可以通过直接调用内核中的函数来请求操作系统服务，无需陷入内核
D. 从核心态切换到用户态，只能由中断或异常引起

**答案**：A

**逐项解析**：

- **A 正确**。关中断（影响 `OS` 对事件的控制能力）、设置时钟（修改全局定时资源）都必须由内核掌控，用户程序无权执行，属于**特权指令**。判别标准就是"**这条指令能否改变系统全局状态或绕过保护机制**"。
- **B 错误**。`trap`（访管/陷入指令）**不是特权指令**，而是一条**非特权指令**。理由：它的设计目的正是"让用户程序主动请求进入内核态"，如果它是特权指令，用户态根本执行不了，系统调用就无法实现。**前半句错**，后半句"会由用户态切换到核心态"是对的——抓住错的那半句即可排除。
- **C 错误**。这正是"为什么需要系统调用"的答案。用户程序不能直接访问内核代码与数据，否则 `OS` 的保护机制形同虚设；它必须通过 `trap` 陷入内核，由内核在核心态代为完成。**用户态根本没有执行 `I/O` 等特权指令的权限。**
- **D 错误**。核心态 → 用户态是内核执行**特权指令修改 `PSW`** 后返回的过程，**不需要**中断/异常。反过来才对：**用户态 → 核心态的途径是中断或异常（含 `trap`）**。D 项把方向说反了——这是本题最经典的设置手法：**"唯一途径"这个词是对的，但只能用在"进入核心态"这个方向上。**

**采分点与常见坑**：
- **采分点**：能准确说出"`trap` 是非特权指令"这一反直觉结论；能记住状态切换的**单向约束**（用户 → 核心靠中断/异常；核心 → 用户靠特权指令）。
- **坑 1**：凭感觉认为"能让我进内核的指令一定很特权"，从而误选 B。**记牢：`trap` 是用户态与内核态之间的"门铃"，门铃必须装在门外。**
- **坑 2**：D 项方向反了却因"中断是唯一途径"这句话熟悉而误选。**做题时一定看清"从…到…"的方向。**
- **坑 3**：C 项把"调用库函数"和"直接调用内核函数"混为一谈。调用 `printf` 是允许的（用户态库函数），但它内部**通过系统调用**才能输出——**用户能"请求"服务，不能"越权"执行服务**。

### 例 2（综合计算题，考点：链接、装入与逻辑地址空间）（真题风格改编）

**题目**：某源程序由 4 个模块组成，经**静态链接**后形成一个装入模块。各模块各段大小如下表：

| 模块 | 代码段 | 只读数据段 | 已初始化数据段 | `BSS` 段（未初始化全局/静态变量） |
| --- | --- | --- | --- | --- |
| 模块 A | 8 KB | 4 KB | 1 KB | 2 KB |
| 模块 B | 8 KB | 0 KB | 1 KB | 2 KB |
| 模块 C | 4 KB | 4 KB | 1 KB | 2 KB |
| 模块 D | 4 KB | 0 KB | 1 KB | 2 KB |

链接器把 4 个模块按 A、B、C、D 的顺序链接，**同类型段合并**，并按"代码段 → 只读数据段 → 已初始化数据段 → `BSS` 段"的顺序自地址 `0x0000` 起**连续编址**。设页大小与段大小均为 `1 KB`（即 `1 KB` 对齐），逻辑地址从 `0x0000` 开始按字节编址。

请回答：

（1）链接后装入模块的逻辑地址空间中，各段的起止逻辑地址分别是多少？（用十六进制表示）
（2）该程序在磁盘上的可执行文件中，`.text` + `.rodata` + `.data` + `.bss` 共占多少字节？其中 `BSS` 段实际占用多少字节？解释原因。
（3）若采用**静态重定位**，装入模块被装入到起始物理地址 `0x20000`。求逻辑地址 `0x6100` 对应的物理地址。
（4）若把装入方式改为**动态重定位**，重定位寄存器的值应设为多少？此时程序能否在主存中被移动？若移动，需要修改什么？若改用**运行时动态链接**，相比静态链接，在"装入速度"和"内存占用"上分别有什么变化？

**解题步骤**：

**第（1）问：合并各段，算逻辑地址**

先合并各段总大小（按类型相加）：

- 代码段：`8 + 8 + 4 + 4 = 24 KB` = `0x6000 B`
- 只读数据段：`4 + 0 + 4 + 0 = 8 KB` = `0x2000 B`
- 已初始化数据段：`1 + 1 + 1 + 1 = 4 KB` = `0x1000 B`
- `BSS` 段：`2 + 2 + 2 + 2 = 8 KB` = `0x2000 B`
- 合计：`24 + 8 + 4 + 8 = 44 KB`

按"代码段 → 只读数据段 → 已初始化数据段 → `BSS` 段"从 `0x0000` 连续排布，**起始地址 = 前面各段大小之和**：

| 段 | 大小 | 起始逻辑地址 | 结束逻辑地址（含） |
| --- | --- | --- | --- |
| 代码段 `.text` | 24 KB | `0x0000` | `0x5FFF` |
| 只读数据段 `.rodata` | 8 KB | `0x6000` | `0x7FFF` |
| 已初始化数据段 `.data` | 4 KB | `0x8000` | `0x8FFF` |
| `BSS` 段 `.bss` | 8 KB | `0x9000` | `0xAFFF` |

（校验：末地址 `0xAFFF` = `0xB000 − 1`，即总长 `44 KB` = `0xB000 B`，与"逻辑地址空间共 44 KB"一致。✓）

**第（2）问：可执行文件与 `BSS`**

- **`BSS` 段不占用可执行文件（磁盘）空间**。它存放的是**未初始化（或初值为 0）的全局变量和静态变量**，其内容全是 `0`，没有必要在文件里存 8 KB 的 `0`；只要在程序头中记录"需要在内存中分配 8 KB 并清零"即可。所以磁盘上只需存代码段、只读数据段、已初始化数据段。
- 磁盘上占用 = `24 KB + 8 KB + 4 KB = 36 KB` = **`36864` 字节**。
- 其中 `BSS` 段实际占用 **`0` 字节**（在磁盘上），但装入内存后仍要占 **`8 KB = 8192` 字节**（由 `OS` 装入器分配并清零）。

**第（3）问：静态重定位求物理地址**

静态重定位在**装入时一次性**把逻辑地址统一加上装入起始地址（重定位因子）：

- 重定位因子 = 装入起始物理地址 − 逻辑起始地址 = `0x20000 − 0x0000` = `0x20000`
- 逻辑地址 `0x6100`：先判断它落在哪一段。`0x6100` 在 `0x6000 ~ 0x7FFF` 之间 → 属于**只读数据段**（段内偏移 `0x6100 − 0x6000` = `0x100`）。
- 物理地址 = 逻辑地址 + 重定位因子 = `0x6100 + 0x20000` = **`0x26100`**

**第（4）问：动态重定位与动态链接的影响**

- **重定位寄存器的值 = 该程序在内存中的起始物理地址 = `0x20000`**。（动态重定位下，逻辑地址**保持不变**，每次访存时由硬件做 `物理地址 = 重定位寄存器值 + 逻辑地址`。）
- **能否移动：能**。因为地址转换发生在运行时、每次访存都重新计算，所以程序换到别的物理区域后，**只需修改重定位寄存器的值**，程序自身的指令与数据**一个字节都不用改**。这是静态重定位做不到的（静态重定位下地址已在装入时改死，无法移动）。
- **改用运行时动态链接的变化**：
  - **装入速度**：**变快**。因为写入可执行文件的模块变少（库模块通常不复制进去），装入时无需处理未使用的模块，且**只链接执行中真正用到的模块**。
  - **内存占用**：**变小**。静态链接把库代码复制进每个可执行文件，运行时每个进程各有一份；运行时动态链接让多个进程**共享同一份库的代码段**，且用不到的模块**根本不装入内存**（例如程序有 100 个功能，本次只用到 3 个，那 97 个对应的模块不会占用内存）。

**答案**：
（1）`.text`：`0x0000 ~ 0x5FFF`；`.rodata`：`0x6000 ~ 0x7FFF`；`.data`：`0x8000 ~ 0x8FFF`；`.bss`：`0x9000 ~ 0xAFFF`（逻辑地址空间共 `44 KB`）。
（2）磁盘上占 `36 KB`（`36864` 字节）；`BSS` 段在磁盘上占 `0` 字节，因为其内容全为 `0`、无需存储，装入时在内存中分配 `8 KB` 并清零。
（3）物理地址 = `0x26100`。
（4）重定位寄存器 = `0x20000`；程序**能**在主存中移动，移动后只需修改重定位寄存器的值；改用运行时动态链接后，**装入速度加快、内存占用减小**。

**采分点与常见坑**：
- **采分点**：
  - （1）必须先"**按类型合并各段**"再排布，不能按模块顺序排列；给出**起始地址**和**段大小**都要有，最好写出结束地址自检。
  - （2）必须点出 `BSS` 的**内容是 0 所以不必存**这一理由，只说"不占空间"不给满分。
  - （3）必须写出"**重定位因子 = 装入起始物理地址 − 逻辑起始地址**"这一步。
  - （4）必须写"**只改重定位寄存器**，不改程序本身"；动态链接的评价要落到"**只链真正用到的模块**"和"**共享库代码**"两点。
- **坑 1**：把 `BSS` 段算进磁盘占用（误得 `44 KB`）。**判别方法：问"内容是否有初值"——无初值（全 0）不占文件，有初值占文件。**
- **坑 2**：把"段大小"和"结束地址"搞混。`24 KB` 的段从 `0x0000` 起，结束地址是 `0x5FFF` 而非 `0x6000`（**结束地址 = 起始 + 大小 − 1**）。这个"减一"在地址计算题里非常容易丢分。
- **坑 3**：把**静态重定位**和**动态重定位**的物理地址算法混用。**静态**：装入时一次性加上偏移，之后不再变；**动态**：每次访存由硬件加，程序内部地址永远是逻辑地址。两者在"给定同一逻辑地址求物理地址"这一步结果相同，但**能不能移动**的结论完全不同。
- **坑 4**：把**动态重定位**当成**动态链接**。前者解决"**地址**怎么变"，后者解决"**模块**什么时候合并"。本题第（4）问同时问了两者，答题时要**分开写、各答各的点**，不要串味。
- **坑 5**：第（4）问答"能移动，需要修改程序中的地址"。错。动态重定位的**全部意义**恰恰是"程序里没有一个绝对地址需要改"——要改的只有**重定位寄存器**（以及第 3 章的**页表**）。

### 例 3（综合题，考点：系统调用的执行过程与状态切换）（真题风格改编）

**题目**：某用户 `C` 程序执行语句 `printf("hello");`，该调用最终通过库函数 `write` 系统调用把数据送到显示器。请回答：

（1）说明 `printf` 与 `write` 的关系，并指出**从用户程序执行 `printf` 到数据出现在显示器上**的全过程中，哪些阶段在用户态、哪些在核心态。
（2）用户程序**不能**直接访问内核代码和硬件。请说明 `OS` 用什么机制既"拦住"用户程序、又"允许"它获得服务，并指出该机制涉及的**状态切换方向**及**触发方式**。
（3）`write` 系统调用完成后，`CPU` **返回到 `trap` 指令的下一条指令**还是**重新执行 `trap` 指令**？为什么？如果这次不是系统调用而是**缺页异常**，返回位置又有何不同？
（4）有同学说："系统调用是一种中断，所以它属于外中断。"请判断并说明理由。

**解题步骤与答案**：

**第（1）问：`printf` 与 `write` 的关系 + 状态划分**

- **关系**：`printf` 是 `C` 标准库提供的**库函数**，运行在**用户态**；它负责格式化字符串（把 `%d`、`%s` 等变成字符），然后**在内部调用系统调用 `write`** 把结果交给内核。所以：
  - `printf` ≠ 系统调用（它是库函数）；
  - `printf` **内部包含**一次（或多次）系统调用；
  - **库函数可以封装系统调用**，这是 `OS` 提供"方便接口"的典型手法。（注意：并非所有库函数都这样，如 `strlen` 就纯在用户态算，不陷入内核。）
- **状态划分**：

| 阶段 | 所在状态 | 说明 |
| --- | --- | --- |
| 调用 `printf`、做格式化（拼字符串） | **用户态** | 纯用户态库代码，无模式切换 |
| 在 `printf` 内部准备 `write` 的参数（文件描述符、缓冲区地址、长度）并执行 `trap` | **用户态**（`trap` 本身是非特权指令） | 参数通过约定寄存器/用户栈传递 |
| 硬件执行**中断隐指令**：切到核心态、保存断点、按向量进入系统调用入口 | **切换点（由硬件完成）** | 从这一刻起 `CPU` 处于核心态 |
| 内核查系统调用号、执行 `write` 服务例程、把数据交给设备驱动 | **核心态** | 真正操作硬件、发出 `I/O` 指令 |
| 内核返回前执行特权指令修改 `PSW`，切回用户态，`printf` 返回 | **核心态 → 用户态** | 返回点在 `trap` 的下一条指令 |
| 设备完成输出后发 `I/O` **外中断**通知 `CPU`（若需要） | **核心态处理** | 这是"异步完成"的后续通知，与本次调用已分离 |

**第（2）问：既拦住又放行的机制**

- **机制：系统调用（配合 `CPU` 的两种运行模式 + 特权指令机制）**。
  - **"拦住"**：`CPU` 的模式位决定用户程序**只能执行非特权指令**，因此它无法执行 `I/O` 指令、无法改 `PSW`、无法访问内核空间——硬件层面直接卡死。
  - **"放行"**：`trap` 指令**被特意设计成非特权指令**，成为用户态通向内核态的**唯一受控入口**。用户程序发 `trap` 时，硬件按约定把 `CPU` 切到核心态并转入内核的**系统调用入口程序**，由内核"代表用户"完成操作。
- **状态切换方向与触发方式**：
  - 进入：**用户态 → 核心态**，触发方式是**内中断（自陷 `trap`）**，由**硬件**在中断隐指令中完成 `PSW` 的切换（同时关中断、保存断点、按中断向量取入口地址）。
  - 返回：**核心态 → 用户态**，由内核执行**特权指令修改 `PSW`** 完成。
  - 一句话：**"进去靠硬件的中断机制，出来靠内核的特权指令。"**

**第（3）问：返回位置**

- `write` 系统调用完成后，**返回到 `trap` 指令的下一条指令**。
  - **理由**：系统调用是通过 `trap` 指令**主动**发起的，`trap` 指令本身**已经执行完毕**（它的唯一作用就是"陷入"），不需要再执行一遍。这与函数调用后返回 `call` 的下一条指令同理。
- 若是**缺页异常**（属于 `fault` 故障），则**返回并重新执行引起缺页的那条指令**。
  - **理由**：缺页指令**没有执行成功**（它需要的数据不在内存），`fault` 是"**可修复的故障**"。内核把页面调入内存、修好页表后，必须**回到原指令重新执行**，这次才能正确完成访问。
- **对照记忆**：
  - `trap`（自陷）：**主动**陷入 → 返回**下一条**（如系统调用、调试断点）。
  - `fault`（故障）：**被动**出错、**可修复** → 返回**重执行原指令**（如缺页、除零被修正后重试）。
  - `abort`（终止）：**不可恢复** → **不返回**，直接终止进程（如硬件故障、控制器出错）。

**第（4）问：判断"系统调用属于外中断"**

- **该说法错误。**
- **错误点 1（分类错）**：系统调用由**当前执行的 `trap` 指令**引起，来源在 `CPU` **内部**，属于**内中断（异常）**中的**自陷 `trap`**，不是外中断。外中断是**与当前指令无关**的外部事件（时钟、`I/O`、键盘）引起的。
- **错误点 2（可屏蔽性错）**：外中断（时钟、`I/O`）通常**可屏蔽**，而 `trap` 引起的自陷**不可屏蔽**。
- **"对"的部分也要说清**（考试常以"半对半错"设置陷阱）：系统调用确实**也是一种中断机制**——在广义上，它就是"中断/异常"这一大类事件中的一种，同样经由**中断隐指令**保存断点、切到核心态、查向量表进入处理程序。所以正确的表述是："**系统调用是一种（广义的）中断事件，但属于内中断（自陷），不是外中断。**"

**采分点与常见坑**：
- **采分点**：
  - （1）必须明确"`printf` 是库函数、`write` 是系统调用、库函数内部调用系统调用"这三层关系；状态划分必须点出"**格式化在用户态、真正 `I/O` 在核心态**"。
  - （2）必须写出"`trap` 是非特权指令，因此是用户态进入内核态的**唯一受控入口**"；切换方向与触发方式（内中断 `trap`，由硬件完成）缺一扣分。
  - （3）必须回答**两个**返回位置并**各给理由**（`trap` 已执行完 vs 缺页指令未完成）；能顺带补上 `abort` 不返回更好。
  - （4）必须同时指出"**属于内中断**"与"**广义上确实是一种中断事件**"，只答前半会被认为理解不完整。
- **坑 1**：把 `printf` 说成系统调用（见到"输出到屏幕"就想当然是系统调用）。**判别标准：名字出自 `C` 标准库的是库函数；出自 `OS` 手册第 2 节（`read`/`write`/`fork`/`open`）的是系统调用。**
- **坑 2**：说"库函数一定陷入内核"。`strlen`、`sin`、纯计算不陷入，题干若给 `printf` 就陷入——**要具体分析，不能一刀切**。
- **坑 3**：第（3）问答成"系统调用也返回重执行 `trap`"。**只有 `fault` 才重执行**，`trap` 返回下一条。
- **坑 4**：第（4）问只答"错，是内中断"就收笔，漏掉"它确实也走中断处理机制"这一层，容易丢"辩证"分。
- **坑 5**：把"状态切换"写成"进程切换"。本例中 `printf`/`write` 的整个过程**只是 `CPU` 模式在切换，并没有引起进程切换**（该进程一直在运行）。**这两个概念在第 2 章是重点，本章先立住。**

## 六、简便方法与易错口诀（速算 · 防错）

> 本节把本章能"省时间"和"防掉坑"的招集中在一处：二轮复习与考前只看这一节。每条都写清**适用条件**。

### 6.1 速算招式

| 场景 | 常规做法（慢/繁） | 简便做法（快/稳） | 为什么成立 / 适用条件 |
| --- | --- | --- | --- |
| 判一条指令是不是特权指令 | 逐条硬背特权指令清单 | 一句话判据：**碰的是"系统级关键状态、硬件开关、其他进程的东西"**——开/关中断、置 `PSW`、`I/O` 指令、修改页表基址、设置时钟、清内存、停机 | 只适用于机器级指令的判别。**订正提示：不能只说"会改变机器状态"**——普通算术、传送指令同样改变寄存器与内存状态；判据必须收紧到"系统级关键状态 + 硬件 + 其他进程"。**`trap`（访管/自陷）是非特权指令**——它正是用户程序被允许主动进入内核的唯一受控入口 |
| 判态切换的方向与"谁动手" | 背"中断、异常、系统调用"一大堆词 | 只记两条：**进内核 = 中断 或 异常（`trap`/系统调用属于异常）**，由**硬件**在响应中断/异常时自动切态；**出内核 = 内核执行一条特权指令（如中断返回指令改 `PSW` 的状态位）**，由**内核（软件）**完成 | 适用条件：讨论的是"用户态 ↔ 核心态"。用户态执行特权指令属**非法**，它引发的也是异常路径，不算合法入口。**状态切换 ≠ 进程切换**：同一个进程内部也会发生态切换 |
| 复述系统调用的执行过程 | 背一整段文字 | 五步：**传参 → 执行 `trap`/访管指令 → 硬件切到核心态 → 内核按系统调用号查表、执行服务例程 → 返回用户态** | 传参三法：寄存器、堆栈（参数个数多于寄存器时）、参数块（参数放内存、寄存器传首地址）。**系统调用本身就是一种异常（内中断 / 自陷 `trap`）** |
| 判断"这段代码有没有发生系统调用" | 看函数名是否眼熟 | 看**它最终是否要请求内核服务**：`printf` 内部最终走 `write`（有）；`strlen`、`sin`、纯计算（无）。库函数**可能封装系统调用，也可能完全在用户态完成** | 判别口径：出自 `C` 标准库的是库函数；出自 `OS` 手册第 2 节（`read`/`write`/`fork`/`open`）的是系统调用。**"用了库函数"≠"发生了系统调用"** |
| 区分静态重定位 / 动态重定位 | 背两张对比表 | 只问一句：**"地址什么时候改？改完还能不能动？"** 静态——**装入时**一次性改好，之后**程序不能移动**（也难共享）；动态——**每次访存时**由硬件（重定位寄存器 / `MMU`）实时相加，**程序可在内存中移动**（便于共享与紧凑） | 适用条件：静态重定位不需要专门硬件，但要求**装入后位置固定、地址连续**；动态重定位**必须有硬件支持**，且装载地址可以不等于逻辑地址（每次访存由硬件加常数，不额外增加访存次数） |
| 区分三种链接方式 | 背"静态链接 / 装入时动态链接 / 运行时动态链接"三个名字 | 只问一句：**"库函数什么时候被拼进来？"** 静态——**链接时**全部拼入，生成完整装入模块；装入时动态——**装入时**边装边链；运行时动态——**运行时**用到才装入 | 静态链接的装入模块大、库升级要重新链接；动态链接（尤其运行时动态链接）让**多个进程共享同一份库代码**、**库升级不必重新链接**——正好呼应"内存共享"这一功能 |
| 区分装入的三种方式 | 逐条背诵 | 一条线串起来：**绝对装入 = 编译时就定死物理地址**（只适合单道）；**静态重定位 = 装入时改一次**；**动态重定位 = 运行时每次访存改**（需硬件） | 适用条件：绝对装入要求编译时程序地址已知；后两种面向多道环境。**注意"动态链接" ≠ "动态重定位"**：前者拼库，后者改地址 |
| 分清中断处理中"硬件做什么、软件做什么" | 背整段流程 | 记"**硬件三件、软件三件**"：`中断隐指令`（硬件）——**关中断、保存断点（`PC`/`PSW`）、取中断向量并转入服务程序**；服务程序（软件）——**保护现场（通用寄存器）、执行中断服务、恢复现场后中断返回** | 适用于绝大多数中断/异常。**适用条件提示：开/关中断的具体位置各教材版本略有差异**（为支持中断嵌套，服务程序中会适时开中断），但"隐指令由硬件、保护与恢复通用寄存器现场由软件"这条分工不能颠倒 |
| 区分外中断 / 内中断 | 逐个例子硬背 | 一句话：**来自 `CPU` 外部、与当前执行的指令无关 → 外中断**（时钟、`I/O`、键盘；按可屏蔽性再分两类）；**由当前指令引起 → 内中断/异常**（缺页、除零、`trap`、非法指令） | 适用条件：`trap`（含系统调用）属**内中断**且**不可屏蔽**；时钟中断属外中断且**可屏蔽** |
| 判断"是虚拟化还是模拟" | 抠术语定义 | 只问一句：**"客户机与宿主机的指令集是否相同？"** 相同 → **虚拟化**（绝大多数指令直接在真硬件上执行，只截获特权指令，损失小）；不同 → **模拟**（逐条解释执行，损失可达几个数量级） | 一句话记忆：**虚拟化是"分权"，模拟是"翻译"**。`VMM` 截获的只是**特权指令**，非特权指令由硬件直接执行——这正是虚拟化性能损失小的原因 |
| 判断 `VMM` 是 `Type-1` 还是 `Type-2` | 背产品名单 | 只问一句：**"`VMM` 的下面是谁？"** 下面是**裸机硬件** → `Type-1`（裸机型，如 `Xen`、`VMware ESXi`、`Hyper-V`）；下面是**宿主 `OS`** → `Type-2`（宿主型，如 `VMware Workstation`、`VirtualBox`） | 适用条件：只按"脚下是谁"判型，不按厂商。`Type-1` 性能与安全性更好（服务器/数据中心）；`Type-2` 安装方便、性能较差（个人开发测试） |
| 判"异常处理完返回哪条指令" | 死记三类异常 | 一句话：**`fault`（故障，如缺页、除零）→ 返回并重执行原指令**；**`trap`（自陷，如系统调用）→ 返回下一条指令**；**`abort`（终止）→ 不返回** | 成立原因：`fault` 是"当前指令没执行成功"，`trap` 是"当前指令已执行完"。**做题先问一句"这条指令做完了没有"** |

### 6.2 口诀与记忆钩子

- **特权指令判据**："**碰开关、碰状态、碰别人**"——开关（开/关中断）、状态（`PSW`、页表基址、时钟）、别人（`I/O`、其他进程的地址空间）；**唯一例外是 `trap`：它是用户程序按的"门铃"**。
- **态切换**："**进内核靠中断异常（硬件动手），出内核靠特权指令改 `PSW`（内核动手）**。"
- **系统调用五步**："**传参 → 访管 → 切态 → 查表 → 返回**"；再加一句"**系统调用就是自陷，属内中断**"。
- **库函数与系统调用**："**库函数是包装纸，系统调用是里头的货；有的包装纸里没有货**"（`strlen`、`sin` 不陷入）。
- **重定位**："**静态装入时改一次，改完钉死；动态访存时一直改，随搬随用**。"
- **链接三兄弟**："**链接时拼（静态），装入时拼（装入时动态），用时才拼（运行时动态）**。"
- **中断处理分工**："**隐指令三件套：关中断、存断点、取向量；服务程序三件套：保现场、干正事、复现场**。"
- **异常返回**："**故障重来，自陷往下走，终止不回头**"（`fault` 重执行原指令、`trap` 执行下一条、`abort` 不返回）。
- **虚拟机**："**脚下是硬件就一类，脚下是 `OS` 就二类**；**虚拟化是分权，模拟是翻译**。"

### 6.3 反例黑名单（这些"简便法"是错的）

- ❌ **"会改变机器状态的都是特权指令"**：普通算术、传送指令同样改变寄存器与内存状态。正确做法是把判据收紧为"**系统级关键状态（`PSW`、页表基址、时钟）+ 硬件开关（开/关中断、`I/O`）+ 其他进程的资源**"。
- ❌ **"`trap`（自陷/访管）是特权指令"**：正确做法是记住 **`trap` 是用户态可执行的非特权指令**——若它是特权指令，用户程序根本无法发起系统调用。
- ❌ **"库函数一定是系统调用（用了 `printf` 就是发生了系统调用）"**：正确做法是**具体分析**——`printf` 最终用到 `write` 系统调用，而 `strlen`、`sin` 等完全在用户态完成。
- ❌ **"系统调用是外中断"**：正确做法是归为**内中断（异常 / 自陷 `trap`），且不可屏蔽**；它只是"广义上确实走中断处理机制"。
- ❌ **"中断处理的全过程都由硬件完成"**：正确做法是**分工**——`中断隐指令`（关中断、保存断点、取向量）由**硬件**完成，**保护与恢复通用寄存器现场由服务程序（软件）完成**。
- ❌ **"动态链接就是动态重定位"**：正确做法是**分开**——动态链接解决"库何时拼进来"（省内存、便于升级），动态重定位解决"逻辑地址何时转物理地址"（需重定位寄存器 / `MMU`）。
- ❌ **"缺页处理完返回下一条指令"**：正确做法是 **`fault`（缺页、除零）返回并重执行原指令**，只有 `trap`（系统调用）才返回下一条。
- ❌ **"微内核把进程管理/调度移到用户态"**：正确做法是**调度等最基本功能必须留在核心态**，移到用户态的是文件系统、设备驱动等服务进程。
- ❌ **"`BIOS` 直接把 `OS` 内核装入内存"**：正确做法是 **`BIOS` 只负责把 `MBR` 读进来，再由引导加载程序装入内核**。
- ❌ **"`MBR` 就是分区引导块"**：正确做法是 **`MBR` 位于整个磁盘的第 0 号扇区，分区引导块位于该分区的第 1 个扇区（第 0 号扇区）**。
- ❌ **"状态切换就是进程切换"**：正确做法是**区分两者**——系统调用过程中 `CPU` 模式在切换，但**进程始终是同一个、没有切换**。
