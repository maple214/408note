## 一、本章知识框架

本章只有一条主线：**用户眼中的"文件"如何一步步落到磁盘上的物理块**。把这条链背下来，全章就串起来了。

```text
用户视角：一个按名字访问的字节流
        ↓  文件 = FCB + 数据
文件的操作：create / delete / open / close / read / write
        ↓  逻辑结构决定"文件内部怎么编址"
逻辑结构：无结构文件、顺序文件、索引文件、索引顺序文件（直接/散列文件）
        ↓  物理结构决定"逻辑块 → 物理块"怎么映射
物理结构：连续分配、链接分配（隐式/显式 FAT）、索引分配（单级/多级/混合索引）
        ↓  数据块住哪由"空闲空间管理"决定
空闲管理：空闲表法、空闲链表法、位示图法、成组链接法
        ↓  文件靠名字找到，名字住在"目录"里
目录：FCB / 目录项、单级 → 两级 → 树形 → 无环图、硬链接与软链接
        ↓  多个文件系统如何共存
文件系统全局结构（外存 layout + 内存结构）→ VFS → 挂载 mounting
```

**一句话记忆**：`目录`管"找得到"，`物理结构`管"存得下"，`空闲管理`管"放哪儿"，`VFS/挂载`管"多套文件系统能同时用"。

**索引结点（`inode`）是本章的枢纽**：目录项里放文件名 + `inode` 号，`inode` 里放属性和物理块地址，数据块里放内容。绝大多数考点都是这三层里问"某一步要读几次盘"。

## 二、概念详解

### 4.1 文件的基本概念

**为什么需要文件**：内存断电即失，用户需要一种"有名字、能长期保存、可被多个进程共享"的信息单位。于是把数据组织成文件，交给文件系统统一管理。

**文件的定义**：文件是**具有文件名的一组相关信息的集合**，是文件系统进行存储、检索和保护的基本单位。

**文件的属性（都放在 `FCB` / `inode` 里）**：

| 属性 | 说明 |
| --- | --- |
| 名称 | 文件名，唯一标识；对用户可见 |
| 标识符 | 文件系统内部的唯一编号（如 `inode` 号），对用户不可见 |
| 类型 | 由扩展名或系统标记决定 |
| 位置 | 文件在外存中的地址（指针） |
| 大小 | 当前长度 |
| 保护 | 访问权限（读/写/执行） |
| 时间 | 创建时间、最后修改时间、最后访问时间 |
| 所有者 | 文件属主 |

**文件名与扩展名**：文件名用于"按名存取"；扩展名（`.c`、`.exe`、`.txt`）只是**约定**，操作系统既可以"根据扩展名判断类型"（如 Windows），也可以"不看扩展名、用文件头魔数判断"（如 UNIX 的 `file` 命令）。`408` 常考判断：**扩展名不是文件类型的唯一判据**。

**文件类型**：按用途分为系统文件、用户文件、库文件；按数据形式分为源文件、目标文件、可执行文件；按存取控制属性分为只读、读写、可执行；按组织形式分为普通文件、目录文件、特殊文件（设备文件）。

**文件系统的作用（要能默写三条）**：

1. **按名存取**：用户只需给文件名，不必知道物理位置，实现"名字空间 → 物理空间"的映射。
2. **统一管理**：管理外存空间（分配与回收）、管理文件目录、提供文件操作接口。
3. **共享与保护**：支持多用户/多进程共享，同时做访问控制，保证文件安全。

> **408 怎么考/常见坑**：选择题爱考"文件系统最基本的功能/目的是什么"，标准答案是**按名存取**，不要选"提高磁盘读写速度"。坑点是把"文件"和"文件系统"混为一谈：文件是数据集合，文件系统是管理它的软件 + 数据结构。

### 4.2 文件元数据与索引结点（`inode`）

**元数据（metadata）**：描述文件自身的数据，即"关于文件的数据"，不是文件内容。包括大小、权限、时间戳、物理位置、链接计数等。

**`FCB`（File Control Block，文件控制块）**：操作系统为每个文件建立的、存放**所有描述信息和控制信息**的数据结构。`FCB` 是文件存在的标志：**有 `FCB` 才有文件**。

`FCB` 的传统内容 = 文件名 + 属性 + 物理位置（磁盘块号表）。

**`inode`（索引结点）**：UNIX/Linux 系的做法，把 `FCB` 中的信息拆成两部分：

- **目录项**：只保留 `文件名` + `inode 号`（俗称"文件名 + 指针"），很短，所以一个盘块能放很多目录项 → 目录检索更快。
- **`inode`（索引结点）**：存放除文件名以外的**全部**元数据 + 物理块地址（直接块指针、间接块指针）。

**`inode` 与 `FCB` 的关系**：`inode` 是 `FCB` 的一种**具体实现/改进形式**。可以说"UNIX 的 `FCB` 就是 `inode` + 目录项里的文件名"。大纲把 `FCB` 和 `inode` 并列，答题时要能说清这个"拆分"动因。

**磁盘 `inode` 的结构（典型）**：

| 字段 | 内容 |
| --- | --- |
| 文件模式 | 类型 + 权限位（如 `rwxr-xr-x`） |
| 链接计数 | 指向本 `inode` 的目录项个数（硬链接数） |
| 属主/属组 | 所有者信息 |
| 文件大小 | 字节数 |
| 时间戳 | atime / mtime / ctime |
| 数据块指针 | 直接指针 + 一级/二级/三级间接指针 |
| 其他 | 块数、标志位等 |

**关键结论**：

1. **`inode` 不含文件名**。原因：一个文件可以有多个名字（硬链接），文件名属于"目录"这一层，不属于文件本身。
2. **`inode` 号唯一标识一个文件**，与文件名解耦，因此重命名不改变 `inode` 号。
3. **磁盘 `inode` 数量在格式化时就固定了**，所以"磁盘最多能有多少个文件"由 `inode` 总数决定（`inode` 用尽时，即使还有空闲数据块也建不了文件），"单个文件最大长度"由 `inode` 里的地址项结构决定——这两个限制**相互独立**，是最爱的选择题陷阱。

> **408 怎么考/常见坑**：① 问"目录项中包含什么"，答案是**文件名 + `inode` 号**，不含大小/权限。② 问"为什么要把 `FCB` 拆成目录项和 `inode`"，答：**使目录项变短，一个盘块容纳更多目录项，减少检索时的磁盘 `I/O` 次数**。③ 问"文件最大长度由什么决定"，答：**`inode` 中地址项的数量与结构（直接/间接）**，不是 `inode` 号的大小。

### 4.3 文件的操作

**六个基本操作**（含系统调用与内核动作）：

| 操作 | 语义 | 内核主要动作 |
| --- | --- | --- |
| 创建 `create` | 建立一个新文件 | 分配 `inode`（找一个空闲 `inode`）→ 在目录中新增目录项 → 写回 `inode` 与目录 |
| 删除 `delete` | 删除一个文件 | 在目录中删除目录项 → `inode` 链接计数减 1 → 为 0 时回收 `inode` 与数据块 |
| 打开 `open` | 建立"进程 ↔ 文件"的使用关系 | 按路径检索目录找到 `FCB`/`inode` → 检查权限 → 在**打开文件表**中登记，返回**文件描述符** |
| 关闭 `close` | 断开该使用关系 | 从进程打开文件表中删除表项，减少系统级表项的打开计数，必要时写回 `inode` |
| 读 `read` | 从文件读数据到内存 | 按 `读指针` 与逻辑块号经物理结构映射求物理块号 → 启动磁盘 `I/O` → 更新读指针 |
| 写 `write` | 把内存数据写到文件 | 必要时分配新块 → 映射求物理块号 → 写盘 → 更新写指针与文件大小 |

**打开文件表（两级结构，必须背）**：

| 级别 | 位置 | 内容 | 特点 |
| --- | --- | --- | --- |
| **系统级（打开文件表）** | 内核区，全系统一张 | 文件名/`inode` 号、文件在外存的位置、打开计数 `count`、访问权限 | 每个**被打开的文件**占一项；多个进程打开同一文件时**共享同一项** |
| **进程级（进程打开文件表）** | 每个进程的 `PCB`/进程表项中 | 文件描述符表：`fd` → 指向系统级表项的指针、**读写指针** | 每个**进程的每次打开**占一项；同一文件被同一进程打开两次 → 两个 `fd`、两个读写指针 |

- **文件描述符 `fd`**：进程级打开文件表数组的**下标**，是一个小整数（0、1、2 通常给标准输入/输出/错误），**只在本进程内有意义**。
- **文件句柄（file handle）**：更宽泛的说法，通常指操作系统返回给应用、用来代表"已打开文件"的标识（在 Linux 里就是 `fd`，在 Windows 里是 `HANDLE`）。答题时把"`fd` 是进程私有的小整数下标"说清即可。

**`open` 之后为什么用索引而不是路径**：用**路径名**访问文件，每一步都要从目录树逐级检索，可能要多次读盘；`open` 一次把检索结果（`inode`/`FCB` 在内存的副本）登记到打开文件表，返回一个下标 `fd`。此后 `read`/`write` 只需 `fd` 一次查表就定位到文件，**把"按名检索"的开销从每次 `I/O` 降到只付一次**。这就是"`open` 是显式操作、`read` 不接收路径名"的原因。

> **408 怎么考/常见坑**：① 判断题高频——"系统级打开文件表的表项数 = 被打开的不同文件数"，"进程级表项数 = 该进程的 `open` 次数"；同一文件被两个进程打开，系统级只有 1 项，进程级有 2 项，读写指针**各自独立**（所以两进程可以各自从不同位置读！这是经典考点）。② "`open` 是否要把文件内容读入内存？"——不，只把 `FCB`/`inode` 调入内存。③ `create` 与 `open` 的区别：`create` 建立文件本身，`open` 只是建立使用关系；已存在的文件不能 `create`。

### 4.4 文件的逻辑结构

**逻辑结构 = 从用户角度看，文件内部是如何组织记录的**（与物理存放无关）。

**按有无结构分**：

- **无结构文件（流式文件）**：内部就是一串字符/字节流，如 `.txt`、`.c`。UNIX/Linux 中绝大多数文件都是流式文件，长度以字节为单位。
- **有结构文件（记录式文件）**：由若干**记录**组成，记录是数据项的集合。又分：
  - **定长记录**：每条记录长度相同 → 第 `i` 条记录的地址可**直接计算**：`地址 = 起始地址 + i × 记录长度`（`i` 从 0 开始）。
  - **变长记录**：长度不等 → 无法直接计算，只能**顺序查找**（除非另设索引）。

**顺序文件**：记录按某种顺序排列的文件，是逻辑结构中最简单、最常见的一种。

- **串结构**：记录按**存入时间**先后排列，与关键字无关 → 检索只能从头顺序扫描。
- **顺序结构**：记录按**关键字**有序排列 → 可折半查找（但仍受"定长记录可直接定位"的便利）。

**顺序文件的检索代价**：

| 情形 | 能否随机存取 | 检索方式 | 平均查找长度 |
| --- | --- | --- | --- |
| 定长记录 + 顺序结构 | 能 | 折半查找 | 约 `log2(N)` |
| 定长记录 + 串结构 | 能（按位置） | 按关键字只能顺序找 | `(N+1)/2` |
| 变长记录 | 不能 | 顺序查找 | `(N+1)/2` |

**索引文件**：为文件建立一张**索引表**，每个表项 = `关键字 → 记录指针`。索引表本身按关键字排序，所以先查索引表（快），再按指针直接取记录（一次访存）。

- 优点：检索快，且**支持变长记录**（因为指针不受记录长度影响）。
- 缺点：**索引表本身占空间**；增加记录时要同时维护索引表；索引表太大时还要给索引表再建索引。

**索引顺序文件**：折中方案——**把文件分成若干组，每组建一个索引项**（记下该组首记录的关键字和位置）。检索时先用关键字在索引表中找到所在组，再在组内顺序查找。这就是**分块查找（块间索引、块内顺序）**的思想。

**平均查找次数推导（必须会算）**：设文件共 `N` 条记录，分成 `N / g` 组、每组 `g` 条记录，索引表有 `N / g` 项。

- 索引表顺序查找平均：约 `(N/g + 1) / 2` 次
- 组内顺序查找平均：约 `(g + 1) / 2` 次
- 总平均查找次数 ≈ `(N/g + 1)/2 + (g + 1)/2 = (N/g + g)/2 + 1`

当 `N/g = g`，即 `g = 根号 N` 时取最小值，**总平均查找次数约为 `根号 N`**。

例：`N = 10000`，取 `g = 100`（100 组，索引表 100 项），平均查找次数 ≈ `(100+1)/2 + (100+1)/2 = 101` 次，远小于顺序文件的 5000 次。

**直接文件 / 散列文件（哈希文件）**：由关键字经**散列函数**直接算出记录地址，理想情况下**一次访存**即可定位。缺点：会有**冲突（碰撞）**，需冲突解决机制，且不利于顺序遍历。

> **408 怎么考/常见坑**：① 顺序文件"能否随机存取"要分两层答——**定长记录的按位置访问可以随机**，但**按关键字检索**在串结构中必须顺序。② 索引顺序文件爱考"分多少组最优"或"给定 `N` 和 `g` 求平均查找次数"，套上面公式，注意**索引表查找也是顺序查找**，不要漏。③ 无结构文件（流式）**没有记录概念**，谈"记录检索"就是错的。

### 4.5 文件的物理结构

物理结构 = **文件在外存上如何分配盘块**，核心是建立 `逻辑块号 → 物理块号` 的映射。假设：一个盘块 1 KB，磁盘共有若干块，块号从 1 开始（题目给定编号方式时以题目为准）。

#### 4.5.1 连续分配（顺序式结构）

为文件分配**一组连续**的盘块，`FCB` 只记 `起始块号` 和 `长度`。

- **寻址**：逻辑块号 `i` 的物理块号 = `起始块号 + i`（`i` 从 0 或 1 起，按题目口径）。
- **优点**：**支持随机访问**（直接算出块号）；顺序读写时磁头移动少、**访问速度快**（顺序访问速度最快）。
- **缺点**：
  1. **外部碎片**（文件之间留下的不连续小空区），需紧凑（`compact`）才能利用；
  2. **不便扩展**：文件变大时后面未必有空块，可能要整体搬移；
  3. 必须**事先知道文件大小**（或预估）。

#### 4.5.2 链接分配

**隐式链接**：每个盘块末尾存一个指向下一块的指针，`FCB` 只存**首块指针和末块指针**。

- **只能顺序访问**：要读第 `i` 块，必须从第 0 块沿链走 `i+1` 次 → `访问第 i 块最多需 i+1 次磁盘 I/O`。
- 指针占空间（每块的有效数据 = 块大小 - 指针长度）；**可靠性差**：链中一个指针坏了，后面全丢。

**显式链接（`FAT`，文件分配表）**：把整个磁盘所有链的指针**集中**存到一张表里，这就是 `FAT`。

- **表项数与磁盘块数相同**：第 `i` 个表项记录"块 `i` 的下一块号"，`FAT` 表项数 = 磁盘总块数（**与文件数无关**）。
- 目录项（`FCB`）里只需记**起始块号**。
- **支持随机访问**：先在内存的 `FAT` 中沿链查表得到第 `i` 块的物理块号（不用读盘），再**一次读盘**拿到数据。
- **代价：`FAT` 必须常驻内存**。设块大小 1 KB、`FAT` 每表项 4 B、磁盘 100 GB，则 `FAT` 占内存 = `100 GB / 1 KB × 4 B = 400 MB`——这就是代价。块（簇）越大，`FAT` 越小，但内部碎片越大。

> `FAT32` 的"32"指表项位数：每表项 32 位（实际 28 位用于块号），因此最多管理 `2^28` 个簇。

#### 4.5.3 索引分配

为每个文件建立一张**索引表（索引块）**，表中第 `i` 项就是"逻辑块 `i` 的物理块号"。`FCB` 记索引块地址。

- **支持随机访问**，且**文件可离散存放、易于扩展**（新增块只需在索引表中加一项）。
- **缺点**：索引表本身占盘块；当索引表也放不下时要用**多级索引**。
- **访存次数**：读文件第 `i` 块，**先读索引块、再读数据块 = 2 次磁盘 I/O**（若索引块已在内存则可只算 1 次）。

**单级 / 两级 / 三级索引**：设一个索引块能放 `n` 个索引项。

| 结构 | 可寻址的逻辑块范围 | 最大块数 | 读一块的访存次数（索引未缓存） |
| --- | --- | --- | --- |
| 单级索引 | `0 ~ n-1` | `n` | 2 |
| 两级索引 | `0 ~ n²-1` | `n²` | 3 |
| 三级索引 | `0 ~ n³-1` | `n³` | 4 |

其中 `n = 块大小 / 索引项大小`（若题目直接给出，就取该值），所以 `一个索引块能寻址的文件大小 = n × 块大小`。

**混合索引（UNIX 多级索引，本章大题核心）**：`inode` 中同时放**直接指针**和**多级间接指针**，兼顾"小文件快、大文件也能存"。

典型结构：`10 个直接地址项 + 1 个一级间接 + 1 个二级间接 + 1 个三级间接`。

**最大文件长度推导模板（务必按这个格式写）**：
设块大小 `B = 1 KB`，每个地址项 `4 B`，则每个索引块可放 `n = 1 KB / 4 B = 256` 个地址项。

```text
直接部分：10 块                        = 10 块
一级间接：1 个索引块 → 256 项          = 256 块
二级间接：1 个一级索引块 → 256 个索引块 → 每块 256 项 = 256 × 256 = 65536 块
三级间接：256 × 256 × 256              = 16777216 块
------------------------------------------------------------
最大块数 = 10 + 256 + 65536 + 16777216 = 16843018 块
最大文件长度 = 16843018 × 1 KB ≈ 16.06 GB
```

**给定逻辑块号（或偏移量）求物理块号的标准解法**：

```text
第 1 步：算每个索引块的项数  n = 块大小 / 地址项大小
第 2 步：划分逻辑块号 b 的区间
         b < 10                     → 直接，第 b 号直接地址项
         10 <= b < 10+n             → 一级间接，第 (b-10) 项
         10+n <= b < 10+n+n²        → 二级间接，令 t = b-(10+n)
                                      一级偏移 = t / n，二级偏移 = t % n
         再往上                      → 三级间接，令 t = b-(10+n+n²)
                                      一级 = t / n²，二级 = (t / n) % n，三级 = t % n
第 3 步：说明访存次数 = 数据块 + 沿途每个索引块各 1 次
```

**偏移量换算**：`逻辑块号 b = 偏移量 / 块大小`（整除），`块内偏移 = 偏移量 % 块大小`。

> **408 怎么考/常见坑**：① "最大文件长度"题最常见的错是**漏掉直接块那一项**或**把 10 个直接项写成 10 块以外又重复加一次**。② 索引项大小不是 4 B 时（比如 2 B）千万别套 256，必须重算 `n`。③ 问"读取某逻辑块需几次访存"，二级间接要答 **3 次**，且要写出"一级索引块 → 二级索引块 → 数据块"，只答 2 次是典型失分。④ 若题目说"索引块已调入内存"，则索引部分不计访存，只有数据块 1 次。

#### 4.5.4 三种物理结构对比表（必背）

| 对比项 | 连续分配 | 链接分配（隐式） | 链接分配（显式 `FAT`） | 索引分配 |
| --- | --- | --- | --- | --- |
| 目录项内容 | 起始块号 + 长度 | 首块 + 末块指针 | 起始块号 | 索引块地址 |
| 支持随机访问 | 支持 | **不支持** | 支持 | 支持 |
| 读第 `i` 块访存次数 | 1 | `i+1`（沿链） | 1（查内存 `FAT`）+ 1 读盘 | 2（索引块 + 数据块） |
| 外部碎片 | **有**（严重） | 无 | 无 | 无 |
| 文件扩展 | 困难（可能要搬移） | 容易 | 容易 | 容易（可加索引块） |
| 额外空间开销 | 无 | 每块一个指针 | **`FAT` 常驻内存** | 索引块 |
| 可靠性 | 高 | 链断则后续丢失 | 较好（可多副本） | 索引块损坏则文件受损 |

**选型直觉**：小文件多、要随机访问 → 连续或索引；磁盘空间碎片化严重、要"任意大小" → 链接/`FAT`；UNIX 系大文件 → 混合索引。

> **408 怎么考/常见坑**：对比题常问"哪种结构不支持随机访问"（答：**隐式链接**）或"哪种结构 `FCB` 只存首块号"（答：隐式链接）。注意 `FAT` 是**显式链接**，虽然链表在表里，但**仍是链接分配**，不要答成索引分配。

### 4.6 文件的保护

**访问类型**：读（`read`）、写（`write`）、执行（`execute`）、追加（`append`）、删除（`delete`）、列表（`list`）。

**访问控制表 `ACL`（Access Control List）**：为每个文件记录"哪些用户/组可以用哪种方式访问"，即一组 `(主体, 权限集合)`。

- 优点：**可以精确到每一个具体用户**，表达能力强。
- 缺点：**表太长占空间**（用户多时）；查找需遍历。
- 改进：**精简访问控制表**——只存三类的权限：**文件属主、组、其他所有用户**（UNIX 的 `rwx` 三组九位权限就是这种精简形式）。若某用户需要特殊权限，再单独列出。

**口令**：文件建立时设置一个口令，访问时对答。优点：**占空间小、实现简单**；缺点：**保密性差**（口令存在系统内部易泄露）、口令一旦泄露无法定位、不易按"访问类型"细分权限。

**密码（加密）**：把文件内容用密钥加密存储。优点：**安全性高**，即使文件被窃取也无法读出；缺点：**加解密增加开销**，且密钥本身的管理是难题。

> **408 怎么考/常见坑**：最爱考"口令 vs 密码"对比——**口令防的是"未经授权的访问"，密码防的是"文件被窃取后内容泄露"**；以及"`ACL` 与精简 `ACL` 的区别"。答题时说清"`ACL` 精确但占空间，精简 `ACL` 省空间但粒度粗"即可。

### 4.7 目录

#### 4.7.1 目录的基本概念与结构

**目录的作用**：实现**按名存取**——把"文件名"映射到"文件控制信息（`FCB`/`inode` 号）"，从而找到文件。

**目录项与 `FCB`**：

- **目录本身也是一个文件（目录文件）**，它的内容就是一个个**目录项（目录条目）**。
- 在传统实现中，**目录项 = `FCB`**（含文件名 + 全部属性 + 磁盘地址），目录项很长。
- 在 `inode` 实现中，**目录项 = 文件名 + `inode` 号**，`inode` 独立存放，目录项很短 → **一个盘块能放更多目录项 → 检索读盘次数减少**。

**目录的基本操作**：

| 操作 | 含义 |
| --- | --- |
| 搜索 | 按名查找目录项，得到 `FCB`/`inode` |
| 创建 | 新增一个目录项（建文件时同时建目录项） |
| 删除 | 删除目录项；空目录才能删（或连同内容递归删） |
| 显示（列目录） | 列出目录下所有目录项的信息 |
| 重命名 | 修改目录项中的文件名部分（不改 `inode`） |

**目录的几种组织方式**：

1. **单级目录**：整个系统一张目录表，所有文件都在这张表里。
   - 优点：简单，能按名存取。
   - 缺点：**不允许重名**（不同用户不能用同名文件）；文件多时检索慢；**无法给文件分类**。
2. **两级目录**：分为**主文件目录 `MFD`**（每个用户一项）和**用户文件目录 `UFD`**（每个用户一张）。
   - 优点：**不同用户可以使用相同文件名**；检索加快；可做用户级权限控制（只能访问自己的 `UFD`）。
   - 缺点：**同一用户内仍不能重名**；缺乏层次，不便分类。
3. **树形目录（多级目录）**：
   - 优点：**层次清晰、便于分类**；不同目录下可重名；检索效率高；便于权限管理（可对目录授权）。
   - 缺点：**路径变长，逐级检索增加访存次数**；不方便共享（要共享必须写多份或用链接）。

**路径与当前目录**：

- **绝对路径**：从**根目录**出发到文件的完整路径，如 `/usr/lib/libc.a`。
- **相对路径**：从**当前目录（工作目录）**出发的路径，如 `../lib/libc.a`。
- **当前目录**：进程的一个属性（在 `PCB` 中），检索相对路径时先找它，**减少从根开始的重复访存**。

#### 4.7.2 无环图目录与文件共享

**无环图目录**：在树形目录基础上允许**多个目录项指向同一个 `inode`**（即有向无环图），从而支持**文件共享**。

- **引用计数**：每个 `inode` 里记 `链接计数（count）`，每多一个目录项指向它就加 1。
- **删除语义**：删除一个目录项时计数减 1，**只有计数为 0 时才真正删除文件**（回收 `inode` 与数据块）。这就是硬链接删除逻辑的基础。

> 真正的"树"要求每个结点只有一个父结点（除根），所以共享会导致"一个文件两个父亲"，必须放宽成**无环图**；并且不允许链接到目录，否则可能形成环。

#### 4.7.3 目录检索的访存次数计算（大题常考）

**核心公式**：要让文件内容到内存，需要读的盘块数 =

```text
读盘次数 = 从根（或当前目录）起逐级检索各级目录所需的盘块数
         + 读取该文件 inode 所在盘块的次数（若 inode 不在内存）
         + 读取文件数据块本身的次数（题目问"访问文件内容"时才加）
```

**要点**：

1. 每读一个**目录文件盘块**算 1 次访存。
2. **根目录的 `FCB`（或根 `inode`）通常已常驻内存**，所以从根开始的检索**不计**读根目录那一次；但读取根目录**内容块**仍要读盘（除非题目说"根目录内容也在内存"）。
3. 目录项若一个盘块装得下，就只读 1 次；否则需读多个块，要按"目录项数 / 每块目录项数"向上取整。
4. 若题目给出"某目录的 `inode` 已在内存"，则读取该目录内容只需 1 次（读其数据块）等——**一切以题目的"已在内存"提示为准**。

**示例**：某系统目录项 16 B、盘块 1 KB（每块 64 个目录项），`inode` 号与属性放在 `inode` 区，`inode` 表已部分缓存。查找 `/A/B/C`（`A`、`B` 各占 1 个盘块，`C` 是普通文件）：

```text
① 读根目录内容块 → 找到 A 的 inode 号          ：1 次
② 读 A 的 inode 所在块（若未缓存）→ 得 A 数据块号：1 次
③ 读 A 目录内容块 → 找到 B 的 inode 号          ：1 次
④ 读 B 的 inode 所在块 → 得 B 数据块号          ：1 次
⑤ 读 B 目录内容块 → 找到 C 的 inode 号          ：1 次
⑥ 读 C 的 inode → 得 C 的物理块号               ：1 次
（若还要读 C 的内容：再 + 1 次）
```

> **408 怎么考/常见坑**：① 目录项变短能让"每块目录项数"增加，从而把"读 2 个块"变成"读 1 个块"，这类题要**先算每块能放多少目录项**再算块数。② 别忘"`inode` 本身也要读盘"——只算目录块、漏算 `inode` 块是最常见失分。③ 题目说"当前目录"时，从当前目录开始算，不要从根算。

### 4.8 硬链接与软链接

**硬链接（hard link）**：在目录中新增一个目录项，指向**已有的同一个 `inode`**。此时一个 `inode` 对应多个文件名，`inode` 的**链接计数 = 目录项个数**。

- 删除其中**一个**名字：只删除该目录项，计数减 1，**文件数据仍在**，用其他名字照常访问。
- 删除**最后一个**名字（计数变 0）：才真正删除文件，释放 `inode` 和数据块。
- 特点：**不能跨文件系统**（`inode` 号只在同一文件系统内有意义）；**一般不允许为目录建硬链接**（防环、防计数混乱）。

**软链接（符号链接，symbolic link）**：新建一个**独立的小文件**，其内容就是**目标文件的路径名**，它有**自己的 `inode`**和独立的数据块（存路径字符串）。

- 删除原文件后，软链接**仍然存在**，但访问它时因路径已失效而报错（成为**悬空链接/断链**）。
- 特点：**可以跨文件系统**（存的是路径字符串，与 `inode` 无关）；**可以为目录创建**；不增加目标文件的链接计数。
- 访问开销：**多一次读链接文件（读路径）的开销**，即"先解析路径、再访问目标"，比硬链接多一次或多次访存。

#### 硬链接 vs 软链接 对比表（必背）

| 对比项 | 硬链接 | 软链接（符号链接） |
| --- | --- | --- |
| 本质 | 新增目录项指向**同一 `inode`** | 新建**独立文件**，内容是目标路径名 |
| 是否有自己的 `inode` | 无（共用目标 `inode`） | **有**自己的 `inode` |
| 链接计数 | **加 1**，计入目标 `inode` | **不变**（不计入目标文件） |
| 原文件删除后 | 只要还有别的名字，文件**仍可正常访问** | 链接文件仍在，但**断链失效** |
| 能否跨文件系统 | **不能** | **能** |
| 能否链接目录 | 一般**不允许** | **允许** |
| 访问开销 | 与直接访问相同（路径解析后即得 `inode`） | **多一次读链接文件路径**的开销 |
| 典型命令 | `ln a b` | `ln -s a b` |

> **408 怎么考/常见坑**：① 经典题："`/a` 与 `/b` 是硬链接，删 `/a` 后 `/b` 还能用吗？"——能用，计数从 2 变 1。② "软链接删掉原文件后呢？"——链接还在，访问失败（断链）。③ 问"访问开销"，**软链接大于硬链接**。④ 问"链接计数存在哪"，答：**存在 `inode` 中**。⑤ 软链接的"文件大小"通常等于路径字符串长度（如 Linux 中 `ls -l` 显示的那个数），这是个冷门但真实的考点。

### 4.9 文件系统的全局结构（layout）

#### 4.9.1 文件系统在外存中的结构

一块磁盘被格式化后，典型布局（以 UNIX 风格为例，从低地址到高地址）：

| 区域 | 内容 | 说明 |
| --- | --- | --- |
| **引导块（boot block）** | 引导程序 | 位于分区起始，用于启动操作系统；每个分区都有，但只有一个被真正使用 |
| **超级块（super block）** | 文件系统的全局信息 | 文件系统大小、空闲块数、空闲块指针（如成组链接法的栈）、`inode` 数量、`inode` 表起始位置等 |
| **inode 区（inode table）** | 所有 `inode` 的数组 | 数量在格式化时确定 |
| **数据区（data blocks）** | 文件数据 + 目录内容 | 占绝大部分空间 |

**内存中的结构**：文件系统运行时会在内存建立若干表以加速访问：

| 内存结构 | 作用 |
| --- | --- |
| **挂载表（mount table）** | 记录每个已挂载文件系统的信息（设备号、挂载点、文件系统类型、指向超级块内存副本的指针） |
| **目录项缓存（dentry cache）** | 缓存最近访问的目录项（名字 → `inode` 的映射），避免重复读目录块 |
| **inode 缓存（`inode` cache）** | 缓存最近使用的 `inode`，`inode` 是访存热点 |
| **系统级打开文件表** | 所有进程共享的已打开文件信息 |
| **进程级打开文件表** | 每个进程的 `fd` 表（含读写指针） |

> **408 怎么考/常见坑**：爱考"超级块里存什么"——答：**文件系统的整体信息 + 空闲空间管理信息（如空闲块数、空闲块栈）**，不要把"文件内容"或"目录项"算进去。另外"引导块是否属于文件系统管理"要答：它由文件系统预留，但**不属于文件数据**。

#### 4.9.2 外存空闲空间管理方法

**① 空闲表法**：为外存上所有空闲区建立一张**空闲表**，每项 = `(起始块号, 空闲块数)`。

- **分配**：检索空闲表，找足够大的空闲区（首次适应、最佳适应、最坏适应均可用于此处）。
- **回收**：把回收区插回表中，并**与相邻空闲区合并**（四种情况必须会画）：
  1. 回收区与前空闲区相邻 → 与前合并，起始块号和长度更新；
  2. 与后空闲区相邻 → 与后合并；
  3. 前后都相邻 → 三者合并成一项（表项数减 1）；
  4. 前后都不相邻 → 新增一项。
- 适用于**连续分配**；空闲区很多时表很长。

**② 空闲链表法**：

- **空闲盘块链**：以盘块为单位，把空闲块拉成链，每块存下一空闲块指针。
- **空闲盘区链**：以"空闲盘区"为单位拉链，每区记 `(起始块号, 块数, 下一区指针)`。
- 特点：分配回收简单、**无外部碎片**（链上块可离散），但**查找合适的空闲区需要沿链扫描**。

**③ 位示图法**：用**一个二进制位**表示一个盘块的状态，`0` 表示空闲、`1` 表示已占用（或相反，**以题目规定为准**）。整个位示图由若干"字"组成，每个字有 `字长` 位。

- **优点**：**一个位对应一个块，非常省空间**，且**容易找到连续空闲块**（找连续 0）。
- **块号换算（核心公式）**：设字长为 `L`，字的编号从 `1` 开始、位号从 `1` 开始（王道常见口径），块号从 `1` 开始：

```text
已知 (字号 i, 位号 j) 求块号 b：
    b = (i - 1) × L + j          （i, j 均从 1 开始，块号从 1 开始）

已知块号 b 求 (字号 i, 位号 j)：
    i = (b - 1) / L + 1          （整除）
    j = (b - 1) % L + 1
```

若**字号、位号、块号都从 0 开始**，则退化为：`b = i × L + j`。**做题第一步先确认编号基准**。

- 位示图大小：磁盘总块数 `N`、字长 `L`，则需 `N / L` 个字（向上取整），占 `N` 个二进制位 = `N / 8` 字节。

**④ 成组链接法（UNIX 采用，大题最爱）**：把空闲块**分组**，每组用一个盘块记录下一组的空闲块号，形成"链"，而**超级块中保存当前可用组的空闲块号栈**。

- **结构**：设每个盘块最多存 `100` 个空闲块号。若干空闲块组成一组，每组的**首块**（栈块）里存 `本组空闲块号 + 下一组栈块号`，超级块中保存"**当前组**"的空闲块号。
- **分配（从超级块栈顶弹出）**：

```text
第 1 步：检查超级块中的空闲块栈是否为空（或只剩栈块指针）
第 2 步：若栈不空 → 从栈顶取出一个块号分配出去
第 3 步：若栈中只剩最后 1 个元素（它是"下一组栈块"的块号）：
        先读入该盘块的内容作为新的空闲块栈，然后再分配该盘块本身
```

- **回收（压入超级块栈顶）**：

```text
第 1 步：若超级块栈未满 → 直接将要回收的块号压入栈顶
第 2 步：若超级块栈已满（已有 100 个块号）：
        先把栈中全部 100 个块号写入"刚回收的这个块"，
        再把栈清空，最后把该块的块号压入栈顶
        （即该块成为新的"栈块"，指向原来的那一组）
```

- **本质**：**链式存储 + 索引（每组有目录）**的结合。分配回收都在内存的超级块栈上进行，**只在换组时才读一次盘**，效率高，且不受连续空间限制。

> **408 怎么考/常见坑**：① 位示图题最常见的错是**编号基准搞混**（字号从 1 还是 0、位号从 1 还是 0），写答案时务必**注明基准**。② 成组链接题必须写清"**先读入下一组栈块，再分配该栈块**"这个顺序，直接分配栈块是错的。③ 成组链接的分配顺序是**后进先出（栈顶）**，回收也是压栈顶；换成队列就错了。④ 空闲表法的合并题要四种情况都判断，不能只顾一种。

### 4.10 虚拟文件系统 `VFS`

**要解决的问题**：一台机器上同时有 `ext4`、`FAT32`、`NTFS`、网络文件系统 `NFS` 等**多种文件系统**，它们的内部实现（目录结构、分配方式）完全不同。如果每个应用程序都要针对不同文件系统写不同代码，就无法维护。`VFS` 就是在**应用程序与具体文件系统之间加的一层抽象**。

**`VFS` 的作用**：

1. 向上：为应用程序提供**统一的系统调用接口**（`open`、`read`、`write`、`close` 等），不管底层是什么文件系统，调用方式相同。
2. 向下：要求各具体文件系统实现**统一的函数接口**（通过一组函数指针表 / 操作集合），从而能"插拔"。
3. 中间：维护**统一的数据结构抽象**，如 `vnode`（虚拟结点）、`file` 对象、目录项对象等。

**`vnode`（虚拟结点）**：`VFS` 对"一个文件"的抽象表示，**与具体文件系统无关**。它包含：

- 文件的**属性**（类型、大小、权限、时间戳）；
- 指向具体文件系统 `inode`（或对应数据结构）的**指针**；
- 指向**函数指针表**的指针（该具体文件系统实现的操作，如 `read`、`write`、`lookup`）。

**三层映射直觉**：

```text
应用程序 → 系统调用（read(fd, ...)）
        → VFS：按 fd 找到 vnode，调用 vnode 里的函数指针
        → 具体文件系统（ext4 / FAT32 / NFS）的 read 实现
        → 磁盘驱动 → 磁盘
```

> **408 怎么考/常见坑**：① 考"`VFS` 的目的是什么"——答：**屏蔽不同文件系统的差异，为上层提供统一接口**（关键词：抽象、统一接口）。② 考"`vnode` 和 `inode` 的区别"——答：`vnode` 是 `VFS` 层的**通用抽象**（跨文件系统），`inode` 是**具体文件系统**（如 `ext4`）的磁盘/内存结构，`vnode` **指向** `inode`。③ `VFS` 也可以抽象网络文件系统，所以它管理的不只是本地磁盘。

### 4.11 文件系统的挂载（mounting）

**为什么需要挂载**：一个文件系统被格式化后是**独立的**（有自己的根目录、自己的超级块），它必须"接入"到操作系统的**统一目录树**中，用户才能用一条路径访问它。

**`mount` 的作用**：把一个**具体文件系统**安装到目录树中的某个**已存在的目录**上，使该目录成为这个文件系统的**入口**。

**挂载过程（标准步骤）**：

1. 操作系统读取该设备（分区）的**超级块**，确认文件系统类型与完整性；
2. 在**挂载表**中登记一项：设备号、文件系统类型、**挂载点**、指向超级块内存副本的指针；
3. 把该文件系统的**根目录**与挂载点关联：此后访问挂载点这个路径，实际进入的是新文件系统的根目录；
4. 挂载点原来的**内容被隐藏**（不是删除），卸载（`umount`）后重新可见。

**挂载点（mount point）**：目录树中被用作入口的那个目录，**必须已存在且通常应为空**（不空也能挂，但原内容会被遮盖）。

**多次挂载可以嵌套**：`/` 挂 `ext4` 根分区，`/home` 挂另一分区，`/mnt/usb` 挂 U 盘，于是**一棵目录树 = 多个文件系统拼接**，这正是 Tree 形目录能"跨越设备"的原因。

> **408 怎么考/常见坑**：① "挂载后挂载点原有文件去哪了？"——答：**被隐藏，未删除，卸载后恢复可见**。② "挂载点能否是非空目录？"——可以，但原内容不可见，所以实践中要求空目录。③ 挂载后新文件系统的**根目录 `/` 变成了挂载点**，注意路径的相对性。④ 判断："一个文件系统必须挂载后才能被使用"——正确（除根文件系统在启动时自动挂载）。

## 四、例题精练（3 道）

### 例题 1（选择题）

某文件系统采用**混合索引**结构，其 `inode` 中有 `10` 个直接地址项、`1` 个一级间接地址项、`1` 个二级间接地址项、`1` 个三级间接地址项。盘块大小为 `1 KB`，每个地址项占 `4 B`。则该文件系统支持的最大文件长度约为（　　）

A. `10 KB`　　B. `266 KB`　　C. `64 MB`　　D. `16 GB`

**逐项解析**：

```text
先算每个索引块能放的地址项数：
n = 块大小 / 地址项大小 = 1 KB / 4 B = 1024 B / 4 B = 256

直接部分        ：10 块
一级间接        ：1 个索引块 → 256 项 → 256 块
二级间接        ：1 个一级索引块 → 256 个二级索引块 → 每个再指 256 块
                  共 256 × 256 = 65536 块
三级间接        ：256 × 256 × 256 = 16777216 块

最大块数 = 10 + 256 + 65536 + 16777216 = 16843018 块
最大文件长度 = 16843018 × 1 KB ≈ 16.06 GB
```

- **A 错**：只算了 10 个直接块，完全漏掉三级间接。
- **B 错**：把 `10 + 256 = 266` 块当成结果，把"块数"当"字节数"（266 × 1 KB = 266 KB），漏了二级、三级间接。
- **C 错**：只算到二级间接（`10 + 256 + 65536` 块 ≈ 64 MB），这是最常见的"少算一级"陷阱。
- **D 对**：`10 + 256 + 65536 + 16777216 ≈ 16843018` 块 ≈ 16 GB。

**答案：D**

**采分点与常见坑**：

- 采分点：写出 `n = 块大小 / 地址项大小`；**明确列出直接、一级、二级、三级四部分**；相加后乘块大小。
- 坑 1：漏掉 `10` 个直接块（数量级不变但数值错）。
- 坑 2：把 `256²` 写成 `256 × 2` 或 `512`。
- 坑 3：单位换算出错，`16843018 KB` 约等于 `16 GB`（按 `1 GB = 2^20 KB` 算，`16843018 / 1048576 ≈ 16.06`）。
- 坑 4：题目若给"每个地址项占 2 B"，则 `n = 512`，答案随之改变——**必须重算 `n`，不能背 256**。

### 例题 2（综合计算题：混合索引求物理块号）

**题目**：某文件系统盘块大小 `1 KB`，`inode` 中地址项结构为：`10` 个直接地址项、`1` 个一级间接、`1` 个二级间接、`1` 个三级间接，每个地址项占 `4 B`。某文件已建立，其 `inode` 中：

```text
直接地址项 di[0..9] = 100, 101, 102, ..., 109
一级间接地址项    = 200
（为简化，二级、三级间接暂不使用）
```

设盘块编号从 `1` 开始，索引块内的地址项按顺序从下标 `0` 开始存放，`inode` 已在内存中，所有索引块都**未**在内存中。请回答：

1. 该文件的最大长度是多少（用块数和字节数表示）？
2. 若要读取文件中偏移量为 `13000 B` 的数据，需要访问哪些盘块？共需几次磁盘 `I/O`？给出最终物理块号的计算过程。
3. 若改为读取偏移量 `12 B` 的数据，需要几次磁盘 `I/O`？为什么？

**解答步骤**：

**第 1 问**：

```text
n = 1 KB / 4 B = 256
最大块数 = 10 + 256 + 256² + 256³
        = 10 + 256 + 65536 + 16777216 = 16843018 块
最大长度 = 16843018 × 1 KB ≈ 16.06 GB
```

**第 2 问**：

```text
第 1 步：偏移量 → 逻辑块号
    逻辑块号 b = 13000 / 1024 = 12（整除，舍去余数）
    块内偏移   = 13000 % 1024 = 13000 - 12 × 1024 = 13000 - 12288 = 712

第 2 步：判断 b = 12 落在哪个区间
    直接区间：b < 10            → 12 不在此区间
    一级间接区间：10 <= b < 10 + 256 = 266 → 12 在此区间！
    一级间接中的下标 = b - 10 = 12 - 10 = 2

第 3 步：沿地址链求物理块号
    inode 在内存 → 直接读出"一级间接地址项 = 200"（不产生磁盘 I/O）
    读盘块 200（一级索引块）→ 取其中第 2 号地址项 → 得数据块号 X
    读盘块 X → 取出块内偏移 712 处的数据

第 4 步：访存次数
    读一级索引块 200 ：1 次
    读数据块 X       ：1 次
    合计 = 2 次磁盘 I/O
```

**第 3 问**：

```text
b = 12 / 1024 = 0，直接地址项 di[0] = 100
inode 已在内存 → 物理块号 = 100 直接得到
只需读盘块 100 一次 → 1 次磁盘 I/O
```

**答案**：

1. 最大 `16843018` 块，约 `16.06 GB`。
2. 偏移 `13000 B` 对应逻辑块号 `12`、块内偏移 `712`；落在**一级间接**范围，间接下标为 `2`；访问路径为「读一级索引块 `200` → 读数据块」；共 **2 次**磁盘 `I/O`。
3. 偏移 `12 B` 对应逻辑块号 `0`，落在**直接地址项** `di[0] = 100` 上；`inode` 已在内存，**只需 1 次**磁盘 `I/O`（读盘块 `100`）。

**采分点与常见坑**：

- 采分点：① 偏移量必须先**整除**求逻辑块号、再取模求块内偏移；② 写清区间判断（`b < 10` 直接、`10 ≤ b < 266` 一级间接……）；③ 一级间接的下标是 `b - 10`，不是 `b`；④ 访存次数要**分索引块和数据块**说明。
- 坑 1：直接用 `13000 / 1024 ≈ 12.7` 取 `13`——**必须向下取整**，偏移 13000 落在第 12 块内。
- 坑 2：以为逻辑块号从 1 开始，把 `b = 12` 当成第 13 块，下标算成 `3`。
- 坑 3：忘了 `inode` 在内存这一条件，多算一次读盘。
- 坑 4：问"几次访存"时只答 1 次要读数据块——**一级间接必须额外读索引块**。

### 例题 3（综合计算题：成组链接法的分配与回收）

**题目**：某 UNIX 类文件系统采用**成组链接法**管理空闲盘块。规定：盘块大小 `1 KB`，**每个盘块正好存放 `100` 个空闲块号**（这 100 个位置中，除用作"下一组栈块指针"的那个位置外，其余存放普通空闲块号），盘块号从 `1` 开始编号。约定栈的读法如下（**栈顶在左，栈顶指针指向栈顶元素**）：

```text
【初始状态】超级块中的空闲块栈共 100 个元素，从栈顶到栈底依次为：
   100, 99, 98, 97, ..., 3, 2, 1
（即此时 1 号盘块是"下一组的栈块"）

【1 号盘块中存放的内容】下一组的 100 个空闲块号，栈顶在左：
   102, 101, 100, 99, ...   （与 1 号块自身无关，均为空闲块号）
```

请回答：

1. 若要分配 `3` 个空闲块，依次分配出哪些块号？请写出每一步。
2. 分配完之后，超级块中的空闲块栈发生了什么变化？
3. 若接着回收盘块 `500`、`501`：请分别说明"回收 `500` 时栈中已有 `99` 个元素"与"回收 `501` 时栈已有 `100` 个元素"两种情形下，系统该怎么做。

**解答步骤**：

**第 1 问**：

```text
第 1 次分配：栈不空，从栈顶弹出 100        → 分配 100 号块
第 2 次分配：栈不空，从栈顶弹出 99         → 分配 99 号块
第 3 次分配：此时栈中只剩 1 一个元素，它是"下一组栈块指针"
           → 先读入 1 号盘块的内容（102, 101, 100, ...）作为新的超级块空闲块栈
           → 由于 1 号块中的内容已全部转入超级块，它本身已可作数据块 → 分配 1 号块
           新栈的栈顶为 102
```

**第 1 问答案：依次分配 `100`、`99`、`1`。**

**第 2 问**：

```text
超级块中的空闲块栈被"换组"：
  原栈只剩栈块指针 1，读入 1 号块后，栈内容替换为 102, 101, 100, ...（共 100 个空闲块号）
  栈顶变为 102，后续分配将从 102 开始继续弹出
```

**第 3 问**：

```text
【情形一】回收 500 号块时，超级块栈已有 99 个元素（未满 100）
   栈未满 → 直接把 500 压入栈顶
   栈变为 {500, 102, 101, 100, ...}（元素数由 99 → 100）

【情形二】回收 501 号块时，超级块栈已有 100 个元素（已满）
   栈已满，不能再压入，必须"另起一组"：
   ① 先把栈中现有的 100 个空闲块号全部写入"刚回收的 501 号块"
   ② 把超级块栈清空
   ③ 把 501 号块号压入栈顶
   → 此时栈中只有 {501}，501 号块成为新的"栈块"，指向原来那一组
   → 之后再回收其它块，就直接压到这个新栈上
```

**答案**：

1. 依次分配出 `100`、`99`、`1`。
2. 发生**换组**：超级块栈的内容被替换为 `1` 号盘块中保存的下一组（`102, 101, 100, ...`），栈顶变为 `102`。
3. 回收 `500`（栈未满）：直接压入栈顶；回收 `501`（栈已满）：先把栈中 100 个块号写入 `501` 号块，清空栈，再把 `501` 压入栈顶，`501` 成为新的栈块。

**采分点与常见坑**：

- 采分点：① 分配必须强调"**先读入下一组栈块内容，再分配该栈块本身**"；② 换组要写出"栈内容被替换"；③ 回收要写清"栈满 → 先写盘、再清空、后压入"三小步。
- 坑 1：第 3 次分配时直接分配 `1` 号块而**不先读入 `1` 号块中的下一组信息**——会导致空闲块链断裂，这是本题最大失分点。
- 坑 2：把栈当成**队列**，从栈底取 `1` 之后又去取 `2`——成组链接是**后进先出（栈）**，取的是栈顶。
- 坑 3：回收时栈满却直接压入，造成栈溢出、块号丢失。
- 坑 4：误认为"回收块号进入的是某个普通空闲链"——正确做法是**进入超级块栈（当前组）**，这正是"成组"的含义。

> **补充题型（同源考点，自己练）**：把本题换成**位示图**：字长 `32` 位、字号与位号均从 `0` 开始、块号从 `0` 开始，第 `100` 个字的第 `15` 位为 `0`，则对应块号 `b = 100 × 32 + 15 = 3215`。若块号从 `1` 开始、位号从 `0` 开始，则 `b = 3216`。**做题时务必先声明编号基准**，这是位示图题的唯一陷阱来源。

## 六、简便方法与易错口诀（速算 · 防错）

> 本节把本章能"省时间"和"防掉坑"的招集中在一处：二轮复习与考前只看这一节。每条都写清**适用条件**。

### 6.1 速算招式

| 场景 | 常规做法（慢/繁） | 简便做法（快/稳） | 为什么成立 / 适用条件 |
| --- | --- | --- | --- |
| 混合索引**最大文件长度** | 画索引树一层一层数 | 三步模板：① 先算一个索引块能放几个块号 `n = 块大小 ÷ 块号字节数`；② 按 `直接数 + n + n² + n³` 展开，**每深一级乘一次 `n`**；③ 总块数 × 块大小 | 适用条件是 `inode` 为"`10` 个直接 + 一级/二级/三级间接各 `1` 个"。本章数值：`n = 1 KB ÷ 4 B = 256`，最大块数 `10 + 256 + 65536 + 16777216 = 16843018` 块 ≈ `16.06 GB`。地址项不是 `4 B` 时**必须重算 `n`**（`2 B` → `n = 512`），不能背 `256` |
| 由偏移量/逻辑块号求**物理块号** | 死记长公式，下标记混 | **区间法**：先 `b = 偏移量 ÷ 块大小`（向下取整）、`块内偏移 = 偏移量 % 块大小`；再定位区间：直接 `0 ~ 9`、一级 `10 ~ 10+n-1`、二级 `10+n ~ 10+n+n²-1`、三级再往后 | 每段长度就是"该级块数"，用 `b` 减去段首即得中间索引下标。二级：令 `t = b - (10+n)`，一级下标 `= t ÷ n`、二级下标 `= t % n`。本章示例：偏移 `13000 B` → `b = 12`，落在 `10 ≤ b < 266` 的**一级间接**，下标 `= 12 - 10 = 2` |
| 读一个数据块的**磁盘 `I/O` 次数** | 一层一层数索引块 | 口诀 **"间接层数加一"**：直接 `1` 次、一级间接 `2` 次、二级间接 `3` 次、三级间接 `4` 次 | 仅在"`inode` 已在内存、沿途索引块都未缓存"时成立（`k` 个索引块 + 最后 `1` 个数据块）。若题目说索引块已在内存，索引部分不计，只剩数据块 `1` 次；若还要先读目录块/`inode` 块，另加 |
| **`FAT`** 的两个结论 | 按文件一个个推 | ① `FAT` 表项数 = 磁盘块（簇）数，**与文件数无关**；② 表项位数定容量：用于块号的位数 `n` → 最多 `2^n` 个块，`单个磁盘最大容量 = 2^n × 块大小` | 只适用于**显式链接**。注意口径：`FAT32` 表项 32 位，但**实际只有 `28` 位用于块号**，所以最多管理 `2^28` 个簇（与本章正文一致）。代价是 `FAT` **常驻内存**：`100 GB ÷ 1 KB × 4 B = 400 MB` |
| **隐式链接**读第 `i` 块 | 沿链画图一步步走 | `i + 1` 次（从第 `0` 块出发走 `i+1` 步） | 只适用于隐式链接（指针存在盘块里、`FCB` 只有首块/末块指针）。它**不支持随机访问**；连续分配、显式链接 `FAT`、索引分配才支持 |
| **位示图**块号换算 | 一位一位数着画 | 先统一基准再套式子：字号、位号、块号**都从 `0` 起** → `块号 = 字号 × 字长 + 位号`；**都从 `1` 起** → `块号 = (字号 - 1) × 字长 + 位号` | **必须先声明编号基准**。本章数值：字长 `32`、字号位号块号都从 `0` 起，"第 `100` 个字的第 `15` 位" → `100 × 32 + 15 = 3215`；若块号从 `1` 起则 `3216`。位示图大小：`N` 块需 `N ÷ 字长` 个字（向上取整） |
| 目录检索的**访存次数** | 凭感觉往上加 | 逐级累加：读目录块 `a` 次 + 读 `inode` 块 `b` 次（问"访问文件内容"再 + 数据块 `c` 次） | 先声明目录项形态：目录项 = "文件名 + `inode` 号"时，每级要**目录块 + `inode` 块**两次；目录项 = `FCB`（属性就在目录里）时**不再另读 `inode`**。根目录 `FCB`/根 `inode` 通常常驻内存，不计。每块目录项数 = `块大小 ÷ 目录项大小`（向下取整），装不下时按 `目录项数 ÷ 每块目录项数` **向上取整**算块数 |
| **索引顺序文件**最优分组 | 每一组都试算一遍 | 取 `g = 根号 N`，总平均查找次数 ≈ `根号 N` | 前提是**索引表也顺序查找**（块间顺序 + 块内顺序）；若索引表改用折半查找，此结论不成立。本章示例：`N = 10000`、`g = 100` → `(100+1)/2 + (100+1)/2 = 101` 次，远小于顺序查找的 `5000` 次 |
| **定长记录**定位 | 从头一条条数 | `地址 = 起始地址 + i × 记录长度`（`i` 从 `0` 起，直接算） | 只适用于**定长记录**；变长记录无法直接计算，只能顺序查找（除非另建索引表）。注意"定长 + 串结构"能按位置随机访问，但**按关键字**仍要顺序找，平均 `(N+1)/2` 次 |
| **成组链接**分配与回收 | 推演整条空闲链 | 口诀 **"先读后分，栈满先写"**：分配时栈里只剩"下一组栈块指针"→ 先把该块内容读入超级块当新栈，再分配该块本身；回收时栈未满直接压栈，栈满则走"写盘 → 清空 → 压入"三小步 | 分配回收都在**内存的超级块栈**上进行，**只在换组时读一次盘**。栈是**后进先出（取栈顶）**，不是队列。本章示例：依次分出 `100`、`99`、`1`，换组后栈顶变 `102` |

### 6.2 口诀与记忆钩子

- **口诀 1（访存次数）**："**直接一、一级二、二级三、三级四 —— 间接层数加一**"。适用条件：`inode` 已在内存、沿途索引块未缓存；否则读目录块和读 `inode` 块的次数要另加。
- **口诀 2（最大文件长度）**："**先除后乘，一级一乘，别丢直接**"——先算 `n = 块大小 ÷ 地址项大小`，从直接块起每深一级乘一次 `n`，最后乘块大小。专治两个高频错：漏掉 `10` 个直接项、把 `256²` 写成 `256 × 2 = 512`。
- **口诀 3（`FAT`）**："**表项随块走，位数定容量，代价常住内存**"。表项数 = 磁盘块数（与文件数无关）；`FAT` 常驻内存，所以"查表不产生磁盘 `I/O`"，只有题目明确问"包括查表动作"时才写成 `2` 次。
- **口诀 4（链接）**："**硬链接共享 `inode`，软链接自带路径**"，再补一句"**硬链接不能跨盘，软链接删源即断**"——硬链接计数减到 `0` 才真删文件；软链接有自己的 `inode`，源文件删掉后链接文件还在但失效。
- **口诀 5（位示图）**："**字号乘字长，加位号；基准不同，先折再加**"。位示图、计组的位运算、计网的掩码是同一套思路：先定位字号/位号，再做乘加。看到"第 `i` 个字""第 `j` 位"先问清是从 `0` 数还是从 `1` 数。
- **口诀 6（成组链接）**："**先读后分，栈满先写，取块后进先出**"——三句话分别对应分配、回收、顺序三个采分点，写大题时一句一条，过程分稳拿。
- **口诀 7（目录检索）**："**目录一次、`inode` 一次，逐级累加；根在内存不算**"。适用条件：目录项 = "文件名 + `inode` 号"；若目录项就是 `FCB`（属性含在目录项里），则 `inode` 那一次不另计。

### 6.3 反例黑名单（这些"简便法"是错的）

- ❌ **"`FAT` 也是索引分配，和索引分配一样"**：`FAT` 是**显式链接**——把整盘所有链的指针集中成一张表，只因"表常驻内存"才带来随机访问，本质仍是链接分配。正确做法是答"链接分配（显式），支持随机访问，`FCB` 只存起始块号，代价是 `FAT` 常驻内存"。
- ❌ **"位示图一律套 `块号 = 字号 × 字长 + 位号`"**：这个式子只在字号、位号、块号**都从 `0` 起**时成立。王道常见口径是三者**都从 `1` 起**，此时正确做法是 `块号 = (字号 - 1) × 字长 + 位号`；本章补充题"字号位号从 `0` 起、块号从 `1` 起"则是在 `3215` 上再加 `1` 得 `3216`。**先声明基准，再套式子**。
- ❌ **"问读一个数据块几次访存，二级间接答 `2` 次"**：正确做法是按"间接层数 + 1"答 **`3` 次**，并写出"一级索引块 → 二级索引块 → 数据块"；`2` 次是单级索引的答案，这是本章最典型的失分点。
- ❌ **"索引项是 `2 B` 时 `n` 还是 `256`"**：正确做法是每次重算 `n = 块大小 ÷ 地址项大小`（`1 KB ÷ 2 B = 512`），最大块数与最终答案随之改变。背数字而不背公式，是这类题最常见的翻车方式。
- ❌ **"隐式链接支持随机访问，可以直接定位第 `i` 块"**：只有连续分配、显式链接 `FAT`、索引分配支持随机访问；隐式链接读第 `i` 块要 `i + 1` 次访存，**不能**直接跳过去。
- ❌ **"逻辑块号可以用 `13000 ÷ 1024 ≈ 12.7` 四舍五入成 `13`"**：正确做法是**向下取整**得 `b = 12`、块内偏移 `712`；取成 `13` 会把一级间接下标算成 `3`，整题连锁出错。
- ❌ **"软链接会增加目标文件的链接计数"**：正确做法是"硬链接计数加 `1`、软链接**不变**"——软链接有自己的 `inode`，内容只是目标路径字符串，所以它还能跨文件系统、还能指向目录。
- ❌ **"混合索引最大文件长度算到二级间接就够了"**：本章选择题的 `C` 项 `64 MB` 正是"只算到二级"的产物。正确做法是四部分全列：`10 + 256 + 65536 + 16777216 = 16843018` 块 ≈ `16.06 GB`，漏一级就差三个数量级。
- ❌ **"成组链接分配时可以直接把'下一组栈块'分出去"**：正确做法是**先把该栈块的内容读入超级块**（栈内容被替换，即换组），**再**分配该块本身；跳步会让空闲块链断裂，这是本章大题的最大失分点。
