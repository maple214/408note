## 2. 专项包（本批 5 个，覆盖 23 道错题）

### 专项 1 · 进程 / 线程 / 调度 / 上下文切换

> 对应错题：23-27、23-29、24-24、24-25、24-28、25-23 ｜ 回链：[操作系统/02-进程与线程](../操作系统/02-进程与线程.md)

**① 判定口诀**

1. **状态转换一句话**：*"缺东西 → 阻塞；能跑没 CPU → 就绪"*。
   - 等 I/O、等信号量 `P` 失败、申请内存失败 ⇒ **阻塞**
   - 时间片用完、被高优先级抢占、I/O 完成、事件到来 ⇒ **就绪**（注意"I/O 完成"是**阻塞→就绪**，不是→运行）
   - 只有被调度程序选中才 **就绪→运行**
2. **周转时间三步**：① 抄下"到达时间、服务时间"；② 按算法**画时间轴**（抢占式要逐时刻检查新到达者是否抢断）；③ 周转 = 完成 − 到达，带权周转 = 周转 ÷ 服务时间。
3. **上下文切换换什么**：
   - 进程 ↔ 进程：PC、通用寄存器、**页表基址寄存器**（`PDBR`/`CR3`）、内核栈指针
   - 同进程内线程 ↔ 线程：**不换页表基址**（共享地址空间），只换 PC/寄存器/栈指针
   - **中断向量表基址寄存器**（如 `IDTR`）任何时候都**不必**换（所有进程进内核都走同一套）
4. **线程共享三件套**：代码段、数据段（全局变量）、打开文件表 **共享**；**栈、寄存器、PC、线程 ID 私有**。
5. **进程终止的"必做/不必做"**：必做 = 回收主存、关闭打开文件、撤销 PCB；**不一定做** = 把页面写回磁盘（未被修改的页无需写回）。

**② 易混对比表**

| 事件 | 正确结果 | 常见错选 |
| --- | --- | --- |
| 执行 `P(wait)` 失败 | 运行 → **阻塞** | 选"就绪" |
| I/O 请求发出后 | 运行 → **阻塞** | 选"就绪" |
| I/O 完成 | 阻塞 → **就绪** | 选"运行" |
| 时间片到 / 被抢占 | 运行 → **就绪** | 选"阻塞" |
| 进程切换 vs 线程切换 | 前者要换**页表基址** | 以为两者一样 |
| 中断向量表基址 | **不必**随进程切换更新 | 以为必须更新 |
| 同进程线程 | 共享数据段、打开文件表 | 以为共享栈 |

**③ 同类变式**

**变式 1.** 下列事件中，会使进程从**运行态**变为**就绪态**的是（　）
A. 等待的 I/O 操作完成　B. 时间片用完　C. 执行 `P` 操作失败　D. 申请内存失败
> **答案 B**。A 是"阻塞→就绪"，C、D 是"运行→阻塞"。

**变式 2.** 三个进程 P1、P2、P3 同时（t=0）到达，服务时间分别为 3、5、2（单位 ms），采用**非抢占式短作业优先**，则平均周转时间是多少？
> **答案 17/3 ≈ 5.67ms**。执行序 P3(2)→P1(3)→P2(5)，完成时刻 2、5、10 ⇒ 周转 2、5、10 ⇒ 平均 17/3。

**变式 3.** 同一进程内的两个线程之间切换时，**不需要**更新的是（　）
A. 程序计数器　B. 通用寄存器　C. 页表基址寄存器　D. 栈指针
> **答案 C**。线程共享地址空间，页表不变——这正是"线程切换比进程切换开销小"的根本原因。

**变式 4.** 同一进程内的多个线程**不共享**的是（　）
A. 代码段　B. 全局变量　C. 打开文件表　D. 栈
> **答案 D**。每个线程有独立栈（否则函数调用会互相踩）。

**变式 5.** 进程终止时，下列操作**不属于**操作系统必做回收动作的是（　）
A. 释放进程占用的主存　B. 关闭进程打开的文件　C. 撤销进程的 PCB　D. 把进程所有页面立即写回磁盘
> **答案 D**。未修改的页面无需写回；"进程终止"不等于"把整个地址空间刷盘"。

**④ 回链**：[操作系统/02-进程与线程](../操作系统/02-进程与线程.md) → 自测清单里的"状态转换图能默画""周转时间能算"两条。

### 专项 2 · IP 地址 / 子网 / CIDR / NAT / DHCP

> 对应错题：23-38、23-39、23-40、25-36、25-37 ｜ 回链：[计算机网络/04-网络层](../计算机网络/04-网络层.md)

**① 判定口诀**

1. **子网三问**：① 掩码 → **块大小 = 2^(32−前缀)**；② 网络地址 = 地址按位与掩码（块大小的整数倍）；③ **可用地址 = 网络地址+1 ～ 广播地址−1**（要减掉网络地址和广播地址两个）。
   例：/20 ⇒ 块 4096，第三字节按 16 分组（0-15、16-31、32-47…）。
2. **最长前缀匹配**：多条都匹配时取**前缀最长**的，不是路由表里第一条。
3. **NAT / NAPT 改什么**：出方向改**源 IP + 源端口**（NAPT；纯 NAT 只改 IP），入方向改**目的 IP + 目的端口**；**IP 首部校验和与 TCP/UDP 校验和都必须重算**。私有地址永不出现在公网。
4. **DHCP 四步**：Discover（源 `0.0.0.0` → 目的 `255.255.255.255`）→ Offer → **Request（同样是广播，源 `0.0.0.0`）** → ACK。
5. **IPv6**：128 位、首部固定 **40B**、**取消首部校验和**、路由器不分片（源端 PMTU）、`Hop Limit` 对应 IPv4 的 `TTL`、过渡技术 = 双协议栈 / 隧道 / 翻译。

**② 易混对比表**

| 项目 | 正确口径 | 常见错解 |
| --- | --- | --- |
| /20 子网可用地址数 | 2¹² − 2 = 4094 | 忘减网络/广播地址 |
| 最小可用地址 | 网络地址 + 1 | 直接用网络地址 |
| NAT 转发表 | 私有 IP:端口 ↔ 公网 IP:端口 | 以为只换 IP |
| 校验和 | IP 与 TCP/UDP **都**要重算 | 只改 IP 不动 TCP |
| DHCP Request | 广播（源 0.0.0.0） | 以为是单播给服务器 |
| IPv6 首部 | 无校验和、无分片字段 | 照搬 IPv4 结构 |

**③ 同类变式**

**变式 1.** 某主机地址 172.16.35.9，掩码 255.255.240.0。写出其网络地址、广播地址与可用地址范围。
> **答案**：网络地址 **172.16.32.0**、广播地址 **172.16.47.255**、可用范围 **172.16.32.1 ~ 172.16.47.254**（共 4094 个）。第三字节掩码高位 4 位有效 ⇒ 每 16 一段。

**变式 2.** 内网主机 192.168.1.5:3000 访问 202.1.1.1:80，`NAPT` 路由器公网地址 203.1.1.1（分配端口 4000）。转换后的（源 IP, 源端口）与（目的 IP, 目的端口）分别是？哪些字段需要重算校验和？
> **答案**：源变成 **203.1.1.1:4000**，目的保持 **202.1.1.1:80**；**IP 首部校验和与 TCP 校验和都要重算**。

**变式 3.** 主机首次用 DHCP 获取地址时，`DHCPREQUEST` 报文的源 IP 与目的 IP 分别是（　）
A. 0.0.0.0 与 255.255.255.255　B. 本机地址与服务器地址　C. 0.0.0.0 与服务器地址　D. 本机地址与 255.255.255.255
> **答案 A**。Request 也是广播——此时主机还没拿到地址，也不知道哪个服务器会确认。

**变式 4.** 路由表：10.0.0.0/8→R1、10.1.0.0/16→R2、10.1.2.0/24→R3、0.0.0.0/0→R4。目的地址 10.1.2.7 从哪条转发？
> **答案 R3**（/24 前缀最长）。

**变式 5.** 下列关于 `IPv6` 的叙述中，**错误**的是（　）
A. 地址长度 128 位　B. 首部中包含校验和字段　C. 用 `Hop Limit` 代替 `TTL`　D. 可通过隧道技术实现与 IPv4 共存
> **答案 B**。IPv6 取消了首部校验和（把差错检测交给上下层，减少路由器开销）。

**④ 回链**：[计算机网络/04-网络层](../计算机网络/04-网络层.md) → `CIDR` 聚合/最长前缀匹配那一节。

### 专项 3 · 排序算法的性质与过程反推

> 对应错题：23-10、24-8、24-11、25-10 ｜ 回链：[数据结构/08-排序](../数据结构/08-排序.md)

**① 判定口诀**

1. **稳定性口诀**："**插冒归基**"稳定（插入、冒泡、归并、基数）；其余（**选择、希尔、快排、堆**）不稳定。
2. **过程反推——看"谁就位/哪里有序"**：
   - **快速排序**：每趟至少一个元素**落到最终位置**，且它**左边全 ≤ 它、右边全 ≥ 它**（"块间有序 + 一个就位"）
   - **堆排序（大根堆）**：序列**尾部逐渐有序**，前面的部分是堆
   - **直接插入**：**前缀有序**（前 i 个已排好）
   - **冒泡**：**后缀有序**（末尾 i 个已就位）
   - **希尔**：整体不有序，但**每个增量分组内有序**
   - **归并**：出现长度 2、4、8… 的**有序块**，块与块之间无序
3. **移动/比较次数**：
   - 元素移动次数**与初始序列无关**的是 **基数排序**（分配+收集，不比较）
   - 简单选择排序移动次数最少（≤ n−1 次），但**比较次数**恒为 n(n−1)/2
   - 比较次数与初始序列无关的是**简单选择**与**归并**
4. **败者树**：每个内部结点存**败者**的段号，**冠军（最终胜者）另存在根之上**。

**② 易混对比表**

| 算法 | 一趟后的特征 | 稳定 | 与初始序列无关的量 |
| --- | --- | --- | --- |
| 直接插入 | 前缀有序 | 是 | — |
| 冒泡 | 后缀有序（最大值到位） | 是 | — |
| 简单选择 | 前缀就位（最小值到位） | 否 | 比较次数 n(n−1)/2 |
| 快速排序 | **轴枢就位**，左右分块 | 否 | — |
| 堆排序 | 尾部有序（堆顶逐次到末尾） | 否 | — |
| 希尔排序 | 组内有序、整体无序 | 否 | — |
| 归并排序 | 长度 2^k 的有序块 | 是 | 比较次数（近似） |
| 基数排序 | 按位稳定收集 | 是 | **移动次数** |

**③ 同类变式**

**变式 1.** 对序列 {49,38,65,97,76,13,27,49} 采用快速排序（取第一个元素为轴枢）进行**一趟划分**，结果序列是什么？这一趟保证了几号元素就位？
> **答案**：{**27,38,13,49,76,97,65,49**}；轴枢 49 落到**第 4 个位置**（下标 3），它左边全 ≤49、右边全 ≥49。识别技巧：看"有没有一个元素左边都比它小、右边都比它大"。

**变式 2.** 下列排序算法中，**一趟结束后一定能确定至少一个元素最终位置**的是（　）
A. 直接插入排序　B. 冒泡排序　C. 快速排序　D. 堆排序
> **答案 B、C、D**。冒泡把最值送到端点、快排让轴枢就位、堆排序把堆顶送到末尾；**直接插入排序每一趟都不保证任何元素在最终位置**。

**变式 3.** 判断"简单选择排序不稳定"的一个具体反例（用三个元素说明）。
> **答案**：对 {2, 2', 1} 做简单选择排序——第一趟选最小值 1 与首元素 2 交换 ⇒ {1, 2', 2}，原来的 2' 跑到了 2 前面 ⇒ 不稳定。

**变式 4.** 下列排序方法中，元素**移动次数与初始排列次序无关**的是（　）
A. 直接插入排序　B. 起泡排序　C. 快速排序　D. 基数排序
> **答案 D**。基数排序靠分配与收集，不做元素比较，移动次数只与位数和元素个数有关。

**变式 5.** k 路归并中的败者树，其每个内部结点保存的是（　）
A. 胜者的归并段号　B. 败者的归并段号　C. 该段的最小关键字　D. 该段的最大关键字
> **答案 B**。结点里记"输家"，一路比上去，**冠军**在根上方单独保存——所以叫"败者树"。

**④ 回链**：[数据结构/08-排序](../数据结构/08-排序.md) → "各排序算法性质对比表" + 稳定性口诀。

### 专项 4 · 存储系统：Cache / TLB / MMU / 虚存

> 对应错题：23-15、24-16、24-17、24-18 ｜ 回链：[计组/03-存储系统](../计组/03-存储系统.md)

**① 判定口诀**

1. **算地址位数的固定顺序**：**先块内偏移，再索引（组号），最后标记**。
   - 块内偏移位 = log2(块大小)
   - 直接映射：索引位 = log2(行数)；组相联：组数 = 行数 ÷ 路数，索引位 = log2(组数)
   - **标记位 = 地址位数 − 索引位 − 偏移位**
2. **`TLB` 的组相联**：把**虚页号**再切一刀——**组号 = 虚页号低 log2(组数) 位**，**标记 = 虚页号高位**（标记位数 = 虚页号位数 − 组号位数）。别把它和"物理地址算 Cache"混起来。
3. **访存次数判定**：
   - `TLB` **命中 ⇒ 不访存页表**；`TLB` 缺失才去遍历页表（多级页表要多次访存）
   - `Cache` 命中 ⇒ 不访主存
   - **直写（Write Through）**：每次写都要写主存 ⇒ 访存次数多；**回写（Write Back）**：需要**修改位（脏位）**，Cache 每行多 1 位
4. **谁触发异常**：**缺页 ⇒ 异常**（OS 处理）；**TLB 缺失、Cache 缺失 ⇒ 不是异常**（硬件/固件处理）；保护位违规 ⇒ 越权异常。
5. **主存-CPU 连接**：先由"容量比"定片数，再定片内/片间地址划分；**`ROM` 在高地址区**时从后往前排地址。

**② 易混对比表**

| 项目 | 正确口径 | 常见错解 |
| --- | --- | --- |
| 标记位 | 地址位数 − 索引 − 偏移 | 忘记减偏移位 |
| TLB 标记 | 虚页号高位（虚页号 − 组号位数） | 用物理地址算 |
| TLB 命中 | **不**访存页表 | 以为仍要访存一次 |
| 缺页 vs TLB 缺失 | 前者是异常，后者不是 | 混为一谈 |
| 回写方式 | 每行要加 1 位修改位 | 只算"有效位" |
| Cache 总容量 | 数据 + 标记 + 有效位（+修改位） | 只算数据位 |

**③ 同类变式**

**变式 1.** 主存地址 32 位、按字节编址，Cache 数据区 32KB、块大小 64B、**4 路组相联**。求块内偏移位数、组索引位数与标记位数。
> **答案**：块数 = 32KB/64B = 512，组数 = 512/4 = **128** ⇒ 偏移 **6 位**、索引 **7 位**、标记 = 32 − 7 − 6 = **19 位**。

**变式 2.** 虚页号 20 位，`TLB` 采用 **8 组 4 路**组相联，则 TLB 的组号与标记各是多少位？
> **答案**：组号 = log2 8 = **3 位**，标记 = 20 − 3 = **17 位**。

**变式 3.** 承变式 1、2：该 Cache 采用**回写**方式，则其总容量（按位）是多少？
> **答案**：每行 = 数据 64×8 + 标记 19 + 有效位 1 + 修改位 1 = **533 位**；总 = 533 × 512 = **272896 位 ≈ 266.5 Kb（≈ 32.75 KB）**。

**变式 4.** 下列事件中，**会触发异常**（需要操作系统介入处理）的是（　）
A. `TLB` 缺失　B. `Cache` 缺失　C. 缺页　D. 分支预测失败
> **答案 C**。缺页由 OS 的缺页处理程序完成调页；A/B/D 都可以由硬件处理。

**变式 5.** 若某次取数时 `TLB` 命中且 `Cache` 也命中，则至少需要访问主存几次？
> **答案 0 次**。TLB 命中免去了页表访存，Cache 命中的数据直接从 Cache 取。

**④ 回链**：[计组/03-存储系统](../计组/03-存储系统.md) → "Cache 映射与地址划分""TLB 与页表"两节。

### 专项 5 · MAC / 以太网（退避 / VLAN / ARP / NAV）

> 对应错题：23-36、24-35、24-36、25-35 ｜ 回链：[计算机网络/03-数据链路层](../计算机网络/03-数据链路层.md)

**① 判定口诀**

1. **二进制指数退避**：第 i 次冲突后从 {0,1,…,2^k−1} 中随机取一个时隙，其中 **k = min(i, 10)**；**最长等待 = (2^k − 1) × 争用期(2τ)**。
   - 10Mbps 以太网的**争用期 = 51.2µs**（512 bit 时间，即 64B 的最小帧长）
   - **连续 11 次冲突 ⇒ k 封顶 10 ⇒ 上限 1023 个时隙**（23-36 与 25-35 考的就是这个"封顶"）
2. **VLAN**：用来**划分广播域**；同一交换机上**不同 VLAN 之间通信必须经路由器或三层交换机**；802.1Q 标签插在**源 MAC 之后**。
3. **ARP**：请求用**广播帧**（目的 MAC = `ff-ff-ff-ff-ff-ff`）、应答用单播；表项是 **IP → MAC**；**跨网段时解析的是默认网关的 MAC**（数据帧的目的 MAC 永远是下一跳的 MAC）。
4. **`NAV`（`CSMA/CA`）**：站点收到 `CTS` 后按其中时长设置 `NAV` 并静默。总时长按图算：**SIFS + 数据帧 + SIFS + ACK**（2024-36 的官方口径即 28+296+28+2 = **354µs**）。

**② 易混对比表**

| 项目 | 正确口径 | 常见错解 |
| --- | --- | --- |
| 退避窗口上限 | k = min(i,10)，11 次后封顶 1023 时隙 | 以为一直翻倍 |
| 争用期 | 10Mbps 以太网 = 51.2µs | 记成 5.12µs |
| ARP 请求的目的 MAC | 广播 ff-ff-ff-ff-ff-ff | 写成目的主机 MAC |
| 跨网段数据帧目的 MAC | **默认网关**的 MAC | 写成目的主机 MAC |
| VLAN 隔离的域 | 广播域 | 说成"冲突域" |
| 不同 VLAN 互通 | 必须经三层设备 | 以为交换机自动通 |

**③ 同类变式**

**变式 1.** 10Mbps 以太网上某站点连续发生 5 次冲突后，第 6 次冲突时的退避窗口最大是多少个时隙？最长等待时间是多少？
> **答案**：k = min(6,10) = 6 ⇒ 窗口 = 2⁶ = **64 个时隙**，最大等待 = 63 × 51.2µs = **3225.6µs ≈ 3.23ms**。

**变式 2.** 同一台交换机上属于不同 VLAN 的两台主机要通信，必须经过（　）
A. 该交换机　B. 路由器或三层交换机　C. 集线器　D. 网桥
> **答案 B**。VLAN 隔离的是广播域，跨 VLAN 属于三层转发。

**变式 3.** 主机 A 与主机 B 同网段，A 的 ARP 表为空。A 发往 B 的**第一个以太网帧**的目的 MAC 是（　）
A. B 的 MAC　B. ff-ff-ff-ff-ff-ff　C. 网关 MAC　D. 00-00-00-00-00-00
> **答案 B**。ARP 请求必须广播；B 的应答才是单播。

**变式 4.** 主机 A 访问 Internet 时，其 IP 分组被封装的以太网帧的**目的 MAC** 是（　）
A. 目的服务器的 MAC　B. 默认网关的 MAC　C. 广播地址　D. 本机 MAC
> **答案 B**。跨网段转发靠网关，目的 MAC 始终是"下一跳"的 MAC。

**变式 5.** 在 `CSMA/CA` 中，某站点收到 `CTS` 后设置 `NAV`。若数据帧传输时间 296µs、ACK 传输时间 2µs、`SIFS` = 28µs，则 `NAV` 应设为多少？
> **答案 354µs**（28 + 296 + 28 + 2）。这正是 2024 年第 36 题的官方口径——**记住"两个 SIFS 夹一个数据帧，再加 ACK"**。

**④ 回链**：[计算机网络/03-数据链路层](../计算机网络/03-数据链路层.md) → "退避算法""VLAN""ARP 与 MAC 帧"三节。
